# D120: Custom fields, phase 3

**Custom fields, phase 3: money, flexible content, the store, customers and orders as things with fields, a loop block, field values on grid tiles, and range filters.** A money field is an amount in a currency the store offers, shown in the market's currency at the store's rates (its own when no rate is known), never as a price: no VAT, no chat, no structured data. Flexible content is a list of rows of owner-defined layouts, stored like a repeater's (shared structure, words by row id).
The store has one set of values for site-wide facts, shown through `source: 'store'` on the fields components and on bindings, also in headers and footers. Customer and order fields are staff-only by rule (own groups, no rules, nothing public, no files or pictures), never read on the shopper's side (a test lists every reader of the values), and a customer's go with the customer.
The loop block draws a repeater's rows from slots (not a nested builder); a content grid can show up to three plain fields on its tiles, read in one batch; number and measurement fields filter as ranges. Left: money in bindings, customer and order fields in exports beyond `customerFieldExport()` (nothing calls it yet), guests' fields (values are by customer account), a measurement range across units.
