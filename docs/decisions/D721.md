# D721: A/B tests as a plan's feature

**A/B tests as a plan's feature: a number of running tests per plan (D148 phase 21, `docs/ab-testing.md` "What phase 21 built"; 17 November 2026, `ab_tests_running` in `src/lib/limits.ts`, `testRoom()` and `plansWithTests()` in `src/server/experiment-admin.ts`).** A/B tests are a plan limit of D314: `ab_tests_running` is how many tests a store runs at once, set per plan, as the platform default or for one store on Platform → Plans → Limits and the store's platform page; 0 is a plan without
A/B tests, a number lowers the engine's five and never raises it, no number is five. A plan without them makes no test (`createExperiment()`, so the form, the builder and `draft_experiment`) and its New A/B test page shows what tests give, the plans that have them and *Choose a plan* to Billing; a start, a schedule, the scheduler and `start_experiment` refuse past the plan's number in its words.
A store that moves to a smaller plan keeps its running tests counting until they are decided; a scheduled one goes back to a draft that says why. The AI manager's `list_experiments` and `suggest_experiments` say the plan's number. The plans' cards say it (nothing at 0, five for no limit). Kaizena Flow's own store, templates and starters are never limited, as every D314 limit.

Date: 2026-11-17

Asked for by the owner ("start phase 21"); Open question 2 asked on/off or a number, and a number holds both, on the screen the owner already sets plan limits on. *Why no plan has a number yet:* the owner chooses which plans include tests; until then every store keeps the five it had, and the comparison's row "A/B tests of pages" is ticked by hand in those plans. *Why a full plan may still draft:* a draft shows nothing, and starts when a test stops.
