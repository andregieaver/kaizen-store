# D235: Kaizen's page builder gets a theme, as stores' have

**Kaizen's page builder gets a theme, as stores' have.** Kaizen's pages and stores' pages are edited by one `PageEditor` and `PageBuilder`; what differed was the context Kaizen's route gave them: no theme (so no Theme tab, no saved colours and gradients, no theme laid under parts, no theme colours for the contrast checker).
Kaizen now has `platform_settings.theme`, kept in a store's shape and read by `parseStoreTheme()` through `platformTheme()`: Minimal until changed, which is exactly what Kaizen's site always drew (`globals.css` holds Minimal's values; a screenshot of the front page before and after is identical), with Kaizen's fonts (`platform_settings.fonts`, its Fonts page) laid over it.
The platform layout draws it as a store's layout does (`StoreThemeStyles`, `themeAttributes()`), `themeElementsFor(null)` lays it under Kaizen's pages, and the builder's Theme tab and saved colours save it through `savePlatformThemeTab()`/`savePlatformThemeLibrary()`, which share the store's pure steps. Still a store's only, by design: custom fields (D118), A/B tests (D148), feature switches (D178), translation (Kaizen's site is English) and visibility conditions about shoppers (D179 phase 4).
Templates (D125, D127) are built around a store (who sees one, activations, the preview's address), so Kaizen's builder can save a page as a template but not browse or apply one yet (answered by D236). Migration version: `20261014193518_platform_theme`, applied by CI in the `release` job on 14 October 2026; advisors checked after: no new finding.
