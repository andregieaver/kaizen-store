# D665: Every picture keeps an 800 px copy, and a grid tile says its real width

**Every picture keeps an 800 px copy, and a grid tile says its real width (bloat review step 0.33; 16 November 2026).** A picture wider than 800 px is stored with a third file beside the picture (at most 1,600 px) and its 480 px copy: `media.medium_url` and `medium_path`, made in the owner's browser (`mediumCopy()`, which raises a portrait picture's bound until the copy is 800 px wide) or by the server's own picture makers (AI pictures, edits, imports, content packs, the API's uploads, copied
pages). It is stored, copied (store copies, sandboxes), compressed, AI-marked and deleted with the picture; compressing removes the old copy even when the original is kept, since nothing else names it. Product tiles, content grids and the product gallery offer the three files by width; a picture stored before has none and is offered as its two files, as before.
`gridSizes()` claims a tile as the screen less the page's sides (`GRID_GUTTER`, 32 px) and the grid's gaps, shared by its columns, in place of a plain `50vw`: on a 3x phone a tile now takes the 800 px file at 390 px and the 480 px file at 360 px (both took the 1,600 px file before). Kaizena Flow's own library is the same code. Migration versions (applied by CI run 1388, 16 November 2026 10:04 UTC): `20261116035930_media_medium_copy`. Advisors after: INFO only.
