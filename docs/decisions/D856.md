# D856: Contract words as rich text: a paragraph's and a clause's doc beside its plain text

Date: 2026-11-20

**A contract's words are written in a rich text editor, not a plain textarea (asked by the owner, 20 November 2026).** A draft's and a
template's paragraphs and clauses were plain text, so a list, a word in bold or an emphasis could not be written.

- **What a contract takes** (`src/lib/contract-rich.ts`, pure): paragraphs, bulleted and numbered lists (nested), line breaks, bold,
  italic and underline. No heading inside a block (a heading is its own block), no link (the PDF renderer refuses every request, and a
  signed document should not point elsewhere), no colour, no text style, no quote and no line: `contractDoc()` checks a document as any rich
  text (`cleanRichText()`) and then cuts it to these, turning a pasted heading or quote into paragraphs.
- **Stored beside the text, not instead of it:** a `paragraph` or `clause` block gains an optional `doc` (Tiptap JSON). Its `text` stays,
  always the document's words as plain text (`contractDocText()`: paragraphs apart by an empty line, "- " and "1. " before list items),
  worked out by `parseBlocks()` on save and never taken as sent. So fields (`fieldsIn()`), the AI manager's contract tools, the template
  preview and the limits read `text` as before, and every block and snapshot written before keeps working with no migration (jsonb).
- **Filled in the same way:** `fillContract()` fills the `doc` with the same fields and values as the `text` (`fillContractDoc()`); a field
  partly bold is still one field, its value taking the marks of where it starts. The snapshot's filled block carries the `doc` (version
  stays 1: the field is optional and older snapshots draw as before).
- **Drawn as elements:** `ContractDocumentView` draws a block's `doc` node by node (`<p>`, `<ul>`, `<ol>`, `<li>`, `<br>`, `<strong>`,
  `<em>`, `<u>`), never as HTML; the signing page, the admin's preview and the PDF are the same view.
- **The editor** (`ContractTextEditor`, loaded lazily through `lazy/editors.tsx`): bold, italic, underline, bulleted and numbered lists,
  undo and redo, and *Insert a field*, which puts `{key}` where the cursor is, so Homer needs no braces. A block written before opens as its
  text made a document (`docFromText()`: an empty line starts a paragraph, a new line is a line break). `BlocksEditor` keys each block so
  a moved block keeps its editor. Words in English and Norwegian (`contracts.format`).
- **Platform:** Kaizena Flow's own contracts are its house store's (D466), so they have the same editor.

Tests: `src/lib/contract-rich.test.ts`, `src/lib/static-markup.test.ts` (a formatted clause drawn as React draws it),
`e2e/signed-in/contracts.spec.ts` (a clause made a list is drawn as one).
