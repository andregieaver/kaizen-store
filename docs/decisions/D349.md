# D349: Pictures made and edited by AI in the library and the product editor

**Pictures made and edited by AI in the library and the product editor (wave 8 unit E, `docs/wave-8-analytics-ai.md` section 4, E); built.** *Make with AI* is in the media library (`MediaLibrary`'s `pictures`, feature `library_pictures`) and in the product editor's pictures (`/admin/{store}/products/picture`, `products:write`, the brief started from the product's title, never a price), the same dialog and `makeSitePicture()` as D283's (`place` names the feature); the picture is shrunk to WebP
with its small copy and kept in the library. A library item says who made it: `media.made_by` (`person`, `ai_made`, `ai_edited`; existing AI pictures marked by their `ai-….webp` name and AI alt text written as they were stored), shown as a chip in the list and a row in the details.
A made picture's alt text from the request is kept only when it passes `findClaims()` (`checkedAlt()` in `src/server/ai-pictures.ts`), else left empty for the alt-text run (D89). *Edit with AI* on a library picture (decision 3: the provider's edit endpoint): *Remove the background*, *New background* and *Change*, both described (`EDIT_ACTIONS`, `editPrompt()` in `src/lib/picture-edit.ts`, keeping the subject and `MADE_PICTURE_RULES`), sent only by `editLibraryPicture()`
(`src/server/picture-editor.ts`) through `editImage()` (`src/server/ai.ts`: the picture provider's OpenAI-compatible `/images/edits`) with the AI settings' new *Model that edits pictures* (`ai_providers.image_edit_model`, never a model in code; the field says the picture itself goes to that provider).
The file sent is the library's own, read from Storage by its row (`downloadStoredFile()`, the `product-media` bucket only, 20 MB), never an address a person typed, as a PNG of at most 1024 px; the result is a new library item (`made_by = 'ai_edited'`, `edited_from` the original, set null if the original goes; the database's checks `media_made_by` and `media_edited`), the original never overwritten, metered `per_image` under the feature `picture_edit`.
Without an edit model the action shows as unavailable with its reason and a link to the AI settings. Routes: `/admin/{store}/media/edit` (`website:write`) and `/admin/platform/media/edit` (platform admins), `maxDuration` 300, same site. An edited picture is an ordinary library file for `mediaUses()` and the store copy. Closes `ai.ai-image-generation` and `ai.ai-image-editing` in the tracker.
Migration versions: `20261028020002_media_made`, applied by CI at 03:29 UTC on 28 October 2026 (with D350's; the run for D349 alone failed a test before release); security and performance advisors INFO only.
