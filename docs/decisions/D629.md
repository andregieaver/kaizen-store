# D629: Read one page, not all of them

**Read one page, not all of them (bloat review step 0.24; 15 November 2026).** `publishedPageById(owner, id, type)` reads one published page and `publishedPageIndex(owner, type)` a small index of a site's published pages (id, address, title and its translations, flags, blog, dates), both 'use cache' under `pagesTag(owner)` with `owned()`, so a publish or delete refreshes them as it does the list.
The front page, Kaizena Flow's role pages, a blog's listing page, the exchange and pay pages, the sandbox and theme previews and checkout terms read the one page; the legal links, the site chat, the account pages, the static params, a blog article, Kaizena Flow's navigation, the page AI and robots.txt read the index. `listPublishedPages()` is left to readers that draw every document (14 lines, 37 before; `pages-list.scan.test.ts` holds that none uses it to pick one page).
The blog's `blogArticles()` still reads the list, since a listing reads each article's categories: 9 prerendered blog entries keep it, until an index carries the categories. Kaizena Flow's own site uses the same reads (owner null). No migration. Commits 530962c1, e72252eb, 0eeff7ab.
