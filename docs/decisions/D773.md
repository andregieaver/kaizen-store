# D773: The production build in CI, tried as a prebuilt preview first

**The production build in CI, tried as a prebuilt preview first (bloat review step 1.29, commit 1; 18 November 2026).** `next.config.ts` splits Vercel's settings: the two that only save memory (`turbopackFileSystemCacheForBuild: false`, `cpus: 1`) follow the machine that builds (`TIGHT_MACHINE`, Vercel's own and not a GitHub runner), and the source-map switches stay on every Vercel deployment, so what production runs and logs does not change; `scripts/next-build.mjs` keeps the 7 GB heap on a
runner. CI gets a manual job, `prebuilt_trial` (Run workflow), that prints the runner's size, builds the commit with `vercel build` and deploys it prebuilt as a preview only, and puts the preview's `/api/health` in the summary; it never prints, uploads or caches what `vercel pull` writes.
Before it can run: the Actions secrets `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` (and `VERCEL_TOKEN`), a database for the build's prerender (a seeded Postgres in the job is preferred to a Preview `DATABASE_URL`), and no production variable marked Sensitive that the build needs.
Commit 2, production deploying the prebuilt output, waits for the trial and for a decision on how it meets D710's newer-push check and D741's deploy fallback (which builds on Vercel's machine), and on the order of two runs (deploy with `--skip-domain`, check again, then promote). The repository is public, so the runner's minutes are free. Commit efe24bc8.
