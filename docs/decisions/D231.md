# D231: The rest of the admin draws in the type scale and shapes

**The rest of the admin draws in the type scale and shapes (`docs/admin-style.md` section 8, step 15).** A codemod over the admin's pages and components (not the builder, the theme editor, previews or print): every `button`, `Link` and `a` is a pill (a bordered one in the `edge` role, as the components are), and so are the shared button constants (`work-parts`, `data/ui`, `privacy/styles` and each file's own); a section's `h2` is `text-title text-ink` and a sub-section's `h3`
`text-body-strong text-ink` (in place of `font-medium` with an ad hoc size); an old figure (`text-2xl font-medium`) is `text-metric text-ink tabular-nums`; the old uppercase label is `text-eyebrow`; and a bordered box inside the page (`rounded-lg … border-line`) is a `rounded-panel`, a sunken notice without its border. Work's shared `card` and the analytics `ChartCard` are cards (`CARD_CLASS`). About 1,000 class lists in 300 files; fields (`input`, `select`, `textarea`) keep their shape.
`admin-type.scan.test.ts` refuses a square button or link (and a square filled or bordered button constant), a `font-medium` section title, the old figure and the old eyebrow. Left: tables that are tables keep their own markup, and white bordered boxes on the canvas are panels rather than cards where code cannot tell where they sit. No migration.
