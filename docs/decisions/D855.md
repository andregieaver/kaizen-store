# D855: The AI manager reads and starts flows: list_flows and start_flow (email plan M3.9)

Date: 2026-11-20

**The AI manager, and the autopilot through it, can see a store's flows and start the ones it lacks (20 November 2026).** Until now
flows (D767) had no tool: the manager could list and write the older email automations but not say which flows run, what they
brought or which goal the store has no flow for, so the autopilot could not propose one (email plan M3.9).

- `list_flows` (read, `marketing:read`): each flow's name, whether it is on, what starts it (`storyLead()`), who started it and the
  orders after its emails in 30 days (`flowReport()`), and why the flow guard switched it off when it did; then the goals without a
  flow, each with whom it would reach now in the store's own data (`flowProposals()`: joined, bought, not ordered for 90 days, bought
  twice; counts only, never who).
- `start_flow` (write, `marketing:write`, no gate): a flow from one of those goals through `startRecipeFlow()`, the same function as the
  Flows page's Start (the owner's own automation's words when they wrote one, else the recipe). It is saved switched off and untested,
  so nothing is sent; switching it on stays on the flow's page after a test, never a tool. A goal that already has a flow is refused.

Both are Email automation's (`owner-tool-features.ts`); `list_flows` is among the reads a goal's review may use (`autopilot-reviews.ts`).
The agents' eval recording is behind the tools until the next run on Platform → AI (D793: it warns, it does not fail).

Idle cost: none per request or run; two tools more in each store's tool list (the surface budget raised by two, and the marketing
round's tool text), sent only in turns that load the marketing area.
