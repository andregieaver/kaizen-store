# D869: Schemas live apart from their helpers; zod loads where a screen runs one

**Schemas live apart from their helpers; zod loads where a screen runs one (bloat review step 2.46; 21 November 2026).** Each
`src/lib` file that held zod schemas beside plain helpers keeps its helpers and constants, and its schemas move to a `*-schema.ts` file
beside it (custom fields, product input, theme, motion, visibility, hover timing, SEO, term SEO and taxonomy, inventory, navigation,
colour library, DAC7, work input and the Work forms, draft input, bonus and referral settings, search rules and synonyms, AI provider,
campaigns, SMS, segments, workflows, stock documents, eBay, discounts, drop shipping, privacy requests, store copy, the support widget,
broadcasts, contract fields, cart reminders, returns, product writing). No helper imports zod or re-exports a schema as a value. Locally
the routes with zod in their first scripts fell from 132 to 60 and the admin client modules reaching zod from 143 to 61; a Work page
fell about 150 KB (`/admin/account/work` 811,885 to 658,820 bytes). `admin-bundle.scan.test.ts` holds a closed list, `ZOD_ALLOWED`: 20
modules that run a schema on their own screen and 41 builder, content, theme and template modules that reach zod through the page model
(code review step 3.1); any other module that reaches zod fails it. The product editor is 1,118,175 bytes against the brief's 1,100,000:
its terms card runs `termRulesSchema` in the browser, which the brief keeps. Each split adds a leaf to the server entries that import both
halves; the route-load rows were moved by exactly that, named in each commit. Live from 21 November (e1fe6feb0). To check on production:
a product save and a field group save still show their empty-name messages. Idle cost: none. Commits ..e1fe6feb0.
