# D582: Chat widgets on the owner's own websites, each with its own look, on one tag per widget

**Chat widgets on the owner's own websites, each with its own look, on one tag per widget (13 November 2026, `docs/support-embed.md`; step 1 of 4 built).** Asked for by the owner: the support chat on external websites with nothing more than a tag in the footer, restricted to the site holding the tag; then, the same day, several widgets per account, each on several sites, with their own styling to match any site design.
A desk (a store's, or Kaizena Flow's) has up to 20 widgets (`commerce.support_widgets`: name, public key, market, privacy page, `style`), each on up to 20 sites (`commerce.support_widget_sites`: host, found by page or DNS); never copied with a store.
The tag loads `public/embed/chat.js`, which frames `/embed/chat/{key}/{host}` from Kaizena Flow's own origin, sent with `frame-ancestors https://{host}` from its own address (`embedFrameHeaders()`); the frame draws the same `ChatWidget` only on a site of that widget whose tag was found (front page through `safeFetch()`, or a TXT record `kaizena-flow-chat={key}`), so the chat's routes still refuse every other origin (`sameSite()` unchanged) and carry the widget's key and the page's host to
`chatPlace()`. The look (`src/lib/support-widget-style.ts`: button colour, background and text colours, corners, side, offsets, icon or words, panel width, font, greeting, own CSS run only in the frame) is drawn by `widgetCss()` over the store's theme, in the frame and in the admin's live preview; the frame tells the loader its state and the room it needs.
There the AI searches only the knowledge base's documents (`embedTools()`, `systemPrompt({embed})`), nobody signs in (no order tools; the sign-in and confirm routes refuse), and `page_path` keeps the site's host for the staff. Admin: Support → Website chat (`/admin/{store}/support/widgets`, `/admin/platform/support/widgets`). Steps 2 to 4 (the sites' own pages read by a crawler, more per widget and figures, the WordPress plugin adding the tag) are in the plan.
