# D241: Themes as one thing

**Themes as one thing (phase 1 of `docs/theme-store.md`).** A design profile is a *theme* in the interface (the store's Design settings, the platform's page titled *Themes*); code keeps `design_presets`. A theme's every Publish of a new look is a version (`design_preset_versions`, append-only, numbered, written in Publish's own statement).
A store has a **theme library** (`store_theme_installs`): several installed, one live by a unique index, every store with its live *Custom* from its first moment (a trigger on `stores`, and a backfill naming the profile a store wears). The live install's look stays in the store's own columns, so nothing a visitor sees changed and every reader is as before; an install that is not live keeps its look in its row.
Applying a theme now installs it and makes it live, the look before put away with every change made to it (no more "Before …" saved theme); *Switch to* swaps in one transaction with the kept look checked as it goes in; *Put back the look from before* switches back; a theme not live can be removed (its pages stay). The plan's one-time page migration (4.4) is a pure, exact `detachThemeValues()` run only as a dry run from the platform's store page. `docs/theme-phase-1.md` is the contract.
