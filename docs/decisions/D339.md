# D339: Private mode

**Private mode (wave 7 unit E, `docs/wave-7-storefront.md` section 4, E); built.** A store is private (`stores.private_mode`, with `private_password` as a scrypt hash and `private_version`, written only by `src/server/private-mode.ts` and audited) or public.
The proxy, from the store's facts it already reads every few seconds (`privateGate()`), serves every page request of a private store from a visitor without a good unlock pass (`kaizen_unlock_{storeId}`, HttpOnly, a signed token of `src/lib/unlock-pass.ts`: `password` for 30 days under the store's version, `staff` for 12 hours) its landing page: the page role `private`, built in the page builder with the *Password* component, drawn at `/s/{store}/private/{market}` under a root layout of its own
(the store's theme, nothing of its header, search, cart, chat or extras), `noindex` and never cached; the pages of what was already sold stay open (`privateDecision()`). The password is posted to `/api/private/unlock` (tries counted by `takeBudget()`), staff use *Preview the store* (`/api/private/preview`, handed to the store's own host by `/api/private/enter`, D193's pattern).
A private store is in no sitemap or llms.txt, its robots.txt disallows all, and its product feeds, chat and recommendations answer no locked visitor. Settings → *Private mode* switches it, sets or removes the password and signs everyone out.

Date: 2026-10-27

*Why:* `storefront.storefront-password-or-pre-launch-page`; decision 5 (a new store is private until it opens: the column's default is on, `completeSetup()` opens it, and the migration left every opened store, template and demo store public).
The landing page has a layout of its own because the market layout's header, search action and chat would reach the catalogue; a store's facts that cannot be read leave requests alone, as the address's own decisions do, so a database hiccup never takes every store down. The test databases (e2e and integration) start stores public, since their stores stand for open ones; the private-mode tests switch it on, and `commerce.test.ts` holds the real default.
No AI manager tool changes it: a password never passes through a model. Migration versions: `20261027165126_private_mode`, `20261027165146_private_mode_sql` (applied by CI in the `release` job on 27 October 2026 at 18:39 UTC; advisors checked after: no warning, INFO only (RLS on with no policy, new indexes not used yet)).
