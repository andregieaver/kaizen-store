# D526: A quick gate before every deploy, and a release waits for every suite

**A quick gate before every deploy, and a release waits for every suite (9 November 2026, `.github/workflows/ci.yml`, `pnpm test:smoke`, `docs/ci-migrations.md`; steps 0.1 and 0.2 of `docs/audits/code-review-2026-11.md`, findings FH1 and FH2).** The owner: *go* on a wait of a few minutes between a push and production.
It changes D5's "deploys to production" at once. **A push without a migration** now runs lint, the type check and the unit tests of money, cart, checkout, discounts and VAT in the `pending` job, before that job calls the deploy hook; a failure deploys nothing. Until now such a push was live before any check had finished, and Vercel's build skips the type check (D378), so a type error reached production unseen.
The gate sits in `pending` and not in a job of its own, so a push still waits for one runner. **A push with a migration** now also needs `hosts` and `signed-in` green before `release` applies the file: they were left out of `needs`, so a migration and its deploy could go out with the signed-in admin or the stores' own hosts broken. **Not built: going back by itself** when a full check fails after a deploy.
It needs a Vercel token as a repository secret and must never undo a newer good deploy; it stays open as the rest of step 0.2. **The platform:** one pipeline deploys the stores and Kaizena Flow's own site, so this covers both. No migration.

Date: 2026-11-09

The review's first finding: nothing held a broken push back.
