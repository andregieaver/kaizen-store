# D280: A look's swatch is drawn in the colours it is shown in

**A look's swatch is drawn in the colours it is shown in.** `swatchOf()` read every look's light palette, so a look that is always dark (Orbit and its presets, Arcade and its presets, Atelier's Noir, Botanica's Night garden, Calm's Ink, Signal's Volt) had a swatch in colours its pages never show (Orbit: cream and blue for a near-black and gold store), and presets that differ only in their dark colours (Orbit's Mars and Nebula, Arcade's Terminal and Vapor) had the same swatch.
Now it takes the palette `baseScheme()` names, the one rule `themeCss()` also draws a theme by: the dark one only when the theme is always dark, else the light one, which a device in light mode and every photograph show (`src/lib/color-mode.ts`, free of zod, as the theme store's client components read the swatch).
Everything drawn from the swatch follows: the dots of the presets on a theme's page and full-screen preview, a card without a picture, *See it live*, the share image drawn from colours, and the backdrop of the highlights, which are composed again for the themes whose own look is always dark (Orbit and Arcade: migration `20261018231022_theme_highlights_dark`, pushed after the code was live so the old code could not compose them first).

Date: 2026-10-18

The owner: "Make sure the colour swatches depict the actual colour scheme of each light and dark preset; they are way off." `theme-store.test.ts` holds every launch theme's looks to the palette each is shown in, and no two looks of a theme to one swatch.
