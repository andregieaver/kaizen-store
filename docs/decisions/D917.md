# D917: Admin API: headers, footers, menus, looks from settings, and an article's first date

Date: 2026-11-28

**The Admin API makes and changes everything a site is built from, not only its pages: headers and footers, menus, looks of the theme
library from theme settings, and an article's first date, each through the admin's own writer and its checks. What visitors see changes
only with the power `content:publish`.** Asked for by the owner while Kaizena Life's site moves into its Flow store (D916): "extend the
Admin API so the importer can make them" (the header, footer and menus), "extend the API" (so the 38 articles keep Life's dates), and
"Do this for me" (Life's theme on the real store).

- **Headers and footers** are pages of their own type (D80), so they live under `/pages`: `type` on `POST /pages` and `GET /pages`, and
  get, update and publish find a row's own type. Each saves through `savePage()` with that type, so a header holds the site's parts as the
  builder offers them, and a page holds none of them.
- **Menus**: `POST /menus` and `PATCH /menus/{id}` go through `saveStoreMenu()`, the menu editor's own save. A menu is not drafted: a change
  to one visitors see (the standard header's or footer's, or named in a published page, header or footer) takes `content:publish`, as a
  published entry's new address does.
- **Looks**: `POST /themes` makes a look of the store's own from theme settings as Design settings keep them (`addOwnLook()`, checked by
  `checkStoreTheme()`), with its own CSS, header and footer; `PATCH /themes/{id}` changes one that is not live (`saveInstallLook()`, which now
  also takes a name, a header and a footer); `POST /themes/{id}/live` makes it live through `switchToInstall()`, Design settings' own switch,
  with `content:publish` (the power the AI manager's `make_theme_live` asks the owner's yes for). A look carries its header and footer, so
  one call makes a site's whole look live; the answer names a header or footer that is not published yet, since the standard one shows
  until it is. `GET /themes/{id}` also answers the look's header, footer and settings whole, so a caller can change one and send it back.
- **An article's first date**: `first_published_at` on `POST` and `PATCH /articles`, for an article brought from another site. It is not in
  the future, and publishing keeps it (`savePage()` keeps a first date it finds), so the site dates the article and orders the blog by it.
  Changing it on an article already on the site takes `content:publish`. The date is checked before anything is saved.
- **Store-only**: Kaizena Flow's own API is read-only (D518) and its own site is written in its admin, so the platform gets nothing here.
  The article date is the API's alone for now; a date field in the article editor's settings is the next step if owners ask to backdate by
  hand.

Idle cost: none. Five new routes and two new fields, read and written only when called.
