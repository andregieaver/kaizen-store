# D848: Admin words load by area: each page imports the areas it names

**Admin words load by area: each page imports the areas it names (bloat review step 2.25; 20 November 2026).** Every admin word area
and every cut of step 2.27 has its module in `src/lib/admin-words/` (110 modules), and a page, layout, route or action reads the
module of each area it names. `src/lib/admin-text.ts` keeps only the areas' types: no table of every area, no `adminText()` or
`adminTexts()`, no value import; `cut()` moved to `src/lib/admin-area.ts`. Tests read every area through `src/test/admin-words-all.ts`.
`admin-text-reach.scan.test.ts` holds what an admin entry reaches: the median 4 areas and 213,137 bytes of catalogues (77 catalogues
and 4.03 MB by any path before), the largest entry (a platform article) 24 areas and 1,736,127 bytes, the platform home 18 areas and
1,126,541 bytes, each only falling. On stand-in builds the orders page's server chunks fell 13,077,616 to 11,223,862 bytes, the
largest admin-store entry 13,656,607 to 12,102,611 and the largest platform entry 13,511,856 to 11,871,363 (route budget lowered).
Nine English defaults became required words. A Norwegian owner's and the platform admin's 26 screens showed no fallback and no raw
key. Kaizena Flow's platform admin reads its areas the same way, so the platform has it in the same change. Live on production from
20 November (5853b6f). Idle cost: none. Commits b702fa1f5..61c5dae7d.
