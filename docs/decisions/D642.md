# D642: pg_cron's own run log is kept to seven days

**pg_cron's own run log is kept to seven days (bloat review step 0.25; 15 November 2026).** `cron.job_run_details` grew by one row a run and nothing pruned it: 402,474 rows, 650 MB of an 824 MB database when the owner was shown the counts (every run succeeded; it holds no shop data).
With the owner's go-ahead the migration `20261115185237_cron_run_log_retention.sql` emptied it once (TRUNCATE where the role may, else a delete of rows older than seven days) and scheduled the pg_cron job `kaizen-cron-log-retention` (03:41 daily) to delete rows older than seven days; a database without pg_cron skips the block, and `src/db/cron-log-retention.test.ts` holds the file to the reviewed SQL. Nothing reads the log: the app's ledger of jobs is `commerce.cron_jobs`.
The baseline was not edited (D572); the job is folded into the scheduler block at the next squash. Rejected: an hourly batch delete (the runner allows 10 minutes, a day adds about 13,250 rows) and pruning from the app's daily route (the app's role has no business in the cron schema). One scheduler, so the platform's jobs are covered too. Migration versions (applied by CI run 1346, 15 November 2026 21:48 UTC): `20261115185237_cron_run_log_retention`.
Production after: 442 rows, 848 kB; the database 176 MB. Advisors: INFO only.
