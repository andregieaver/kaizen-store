# D572: Migrations squashed to a baseline

**Migrations squashed to a baseline (code review step 1.7, finding FD3; 11 November 2026, `scripts/squash-migrations.mjs`, `scripts/db-migrate.mjs`, `src/db/migration-files.ts`, `supabase/archive/20261111172838/`, `docs/ci-migrations.md`).** 789 migration files in 47 days (9.2 MB) were replayed by every fresh database: CI's jobs, a lane's template, `db-setup.mjs` and the tests' PGlite template.
They are now four: the three sections of a `pg_dump` of a database built from them all (schema, the reference data they wrote, then keys, indexes, triggers and row security), and one kept by hand for what one database's dump cannot carry (the `postgres` role's limits; on Supabase only, Storage's buckets, the scheduled jobs and the scheduler's secret, written from production as it stood, each guarded).
Each starts `-- kaizen:baseline-through=20261111172838_sms_campaign_index.sql`: an empty database runs it, and production's runner, whose ledger has that file, records it without running it.
The script builds a database from the files and one from the baseline and compares their dumps before it writes: the schema the same line by line but for 63 checks whose parentheses Postgres regroups, the data the same row by row; a rehearsal on a copy built from the 789 files with all of them in its ledger recorded the four and ran nothing.
The squashed files move to `supabase/archive/`, outside every path that applies migrations; the tests that read an old file or replay history (the VAT migration on old data) find it through `src/db/migration-files.ts`; Drizzle's journal lists the baseline in their place. *Why:* a fresh database's cost grew with every change; it now takes about five seconds. *Rejected:* Supabase's own `db dump` (it needs the CLI and a live project, and would dump production's drift as well as its schema); one
dump file (PGlite and `postgres.js` cannot read `COPY … FROM stdin`, so the data goes as inserts, and the sections keep a restore's order: data before keys and triggers). Repeat each quarter.
