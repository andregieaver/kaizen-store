# D94: Each store has an owner assistant in its admin, modelled on Kaizen Life's, working on its own

**Each store has an owner assistant in its admin, modelled on Kaizen Life's, working on its own.** Owners (not other staff) talk or type to it at `/admin/{store}/assistant`; it runs a tool loop with the store's own AI (D73, `streamWithTools()`: the answer streams in, with a line saying which tools it uses) over a catalogue of the store's reads and writes (`OWNER_TOOLS` in `src/lib/owner-tools.ts`, handlers in `src/server/owner-tools.ts`): the store at a glance, sales over a period (sums, refunds
and averages worked out in code, never by the model), orders, products, stock, bookings, coupons, pages and searches; notes on orders; and changes. The catalogue has Kaizen Life's shape (name, description, arguments as JSON Schema from zod), so the store's MCP server can serve the same tools.
Changes that send something in the store's name, change what the site shows or cost money pass the approval gate, as Kaizen Life's: the exact call is kept (`assistant_approvals`) with a description written by code from its arguments and the store's data, the owner approves or declines it on a card under the answer, and approving runs that call once (claimed in one update), writes it to the audit log and says in the conversation what happened.
Conversations are the owner's (`assistant_conversations`, `assistant_messages` with the tools used, never their data), kept until deleted; 300 messages a day per store. It needs nothing from Kaizen Life; connecting Kaizen Life only adds tools.

Date: 2026-09-28

Asked for by the owner, as the store side of connecting Kaizen Life's and Kaizen Store's assistants; the store's must stand alone.
