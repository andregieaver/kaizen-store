# D908: The phone app, a Capacitor shell around the admin, for iPhone and Android

Date: 2026-11-26

**Kaizena Flow as an app, as Kaizen Life is (26 November 2026, the owner: "I want the same for the kaizena Flow").** Decision 6 of
`docs/parity-plan.md` said native apps were not worth it yet. A thin shell changes that sum: the app loads the deployed admin, so there is
no second code base and every web deploy reaches it. How to build, sign and release it is `docs/mobile-app.md`.

- **The shell** (`capacitor.config.ts`, `android/`, `ios/`, Capacitor 8.6): `com.humanweb.kaizenaflow` (never changed once published),
  named Kaizena Flow. It loads `https://kaizenaflow.com` (`CAPACITOR_SERVER_URL` at sync) and starts at `/admin` (`appStartPath`).
  Never `/admin` as the address itself: on iPhone, Capacitor sends any address that does not start with it to Safari, `/auth/…` included.
  Its own pages are `capacitor-www/`: the offline page (`server.errorPath`, the admin's offline words, held by a test) and the index
  Capacitor requires. Icons and splash screens are drawn from the platform's icon (`resources/`).
- **The app says it is the app**: `appendUserAgent` adds the word `KaizenaFlowApp` (`NATIVE_APP_MARK`, `isNativeAppAgent()`,
  `src/lib/native-app.ts`). Capacitor adds nothing by default, so without it the server cannot tell.
- **Signing in.** A password, the two-step code and an email's link work as in a browser. Sign in with Kaizen Life (D95) opens in the
  phone's browser, as the app opens every other site there, and comes back at `kaizenaflow://auth/callback` (`signInReturnUrl()`); the app
  opens that as `/auth/callback` in its own web view, where the sign-in's PKCE cookie is (`nativeOpenPath()`). An email's sign-in link
  (`/auth/confirm`, a token hash) opens the app once the link files are served: `/.well-known/apple-app-site-association` and
  `/.well-known/assetlinks.json` (`appLinksEnv()`: `APPLE_TEAM_ID`, `ANDROID_APP_SHA256`; each 404 while empty). Never `/auth/callback`
  as an app link: its code works only in the browser that asked, so a web sign-in on a phone with the app would break.
- **In the app only.** `NativeApp` (the admin's root layout, sign-in included) loads `src/lib/native-app-bridge.ts` with `import()` when
  Capacitor's bridge is there, so a browser fetches none of it. It opens the addresses handed to the app, each once (an iPhone hands
  the launch address twice; `kaizen_native_launch` in session storage, in `KNOWN_COOKIES`), sets the status bar for the admin's colours, and saves
  downloads: a web view saves no file, so a press on an `<a download>` fetches it with the person's session and hands it to the phone's
  share sheet (`downloadName()`).
- **Not yet, the next steps:** push to the app (Web Push never reaches a web view: FCM and APNs, and a device table beside
  `push_subscriptions` written only by `src/server/push.ts`); no plan purchase in the app before App Store review (guideline 3.1.1, as
  Kaizen Life does); downloads that are no `<a download>` (the capacity CSV, the orders export page, a form's download); order links in
  emails opening the app.
- Operator: `kaizenaflow://auth/callback**` among the redirect addresses of Supabase Auth in this project, the two settings, signing and
  the store records (`docs/mobile-app.md`).

The app is the admin, the platform admin included: nothing in it is store-only. Idle cost: nothing on the server; two small public files.
