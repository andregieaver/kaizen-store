# D88: Each site has a media library of every picture and video it uploaded, anywhere in the admin, with where each is used

**Each site has a media library of every picture and video it uploaded, anywhere in the admin, with where each is used.** `commerce.media` keeps one row per file (the store's, or Kaizen's with a null store): its address and small copy, Storage bucket and paths, name, type, size, width and height (read from the file's first bytes on upload, `imageSize()`, else measured by the browser when shown) and a description.
Every upload action registers its file (`uploadToLibrary()`, `registerVideo()`); files uploaded before are read from `storage.objects` by the migration. The library (`/admin/{store}/media`, `/admin/platform/media`) adds files in bulk, and searches as the storefront does: keyword (the name's words and the description, with prefixes and trigrams) and, with the site's AI, meaning (`media_embeddings`, the name, description and uses embedded in the five-minute cron), merged by reciprocal rank fusion.
Where a file is used is worked out when asked (`mediaUses()`: products and variants, pages of every type, draft or published, menus, saved parts, the logo and icon, search and sharing, the theme, the chat agent's picture), never stored. Deleting removes the file from Storage after a confirmation that lists those places. AVIF is accepted wherever pictures are uploaded (shrunk to WebP in the browser as the rest).

Date: 2026-09-28

Asked for by the owner. Registering at upload keeps one list of what the site owns without scanning Storage on each visit; working out uses on request means a deleted page or a changed menu is never reported stale. Pictures keep their addresses, so pages that use one keep working until it is deleted, which is why the confirmation says where.
