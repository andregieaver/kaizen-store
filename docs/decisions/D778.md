# D778: Page lists, pickers and grids open no document

**Page lists, pickers and grids open no document (bloat review step 2.17; 18 November 2026).** The Pages and Articles lists read the columns of step 2.16 (D775) instead of two documents a page, show 100 a page with the admin's shared pager (`ListPager`) and start their reads together; the list's sentence and the own-page pickers read `pageTitles()` (with `live` and `publishedAt`), so they still see every page.
A grid of pages or articles draws its cards from SQL (`pageCards`, `pageCardColumns` in `src/server/pages.ts`) and opens a document only for a card with no excerpt (one statement for all of them); the feed reads 50 cards, filtered by blog and market in SQL, and no document; the static params, the search picker and the blog's categories read the index. Documents read per page locally: a cold store home 1, a built page 1, a product page 0, the blog listing 0.
The ratchet holds every statement that may return whole page documents: `pageDocuments` (17 that can return many rows, each with its reason) and `pageDocumentsOneRow` (33 single-page reads); an unnamed statement or a stale entry fails. The list's unpublished-changes flag compares draft and published inside the database, so neither document leaves it.
Sitemaps and llms.txt still read `listPublishedPages()`: moving them needs stored pictures and excerpts that only a change to `savePage()` could write. A document that does not parse now shows its stored title in a list and, without an excerpt, in a grid. CI green on 13522625. Commits e07b10f7, 31149ddb, d6ea1499, bf4d7b87, 13522625.
