# D306: Custom CSS on the live site

**Custom CSS on the live site.** Beside *Edit text* (D192), staff who may change a page's words there have *Custom CSS*: the builder's CSS panel over the published page (`src/components/inline-edit/site-css-editor.tsx`, loaded only when opened), with the page's own CSS and, for those who may change the website (`website:write`, a platform admin for Kaizena Flow's), the whole site's.
While it is open the page shows the CSS as typed (the site's own `<CustomCss>` styles for it switched off by their `data-href`, the typed CSS drawn in their place, a CSS with a problem not drawn); closing without saving puts the page back.
Saved through `/api/platform/editor/css` (`src/server/page-css-edit.ts`): same site only, checked by `cssProblem()` as the builder does, refused when either CSS changed since it was read (the revision of both), for a page that is not published or in a running A/B test, written into the page as visitors see it and into the draft where the draft still has the CSS the page had (otherwise it keeps its own and the person is told), kept as a version (D305), audited
`{store|platform}.{page|article}_css_edited` with the length, never the CSS; the site's CSS through `saveSiteCss()`. On a store's own domain the editing pass answers as for the words (D193).
