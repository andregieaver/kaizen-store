# D234: Signed-in admin tests

**Signed-in admin tests.** The e2e suite could only see the admin signed out, which kept several parity rows Partial (D158 onward).
`e2e/fixtures/auth-stub.mjs` is a stand-in for Supabase Auth (password and refresh-token grants, `/user`, logout; HS256 tokens, so `getClaims()` asks `/user`, as it does for a real HS256 project), and CI's `signed-in` job builds the app with `NEXT_PUBLIC_SUPABASE_URL` pointed at it, so the admin's own sign-in form, `readSession()`, the two-step gate (`factors: []`, no platform admin) and the permissions run unchanged: nothing in the app knows it is a stand-in, and no test bypass was added to it.
`e2e/signed-in/auth.setup.ts` makes a store as the platform approves one (past its setup), an owner, a Read-only member and a member who never acts, signs the first two in through the form and keeps their browser states; specs choose one with `test.use()`. The tests run only with `E2E_SIGNED_IN=1` (otherwise they are not Playwright projects at all), so the main e2e job, built without Supabase, is unchanged.
First specs: what each person may open (a refused page is the 404), the activity log's person filter (D158 fix of 2026-10-14) and bulk price editing with its confirmation and undo. The job is not yet one `release` waits for, like `hosts`.
