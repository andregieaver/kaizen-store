# D879: An email's own HTML block, cleaned by sanitize-html on the server each time it is sent (email plan M4.1)

Date: 2026-11-23

**An email's own HTML block (23 November 2026, email plan M4.1, for Lisa).** An owner who writes HTML could not put a table, a styled
box or an exact layout in a marketing email; the blocks cover Homer, and Lisa needed one step further.

- The block keeps the HTML as written (at most 20,000 characters) and the server cleans it each time it is sent or previewed:
  `cleanEmailHtml()` in `src/server/email-html.ts`, with `sanitize-html` 2.18.2, the one new package (server only; the owner allowed it on
  23 November). An allowlist: text, headings, lists, tables, links and pictures; inline styles of look only (colour, size, spacing,
  borders, alignment); no scripts, styles, forms, frames, classes, ids or event handlers, and the words inside a removed script or style
  are dropped too. A link keeps only an https, mailto or tel address, a picture only an https one, and the send check asks that picture
  be the store's own library's, as any picture in an email.
- Cleaning at send, not at save, means a rule made stricter later applies to every email already written, and HTML that came in another
  way (the API, a saved block) is never sent as written. `buildBroadcastEmail()` takes the cleaner as an argument and leaves the block out
  without it, so no screen loads the package and nothing sends raw HTML.
- Personal fields are filled before the cleaning, so a reader's name can never add markup. Links in the block are not tracked: presses
  are counted on the blocks Homer uses.
- In the editor it sits under *More blocks*, out of Homer's way; *Show how it looks* draws the cleaned HTML in a frame with an empty
  `sandbox`, so nothing in it runs or reaches the admin.

Idle cost: none; the cleaning runs only for an email that has the block.
