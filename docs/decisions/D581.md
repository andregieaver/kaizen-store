# D581: Code outside the admin reads admin words through per-area modules

**Code outside the admin reads admin words through per-area modules (bloat review step 0.7; 13 November 2026, `src/lib/admin-words/`).** Eighteen areas that code outside `src/app/admin` and `src/components/admin` reads (assistant, books, common, customReports, customers, experiments, invoices, oauth, order, platformSite, platform, reports, sandbox, screens, signIn, staffEmails, website, work) each have a module `src/lib/admin-words/{stem}.ts` exporting `{AREA}_WORDS: Record<AdminLang, Messages>`
with both languages; `admin-text.ts` builds its registry from them, so the two never differ. The 35 files outside the admin that imported the registry (the email senders, the two-step sign-in, staff alerts, reports, Work, the platform's site and more) index `{AREA}_WORDS[lang]` with the language they passed before.
`src/lib/admin-text-reach.scan.test.ts` fails when a file outside the admin imports the registry and holds each shopper entry to a ceiling of catalogue files, as a floor too so a fall is written down: the proxy 10, each of the four visit beacons 3, `/api/recommendations/events` 2, the storefront layout 14 (135 each before; 0 of 282 entries outside the admin now carry the admin's words, 255 before).
