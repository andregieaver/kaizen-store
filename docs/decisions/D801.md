# D801: The session is kept by Supabase's auth client alone

**The session is kept by Supabase's auth client alone (bloat review step 2.31; 19 November 2026).** `SessionKeeper` refreshes the
session with `@supabase/auth-js` alone (`src/lib/supabase/auth-client.ts`, which mirrors `@supabase/ssr`'s cookie options and is
loaded with `import()` once the page is idle); the full Supabase client (realtime, storage, the Data API) loads only on an upload's
press. A scan in `admin-bundle.scan.test.ts` holds that no admin client module imports the full client statically. Measured in
the signed-in build: an idle store home 953,731 to 812,820 bytes of script, orders 798,324, none of the realtime, storage or
database client in either. The brief's ceiling of 800,000 is not reached, so the budget holds today's figure (the rule from step
0.43). On production the owner checks that a tab left open past the access token's hour opens the next page without the sign-in
screen. Commits c666734f5, dca90b410.
