# D299: Discounts in depth

**Discounts in depth (wave 5 unit E, `docs/wave-5-marketing.md` 7), built in four steps; E1 codes in depth.** A code (`discount_codes`) may reach products in chosen categories and tags (`term_ids`, matched through `termsOfProducts()` like campaigns, `reaches()`) as well as chosen products, ask for a minimum number of items (`min_quantity`, 1 to 1,000, units of the lines it reaches that are bought once and cost something today: `minimum_quantity`), and be for customer groups (`tier_ids`) or up to
100 named customers (`customer_ids`, typed as emails and kept as ids): a guest is asked to sign in, anyone else gets `not_eligible` (hand-written nb, sv, da, en).
A code may hand out single-use codes instead (`unique_codes`; its own text is then no code): `discount_code_items`, made by `generateCodes()` (1 to 10,000 at a time, 100,000 per code, a prefix and eight characters without look-alikes from `randomBytes()`, never the text of another code or generated code of the store: unique index and the trigger `discount_code_text_unique()`), each used by one order not cancelled (`orders.discount_code_item_id`, counted under the item's row lock in
`placeOrder()`; the code's own limits do not apply to them), and downloaded as a CSV (code, used, made on) from the code's page (`marketing:write`, audited `discount.codes_generated`/`codes_exported` with counts only). The order keeps the generated text as its `discount_code`. A store's copy carries the new settings with its own categories and groups, never its customers (a code for named customers is copied switched off) or generated codes (`never`).
Steps to come: several codes per order under each code's combination choice (E2), automatic amount off, free shipping and tiers (E3), buy X get Y (E4). **E2, several codes on one order (2026-10-21):** a code is of one class (`codeClass()`: `shipping` for free shipping, `products` for one naming products, categories or tags, `order` for one on everything) and says which classes it may be used with (`discount_codes.combines_with`, empty by default, so every code there today keeps working alone);
two are used together only when each allows the other's class (`combines()`). The cart holds up to five codes (`carts.discount_code` the first, `more_codes` the rest; applying adds, a sixth is `codes_full`), each removed by itself.
Which apply is only `stackCodes()` (pure): of every set whose codes all combine, applied in turn (product codes, then order codes, then free shipping, each counting what the ones before it left, no line below zero) and all still applying, the one taking most off, the first typed winning a tie; every other code says why (its own reason, `not_combinable` with the code it cannot be used with, or its reason beside the others).
`stackForBasket()` (all codes locked first, in id order) is what `cartSummary()`, the checkout's code field and `placeOrder()` use; a code that fails on its own still stops the checkout, one left out beside a better one does not.
The order keeps the codes used joined by ` + ` in `discount_code` (so invoices, emails, exports and Stripe's one coupon need nothing new), the first's ids, every code in `order_discount_codes` with what it took off (fixed by a trigger), and every code typed in `entered_codes` (the changed-cart check compares those).
A code's uses and a generated code's use count its places in `order_discount_codes` too; the analytics coupon table counts an order under each of its codes, the discount split by what each took off. `duplicate_store()` carries `combines_with` (patched in place); `order_discount_codes` is `never` in `COPY_RULES` and in `NOT_PERSONAL`.
Words `m.codeProblems.not_combinable` and `codes_full`, nb, sv, da and en by hand; the editor's *Using it with other codes*. **E3, campaigns in depth (2026-10-21):** three more kinds of campaign, worked out by the same `applyCampaigns()` in the cart and in `placeOrder()`.
An **amount** off (`campaigns.amounts`, per country in its own currency, optionally over a threshold) competes with the percentages and the "3 for 2" for the lines still free, split over the lines it reaches by what each costs (`splitAmount()`, largest remainder, never more than a line costs); it does not stack.
A **tiered** campaign (`tier_basis` `quantity` or `spend`, two to five `tiers`, each step asking for more and giving more) takes the percentage of the highest step its reached lines come to (`tierPercent()`) and may stack (it then counts its lines before any reduction). **Free shipping** (optionally over a threshold, counted after the reductions) is decided after the price campaigns and gifts, the oldest that qualifies, takes the order's whole first shipping before codes, never with a
subscription; it is part of the order's `discount_minor` and `campaign_discount_minor` (so the invoice's campaign row and the shipping's VAT follow as a free-shipping code's do) and kept as `orders.campaign_shipping` (`{ id, name, minor }`, a check holds it within the campaign discount); a campaign's uses and what it gave count it beside the lines' parts (`ordersOf()`). Amounts reach the cart in the currency shown (`shownIn()`).
`nextSteps()` says how far a campaign's next step is (a tier's next step, an amount's or free shipping's threshold), only where no other campaign holds the lines; the cart shows it (`nextStepText()`). Notices say an amount, free shipping and a tier's ladder (`m.campaigns.*`, nb, sv, da, en by hand); cards carry only percentages, "3 for 2" and *Up to n % off*.
`duplicate_store()` carries the new columns (patched in place). **E4, buy X get Y (2026-10-21):** a campaign of kind `bxgy`: its reach is the buy set, one use asks for `buy_min_quantity` units or `buy_min_amounts` per country (exactly one), the get set is `get_product_ids`/`get_term_ids` (both empty: the buy set), and each use gives up to `get_quantity` units `free`, at `get_percent` or `get_amounts` off each (never more than a unit costs), at most `uses_per_order` times.
`bxgyOff()` (pure) counts the dearest unused units of the buy set as bought and gives the cheapest unused units of the get set, never one counted as bought; a use that gives nothing does not count. It competes for lines with the other price campaigns, takes every line it counted or gave, does not stack, and the shopper adds the given units themselves; the order keeps it on the given lines' campaign parts.
Notices on the products of both sets (*Kjøp 2, få 1 gratis*, `m.campaigns.bxgy*`, nb, sv, da and en by hand), on cards only when it needs no amount. The database check is one `campaigns_bxgy` wrapped in `coalesce(…, false)` (a null would pass a check). `duplicate_store()` carries the columns with the get set remapped and switches off a copy whose get set lost everything (patched in place).
