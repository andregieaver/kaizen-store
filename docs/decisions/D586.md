# D586: AI-translated interface text costs what it uses

**AI-translated interface text costs what it uses (bloat review step 0.8; 13 November 2026, `src/server/ui-text-read.ts`, `src/lib/ui-registry.ts`).** The reader of `commerce.ui_translations` is a file of its own, `src/server/ui-text-read.ts`: the start hook (`src/instrumentation.ts`) and the pages import it, never `src/server/ui-text.ts`, which holds the tools that make the text, so the hook reaches 12 files where it reached 383 (no AI SDK, no schema, no admin words).
An instance reads the text at start with two statements whatever the number of languages (one for the stamp and each language's version, one for every changed language; one in all with none), and registers makers, not built messages: `registerMessages(lang, { makeUi, makeEmail, texts })`, and `registeredUi()`/`registeredEmail()` build a language on its first read and keep it, so an instance never asked for a language never builds it (a maker that throws is dropped and the language reads as
English; a new maker drops the build before it). `commerce.platform_settings.ui_text_version` is a one-row stamp raised by the two writers of the table, `saveRows()` (each saved batch) and `clearUiTexts()`; `markUiReviewed()` changes no text and does not raise it.
The timer is a chain of ten-minute timeouts (`POLL_MS`, no `setInterval`) that reads only the stamp, and only on an instance that was asked for a translated language since its last tick (`uiTextsFor()`, `returnsTextsFor()`); the languages are read again only when the stamp moved; the shopper and staff emails call `ensureUi()`, which polls the same way.
So an edit on Platform → Languages reaches another instance within ten minutes, where it reached it within one, and an idle instance costs no statement: 2 statements in an unserved day and 146 in a served one, where the minute's poll of the whole table made 1,440 a day per instance.
The browser gets only what its components read: `uiTextsFor()` hands `UiTexts` the 114 keys of `en-browser.ts` (under 9 KB, where it sent all 1,673 texts, 93 KB), and the withdrawal page sends its own with `returnsTextsFor()` and `<UiTexts part="returns">`, which `returnsText()` lays over the English.
Kaizena Flow's own site in more than one language (D312) reads through the same reader: nothing to tick in `docs/platform-parity.md`. *Why:* findings SG-5, SF-3, SD-7, TX-3, TX-12 and others of `docs/audits/bloat-review-2026-11.md`: every instance read and built every translated language at start, polled the table each minute for ever, and sent each visitor's browser the whole catalogue.
