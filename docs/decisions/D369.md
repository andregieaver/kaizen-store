# D369: Sign-up with a password, and no live payments before a store opens

**Sign-up with a password, and no live payments before a store opens (wave 10 unit F, `docs/wave-10-must-haves.md` 4); built.** The self-serve confirmation page (D359) offers an optional password (the rules of `src/lib/password.ts`): `confirmSelfSignup(token, { password })` checks it against the request's address before the link is used (a weak one is refused as `password`, worded in English and Norwegian, and the link still works), makes the store as before, then sets the password through
Supabase Auth's admin API (`setOwnerPasswordWithSupabase()`: a new user with the address confirmed, or the existing one's password; injectable for tests), and the page says to sign in with it; a password that could not be set leaves the emailed link and never undoes the store.
`startCheckout()` refuses a live payment for a store that is still private with its setup not completed (`not_open`, worded in the four languages): whoever has the private password cannot pay a store that has not opened, while its owner tries checkout in test mode; `completeSetup()` opens it. `platform.self-serve-sign-up-and-onboarding` moves to full. No migration.
