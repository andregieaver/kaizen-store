# D518: Kaizena Flow's own API

**Kaizena Flow's own API (C4 step 4 of `docs/platform-parity-plan.md`, 9 November 2026, `commerce.platform_api_tokens`, `src/lib/platform-api.ts`, `src/server/platform-api-tokens.ts`, `src/server/platform-api.ts`, `GET /api/platform/v1/…`, Platform → Settings → Integrations → API).** The owner: *continue* (C4's steps 3 and 4).
The stores' Admin API (D355) for the platform's own tools (a dashboard, a script, a spreadsheet), and **read only**: its owners' stores, each with its plan (`/stores`, `/stores/{id or address name}`), the plans and their prices (`/plans`), the requests for a store by state with who asked (`/requests`, the operator's own leads, as Zapier and Make get them, D465) and the home's figures (`/figures`, D513).
A token (`kfp_` and 32 random bytes, kept only as its SHA-256, shown once) is made by a platform owner with the scopes it needs (`stores:read`, `plans:read`, `requests:read`, `figures:read`) and reads as them, read again on every call: a revoked token, or one whose maker is no longer an owner of the platform or whose account is disabled, is a 401.
Each call: a scope it lacks is a 403 naming it, the request budget `api` (120 a minute a token) a 429; money in minor units with its currency, lists by `limit` (at most 100) and `before` (a `created_at`). Under `/api/platform`, where the live editor's routes already are (`docs/security.md` 2.11), and not in the stores' API contract: it is Kaizena Flow's, not a developer's. A write (approving a request, changing a plan) is a decision of its own when one is wanted.
This ends C4: own endpoints and *Add to Slack* (D515), workflows (D516) and this API.
