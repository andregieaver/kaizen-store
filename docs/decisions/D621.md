# D621: The challenge's order and stock tools and order events

**The challenge's order and stock tools and order events (`docs/100-day-challenge.md` C2, C3, C5, C6; 15 November 2026, `src/server/supply-tools.ts`, `src/lib/purchase-budget.ts`, `src/lib/purchase-order-email.ts`, `src/lib/autopilot-events.ts`, migration `20261115120423_lethal_prism`).** Four owner tools. **`cancel_order`** (C6) cancels a paid order that is not sent with the order page's own `cancelOrder()`, which refunds it in the same step, so it is in `NEVER_AUTOMATIC` and a refund in the
intervention log (`REFUND_TOOLS`): in the challenge it waits in the owner's refund queue; an order sent, partly sent, unpaid or with a change waiting is refused before anything is kept (`orderToCancel()`). **`create_purchase_order`** (C3) makes and places a purchase order with the screen's own `createPurchaseOrder()`/`placePurchaseOrder()` (a line's cost from the variant when none is given and the order is in the main currency) and emails it to the supplier when the store has a supplier of that
name with an order address, in its order language (email kind `supplier.purchase_order`, no person's details); area `money`, and the autopilot places one itself only within the purchasing budget, `budgets.purchasePerOrder` and `purchaseMonthly` in the main currency (`purchaseBudgetProblem()`: no budget, another currency, a month in more than one currency, or over either asks; the month counts every order placed this UTC month), set by the owner on the Autopilot page or by the challenge
(`challengeSchema.purchasePerOrder`/`purchaseMonthly`, on the console). **`list_supplier_orders`** and **`answer_supplier_order`** (C2) read the drop-ship suppliers' refused and late orders (the supplier's reason passed as their text, with an eval case, `manager-supplier-reason`) and send one again or cancel it with `answerSupplierOrder()`; area `catalogue`; the list is a review tool too. **Six order events** (C5) beside the three of D331, found by `detectOrderEvents()` among orders of the last
14 days: `order_unsent` (paid, goods to send, no parcel after 48 hours), `delivery_problem` (tracking `problem`, `attempted` or `returned_to_sender`), `supplier_problem` (refused or late), `order_held`, `dispute_opened` (waiting for an answer, never test mode) and `payments_failing` (at least 5 failed and 30 % of payments in a six-hour window); each once per reference, with its own tools and lines, checked again before its turn (`stillOpen()`).
As every event, none writes to a customer: the turn leaves a note on the order; a held order is released and a dispute answered by a person (C6, C7). The migration widens `autopilot_events_kind` only. Store-only by nature: Kaizena Flow sells plans, not goods, so it has no orders to send, suppliers or purchase orders.
Migration version `20261115120423_lethal_prism`, applied by CI (run 1304) before the code (its commit message says D618: the number moved twice as other work took it); advisors after: INFO only.
