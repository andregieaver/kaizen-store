# D530: A deploy reads the migration ledger again against the head of `main`

**A deploy reads the migration ledger again against the head of `main` (10 November 2026, `.github/workflows/ci.yml`; an incident the same day).** Vercel's deploy hook builds the head of `main` when it is called, not the commit whose run calls it. At 09:56 UTC a push with a migration (D529) landed while an earlier push's run, which had no migration, was still in its quick gate; that run then called the hook and production got D529's code on a schema without its function.
Every store's Stripe webhook would have answered 500 from then until the migration was applied; none arrived in that time (the newest event in `webhook_events` was of 8 November), and Stripe retries for three days.
The hole is older than the quick gate (D526), which widened it from seconds to five minutes. **Now** both paths (`pending` and `release`) fetch the head, read the ledger against its migration files just before the hook, and do not deploy a head that has a migration production has not had: that head's own run releases it. **What it does not cover:** a push that lands in the seconds between that reading and Vercel starting its build. **The platform:** one pipeline, so the same. No migration.

Date: 2026-11-10

New code on an old schema is the one thing the release job exists to prevent.
