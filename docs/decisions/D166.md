# D166: Production is deployed by CI after the migration, and at once when there is none

**Production is deployed by CI after the migration, and at once when there is none.** Vercel's own build of `main` is off (`vercel.json`); `.github/workflows/ci.yml` calls a Vercel deploy hook.
A `pending` job reads production's migration ledger: with nothing to apply `pending` deploys about two minutes after the push and the checks (static, integration and e2e jobs side by side) run beside it; with a pending migration `release` waits for those three, applies the files over a direct Postgres connection and deploys, in one job (no `check` aggregate and no separate migrate and deploy jobs: each is a runner to queue for, which was the slow part when GitHub's queue was long).
Pushes of `*.md` and `docs/**` alone run nothing.

Date: 2026-10-05

Asked for by the owner: waiting about twenty minutes on every push made development slower, not faster. The risk accepted: a broken push that skipped the local checks can reach production before CI reports it (roll back with Vercel's *Promote to Production*). Migrations are no longer applied by hand first (CI would apply the file again). `AUTO_MIGRATE` and `DEPLOY_VIA_CI` are repository variables, not secrets. See `docs/ci-migrations.md`.
