# D588: Admin screens load an editor only where they draw one

**Admin screens load an editor only where they draw one (bloat review step 0.10; 14 November 2026).** A route loads every client component its server modules import, so the page builder (3.3 MB) came with 13 preview routes and the rich text editor with 34 routes that only list or show data.
Previews are `preview-views.tsx` (a store's and Kaizena Flow's, with the platform's shared `page-load.ts`) and the sandbox's address helpers are `src/app/admin/try/[sandbox]/params.ts`; the categories screen is `terms-views.tsx`; the content type and entry screens are `src/components/admin/content-type-views.tsx` and `content-entry-views.tsx`; the pages table reads `src/lib/page-role-copy.ts` (`page-roles.ts` re-exports it).
The rich text part of `page-content.ts` is `src/lib/rich-text-doc.ts` (re-exported, same public surface), `moveItem()` is `src/lib/move-item.ts` and the address-change sentence is `src/lib/address-change.ts`, so the product editor no longer pulls the page model and two English catalogues.
The staff's field card and the rich text editor inside the custom-field forms come from `src/components/admin/lazy/editors.tsx` (`lazyView(dynamic())`, drawn by the server, loaded where drawn); the builder and the block fields keep their direct import.
On a local build: a page preview 3,303,372 to 877,072 bytes, an order page 1,998,644 to 913,239, a product's editor 2,130,796 to 1,102,108, the pages list 658,928, the content list 619,531; routes with the editor 73 to 26 (all the builder's own); routes over 1,300,000 bytes 90 to 28 (26 builder routes and the two AI manager pages, which step 0.11 takes off).
`e2e/signed-in/admin-scripts.spec.ts`: a new product 1,250,000, pages 790,000, and new budgets for a page's preview (1,020,000) and the content list (750,000). *Why:* findings AC-2, BN-14, AC-3, BN-5 and DP-5 of `docs/audits/bloat-review-2026-11.md`. Commits f3cb2c5, 158a10b, 7006194, 0d31743; production on 0d31743 answered 200 on its pages and the Mollie probe with no new runtime error. No migration.
