# D397: Stock per location in the product editor

**Stock per location in the product editor (wave 12 unit C, `docs/wave-12-after-the-core.md` C): built.** With more than one active location the editor's context lists them by rank (`EditorContext.locations`), `getProductForEdit()` reads each shipped variant's level at each (floored at zero, as the editor shows a level) into `VariantInput.locationStock` (`locationId`, `onHand`, `loaded`), and each variant's details hold one field per location (`LocationStock`), the total beside the variant kept
as their sum; a bundle has none (its components hold its stock). `saveProduct()`'s `writeStock()` writes a figure only where the person changed it from what the editor read, as typed, to that location of the store's own that is active, as a `correction` movement from `editor`, after locking the levels in (variant, location) order; a figure left as read is left alone, so a sale paid since the editor opened stays paid, and a location of another store is never written.
A new variant opens at each location it was given stock at (`opening`), else at the default location as before. With one location nothing changes (`stock` is that location's). Held by `product-location-stock.int.test.ts` and the editor's render test. The row `orders.multi-location-inventory-and-routing` is re-read against its criteria: its other gaps were closed by D383. No migration.
