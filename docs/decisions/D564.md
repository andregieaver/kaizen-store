# D564: Three tests that failed now and then, and the *Saved* message they found lost

**Three tests that failed now and then, and the *Saved* message they found lost (11 November 2026).** CI runs 1210 to 1212 each failed on a test unrelated to their change. **The Dream Factory's integration tests** (`dream-rework`, `dream-factory`, `ai-pause`): `advanceDreamRuns()` claims the next due run of any store, so a test's minute could take a run another file had left due (`ai-pause` leaves one) and play its own stand-in AI on it, one turn too many; it now takes `storeId`, which the tests
pass and the cron does not. **Checkout look** (`checkout-branding.spec.ts`): the Design settings editor was keyed on the store's theme, so the refresh after its own save mounted a new editor, and the *Saved* message was lost whenever the refresh landed after it, a real fault an owner could meet, not only the test's; `ThemeEditor` now follows a changed theme itself (a theme applied or switched elsewhere starts it again, its own save does not; compared regardless of key order), and the store's and
the platform's pages no longer key it.
The test also had more of its own waits than a test's 30 seconds (now 120), and a retry typed the colours the last attempt had saved, which the editor (reading the store through its cache) already showed, so nothing was left to save: it now chooses colours the editor does not show. **The admin's accessibility scan** (`e2e/a11y.ts`): the admin eases each page and streamed part in (`admin-enter`, opacity over 0.2 s), and axe reading text halfway found a contrast of 4.1 against 4.5; the scan now
waits for finite animations to finish and, when it finds something, settles and scans again, counting only the second (a fault at rest is found both times). Checked locally: the three Dream Factory files in the order that failed; checkout look and the accessibility scans six times over with no retries (116 of 116, from 5 failures in 25 before), and every theme and Design settings spec. No migration.
