# D710: A run whose commit is no longer the head leaves the deploy to the newer run

**A run whose commit is no longer the head leaves the deploy to the newer run (17 November 2026, `.github/workflows/ci.yml`, `scripts/newer-push.mjs`, `docs/ci-migrations.md`).** The deploy hook builds the head of `main` when it is called (D530), so pushes landing within minutes each called it and Vercel built the same head several times (three builds of `61dcec1`, three of `0624ff3c`).
In `pending` and `release`, after the head check, a run whose commit is no longer the head skips the hook and the wait when a commit between starts a CI run of its own (anything but `*.md` and `docs/**`, `content/**` back in): that run deploys the head, this commit with it, and its wait verifies it (`await-deploy.mjs` counts a later commit). A newer commit of words only starts no run, so the run deploys as before; any doubt (head unknown, files not listable) deploys too.
If the newer run's gate fails, neither is deployed: before, the stale run deployed that unchecked head. The manual `redeploy` is unchanged. **The platform:** one pipeline for both. No migration.

Date: 2026-11-17

The owner asked, after seeing `61dcec1` built three times.
