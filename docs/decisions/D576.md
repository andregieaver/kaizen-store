# D576: The schema is not loaded at run time, and light routes import helpers from the files that define them

**The schema is not loaded at run time, and light routes import helpers from the files that define them (bloat review step 0.4; 12 November 2026, `src/db/client.ts`, `src/lib/route-fail.ts`).** `db()` calls `drizzle({ client: pool })` without the schema: no query used Drizzle's relational API, and loading `src/db/schema.ts` put every table's definition in each server route. `schema.ts` stays drizzle-kit's source for migrations and `db:check`.
`fail()` moves to `src/lib/route-fail.ts`; `sameSite()` is imported from `src/lib/same-site.ts` and `visitorKey()` from `src/server/chat-turns.ts`, so the visit and recommendation beacons no longer load the chat module, the AI providers or the admin's texts. Two scan tests hold it: `src/db/schema-import.scan.test.ts` (no runtime file imports the schema) and `src/server/beacon-imports.scan.test.ts`.
Measured on a build: `/api/visit` 639 server modules and 1,188 KB (was 1,890 and 10,475), `/api/health` 259 and 418 KB (was 308 and 1,155); the five beacons reach 100 to 107 source files (was 1,308). In production after `afff453`: the deploy's page checks passed, a store page's beacon answered 204 and its visit was counted, no new runtime error.
