# D682: Each check runs once in CI, and a tests-only push does not deploy

**Each check runs once in CI, and a tests-only push does not deploy (bloat review step 0.38; 16 November 2026).** The three browser jobs (e2e, hosts, signed-in) build with `SKIP_BUILD_TYPECHECK=1`, so `next build` leaves the type check to `static` and the quick gate, which run `pnpm typecheck` on the same project; Vercel's build skipped it already (D378), and a local `pnpm build` still checks. The schema check (`pnpm db:check`) runs in integration shard 1 only.
`pnpm lint` keeps a content-keyed cache in `node_modules/.cache/eslint`, restored in CI's two lint jobs by the lockfile and the ESLint config (a second run: 9 s); `src/lib/ci-once.scan.test.ts` holds that no rule reads across files.
In `pending`, `scripts/deploy-needed.mjs` compares the push with the commit production reports and answers no only when every changed file is a test (`*.test.ts(x)`, `*.spec.ts`, `e2e/`, `e2e-live/`, `test/`, `src/test/`); any doubt means deploy, and a push with a migration always deploys through `release`. The first CI run (16 November) showed the browser builds without their type check, the schema check in one shard, and the deploy. Commits 6a78de64, 46673cc1, 30256940, 5336001d.
