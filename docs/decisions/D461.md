# D461: The phone's first paint, from PageSpeed

**The phone's first paint, from PageSpeed (5 November 2026, `docs/performance.md` Fonts found late, `src/components/font-preloads.tsx`, `src/server/font-trim.ts`, `src/lib/font-axes.ts`).** Lighthouse as PageSpeed Insights runs it scored kaizenaflow.com 83 to 88 on a phone (66 while a deploy went live) and 97 on a computer; the phone lost its points on the largest paint (3.7 to 4.3 s), which the simulated slow 4G charges with every file finished before it.
Three changes. **Fonts preloaded**: `StoreThemeStyles` preloads the file each site family draws upright Latin text from (`FontPreloads`, `latinUprightFile()`, only where one file serves every upright weight), which React names in the `Link` header, so the font no longer waits for its stylesheet. **Variable fonts cut to the installed weights**: Google sends a variable family's whole weight axis whatever is asked for; the five-minute dispatcher's `fonts` step cuts each file not yet looked at
(`font_files.trimmed_at`) with HarfBuzz (`subset-font`, BSD-3-Clause, HarfBuzz in WebAssembly, read from `node_modules` by that route only: `serverExternalPackages`, `HARFBUZZ_FILES`) to its family's installed weights (`installedWeightRange()`, 400 to 700 from the builder), keeping every character, feature and other axis, under the same name (a hash of Google's file), so no stylesheet or page changes; drawn at those weights the glyphs are the same and a line's width within 0.1 %.
Inter's Latin file 48 to 34 KB, Montserrat's 35 to 32. **Shop parts only where they draw**: `PageArticle` imported `StorePartSection` (the cart, checkout, order, My account, cookie list), so every page built in the builder loaded their client components; `RolePage`, the one place that draws a working page, now hands it in (`StorePartDrawer`).
Measured on a build: Kaizena Flow's front page's route scripts 96 to 71 KB compressed, a store's front page 100 to 76, a product page 116 to 100, the cart unchanged. Not changed: the heading order on the front page (an H3 under the H1, accessibility 98), which is the owner's content.
