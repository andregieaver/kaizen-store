# D243: Seamless switching, step 2

**Seamless switching, step 2: the page migration run for real (`docs/theme-phase-2.md`).** *Let pages follow the theme* on Design settings (`website:write`) takes out of a store's pages every style setting that only repeats the live theme, section styles included (`detachThemeValues()`, D241: a setting goes only when the row laid under the theme comes out identical), so every page is drawn exactly as before and follows the theme it is switched to. *Count the settings* is the dry run.
`runDetach()` runs in one transaction under the store's row lock, on drafts and published versions alike, and keeps each changed page's versions before and after in `commerce.page_theme_detaches` (a run's rows keep what they recorded: only `undone_at` changes, once, by trigger); `undoDetach()` puts back each version only while it is still what the run left, so a page changed since keeps the change (counted and said).
Left alone: global parts (D98), versions of A/B tests and pages in a running or scheduled test (D148), and headers, footers and product layouts an installed theme that is not live chose (they are drawn under that theme). Runs are kept 90 days (`pruneThemeDetaches()` in the daily job). Words, pictures, videos and links are never touched. Audited `store.theme_pages_detached` and `store.theme_pages_detach_undone` (area website).
