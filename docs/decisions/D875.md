# D875: Saved email blocks: a store keeps up to 50 named blocks to add again to broadcasts (email plan M4.1)

Date: 2026-11-23

**Saved email blocks (23 November 2026, email plan M4.1).** An owner who ends every email with the same footer, social links or pair of
columns wrote them again each time; a whole broadcast could be kept as a template (D368), but not one part of it.

- `commerce.email_saved_blocks` keeps one block of an email by name, at most 50 a store, written only by `src/server/email-saved-blocks.ts`
  (staff with `marketing:write`, audited `email_block.*` with ids and the block's type, never its words). A block is checked as an email's
  is (`broadcastBlockSchema`), and its picture must be the store's own library's JPEG, PNG or GIF, as any picture in an email.
- In a broadcast's editor each block has *Save for later*, which asks a name (filled with the block's kind); the store's saved blocks sit
  beside *Add*, one press adding a copy (later changes to the email never change the saved one), and a small cross deleting one.
- Kaizena Flow's own broadcasts are its house store's (D467), so the platform has saved blocks too. A store copy starts without them (its
  staff's working parts); the whole-store file carries them, as it carries own templates.
- Flow emails are written on the flow canvas, not this editor; saved blocks reach them as the canvas grows its own block list.

Idle cost: none; one indexed read when a broadcast's editor opens.
