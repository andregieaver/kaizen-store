# D861: A listing draws its grid once and reads its list once

**A listing draws its grid once and reads its list once (bloat review step 2.12; 20 November 2026).** A standard listing (All
products, a category, a tag) reads its first page once: the list it prerendered is the list it shows, and a built product grid with
Filter and sort is drawn once, with the controls and Show more streaming beside it. With a filter or sort in the address, the chosen
grid takes the built grid's place (`.listing > [data-grid-listed] ~ [data-grid-built] { display: none }`); at most one grid shows at any
moment (a 50 ms sampling on Slow 4G). Locally `/s/demo/no/products` fell from 128,622 to 97,856 bytes with each tile once in the markup
and once in the payload (twice each before), held at 120,000 by an e2e test; an unfiltered category or tag page runs no list query
(a sorted one runs one). `listing.int.test.ts` holds that the prerendered first page and `listingPage()` give the same products in the
same order. render-modes records the products and category pages with two holes, not one: the built grid is now in the prerendered
page and the controls stream in a boundary of their own. Two specs count visible matches (the hidden built grid stays in the page),
fixed in 9c6d96830 after run 1791. Live from 20 November (c0e16999a). Idle cost: none. Commits ac352b258, 388afef9b, c0e16999a.
