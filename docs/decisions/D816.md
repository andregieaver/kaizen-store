# D816: The proxy imports leaf readers only

**The proxy imports leaf readers only (bloat review step 2.20; 19 November 2026).** `src/proxy.ts` runs on every request, and it
reached 321 source files through the modules it read from. Its readers now live in leaf files that import nothing the proxy does
not need: `store-facts.ts` (private mode, a store's facts), `holding-read.ts`, `site-switch-read.ts`, `experiments-running.ts` and
`not-found-record.ts`; the old modules re-export them, so no caller changed. Cache tag names live in `src/lib/cache-tags.ts`. The
three short memories became one helper, `src/server/short-memory.ts`: an answer kept a few seconds per instance, a read in flight
shared by every caller of the same key (a cold instance asks once per key, not once per request), a failed load not kept, and a
load forgotten while it ran (a write since) never stored. The graph test forbids the proxy anything outside its list.

Measured on a local build: proxy source files 321 to 57; its chunk 2,253,770 to 585,983 bytes (budget 1,048,576); its trace
60.7 MB to 2.1 MB; its cold load about 145 ms against 290 to 330 ms more than an empty function before. CI's hosts, signed-in and
e2e jobs passed with it, and production answered as before on 19 November: the platform's front page, the demo store, a store's
manual redirect, a private store's landing (noindex) and an unknown address (404). The proxy's cold-start p50 in Usage and limits
is read a few days on. Commits 8af4efe0d, f7f67401c, c6e45322b, 73f6e974a, 5f85cefad.
