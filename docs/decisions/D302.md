# D302: Product feeds

**Product feeds (wave 5 unit H, `docs/wave-5-marketing.md` 13).** One normalised list of a store's variants per market (`storeFeed()`, `src/server/feeds.ts`, from the catalogue's own cached reads `listProducts()`/`getProduct()` and stock per request, so a feed's price is the storefront's: with VAT, in the market's currency, converted as shown), written by the pure `src/lib/feeds.ts` as Google Merchant Center RSS (`googleFeed()`: the 30-day reference as `price` and the current price as
`sale_price` only for a genuine reduction, GTIN else `identifier_exists` no, unit pricing from D160's measure, the flat rate as shipping, 0 over the free threshold) and Meta, TikTok and Pinterest CSVs (`CSV_COLUMNS`, through `writeCsv()`). One item per variant (SKU else id, the product's id as group). Left out, each named with its reasons on the admin's page (`feedProblems()`): not goods, sold only as a subscription, for businesses only, no picture, no price.
The address is secret: `commerce.feed_settings` (one row a store, the token's SHA-256 hash and the token encrypted with `SETTINGS_ENCRYPTION_KEY` so the owner can see the addresses again, `on`), written only by `src/server/feed-settings.ts` (audited `marketing.feed_on`/`_renewed`/`_off`, never the token), `never` copied, RLS on.
`/api/feeds/{token}/{market}-{channel}.{xml|csv}` answers 404 for a wrong token or file, a store that is not open, a template or starter, the shop off or a market not offered, 429 past the `feed` budget, and otherwise the file with `s-maxage=900` (the stated refresh: 15 minutes) and `noindex`.
Marketing → *Product feeds* (`/admin/{store}/feeds`, `marketing:read`, changes `marketing:write`) turns them on, shows each market's four addresses to copy, makes a new address (the old one stops at once) and turns them off. Not done: custom labels, and no channel API sync (the channels fetch the address on their own schedule).
