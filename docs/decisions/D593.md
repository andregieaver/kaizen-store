# D593: A store page makes no call of its own after load for a visitor with nothing to fetch

**A store page makes no call of its own after load for a visitor with nothing to fetch (bloat review step 0.15; 14 November 2026).** Three requests every new visitor made are gone. (1) The wishlist hearts (D34) ask `/wishlist/saved` only when the marker cookie `kaizen_mine_{storeId}` is present: '1', not httpOnly (the hearts' script reads it), a year, set by `markMine()` in `currentOwner()` when a list is made or a product saved and in `startSession()` on every sign-in, so an account's hearts
show on any device it signs in on; it is necessary and declared in `KNOWN_COOKIES` in four languages.
The test in the browser matches any store's marker on the host, which at worst costs one extra request; a visitor whose list or account predates the marker sees empty hearts until they save or sign in again (no store was open). (2) A content grid reads the store's two tile switches (D557) on the server from `productSettingsCached()` ('use cache', `cacheLife('hours')`, tag `product-settings:{storeId}`, never the catalogue's, refreshed by `saveProductSettings()`), and `tileAskFor()` draws no
island and asks nothing when neither stock nor the chooser would show; a grid's own hide still beats the store, and the route still answers with fresh settings so a switch turned off stops at once. (3) The search box asks for suggestions only after a key or a focus. Production on acc324b: 0 such requests on the demo store's front page, search results and a product page (12 local pages likewise; 1 or 2 each before).
The visit record's POST and, on product pages, Stripe.js's own beacons remain and are not this step's. Kaizena Flow's own site has no hearts, tiles or shop search, so nothing applies there. No migration. Commits 7d15785, df83014, f10b77c.
