# D781: The second-factor mirror is kept right at every sign-in

**The second-factor mirror is kept right at every sign-in (bloat review step 2.33, commit 1; 18 November 2026).** `commerce.accounts.two_step_since`, the mirror that will let the gate skip its Supabase Auth call, is set from the Auth server's own list of factors (`getUser()`, never the cookie's copy) at every sign-in (`reconcileMirror()` in `src/server/sign-in.ts`), and a sign-in whose factors cannot be read is refused (fails closed); a one-time migration set it for every account with a verified
factor. Migration versions (applied by CI, 18 November 2026): `20261118224706_two_step_mirror_reconcile`. In production after it: 10 accounts, 1 with a verified factor, mirrored; none verified without the mirror.
Commit 2, the gate trusting an empty mirror, is not made: it would let an account whose factor the mirror misses, or one whose factors cannot be read while Auth is down, in without the second step, and two existing gate cases hold that today; it waits for the owner's decision, with the JWT signing key's answer. Commits 00d7bddd.
