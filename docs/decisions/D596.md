# D596: A checkout question can be half width

**A checkout question can be half width (task 2 of `docs/checkout-fields-tasks.md`; 14 November 2026).** `checkout_fields.width` is `full` (the default) or `half`; only `half` is kept, never a side, so moving a question can never leave a right-hand one alone. The cart draws the questions in a two-column grid where a full one spans both columns: two halves next to each other share a line and one alone takes its left half. From a tablet's width up (`sm`); on a phone every question is full width.
A container query was tried first and dropped: the cart's summary column is narrower on a desktop than a phone's whole page, so it drew halves on the phone and none on the desktop. In the editor the choice is under the question's *Customise* (Homer sees nothing new; open from the start only for a half-width question), and the list says *Half width*.
A change made without a width keeps the question's width (`saveCheckoutField()`: the AI manager's `save_checkout_question` and an older Admin API caller), so nothing reverts a half-width question by accident; `checkout_questions` returns it. Admin API contract 1.16 (`width` on a question, optional when written). Tests: `checkout-rules.int.test.ts`, `checkout-question-tools.int.test.ts`, `commerce.test.ts`.
