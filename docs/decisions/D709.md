# D709: The build without source maps on Vercel

**The build without source maps on Vercel (17 November 2026, `next.config.ts`, `docs/build-memory.md`).** Vercel's builds of `d066e58d` and `0624ff3c` were killed for memory; CI's wait then failed.
Measured again as D378 did (seeded database, 8 GB cgroup cap, memory per process each second): Turbopack's compile had grown from 5.8 to 7.5 GB with the code (+37% source, 480 to 588 pages, 189 to 280 routes since 28 October), the build peaked at 8.35 GB, and under the cap it was killed as page data started, as on Vercel.
On Vercel only, `turbopackSourceMaps` and `turbopackInputSourceMaps` are off: the compile holds 6.2 to 6.3 GB, the build peaks at 6.3 to 7.0 GB and passes under the cap, and it compiles about 20 s faster. Production never read the 8,129 server maps (no `--enable-source-maps`, Next uses them only for its debug prerender; browser maps were never made), so logged stacks are unchanged.
The margin is about 1 to 1.7 GB, two to three weeks at the code's growth: the lasting answer is Vercel's Enhanced build machine (16 GB), a paid setting only the owner changes. **The platform:** one build serves both. No migration.
