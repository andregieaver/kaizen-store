# D148: A/B testing for store owners and the platform is designed before it is built

**A/B testing for store owners and the platform is designed before it is built** (`docs/ab-testing.md`).
Decided: only visitors who accepted the `statistics` category, and signed-in customers (subject to a legal check before the first live test), are enrolled, everyone else sees the original and is not counted; version 1 tests whole pages and parts of pages, never prices, discounts, shipping or legal pages; owners and staff can run tests (platform admins on Kaizen's pages); it is a paid-plan feature through one row in the plan comparison.
Variants are served from the cache: enrolled visitors, found by a cookie, are rewritten to the variant's page by a `proxy.ts` (an experiment start or stop is a database change, no deploy), everyone else never reaches it.
The phase 0 spike proved this locally (+0.5 to 0.9 ms) and found that a browser's cached copy goes stale after assignment (a page marker and one reload fix it) and that a dynamic hole flickers; the check on Vercel's network and the proxy's region are still open; one running test per target; variants locked once running; one goal per test, verdict only after the planned minimum, said in plain language with an estimate of the runtime before launch.
Phase 1 is built (`docs/ab-testing.md`, "What phase 1 built"): the engine, tests of whole store pages, the admin at `/admin/{store}/experiments`, the proxy, results computed on read and the guardrail job; versions are pages of type `variant`, a page in a running test cannot be unpublished or have a change published, and the migration is `ab_experiments`.
Phase 2 adds tests of a part of a page (a row, column or component chosen in the builder with "A/B test this"; a version may differ from the original in that part only, and applying a winner puts only the part into the page as it is then) and a scheduled start, the migration `ab_part_tests`.
Phase 3 adds tests of a store's header, footer and product layouts: a visitor's versions travel in the market part of the address the proxy rewrites to (`no~{test}{version}`, taken off again by `resolveShop()`), so every page and the product pages are served from the same routes, and the migration is `ab_site_tests`.
Phase 4 adds the AI manager's seven A/B test tools (list, explain, suggest, draft, start, stop, apply): the model words and drafts, code counts and decides, the three that change what visitors see are kept for the owner's yes and checked first; no migration.
Phase 5 adds the platform's read-only view of every store's tests at `/admin/platform/experiments`, with the ones that need a look first (a version lowering orders, an uneven split, nobody seeing a running test, a test past its end or left undecided); no migration. Phase 6 emails the store's owners, and whoever made the test, once each when the guardrail stops a test, with the counted figures and what they may do; no migration.
Phase 7 moves the search test (D77) and the recommendations held-out ranking (D140) onto the engine's arithmetic (`src/lib/experiment-units.ts`: the same comparison of rates, split check and rule for calling a difference, the old formulas kept in `experiment-legacy.ts` and checked to give the same numbers on the same data) and lists them beside page tests in the platform's view; they keep their units (a search, a tab), their own logs and no cookie, and make no experiment row, so no migration.
Phase 8 gives the platform's AI manager two read-only tools over every store's tests (`list_ab_tests`, `explain_ab_test`), with a playbook; it has no tool that starts, stops or changes a store's test, since a platform admin cannot, and says what to tell the owner instead; no migration.
Phase 9 lets a store test a modal (a popup that opens by itself may be left out of a version, to see whether it helps; every modal keeps its address name) and the rows around the shop's own component on its working pages (cart, checkout, order confirmation, My account, sign-in, wishlists, a subscription, weekly deliveries: by a part only, served from the page's own route like a header's, the shop's logic never varied); the migration is `ab_working_pages`.
Phase 10 makes the store's front page and All products page testable, whole or by a part, served from their own routes like a working page and held in place while a test runs (`commerce.page_place()`, migration `ab_front_pages`); a part test compares the original as it would be saved, since saving keeps only the store's own languages.
Phase 11 adds the goal "more people sending a form" (`form`, an email form or newsletter sign-up chosen on the page, counted once per visitor in their version when the site accepts the answer: `recordFormSent()` from `submitForm()`; migration `ab_form_goal`).
