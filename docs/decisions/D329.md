# D329: Web research for the AI manager and the autopilot

**Web research for the AI manager and the autopilot (`docs/ai-autopilot.md` unit E, section 13).** `search_web` asks the platform's web search service (`SEARCH_APIS`, Brave Search first, behind one setting so others can be added: `commerce.search_settings`, the key encrypted and set by platform admins on Platform → AI's *Web search* card) and answers titles, addresses, descriptions and ages; `read_web_page` reads one public page through `safeFetch()` (2 MB, HTML or text, its readable text cut
at 12,000 characters by `pageText()`); `save_research_note`/`list_research_notes` keep findings that may cite only addresses the store searched or read within 30 days (`research_sources`, kept 90 days); `compare_options` adds up weighted 1–5 scores in code (`compareOptions()`) and keeps the ranking as a note. The same tools serve a store and Kaizena Flow's own site (`RESEARCH_TOOLS`), ungated, `marketing:read`/`marketing:write`; a goal's review (D328) may search, read and list notes.
Searches run on Kaizena Flow's key and are metered: an `ai_usage` row of kind `search` (`searches`), feature `autopilot` inside its turns and `web_research` otherwise, priced by the new `ai_model_prices.per_thousand_searches` through the one cost SQL and `callCost()`, so they count in a plan's `ai_cost_month_micros` and the autopilot's budget; at most 100 searches and 200 pages a store a day. Brave is a US company: a search sends only the words the AI chose, and the card says so.
What a search or page says is untrusted text (the prompt's `UNTRUSTED_TEXT`; eval case `manager-web-research`).
