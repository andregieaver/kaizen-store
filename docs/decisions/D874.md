# D874: The account's own sending domain, for every store of the account without its own (D748 E10 part two)

Date: 2026-11-23

D748 section 10 gives own sending domains an account level, so a standalone account sends from its domain and stores can still each have
their own. Done when (step E10): a standalone account sends from its own domain. Before this, a workspace (D748 E7) could not: a store's
sending card sits on Settings, Notifications, which shows only with an online shop. The owner settled the plan's open question 5 the same
day: an own sending domain stays in every plan, since it sends the order emails too.

- **A row of the account.** `sending_domains.organisation_id` (null for a store's and Kaizena Flow's own; a row is one of the three,
  `sending_domains_one_owner`), one per store, per account and Kaizena Flow's own (`sending_domains_owner_key`). The server takes an owner
  (`SendingOwner`: a store's id, `{ organisationId }`, or null for Kaizena Flow's) everywhere it took a store's id; the account's row is
  added to Resend and SES, checked, renamed and removed exactly as a store's. Its records are written into the zone a store of the account
  keeps for that domain (D315), else shown to copy.
- **Which address.** A store's own verified domain first, then its account's, then the shared address: for order emails (`senderFor()`)
  and for marketing (`marketingRoute()`, D872) alike, each store with its own name and reply address. Another account's stores and Kaizena
  Flow's own never use it.
- **Where.** Your domains carries *Send from your own address* for the account, shown only to its owner (`ownedAccount()`), with the domain
  the account holds filled in. A store's card says when its emails go from the account's address and that adding a domain gives the store
  its own; the phone's row says the same.
- **Parity.** Kaizena Flow's own sending domain was already its own level (no store, no account); the platform has no account of stores
  for this to apply to, so nothing is added there.

The older one-per-store key (`sending_domains_store_key`) stays until the code that named it has been replaced in production, then goes
in the next change (it allows only one row without a store, so an account's domain and Kaizena Flow's own cannot both be kept until then;
production keeps none yet).

Idle cost: none per request; a store's sender read looks at its account's row in the same statement.

Migration versions: `20261123112157_late_deadpool` (the column, its key, check and index).
