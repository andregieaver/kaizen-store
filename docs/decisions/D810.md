# D810: Contracts in the Admin API: read-only, the webhooks' fields and drafts, under customers:read

**Contracts in the Admin API: read-only, the webhooks' fields and drafts, under customers:read (19 November 2026).** The contracts' design
(`docs/contracts.md` 6) said the Admin API reads contracts; the owner asked for it after step 4. `GET /contracts` (newest first in pages,
narrowed by `status`, `deal_id` and `updated_after`) and `GET /contracts/{id}` (`src/lib/admin-api-contracts.ts`,
`src/server/admin-api-contracts.ts`) answer the `contract.*` webhooks' fields, drafts too, with each signer's opening time added: never a
signer's email, the reason a signer gave for declining or the contract's words, which stay on the contract's page, as the AI manager's
`list_contracts` leaves them out. The scope is `customers:read` and the staff permission `customers:read`, as the deals pages ask (a
contract names its signers); no new scope, so no token or app changes. Behind the feature `sales`, and the Deals and contracts extension
(D748): without it they answer `feature_off`, as the deals pages show the extension's marker. Read only: a contract is drafted, sent and
signed in the admin (sending draws its PDF with Chromium, which only the contract's page route carries). API contract 1.46. Tests:
`admin-api-contracts.int.test.ts`.

Date: 2026-11-19
