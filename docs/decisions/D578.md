# D578: Heavy server packages and the AI manager's engine load on first use

**Heavy server packages and the AI manager's engine load on first use (bloat review step 0.5; 12 November 2026, `src/server/sharp-load.ts`, `src/lib/mcp-catalogue.ts`).** sharp (about 21 MB of native code) is loaded by `loadSharp()`, which each of the 28 functions that draw a picture awaits when it runs, so a route that draws none never loads it; `font-outlines.ts` loads opentype.js with `await import()` where it parses a font.
The two assistant action files (a store's and the platform's) load `@/server/owner-assistant` with `import()` inside each action, after the permission check, so the admin layouts that hold the launcher no longer carry the AI manager's engine; `follow-ups.ts` takes its error helper from `owner-tool-error.ts`. `mcpTools()` builds the owner MCP's tool list on first use, the same array that `MCP_TOOLS` was at import.
`lazy-packages.scan.test.ts` fails on a static value import of sharp, opentype.js, playwright-core, @sparticuz/chromium, mammoth or unpdf outside tests and the loaders (the first of step 4.1's boundary rules for packages), and `assistant-actions.scan.test.ts` on a top-level import of owner-assistant in an action file. Not done: sharp is not excluded from file tracing, since a route that then called it would fail only in production. Commits f5745c3, 993a364, 1350a6f.
