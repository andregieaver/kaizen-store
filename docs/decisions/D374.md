# D374: Labels for several orders in one action

**Labels for several orders in one action (wave 10 unit K, `docs/wave-10-must-haves.md` 4); built.** The Orders list's bulk bar gains *Book labels* (`BULK_ACTIONS` `book_labels`, `orders:write`, at most `BULK_PRINT_MAX` 100 orders a request, ticked or all matching, as its labels are printed together and each order waits for its carrier's answer).
After a confirmation that says what will happen (the carrier the customer chose at checkout, or Posten / Bring's home parcel `5600` for an order that chose none, `BULK_BRING_SERVICE`; the weight from the products; each order marked sent; nothing shipped while a carrier is in its test environment) and *Tell the customers* (off by default), `runBulk()` books each order's units still to send as one parcel, one order after another, only through the order page's own functions (`bookOrderLabel()` in
`src/server/bulk-labels.ts` calls `bringBook()`, `helthjemBook()` or `porterbuddyBook()`, so D372's lock, the parcel's checks, the test environment and `markSent()` are theirs, never a second path). *Mark as sent*'s blocks come first (`markSentBlock()`: not paid, copied, already sent, withdrawn, a change waiting, units waiting for stock, a pickup order), then a local delivery (`local_order`), a carrier that cannot book (`carrier_cannot_book`, PostNord), a carrier not connected (`no_carrier`),
something left to send without a weight (`no_weight`, `remainingWeights()` over `commerce.line_to_send()`), a test booking (`test_booking`: booked at the carrier's test environment, nothing sent, no label) and the carrier's own refusal (`carrier_refused`, its sentence kept as `BulkRefusal.detail` and shown with the order's number). Each refusal is listed by order number with its reason (en and nb in the `orders` catalogue).
The labels booked come back as `BulkResult.labels`, in the order they were booked, and the result panel offers *Print the n labels*: `/admin/{store}/orders/labels?ids=` (`orders:read`, `labelsToPrint()`: this store's parcels with a carrier label, not undone, others counted and left out) shows them one after another, each the order's own label route (`carrierLabel()`: fetched from the carrier's own host with the store's agreement when it is shown, never kept) in the browser's PDF viewer, where it
is printed. One audit entry per batch with counts (`order.bulk_labels_booked`: requested, applied, refused, labels; never an order number); each booking keeps its own `shipping.*_booked` entry.
Held by `bulk-labels.int.test.ts` (faked Bring and Helthjem: a flat-rate order to Bring's home parcel, a partly sent order's remaining unit only, Helthjem for its chooser, PostNord, no weight, a carrier's refusal and an unpaid order each named, the labels in order and printable, run again books nothing twice, the test environment, a carrier not connected, more than 100 refused), `order-actions.int.test.ts` (no access without `orders:write`), and the unit and view tests (`order-bulk.test.ts`,
`order-list-admin.test.ts`, `orders-views.test.ts`).

Date: 2026-10-28
