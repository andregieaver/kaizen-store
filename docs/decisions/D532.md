# D532: Only the newest Drizzle snapshot is kept, and the unit tests build their database once

**Only the newest Drizzle snapshot is kept, and the unit tests build their database once (10 November 2026, `scripts/prune-snapshots.mjs`, `src/db/snapshots.scan.test.ts`, `.vercelignore`, `src/db/testing.ts`, `src/test/test-db-template.ts`; steps 0.3 and 0.4 of `docs/audits/code-review-2026-11.md`, findings FD1, FH3 and FD2).** `drizzle-kit generate` writes the whole schema as JSON beside every migration and reads only the newest.
There were 775 of them, 1.1 GB in every clone, CI job and agent's checkout against 6 MB of SQL, and the folder had once taken the build down through Tailwind's scan (D378). All but the newest are deleted: `pnpm db:check` passes and a new migration generates from the one left. `pnpm db:generate` prunes after generating; after `drizzle-kit generate --custom` it is `node scripts/prune-snapshots.mjs`, and a scan test fails at more than five.
`.vercelignore` keeps the folder out of the build. **The tests:** each of some 65 test files applied every one of some 780 migrations to a PGlite of its own. A Vitest global setup now applies them once, keeps the database (`node_modules/.cache/kaizen-test-db`, named by the migration files' names and sizes) and each file loads a copy; without the kept one a file makes its own as before.
The unit run went from 7 min 35 s to 5 min 34 s on the machine it was written on. **The platform:** tooling, the same for both. No migration.

Date: 2026-11-10

The review's findings FD1, FH3 and FD2.
