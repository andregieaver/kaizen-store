# D309: Goals, plans and the work loop

**Goals, plans and the work loop (`docs/ai-autopilot.md` unit B).** The AI manager keeps a store's goals (the owner's vision and up to five targets the code measures from the store's own figures, `goalProgress()`, never the model) and plans: steps of fixed kinds (`STEP_KINDS`: one tool call run by code, a task run as a headless turn limited to its tools, a question for the owner, a wait), each checked when the plan is made (`checkPlan()`) and checked again in code after it runs (`CHECK_KINDS`).
A plan starts only on the owner's yes (gate `plan`, for the version they were shown) and runs in the name and with the role of whoever made it, read again before every step.
The loop (`/api/cron/autopilot`, every minute, one step per store) runs within the owner's autonomy levels per area (*Ask me first* by default, *Do it and tell me*, *Just do it*) and budgets (AI cost a month, deepest discount, largest price change); some calls are never automatic (`NEVER_AUTOMATIC`: staff, domains' DNS, refunds, order changes, credits, the plan, features, opening the store).
Three failed tries become a question; the owner sees everything waiting on one Decisions page, a daily digest and a weekly report; the audit log says whether a person, the AI manager or the autopilot acted (`audit_log.by`). Built in three parts, B1 to B3 (section 7).
