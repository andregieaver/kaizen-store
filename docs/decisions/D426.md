# D426: A column goes with what it holds

**A column goes with what it holds.** A row (or a line of it) taking a layout with fewer columns, where the columns that go hold anything, asks first (`columnsLostTo()`, `LostColumnsQuestion`): *Delete them* is the main choice, *Move them to column n* keeps the old behaviour, and *Keep this layout* changes nothing. A column's settings have *Delete column*, asked first only when it holds text.
Its tools sit a step above its top, so they never cover its first component's in a narrow column (raised only while a component was pointed at, they slipped away from the pointer going to them).

Date: 2026-11-02

Asked for by the owner: "it's time consuming to first delete components in the column before deleting the column." Fewer columns used to move the text of the columns that went into the last one, so removing a column meant emptying it first. *Why ask rather than delete:* text is the owner's work and a layout pick is easy to make by mistake; undo still takes either answer back.
