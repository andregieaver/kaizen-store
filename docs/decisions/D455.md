# D455: The phone browser's colour follows the header

**The phone browser's colour follows the header (5 November 2026, `src/lib/header-color.ts` pure, `src/components/header-theme-color.tsx`).** On every site, Kaizena Flow's own (its pages and the docs portal) and every store's, `<meta name="theme-color">` is the colour the page's header is drawn in, so the status bar and address bar on phones look like part of it.
It is read in the browser from the header as drawn, never worked out from settings: at the `<header>`'s top edge, near its left side, every see-through layer down to the page is mixed (`composite()`), so the theme's header background (page, surface, accent, inverse), light or dark, a row's own background, a gradient's first colour and a header lying see-through over the page's first row all come out as seen; a picture counts as the page's colour.
A notice strip above the header (preview, test payments) is not the header. It is read again on scroll, resize, a change of light or dark, the header's own changes and each navigation; while the header has slid away the last colour stays. `HidingHeader` does it for every site header (`themeColor={false}` for the admin's), `<HeaderThemeColor />` for a header drawn without it (the docs portal's). One tag without `media`. No migration.
