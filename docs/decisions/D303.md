# D303: Ad pixels, conversion events and campaigns

**Ad pixels, conversion events and campaigns (wave 5 unit I, `docs/wave-5-marketing.md` 12), built in three parts; I1 events in the browser and the new tags.** `TrackingSettings` gains `googleAds` (`AW-…`), `tiktokPixel` and `pinterestTag` (store only: `STORE_ONLY_TOOLS`, dropped by `saveTracking()` for Kaizena Flow's own site), each a `marketing` tool in `toolCategories()`, its cookies in `KNOWN_COOKIES` (a cookie's `tool` may now name several), named in `TRACKING_TOOL_NAMES` for the privacy
starter, loaded by `ConsentManager` only after consent (Google Ads on the same gtag with Consent Mode v2's ad signals).
Components call `trackShop()` (`src/lib/shop-events.ts`, no zod): `view_item` once per variant shown (`VariantChoice`'s `track`, `ShopTrack` in `shop-track.tsx`, given only while the store has a tag: SKU else id, the price as shown in major units), `add_to_cart` after the server accepted the add (the units asked), `view_item_list` on listings and `search` (`TrackOnView`); search words go only when `searchWordsSendable()` (no six-digit run).
`ConsentManager` passes each to the loaded tags in their own words (`mapEvent()`: GA4/gtag, GTM's data layer, Meta, TikTok, Pinterest) and replays this page's events heard before it listened (`takeRecentShopEvents()`, memory only). Checkout and purchases are not browser events: pay routes load no tag (D158) and the server will send them (I2).
A conversion label for Google Ads is not kept (no browser purchase to attach it to). **I2:** carts keep `ad_consent_at` and `ad_signals` (`cleanAdSignals()`: Meta `fbp`/`fbc`, Google `gclid`/`gbraid`/`wbraid`, TikTok `ttclid`/`ttp`, Pinterest `epik`), written only by `recordAdSignals()` from `/api/ads/signals` (same site; the shopper's own cart cookies of the store; the consent manager posts them after a choice with marketing, on page load and after an add to the cart, and clears them when
marketing is withdrawn); an order takes them from its cart by trigger (`orders_ad_consent()`, set once, the ids only cleared). `commerce.ad_connections` (Meta, GA4, TikTok, Pinterest: the platform's id, the encrypted token with its hint, `data_level` standard or enhanced, a test code, on) is written only by `src/server/ad-connections.ts`, owner-only, audited without the token, `never` copied.
`queueAdConversions()` (the every-minute marketing job) makes one `commerce.ad_conversions` row per order, platform and event (`begin_checkout` for an order made, `purchase` once a payment is captured and none is Stripe test mode) for orders with consent, from a shopper's checkout, not copied, a host's, restricted or gift cards only, of an open store; `sendAdConversions()` builds each request with `adRequest()` (`src/lib/ad-payloads.ts`, pure; the order's id as event id; hashes of the normalised
email and phone only at the enhanced level; no IP or user agent), sends to the platform's one host with a 5 s limit, three tries, then `failed` with the answer code. Ids on orders are cleared after 90 days (`pruneAdSignals()`, daily) and on erasure. Marketing → *Ads and conversions* (`/admin/{store}/ads`) shows each platform's connection and the last seven days' counts. Queued by the job rather than at the payment, so an event goes within a minute of the order or the capture.
Google Ads conversions by API and refunds are not sent. **I3:** Marketing gains *Campaigns* (`campaignReport()`, rows by source and campaign through `campaignRows()`, `campaigns-view.tsx`, CSV `marketing.campaigns`): sessions, paid orders and revenue of visits with a campaign tag, new customers, the spend entered under the campaign's name (case-insensitive), CAC and ROAS, by **Last visit** (default) or **First visit in 30 days** (`?model=first`, saying how many paid orders know their first
visit).
The first visit is kept only for a visitor who accepted statistics: `TouchKeeper` writes `kaizen_touch_{store}` (channel words, source, campaign and a day, no id; `KNOWN_COOKIES`, declared by `siteCookies()` only while visit counting and a statistics tool or a running test are on) and posts it to `/api/visit/touch`, which `recordTouch()` writes onto the same day's visit (`visits.first_*`, set once, with the page view's checks); the visit beacon stays cookie-free. *Make a campaign link*
(`campaignLink()`) tags a store's own address and names the channel. Ad spend is imported from a CSV (`importSpend()`, `analytics:write` like typing it, 2000 rows, a row already entered for its day, channel and campaign left as it is, other currencies refused by line), not a D165 job.
