# D663: Visitors who meet an error page, watched hourly

**Visitors who meet an error page, watched hourly (`docs/100-day-challenge.md` F4; 16 November 2026, `src/lib/autopilot-watch.ts`, `src/server/analytics-visits.ts`, migration `20261116100523_curly_machine_man`).** The watch judged each autopilot change on conversion and add-to-cart only: errors were counted per day (`store_usage_daily`, from Vercel's log drain), too coarse to blame one change, and production has no drain yet, so it has no error counts at all.
Now the store's error page (`s/[store]/[market]/error.tsx`, REL-01) says it failed: where the visit beacon runs (the store counts visits) and the browser sends no privacy signal, it posts the store and the path to `/api/visit/error`, and `recordPageError()` writes the time of the visitor's first error that day on their counted visit (`visits.error_at`, a nullable column on a hot table, added without a default).
It takes the visit's own checks (robots, Global Privacy Control and Do Not Track, the store's own pages, counting on, a page of the store) and marks only a visit already counted, so it starts no row, an error never counts a visitor, and nothing new about a person is kept: the visit is still a daily keyed hash.
The watch counts visitors who met an error in the hours since a change and in the same hours of the four weeks before; errors can rise from none, so the expected share is smoothed (`errorReading()`, half an errored visitor added to the weeks before), and a rise is clear at three times the expected share, three standard errors above it and at least five errored visitors (`ERROR_RISE_TIMES`, `ERROR_RISE_Z`, `MIN_ERRORS_AFTER`), checked after conversion and add-to-cart.
A clear rise undoes the change as a clear fall does. Server errors per hour (5xx) wait for the log drain, an owner step in Vercel (`docs/capacity.md`). Store-only: Kaizena Flow's own site has no autopilot changes to watch.
