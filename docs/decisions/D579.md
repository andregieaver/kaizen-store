# D579: Every dialog in the page builder moves and resizes as the settings panel does

**Every dialog in the page builder moves and resizes as the settings panel does (12 November 2026, `src/components/admin/movable.tsx`).** The owner asked that the media library's picker, the text styles and the builder's other dialogs move by their title bar and resize from any edge or corner, like a component's settings panel (`FloatingPanel`).
The panel's geometry (`clampRect`, `resizeRect`, the eight handles, the move button with the arrow keys) moved into `useMovable`, which the panel and `Modal` now share, so every dialog on `Modal` across the admin behaves the same; the builder's own native dialogs (a template's preview, scheduling a page, publishing with problems) use it too.
A dialog stays modal and opens centred by its CSS; the first drag or resize takes its place from the screen, and the end of a drag never counts as a click on the backdrop. One given `remember` keeps its place and size in the browser (`kaizen-window-{name}`): the media picker, a picture's details, the text style editor and library, and the template preview; the panel keeps its old key. Focus on opening is unchanged (`focusPastMoveButton()` steps past the new move button).
The picker's and the text styles' grids fill the dialog's width (`auto-fill`), so a wider dialog shows more in a row. Tested in `builder-resize.test.ts`. The text style dialog's gallery also ends in **Start from scratch** (the owner's request the same day): no look, an empty editor for the style's own CSS (`custom`, opened under Advanced); pressed again it keeps what was written, and choosing a look takes over as before (`e2e/signed-in/text-styles.spec.ts`).
