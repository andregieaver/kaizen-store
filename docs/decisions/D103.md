# D103: The owner assistant becomes the AI manager

**The owner assistant becomes the AI manager: a guide to the whole admin that works for store owners and for Kaizen's platform admins, learns how each person works, and opens from every admin page.** Modelled on Kaizen Life's assistant. It knows every admin page from a map in code (`src/lib/admin-map.ts`, each page's section, purpose and tasks, and whether it needs bookings, subscription boxes or an owner; a unit test walks the app's `page.tsx` files so the map cannot fall behind).
The prompt carries the map, the page the person is on (from the address their browser sends, used only if it is a page of the store or area it works in), its playbooks and what it knows about them. It can find pages by words (`find_admin_page`) and open them (`open_admin_page`: the browser goes there, a page that needs an id only with an id from a tool).
Playbooks for jobs people come back to (`src/lib/assistant-skills.ts`: getting ready to open, adding a product, the weekly review, sending orders, refunds, a sale, search, SEO, design, bookings, subscription boxes, selling more; and on the platform access requests, the platform's health and a store's plan) are listed by name and loaded with `use_skill`.
Store owners get new tools too: setup progress, a store checkup, customers, subscriptions, cart reminders, wishlists, emails and subscription boxes to read, and refunds (spend) and coupons (public) kept for approval. Platform admins get their own (`PLATFORM_TOOLS`: an overview, access requests (approving or declining kept for approval), stores, plans, owners, plan reminders and emails) and conversations of their own (a null `store_id`), refused to anyone but a platform admin.
Memory (`commerce.assistant_memories`, `src/server/assistant-memory.ts`): per account, about one store or everywhere, of four kinds (how they like it, their business, routines, goals). It is kept when the person asks (`remember`, `forget`, `recall`), learned after each turn by a short model call that keeps at most three lasting notes and never customers' details, emails, card numbers or passwords, and learned from thumbs on answers.
It is found by keyword and by meaning (vectors with their `space`, D73) fused by reciprocal rank, weighed 0.6 relevance, 0.25 recency (30-day half-life) and 0.15 importance, with the strongest preferences always given, and similar notes merge. Learned notes nobody uses fade daily and go after 180 days; what the person told it stays. The Memory tab shows every memory to edit or forget, forgets everything, and switches learning off (`accounts.assistant_learns`).
It is opened from an AI manager button in the store admin's header (owners) and the platform's bar, or ⌘K / Ctrl+K on any of their pages, as a panel beside the page that stays open across pages. Each has a full page (`/admin/{store}/assistant`, `/admin/platform/assistant`).

Date: 2026-09-29

Asked for by the owner: an AI store manager that knows every part of the admin, guides owners as the chat agent guides shoppers, learns their preferences, and is easy to reach in both admins. A map in code rather than crawling pages keeps it fast, cheap and exact, and the coverage test keeps it true. The panel is not modal, so the page it opens is the one being talked about.
Memory follows Kaizen Life's design and D94's rules: the model only suggests notes, code filters them, the person sees and controls every one, and store data is never copied into memory (tools read it fresh). Kaizen Life's MCP (D96) still serves the owner tools only; guiding and memory are for the admin. Not yet: staff who are not owners (a skill an owner shares with the store, D350, reaches the store's other owners), memory shared between people of a store, and scheduled briefings.
