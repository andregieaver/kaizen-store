# D128: Motion design

**Motion design: curated effects on components, rows, columns and backgrounds, and a "Make my page cool" button.** Owners pick from lists (`src/lib/motion.ts`: 20 entrances, 10 hover effects, 9 scroll effects, 6 background effects, animated gradient backgrounds `shift`/`aurora`/`mesh`/`conic` with optional grain) in a Motion tab of every settings dialog and under a background; only names and small named amounts are stored (`PartBase.motion`, row/column `backgroundMotion`, schemas shared with the
server), never CSS or code. It is CSS first (`src/app/motion.css`: keyframes, `animation-timeline: view()` for scroll effects, hover) with a small lazy runtime (`src/lib/motion-runtime.ts`, the `motion` package's `scroll()` only for browsers without scroll timelines, about 3 kB gzip) for waypoint entrances (`inView`-style, `start` early/middle/late, `once`), text splitting, tilt/magnetic/spotlight and the Firefox fallback; it loads only where a page needs it (`pageUsesMotion()`).
Rules: content is always in the HTML and shown without JavaScript, with `prefers-reduced-motion`, and after a 4 s failsafe; `load` entrances and the first flow row are pure CSS and never wait for JS; a first-row picture never starts transparent (LCP); only `transform`, `opacity`, `filter` and `clip-path` move, so nothing shifts the layout.
`partFx()`/`backgroundFx()` turn the data into `data-fx-*` attributes and `--fx-*` custom properties for the site and the builder's canvas ("Preview motion", live preview in the tab). **Make my page cool** (wand button in the builder toolbar, `MakeCoolDialog`, `planMotionAction`, `planPageMotion()` in `src/server/motion-ai.ts`, feature `page_motion`): the site's AI gets a compact outline of the page (structure and headings' words, no prices, emails, links or form data) and may only choose effect
and part ids; `cleanMotionPlan()` enforces one coherent style, caps (about one part in three, at most two entrance families), the first row's rules and no nesting, and the summary is written in code; without AI, or if its answer is unusable, `ruleBasedPlan()` gives a standard design. `applyMotionPlan()` never changes motion the owner already set, the result lands in the editor unsaved with one Undo, and the canvas plays it. No database change (motion is part of a page's content).
