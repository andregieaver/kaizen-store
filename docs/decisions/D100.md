# D100: Owners write their own CSS in the page builder

**Owners write their own CSS in the page builder: for one page, and globally for the whole site.** The Custom CSS button in the builder's bar opens a side panel over the editor's right column with two tabs.
This page (or header, footer, article, layout) is `PageContent.css`, saved with the page and live when it is published; Global is the owner's for every page of the site (`stores.custom_css`, `platform_settings.custom_css`; headers and footers too), live when saved from the panel (`saveSiteCss()`, `src/server/site-css.ts`, audited). The canvas shows both as they are typed.
On the site, `<CustomCss>` puts the site's, the header's, the footer's and the page's in the head after the theme (`precedence="custom"`), so they win over it and, unlayered, over the utility classes.
Because the CSS is shown on Kaizen's own address until stores have their own hosts (P7), and in the admin, it is checked the same in the browser (`pageInput`) and on the server, and again before it is drawn (`cssProblem()`, `siteCss()`, `src/lib/custom-css.ts`): no `<`, which could end the `<style>`; braces that balance and backslashes only in quotes, so it cannot leave the block it is put in or hide a word; no `@import`, `@charset` or `@namespace`, and no function that loads a file but `url()`;
`url()` only to the site itself, the media library (Kaizen's storage) or a `data:` picture or font, so it asks no other site for anything: no visitor is tracked without consent (D58) and nothing on a page can be sent away. In the admin (the canvas, previews) it is kept inside its box with `@scope` and paint containment, so it never styles or covers the admin; there `body` and `html` rules have nothing to match. At most 50,000 characters each. New stores start with none of their own.
