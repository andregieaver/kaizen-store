# D902: The CRM reaches Zapier, Make and the Admin API (D901 P29)

**Until Kaizena Flow's own Pipedrive and HubSpot connections exist (D901), an owner can already keep another CRM in step through Zapier, Make or their own code (unit P29 of `docs/pipedrive.md`, built 25 November 2026).** It has two parts.

**The events.** Eight topics now reach Zapier and Make, not only an owner's own endpoints: `deal.created`, `deal.stage_changed`,
`deal.won`, `deal.lost`, `activity.created`, `activity.done`, `lead.dismissed` and `lead.deal_made`. Their payloads are the endpoints'
subjects, ids and facts as before (D718, D757). Slack is told of the four deal topics as messages (`dealMessage()`): the title, escaped,
the worth and where the deal stands. It is never told of an activity or a lead decision, which are each person's own work
(`NOT_TO_SLACK`, `serviceEventsOf()`, `isServiceEventOf()`). The activity and lead topics now belong to the Deals extension
(`TOPIC_EXTENSIONS`), as the deal topics did, so they are offered only where Deals is.

**The Admin API, read** (`src/lib/admin-api-crm.ts`, `src/server/admin-api-crm.ts`), all under `customers:read`:

* `GET /pipelines`, with their stages.
* `GET /deals` and `/deals/{id}`, narrowed by status, pipeline, stage, owner, person and company. A page is chosen in SQL and read through
  the board's own `listDeals()` (it now takes `ids`), so a deal's worth is the board's.
* `GET /activities` and `/activities/{id}`, narrowed by done, deal, person, company and assignee.
* `GET /leads`: the inbox through `leadsOf()`.
* `GET /companies` and `/companies/{id}`, with how many customers buy for each.
* A customer's answer gains `company_id`.

Deals, activities and leads answer `feature_off` without Deals or its extension. Never a lost deal's reason, an activity's note or a
lead's words. `customers:read`'s words say it reads these. API contract 1.61.

*Not yet:* writing deals and activities over the API. A write needs a scope no older token holds (D440's rule), so it comes with a new
scope of its own rather than growing `customers:manage`.

Date: 2026-11-25

Tests: `admin-api-crm.int.test.ts` covers the reads, filters, pages, another store's records, a token without the scope, and the words
that never leave. `admin-api.int.test.ts` parses every operation. `integrations.test.ts` and `slack.test.ts` cover what each service is
sent and Slack's deal messages. `extensions.test.ts` checks that the new topics are offered only with Deals. No migration: the database
already queues whatever a service chose.

One budget rose on purpose: the docs feedback route reaches one file more, the slice's own (`route-load.baseline.json`, 291 to
292), as `docs-reference.ts` reads every operation.
