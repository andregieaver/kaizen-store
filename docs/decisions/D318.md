# D318: PSI follow-ups while building

**PSI follow-ups while building (`docs/audits/psi-2026-10-24.md`, `docs/audits/psi-followups.md`).** The audit's fixes that make development faster without lowering the build are made now, and the rest are tracked in the follow-ups for later. Every system prompt that takes words someone else wrote (a shopper's message, a page, a product, an email, a tool's answer) says so (`UNTRUSTED_TEXT`, `RULES_STAND` in `src/lib/prompt-safety.ts`, held by `prompt-safety.scan.test.ts`).
Storefronts have their own error page in the visitor's language and the app a root `global-error`. Every route sends `nosniff`, and the admin may be framed only by itself and the theme store's host. Scheduled jobs are recorded in `commerce.cron_jobs` (`tracked()`, `runJobs()`, `trackedRoute()` in `src/server/cron-runs.ts`; never throwing) and judged by `cronHealth()`. The platform's home names jobs that are late or failing, and the capacity page lists them.
Server code logs one JSON line through `log()` (`src/server/log.ts`). Raw SQL reads move to `typedRows()`/`typedRow()` (`src/server/typed-rows.ts`: zod shapes per column, an error names the column and never the value), starting with the gift-card figures.
The AI agents (the chat agent and the AI manager) have an eval (`src/lib/agent-eval.ts`, `src/server/agent-eval.ts`): nine cases (ten since the support tools) with the real prompts and tools, a scripted tool layer that runs nothing (gated calls answer *kept*), and a pass only when every case passes. It is run from Platform → AI and kept in `commerce.ai_eval_runs`. Migration versions (applied by CI, 24 October 2026 20:12 UTC): `20261024193327_cron_jobs`, `20261024193354_cron_jobs_rls`.
Advisors checked after: the new table shows only the expected `rls_enabled_no_policy` notice. Two warnings were there before: `public.rls_auto_enable()` executable by anon and authenticated (a dashboard setting, not in the repository; it returns `event_trigger`, so it cannot be called directly), and leaked-password protection off. Both are in the follow-ups.
Then `20261024200331_ai_eval_runs`, `20261024200349_ai_eval_runs_rls` (applied by CI 24 October 2026 20:50 UTC; advisors after: nothing new). The AI manager can now schedule (AGT-04, AGT-11). `start_experiment` takes an optional `at` (the store's wall-clock time) and then schedules the test through `scheduleExperiment()`, with the same checks.
Follow-ups (`follow_up`, `list_follow_ups`, `cancel_follow_up` in `MANAGER_TOOLS`; `src/lib/follow-ups.ts`, `src/server/follow-ups.ts`, `src/server/follow-up-runner.ts`, `commerce.assistant_follow_ups`) give a task back to the AI manager at its time, as a turn in the conversation it was asked in. The turn runs in the person's name with what their role may do that day, sets no further follow-up and decides nothing in words.
The person gets an email (`assistant.follow_up`) saying where to read the answer, never the answer itself. A follow-up can repeat daily or weekly at the same local time, and a failing one stops after three tries. Migration versions: `20261024204840_assistant_follow_ups`, `20261024204856_assistant_follow_ups_rls` (applied by CI 24 October 2026 23:06 UTC).
Task parity, marketing first (AGT-01): the AI manager lists, drafts and sends or schedules broadcasts (the send waits for a yes), counts segments, tags customers, and lists and switches email automations (the switch waits for a yes), each through the screen's own function. Review moderation gets no tool: a review's words never go to a model (D301), so an agent could not judge one.
Turns started by events (AGT-04): the order rule action *Ask the AI manager* queues a follow-up for the paid order, in the name of whoever last saved the rule while they are an owner, at most 20 a store a day. Restores (REL-04): `docs/runbooks/restore.md` has the targets and the copy's scheduled jobs as the first step, and `scripts/restore-check.mjs` runs the drill's checks read-only.
`public.rls_auto_enable()` is no longer executable by `anon` and `authenticated`; its event trigger still fires, tested. Migration versions: `20261024213329_revoke_rls_auto_enable`, `20261024214224_follow_ups_from_rules` (applied by CI 24 October 2026 23:06 UTC).
Advisors after: the `rls_auto_enable` warning is gone (EXECUTE only for `postgres` and `service_role`); the new tables show only the expected `rls_enabled_no_policy` and `unused_index` notices; leaked-password protection is still off (a dashboard setting).
Answering support (AGT-01): `get_support_conversation` reads a conversation as the inbox does (no partner's help, no contact details; an eval case hides an instruction in a transcript), `add_support_note` and `end_support_conversation` act as the person, and `reply_to_support` (gate `send`, the exact words approved, the claims filter first) takes the conversation over and answers in their name, all through `agentAct()`.
This revises 5.5's "never transcripts" for a member with `support:read`, who reads them in the inbox anyway.
The team and the plan (AGT-01): `list_staff`, `invite_staff`, `change_staff_role`, `remove_staff`, `billing_overview`, `change_plan` and `end_plan`, the owner's alone, through the Staff and Billing pages' functions with the membership read again; the team's changes wait for a yes under a new gate category, `access` (migration `20261025091235_approvals_access`, applied by CI 25 October 2026 09:56 UTC; advisors after: nothing new), the plan's under `spend`; the first plan is never chosen by a
tool. Order changes and exchanges (AGT-01): `preview_order_change`, `change_order` (spend: a lower total refunded at once, a higher one sent as a pay link; the order's state previewed is kept with the approval and a moved order is refused), `preview_exchange`, `propose_exchange` (send, by email only) and `process_exchange` (spend), all through the order editor's and the exchange builder's own functions; replacements only at their list price.
Work (AGT-01): `work_overview`, `list_work_clients`, `list_work_assignments`, `log_time` and `issue_work_invoice` (send: issued through Work's own issue and emailed), only while the store has Work on.
