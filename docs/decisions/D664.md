# D664: The invoice job asks only stores it can issue for

**The invoice job asks only stores it can issue for (bloat review step 0.30; 16 November 2026).** `storesWithDocumentWork()` lists a store only when its waiting orders pass `invoice_eligibility` and `invoice_readiness` (behind the cheap tests, so the list stays fast with many waiting orders), the store whose order has waited longest first. `invoiceJobs()` calls `issue_missing_credit_notes` on its own only when no invoices were issued, since `issue_waiting_invoices` already performs it.
Saving the business details, the tax profile or the invoice settings issues the invoices that waited for them. A live drill (`invoices`) proves the chain: a paid test order gets its invoice; `live_drills.kinds` takes 1 to 20 kinds. Kaizena Flow's own invoices for plans come from Stripe, so the job is store-only. Migration versions (applied by CI run 1388, 16 November 2026 10:04 UTC): `20261116033159_live_drill_kinds`.
