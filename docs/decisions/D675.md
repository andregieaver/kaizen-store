# D675: The autopilot processes a confirmed exchange

**The autopilot processes a confirmed exchange (`docs/100-day-challenge.md` B3; 16 November 2026, `src/lib/autopilot-autonomy.ts`, `src/server/autopilot-gate.ts`, `src/lib/autopilot-events.ts`, `src/server/autopilot-events.ts`, `src/server/exchange-tools.ts`, migration `20261116115735_rainy_jasper_sitwell`).** An exchange the store proposed for a return (D239) and the customer confirmed waited for a person to press Process: `process_exchange` is never automatic.
The challenge's re-sort (4A2) lets an exchange's goods move by themselves and keeps its money for a person. A customer confirming now raises an `exchange_confirmed` event (once per exchange, while it is confirmed and within its time, the order still the person's), whose turn has `get_order`, `process_exchange` and `add_order_note` and is told never to write to the customer.
In challenge mode `autonomyDecision()` runs `process_exchange` itself, under the area `messages`, only when processing gives nothing back to the customer: `exchangeRefundOf()` reads the exchange as confirmed and takes the refund of `exchangeOutcome()` (even, or the customer pays the difference by a link, is 0); one that refunds, or one whose refund cannot be read, is kept for the owner, so it reaches the refund queue (A3).
`processExchange()` checks the credit again when it runs and refuses a changed one. Outside the challenge nothing changes: `process_exchange` still always waits for a yes. Resending goods for a lost parcel stays a person's: a replacement costs goods and needs its own tool. Store-only: Kaizena Flow sells plans, with no returns to exchange. Since D679 that tool is `send_replacement`. Migration versions (applied by CI, 16 November 2026): `20261116115735_rainy_jasper_sitwell`.
Advisors checked after: INFO only.
