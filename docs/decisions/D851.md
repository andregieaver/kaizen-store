# D851: A page's permission is its own, not its place in the menu: every nav item names its area, areaOfPath and platformAreaOfPath read it, and page guards take their key from the path

**A page's permission area is written on its navigation item, never taken from the section it is listed in (code review step 1.17,
finding FN2; 20 November 2026).** Before, `areaOfPath()` gave a store page its section's key, four addresses aside (`AREA_OVERRIDES`),
and `platformAreaOfPath()` the area of the list or tab a platform page sat in: moving a page in the menu changed who could open it.
Every `StoreItem` now names its `area` (`item()` requires it; today's section key, so nothing changed): Team, Billing and Books name
`staff`, `billing` and `books`, and Forms names `/forms/responses` the customers' (`within`), so the overrides went. `navAreas()`
(`src/lib/store-nav.ts`) lists each address with its page's area (an item's path, `also` and `within`, and a page of cards, which is
its section's own page); `areaOfPath()` reads `STORE_NAV_AREAS` by the longest address, as `sectionOf()` did, so a deep page or an
action has its item's area. Platform, in the same change: each `SectionItem` names its area, the pages outside a sidebar (the two
hubs, Themes, Stores, Customers, Access requests, the docs folder) are `PLATFORM_PAGE_AREAS`, and `platformAreaOfPath()` reads both
the same way; Home is `home`, an address in none the owners'. Its tabs and sidebars are untouched (step 1.18).

Guards keep their key in code, as a copy their path's area is checked against, not read from it: a server component is not told its
route, an action can be posted to any page's address (D510), and a literal is what the scans read. `permissions.scan.test.ts` already
held every store entry point's key to `permissionOfPath()` of its folder (209 of 287 store pages name one by hand, the rest through a
wrapper or membership only); `platform-access.scan.test.ts` now holds `platformCan(account, "area")` in a folder to it too, as it
held `requirePlatform()`. No key differed, so no page changed. Taking the key from a route string on 200 guards would add a second
hand-written copy (the route) and no guarantee the scans lack.

The step's test is met by what the baseline is compared with: `permissions.baseline.json` records what each file asked for before
roles, not an area, so a move could never change it. The scan tests move every item, store and platform, to the next section in a
copy and find every entry point's, folder's and map page's area unchanged; an item given another area takes only its own pages along.
Compared before and after: 758 store addresses (area, read and write keys) and 274 platform addresses, all the same. Phase 2 of the
admin audit may now regroup the menu. Nothing a person sees changed.

Date: 2026-11-20
