# D406: Live drills

**Live drills: the platform runs a store's money paths for real in Stripe's test mode (consolidation, `docs/consolidation.md`).** A platform admin (or the platform's AI) asks for a store's drills (`requestDrills()`, `commerce.live_drills`, refused unless the store's checkout is in test mode); the five-minute dispatcher runs one request at a time (`runLiveDrills()`): `webhooks` (Stripe's endpoints at the site's address, the last day's events processed), `payment_facts` (each paid test payment
read from Stripe), `mark_sent` (`markSent()`), `partial_refund` and `full_refund` (`refundOrder()`, the refund row and Stripe's reference checked, what is left to refund recomputed). A drill touches only an order whose every payment was made on a test account and whose email is at Resend's test domain (`DRILL_EMAIL_DOMAIN`), so never real money and never a shopper; results are kept with order numbers and amounts only.
Also in this change: Stripe's endpoints kept at the site's own address (`keepStripeWebhooksCurrent()`, moved in production on 29 October at 21:30 UTC; they had pointed at the old domain, which answers 308, so no Stripe event had arrived since the move), `testPayment()` for every reader that asks whether a payment was a test, booking words that fit stays and rentals, and the integration tests in three CI shards.

Date: 2026-10-29

*Why:* the owner's principle that the AI should be able to run every live check itself; staff actions need a signed-in member and the Admin API and AI manager keep refunds for a person's yes, so neither could.
