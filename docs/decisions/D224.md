# D224: The admin's pages draw in the colour roles only

**The admin's pages draw in the colour roles only: no older token names and no fixed palette colours (`docs/admin-style.md` section 8, step 8).** A codemod over `src/app/admin`, `src/components/admin`, `src/lib/work-ui.ts` and `src/lib/return-admin.ts` rewrote class lists: the older names to their roles (as `admin.css` drew them, so the look is unchanged in meadow: `bg-background` card, `bg-surface` sunken, `border-border` line, or edge on a button, `text-foreground` ink, the main action
`bg-brand text-brand-ink`, a plain `bg-foreground` brand and one behind a variant or with an opacity inverse, `border-foreground` and `accent-foreground` brand), and fixed palette colours to signals by meaning (red danger, amber warning, green positive, blue insight, grey neutral; their `dark:` twins removed). A solid red button with white words became the danger button of 5.6.
About 3,500 old names and 400 fixed colours in 459 files; the strings the parser could not split safely were changed by hand. Left alone: where a store's look or a printed document is drawn, and three colours that are someone else's (the builder's resize handles, carriers' brand marks, the search engine's preview). `admin.css` matches both spellings while the old one remains there; `admin-type.scan.test.ts` refuses either in the admin from now on.
Twelve unit tests that named the old classes now name the roles. No migration.
