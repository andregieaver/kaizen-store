# D472: Kaizena Flow's site reads in dark mode again

**Kaizena Flow's site reads in dark mode again (6 November 2026, migration `platform_dark_navy`).** The live accessibility scan (`e2e-live/a11y.spec.ts`, Live accessibility) failed every day from 4 November on `/` and `/no` in dark mode: two headings' highlighted words at 1.22:1 (#2A2A72 on #262522).
D408's dark-mode rule gives the site's highlighted words (`.green-text`, `.super-heading.dark-color`) a light colour where no light row is behind them; when the site's accent turned from green to navy (the *Colour* text style, 4 November) that rule's colour was set to the navy itself, so dark mode drew navy on near-black.
It is now a light tint of the same navy, #9E9EDB (6.1:1 on #262522, 7.1:1 on #171717, 5.0:1 even on the navy), and the *Colour* style's words (`.ts-colour`) take it too where no light row is behind them; light mode is unchanged. The site's CSS and Kaizena Flow's own store's copy of it (D469) keep their versions first (D305); CSS without the rule is left as it is (`src/db/platform-dark-navy.test.ts`).

Date: 2026-11-06

Asked for by the owner ("Fix the live a11y scan on kaizenaflow.com"). *Why a tint and not the green back:* the navy is the owner's new accent; dark mode needs it light, not another colour.
