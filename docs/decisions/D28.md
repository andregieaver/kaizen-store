# D28: Shoppers get My account per store, signed in with an emailed code or a password they chose

**Shoppers get My account per store, signed in with an emailed code or a password they chose.** The code (six digits, ten minutes, five tries, at most five an hour, stored only as a hash) also proves the address, so every order and subscription placed with it joins the account, and later ones join when paid. After that, the customer can add a password (at least 12 characters, scrypt, ten wrong tries lock it for 15 minutes); codes keep working.
Nothing on the sign-in page reveals whether an address has an account. The account shows orders (with tracking, downloads and refunds), subscriptions (managed on their own page), the customer's name, phone and address, the password, and deleting the account. A session is a random token in an httpOnly cookie for the store, of which only a hash is stored; it lasts 60 days.

Date: 2026-09-24

Guest checkout stays as it is. Deleting an account removes the customer's details, password and sessions; orders stay with the store, as bookkeeping law requires, without the link to an account. The account's address starts as the one the last order went to. Signing in by code needs email to be set up (D26); until then codes are only recorded, so shoppers cannot sign in on a store in production. Checkout does not yet prefill from the account.
