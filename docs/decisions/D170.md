# D170: The WordPress plugin gets product pages and a slide-out cart; the checkout stays in the store

**The WordPress plugin gets product pages and a slide-out cart; the checkout stays in the store.** A page of the site holding `[kaizen_product]` shows any product of a store a saved view uses (made on the server for search engines, with structured data; an unknown product is a 404), with its options chosen on the page, its price and stock as Kaizen says; products go into a cart kept in the browser and shown in a slide-out dialog (`assets/cart.js`), priced live by
`POST /api/wordpress/v1/stores/{slug}/cart/quote`; *Checkout* calls `…/cart/handoff`, which makes the same cart in the store, checked line by line as if added there (`sellableQuantity()`, goods and downloads only, a quantity cut to the stock, no cart when nothing can be bought) and gives a one-time link (`carts.handoff_hash`, 15 minutes) that `/s/{store}/{market}/cart/resume` opens once to make it the browser's cart before sending the shopper to the checkout.
The subtotal is a sum of the lines; shipping, discounts, campaigns, VAT and payment are the store's. The token now also **makes carts** (stated on the approval page): it still reads no order, customer or setting and changes no product, price, order or setting. `docs/wordpress-plugin.md` is the contract.
