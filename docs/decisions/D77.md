# D77: Search test

**Search test (Phase 2, S5): platform admins start a randomised test at Platform → Search test; while it runs, each search in every store is given hybrid search (words, meaning and understanding) or keyword search alone at random, and the page compares the two.** Assignment is per search, drawn on the server when the search runs (`drawArm()`, `commerce.search_experiments.keyword_share`, 5–95 %, one test at a time); the keyword arm asks no model.
Each search's log row keeps its test and arm (`search_queries.experiment_id`, `arm`), and its result links go through `/s/{store}/{market}/search/go`, which records which result of which search was opened (`search_clicks`, with its place in the list) and opens the product; the links are plain `rel="nofollow"` links, never prefetched, and results pages ask crawlers not to follow them.
The results (`experimentResults()`, arithmetic in `src/lib/experiment-stats.ts`) compare the arms on the share of searches with results where one was opened (primary) and the share that found nothing, each with a 95 % interval for the difference, the average place of the first opened result, and week by week.
Decision rule fixed in advance (`verdict()`): nothing is read before 200 searches in each arm; hybrid is better or worse only when the whole interval is on one side; a sample-ratio check (chi-square against the share asked for) below p = 0.001 marks the results as broken.

A shopper can meet both arms in one visit. Clicks go with their search after 90 days.
