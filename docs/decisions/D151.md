# D151: A picture keeps its own size

**A picture keeps its own size.** In the page builder a picture block was stretched to its column; it is now drawn at the picture's stored width and height (for a crop, the largest crop of that shape inside it), never larger, and still shrinks to fit a narrower column or a phone, keeping its shape.
Its Style tab has **Width** (pixels, `maxWidth`, down to 16, a slider and a number, with *Own size* to reset) and **Position** (left, centre or right by screen, `align`, the same choice as a button's; the caption follows). The block's frame (border, shadow, corners, spacing, id, classes and motion) is on a box as wide as the picture, not on the empty column beside it.

Date: 2026-10-02

Asked for by the owner: the picture's original height and width must be kept, with a way to make it smaller. Stored as two optional keys in the page's JSON (left out at the picture's own size and at the left), so there is no migration. The size is worked out only by `imageDisplaySize()`; `blockBox()` limits the box with the class `max-w-(--picture-width)` and a custom property, never an inline width, so owner CSS and the page replicator's rules can override it.
Pixels were chosen over a percentage so the number means the same when the picture is replaced or cropped, and for a picture taken from a custom field, whose real size is not known (it stands in as 1600 × 1200, `BOUND_PICTURE_SIZE`).
Consequences: existing pictures narrower than their column stop stretching and sit at the left (Position moves them); uploads are at most 1600 px, so a large one still fills a content column (the page is narrower than that), but in a wider, full-bleed row it now stops at its own size and sits at the left until Position moves it; a left or right margin set under Spacing wins over Position; copies made by the replicator keep their measured size because their own rules win.
A *fill the column* choice is not offered.
