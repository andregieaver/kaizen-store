# D640: A customer's address change and cancellation carried out by code

**A customer's address change and cancellation carried out by code (`docs/100-day-challenge.md` B3, the Day 1 part; 15 November 2026, `src/server/support-requests.ts`).** The support chat passed every change to an order to a person as a staff request.
Now the chat's `request_staff_action` takes the new delivery address as fields for an address change (`requestAddress`, as the customer wrote it; an incomplete one is asked for again), and a request code may carry out is a `staff_request` event: an address change with an address, or a cancellation, asked on the store's chat by the order's own signed-in customer (the conversation's customer is the order's, by id or by the account's email), the order paid, not held and nothing of it sent.
Never a request by email, whose sender cannot be checked, nor a visitor who typed an order number. The turn changes the address with `carry_out_address_change` (gate `send`, area messages, `orders:write`), which checks all of it again (`requestOf()`, `refusal()`), keeps the order's email, writes through the order page's `updateOrderContact()` and decides the request through `decideRequest()`, so the customer gets the same line and email as when a person decides it.
A cancellation goes through `cancel_order`, which refunds and so waits for the owner (the refund queue in the challenge); when it is done it closes the order's open cancellation requests (`closeCancelRequests()`). A refused request stays a person's, with a note on the order. Resending and exchanges stay a person's.
