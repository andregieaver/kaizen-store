# D563: A product passport's address with no published passport is a real 404

**A product passport's address with no published passport is a real 404 (11 November 2026, `src/app/passport/[id]/layout.tsx`, `publicPassport()` in `src/server/product-passports.ts`).** D554's page read the passport inside a `<Suspense>` after its frame had been sent, so an unknown or unpublished address answered 200 with a page that said nothing was there (a soft 404, which search engines and scanners read as a page).
The passport is now read in its own root layout before anything is sent, through a cached read (`'use cache'`, hours at most, tagged `passport:{id}` and the store's catalogue tag; only a well-formed id reaches the cache), and a missing one throws `notFound()` there, so the platform's `global-not-found` answers 404; the page draws from the same read, and `<html lang>` is the passport's language. Saving a passport refreshes its tag, so a draft read before it was published is never kept as missing.
`/passport/[id]/json` already answered 404. Store-only, as D554. Tested in `e2e/signed-in/passport-claims-ebay.spec.ts` (an unknown id, a malformed one and the data address all 404). No migration.
