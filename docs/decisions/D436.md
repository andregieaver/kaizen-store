# D436: New interface text reaches the machine-translated languages by itself

**New interface text reaches the machine-translated languages by itself.** Once a night the platform's AI (`aiFor(null, { feature: 'ui_translation' })`, Kaizena Flow's own key) translates the interface texts each kept-up language has none for yet: a language switched on in `commerce.platform_languages`, not written by hand (nb, sv, da, en never are), that already has interface text, which a platform admin gave it with *Translate* on Platform → Languages (D111).
Only missing texts (`planGeneration(lang, "missing")`, checked again when the answer is kept, `generateChunk(…, { missingOnly: true })`): never a text that has one, so nothing is translated again, a person's text is never touched and a text whose English changed waits for a person's *Update … whose English changed*; never a hand-written-only key (the catalogue leaves them out, and the plan drops any it is handed).
At most 300 texts a language a night (`UI_NIGHT_KEYS_PER_LANGUAGE`), in calls of 40 as *Translate* sends them, the languages with the fewest missing first, and no new call after two minutes (`UI_NIGHT_BUDGET_MS`), so the run fits the dispatcher's 300 seconds beside its other jobs; a language the AI does not answer for waits for the next night and the others are still tried.
Kept as unreviewed AI drafts exactly as *Translate* keeps them, audited as `language.ui_generated` with no account and `nightly: true` (as the platform's other jobs audit, `retention.run`), logged with `log()` (language codes and counts only).
It runs from the five-minute dispatcher as `uiTranslations` (`src/server/ui-nightly.ts`, pure parts `src/lib/ui-nightly.ts`): from 02:00 Oslo time the first run claims the day in the job ledger (`claimDay()`, new in `src/server/cron-runs.ts`: one run a day takes it, also when two run at once) and runs as `daily.ui-translations` (every 86,400 s, so the platform home says when it is late or keeps failing); the dispatcher's answer says why a run did nothing (`not_yet`, `done_today`, `paused`,
`no_language`, `no_ai`, `nothing_missing`), and it waits while AI that acts on its own is paused (PSI AST-07). Platform → Languages says in one line that texts added since are translated each night, up to 300 a language.
No migration. *Cost today:* production has 23 languages switched on for stores to choose (D111 started with every EU language) but `commerce.ui_translations` is empty and every store's countries use nb, sv, da or en (one store template also offers Spanish), so no language is kept up and the job reads two tables a night and spends nothing until a platform admin translates a language.

Date: 2026-11-03

Asked for by the owner: a text added to English after a language was translated showed in English there until someone pressed *Translate* again. *Why only languages already translated, not every one switched on:* all 23 switched-on languages are there for stores to choose, not because anyone translated them; translating them all would start about 1,700 texts each, every night until done, for languages no shop sells in, and a platform admin's press of *Translate* is the choice to have a
language's interface at all. *Why 300 a night:* the catalogue holds about 1,700 texts and a day's work adds a few dozen (the whole of D431 about 40), so 300 keeps a language current after the busiest day while a bad night costs at most about eight calls a language; a longer backlog is *Translate*'s. *Why missing only:* the AI never replaces a text, so what a person reviewed or wrote stays as they left it; a changed English text is counted out of date on the language's page for a person to
update. *Why the ledger for the day:* the job is the platform's, with no table of its own, and the ledger already keeps one row per job; claiming the day there needs no migration and gives the platform home the run to watch.
