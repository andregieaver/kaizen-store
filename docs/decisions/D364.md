# D364: Refund to store credit

**Refund to store credit (wave 10 unit A, `docs/wave-10-must-haves.md` 2); built.** Staff choose *Refund to: the original payment / store credit* in an order's refund form.
A store credit refund asks no provider: `refundOrder({ toCredit })` splits the amount over the order's captured payments as any refund (`splitRefund()`, so the card can later be refunded only what is left) and records each part as a refund of kind `store_credit` (`REFUND_KINDS`; created `succeeded`, never an exchange's or a change's, capped by the database like money taken outside, `refunds_manual_cap()`); a gift card's own part still goes back on that card.
In the same transaction the database issues ONE gift card for the credit (`commerce.gift_card_issue_refund()`: source `refund`, `gift_cards.refund_id`, the order's currency and mode, for the order's customer and address, its expiry from the store's settings, once per refund), its code set and the card delivered; after the commit the code is emailed to the order's own address (`sendRefundCredit()`, `gift_card.issued`, the code a secret of the email log) and shown once to the staff member.
It is a refund everywhere a refund counts (its credit note, sales, bonus and referral reversals); Kaizena Flow's fee is not returned, as Stripe is not asked. Refused for an amount of zero, a host's booking and any caller's own transaction, exchange or payment. Words: `giftCardEmail.refundSubject`/`refundText` (nb, sv, da, en, `HAND_WRITTEN_ONLY` with the gift card email), the `order` catalogue's `refundTo*` and `credit*`. `orders.partial-and-full-refunds-with-restocking` moves to full.
