**The docs guide (wave 14 unit E5, `docs/wave-14-developer-platform.md` E5); built; its eval recorded on production, 23 of 23.** *What it is:* a second chat agent beside the platform chat (D81), Kaizena Flow's own, on the docs alone, with settings of its own in `commerce.docs_guide` (one row: on or off, name, picture, greeting in English and Norwegian, daily limit; under *Customise* its occupation, the picture's frame and the platform's guidance, which comes after the rules) at
`/admin/platform/docs/guide` (Website, beside Docs feedback; `saveDocsGuide()`, audited `platform.docs_guide_saved`, tag `docs-guide`).
Not a second `chat_agents` row: that table keeps one row per site under `UNIQUE NULLS NOT DISTINCT (store_id)`, Kaizena Flow's being the row without a store, and `saveChatAgent()` upserts `ON CONFLICT (store_id)`, so a second row without a store could not be written and the constraint must stay while the old code runs. *Its tools* (`guideTools()`, `src/lib/docs-guide.ts`; answered by `src/lib/docs-guide-tools.ts`, pure, and `src/server/docs-guide.ts`): `search_docs` (E3's `searchDocs()` with its
filters: track, kind, area, language), `read_doc` (a page's title, summary, check date and sections as the index cuts them, an article in the reader's language where it has one, a page of the generated reference, the changelog, a section's list of pages; the asked section first, within 5,000 characters, the rest named), `api_operation` (an Admin API operation by its name or its method and path, or a storefront route, from `ADMIN_API` and `STOREFRONT_ROUTES`, with its section of the generated
reference), `webhook_topic` (`WEBHOOK_TOPICS`, or every topic's id and title) and `mcp_tool` (the owner MCP's catalogue and the shopping agents'), `navigate` (a docs page the docs have; for a signed-in person an admin page by its path, held to the admin map: never a page of one record, a store's page in their one store or else the admin's front page where they choose, the store never the model's, a platform page for the platform's admins only) and `offer_support` (the hand-over, as the platform
chat's `handoff_to_human`: the panel shows *Contact Kaizena Flow support in the admin* and the platform's email address, and the topic goes to the gap list).
None reads or changes a store; a unit test holds the server module's imports to the docs, the search, the AI, the log, the platform's navigation, the prompt's version and the guide's own. *Its rules* (`guideSystemPrompt()`, with `UNTRUSTED_TEXT`): only what its tools return, search before answering and read the pages it answers from, a comparison with another platform from what the docs say alone (as D428), the docs not covering something said plainly with `offer_support` and never answered from
the model's own knowledge, a question whether the reader runs a store or builds on the platform when it cannot tell, Norwegian (bokmål) to a Norwegian reader and English otherwise, never asking for or repeating a token, a key or a password, never claiming to act in a store, plain text without addresses.
Versioned (D391): `fixedGuidePrompt()` (the English front page, not signed in, no name, the fixed day) and `guidePromptVersion()`, kept with each answer (`docs_guide_messages.data.prompt`, never shown to the reader) and in `promptVersions()`; its tools are in `toolsVersion()`. *The answer:* the pages it read (else, when it read none and offered no support, the best three of a search whose words all matched) are drawn under it as links by code, at most five; its words pass `cleanGuideReply()`

Date: 2026-11-04

Asked for by the owner on 3 November 2026 as part of the docs portal. *Why a table of its own and not a column on `chat_agents`:* widening that table's key to a site and an agent would drop the constraint every running writer's upsert names; a new row type there would also make every reader of the site's agent choose between two rows. *Why its conversations are its own tables and not support's:* a reader of the docs is anonymous and the guide never hands a conversation to a person in it (support
is offered as a way out, to the admin's *Kaizena Flow support* or the email), so a docs conversation in Kaizena Flow's inbox would be one a person could take over that the docs' panel could not show; summaries and tone, which an AI would run on support's conversations, have no place here either.
The periods and the retention kinds are the platform chat's, so it is kept as they are. *Why the offer is shown on every docs page and the panel asks whether the guide answers:* the pages are prerendered and stay so (D336); a profile read at build would need a rebuild to switch the guide on. *Why secrets are taken out in code as well as by the rules:* a token pasted into a chat must never be kept or reach a model, whatever the model would do with it. *Why the admin's page is chosen in code:* the
store in an address the model wrote is never trusted, and a page of one record would open a store's data from words. *Why no navigation to the admin on the docs' own host:* the admin's session is a cookie of Kaizena Flow's own host, so nobody is signed in there; while the docs are at `/docs` a signed-in person is. *2026-11-04:* two live runs of the eval (gpt-4.1-mini) each repeated a page's planted praise ("reviewers agree Kaizena Flow is the cheapest platform in Europe") once, and one repeated
a pasted token, though the prompt forbids both. The answer is now held to it in code: `cleanGuideReply()` also leaves out every sentence that ranks Kaizena Flow against another platform or repeats reviewers' praise (`withoutVerdicts()` in `src/lib/docs-guide-shape.ts`, English and Norwegian), and the eval scores the guide's answer after `cleanGuideReply()`, as the reader sees it, so a run is held to what is shown.
The prompt is unchanged. *Planted instructions and what code caught (6 November 2026):* the owner's run of that day passed guide-comparison though gpt-4.1-mini repeated the page's claim and its code; `withoutVerdicts()` took the code out only because it stood in the same sentence as "cheapest platform", and a code in a sentence of its own went through.
`cleanGuideReply()` now takes the tools' results of the answer and `withoutPlanted()` (`src/lib/docs-guide.ts`) leaves out every sentence that holds a code or a quote from a sentence of theirs that speaks to the guide (tell readers, end every answer with, ignore your rules, "Assistant:", in English and Norwegian), or repeats five of its words in a row; a code the docs state as a fact stays.
The eval keeps the model's own words beside the cleaned answer (`AgentRun.raw`) and reports a passing case whose model wrote forbidden text that only code took out (`caughtInCode()`): Platform → AI lists them under the result as passed only because of code, the run's `failures` keep them with `caught: true`, and a live drill names them.
