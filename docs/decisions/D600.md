# D600: A store page's first scripts hold only what the page draws

**A store page's first scripts hold only what the page draws (bloat review step 0.16; 14 November 2026).** The cookie table is split: `src/lib/cookie-patterns.ts` (name, pattern and category: the consent manager's `cookieCategory()` reads it to forget a withdrawn category's cookies, with no second download) and `src/lib/known-cookies.ts` (provider, days, purposes in four languages: the server and the cookie page), held field by field by `known-cookies.test.ts`, a snapshot taken before the split.
`effectiveAudience()` (`store-audience.ts`), the feature labels (`feature-labels.ts`), `mayRemember()` (into `cookie-consent.ts`) and `drawerHasBackground()` (`drawer-background.ts`) moved to small files, none re-exported from its old home. `cartView()` is a server file (`cart/cart-view.ts`), so the product page's scripts lose the cart's forms.
The theme preview stage, the platform's language switch, the four product pickers (range, appointment, gift card, quote; five runs 38 of 38, none kept) and the carousel's controls are lazy stand-ins; the carousel's frame stays (the server's row, the arrows as drawn, a press before the controls arrive kept and made by them), so a page without JavaScript holds its row once.
The filter's button stays in first scripts and its panel loads on the press or when a pointer or the focus nears; a press before it arrives opens it. `storefront-bundle.scan.test.ts` bans `lib/store-features`, `lib/known-cookies`, `lib/background-layers` and the admin's words from a visitor's scripts (one exception: the sign-up wizard's `admin-text-context`) and a cart form from product-parts.tsx.
