# D362: The storefront API

**The storefront API (wave 9 unit I, `docs/wave-9-platform.md` section 3, I); built.** Settings → Apps and API gains *Storefront API*: an owner makes a token for one of the store's offered markets (`commerce.storefront_tokens`: a name, the token `kfs_…`, the market's slug; at most `STOREFRONT_TOKENS_MAX` 10 in use; written only by `src/server/storefront-api.ts`, audited `integration.storefront_token_*`, `never` copied) and revokes it there.
The token is public by design (a site's own code holds it, so it is kept and shown as it is, not as a hash) and opens only what any visitor of its market sees.
`/api/storefront/v1/{store}/` answers `GET products` (`?category=`, `?tag=`, `?sort=`, `?limit=` up to 48), `GET products/{handle}`, `GET categories`, `POST cart` (`{ lines: [{ variantId, quantity }] }`: each line's live price, stock and the quantity the store's rules allow, and a subtotal) and `POST checkout` (the cart made in the store with its own checks and a one-time address of its checkout), each only through the storefront's own reads, the WordPress plugin's (`viewOf()`,
`productPageOf()`, `termsOf()`, `quoteCart()`, `handoffCart()`), so this API prices nothing of its own and places no order.
Every call goes through `asStorefront()` (`src/server/storefront-route.ts`): the token of the store the address names (401 otherwise, never saying which), a store that is not open, a template or demo store, without the shop or private answers 404 (`storefrontProblem()`), and the token's budget (`takeBudget()`'s `storefront`: 1,200 a minute a token, 6,000 a store; 429 with `Retry-After`).
Any site may call it from a browser (CORS `*`, preflight answered, `Vary: X-Storefront-Token`); reads are cached a minute and the catalogue reads under the store's own tags. The cart is the site's, quoted and handed over, not kept by the API (as the WordPress plugin's). `platform.storefront-api-and-headless` stays partial.
