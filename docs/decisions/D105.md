# D105: The AI manager talks over a full-duplex live voice model when the site has one, as Kaizen Life does

**The AI manager talks over a full-duplex live voice model when the site has one, as Kaizen Life does.** The AI settings take a live voice model and its voice (`ai_providers.live_model`, `live_voice`), from the provider above or another with its own address and key (`live_provider`, `live_base_url`, `live_api_key_encrypted`, as pictures, D92); the provider catalogue suggests the names it knows, and a newer model is a new name in the settings, never in code.
Voice mode then calls instead of running the hands-free loop (D104, still used without one).
The call is Kaizen Life's design: the admin's `…/assistant/live` route makes the session with the site's key (`POST {address}/live/sessions`, WebRTC, `store: false`, a hashed account id for the provider's abuse checks) with thin instructions (who it is, how it talks, when it hands work over) and the conversation's last turns; the browser only gets the answer to its offer and may only add context, hand back results, mute and hang up.
The voice has no tools: when it needs the store's data, a change, a page or a playbook it delegates, and the page sends the call's unsaved transcript to `…/live/delegate`, which runs the request (the last thing said) as a turn of the AI manager in voice mode, with every tool, memory, the approval gate and `decide_approval`'s own check of their spoken yes; the answer goes back for the voice to say, and pages opened and changes kept show on screen.
The call is kept in its conversation (the one open, else one used in the last six hours, else a new one named after the first thing said): what was said before each request and the rest of the transcript (`…/live/transcript`, also as a beacon when the page closes), in order through one queue, the answer as the voice said it.

Date: 2026-09-29

Asked for by the owner ("be sure that we are able to use the newest full-duplex live voice model"). A full-duplex model hears while it speaks, so barge-in and backchannels are natural rather than detected. Delegating keeps one assistant: the voice never answers store questions from its own knowledge, and the rules that keep AI grounded (tools, sums in code, approvals) stay in one place.
The model is a setting so the owner chooses the provider and its data processing; the audio goes to that provider. Not yet: the call's camera or screen, and a spoken greeting when Kaizen has news (Kaizen Life's invites).
