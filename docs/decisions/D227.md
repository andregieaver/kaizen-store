# D227: Tables that are lists of records are lists in a card

**Tables that are lists of records are lists in a card (`docs/admin-style.md` section 8, step 11).** A table is a list when each row is a thing you open (a customer, a coupon, an invoice, a page, a return) with a few facts of its own, nothing in the row is edited or selected, and nothing is compared down a column; it stays a table when it compares figures (analytics, reports, VAT, prices, host payouts, attributions), is a grid you edit or select in (inventory, products, bulk edits, the order
list, redirects, settings tables, the bookings calendar), lists a document's lines (order and subscription lines) or holds values to copy (DNS records).
The list parts gained `RowLead` (the title, linked when the row has buttons of its own, a sub line and an avatar), `RowFact` (a fact that names itself, since a list has no header row: "4 orders", "Used 3 of 10", with a line under it and a class to hide it on small screens) and `RowActions` (the row's own buttons on the right, as quiet dense `Button`s); a status is a `Chip` with a signal (`ORDER_STATUS_SIGNAL` in `src/lib/order-status.ts`, `STATUS_SIGNAL` in `src/lib/experiments.ts`, per-page
maps elsewhere).
Moved: the store's customers, coupons, campaigns, companies, subscriptions, A/B tests, custom field groups, wish lists, a customer's orders and bonus history, cart reminders and their carts, draft orders, returns, pages, headers and footers, invoices' waiting queues, recent exports, an integration's events and the referrers; the platform's customers and a customer's stores, stores, coupons, A/B tests and plan reminders; the owner's referrals; Work's clients and invoices at both levels (one list
at every size in place of a table and phone cards); privacy requests. Where a row had a link in a cell beside its title (a customer, a store, an order), it stays a link in the sub line, and print routes keep `prefetch={false}`. Four unit tests that named a table or caption now name the list, and `ui.test.ts` holds the new parts. No migration.
