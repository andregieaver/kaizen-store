# D793: A stale eval recording or a long wait never holds back a release that passed

**A stale eval recording or a long wait never holds back a release that passed (19 November 2026; the owner: "We really need to address and fix the reasons for CI failing multiple times now").** From 08:42 to past 11:30 every run on main failed and production stayed on c0d23751 while migrations up to `20261119105243_fantastic_switch` were applied. Two causes kept coming back:

1. **The agents' eval replay (D391) behind the code.** A changed tool or prompt makes `agent-eval-replay.int.test.ts` fail until
   the eval is recorded again, which can only be done on production running the change; a push with a migration deploys only after
   every check passes, so with several sessions pushing, the head of main nearly always had both and nothing could deploy (runs
   1660 and 1661: their only failure). The owner chose (asked, since it loosens a safety check): a recording that is behind warns
   and does not fail. `agent-eval-replay.int.test.ts` writes a `::warning::` annotation naming what changed and skips the replay;
   while the recording matches, a replay that fails still fails. Nothing goes out less checked than before: a push without a
   migration already deployed on the quick gate, without this check. Platform → AI still marks each run's prompts as current or
   older; the eval is recorded once production runs the change. The rule "never change a prompt in the same push as a migration"
   is retired.
2. **The fallback's wait (D741) running out.** A run takes about 30 minutes; with pushes every few minutes a newer run was always
   going, so `deploy-fallback.mjs` failed after its 40 (30) minutes (runs 44492850303, 44506837136). Now, once the wait is over,
   it deploys its own commit (which passed its checks, with its migrations applied) unless a newer run's `pending` or `release`
   job is deploying right then, which it waits for ten minutes more at most (`GRACE_SECONDS`), and looks at production once more
   before it deploys. The jobs' limits rose to 60 and 55 minutes to hold it. `src/lib/deploy-fallback.test.ts` holds the rule;
   `docs/ci-migrations.md` says it.
