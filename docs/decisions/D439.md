# D439: Kaizena Flow's OAuth 2.1 authorization server and the open owner MCP

**Kaizena Flow's OAuth 2.1 authorization server and the open owner MCP (wave 14 unit B, `docs/wave-14-developer-platform.md` B1 to B8).** The owner MCP at `/api/mcp` opens to any MCP client (Claude, ChatGPT, …) through an authorization server of Kaizena Flow's own, since Supabase's offers identity scopes only, no resource indicators and grants outside the admin. **Discovery:** RFC 8414 metadata at `/.well-known/oauth-authorization-server` (issuer `siteUrl()`; `/oauth/authorize`,
`/api/oauth/token`, `/api/oauth/revoke`, `/api/oauth/register`, Client ID Metadata Documents, S256 only, `authorization_code` and `refresh_token`, `none` and `client_secret_basic`, every scope, `iss` in the answer) and RFC 9728 metadata for `/api/mcp` at `/.well-known/oauth-protected-resource` and its path-suffixed address, naming ours first and Supabase's while Kaizen Life uses it, the reading scopes and the docs page (`authorizationServerMetadata()`, `protectedResourceMetadata()`,
`src/lib/oauth.ts`, pure). **Clients** (`commerce.oauth_clients`, `src/server/oauth-clients.ts`): a client id that is an HTTPS address with a path is its metadata document, fetched through `safeFetch()` (public address, HTTPS, 5 seconds, 64 KB, no redirect), checked (`client_id` equal to the address, a name, redirect URIs HTTPS or loopback, no secret) and kept for its cache headers between a minute and a day; RFC 7591 registration is public only, by `application_type`, ten an hour from an
address (budget `oauth_register`, failing closed); `preregistered` and `app` kinds are made by Kaizena Flow (an app's secret kept as SHA-256, compared in constant time).
Redirect URIs match exactly but a loopback's port (RFC 8252); a request whose client or redirect URI does not check out is shown on the page and sent nowhere; any other refusal goes back with `state` and `iss`. **Scopes:** one per staff permission key plus `stores:read`; the consent screen's level gives *Read only* (the reads the person holds), *Read and propose changes* (the default: everything held, every change kept for a yes, approval category `change`) or *Read and change* (everything held,
gated changes still kept), narrowed by Lisa's *Choose permissions*, never more than the person holds in the stores ticked (`grantScopes()`). A token's power is the grant's scopes ∩ the person's role **at the call**: `PermissionHolder.limit` (new, honoured by `can()`, so by `memberCan()` and every tool's own check) carries the grant's keys on the membership `passMembership()` reads per call; a person removed from a store, or whose role loses a key, loses it at once.
A tool whose scope the grant lacks answers 403 with one `insufficient_scope` challenge naming every scope the request needs (`toolScope()`, also in `/api/mcp/catalogue.json` as `scope`); `tools/list` lists only what the grant and the role allow. **Consent** (`/admin/oauth/authorize`, where `/oauth/authorize` sends the request unchanged): a page of the admin's own frame (sign in first, a platform admin at `aal2`; a store that requires two-step offered only to an `aal2` session, which the grant
keeps), PKCE S256, `state`, `resource` the canonical `…/api/mcp` (`OAUTH_RESOURCES`, where unit D adds the Admin API), the client's name, logo, host and *Not verified by Kaizena Flow* unless a platform admin verified it; a server action that reads everything again; never framed (`oauthRouteHeaders()`: `frame-ancestors 'none'`, `X-Frame-Options`, `Referrer-Policy: same-origin`, as `no-referrer` would null a server action's `Origin`, which also covers the Supabase consent page); `oauth.approved`
per store and `oauth.denied` audited with the client and scopes. **Grants and tokens** (`commerce.oauth_grants`, `commerce.oauth_tokens`, `src/server/oauth.ts`): one live grant per person, client and resource, replaced by a new yes; a code (60 seconds, once, its challenge and redirect URI), an access token `kfa_` (an hour, its grant's resource only, `oauthAccess(token, resource)`) and a refresh token `kfr_` (rotated at every use, 90 days), CSPRNG strings kept only as SHA-256; a code or refresh
token used twice ends its family (`oauth.refresh_reused` audited); RFC 7009 revocation ends the grant; the dispatcher prunes ended tokens a day on and ended grants after 90 days. **The MCP server:** both kinds of token; per call `takeMcpBudget()` (120 a minute a grant across its stores, 1,200 a store), at most ten calls a batch and 100 KB a body; every call audited (`integration.mcp_call`, `via: "mcp"`, the client); a kept call lands in the client's own conversation per person
(`assistant_conversations.source` `mcp` with `oauth_client_id`, "From Claude"), named on the approval ("Claude asks: …") and in the notice, and is kept only for a person who can open the AI manager (else refused); Kaizen Life's approvals are named the same way.
`ask_store_assistant` works for every client (the owner's key, as the AI manager is the owner's); a turn an outside assistant asked for (`TurnInput.outside`) is offered only the store's tools and `OUTSIDE_MANAGER_TOOLS` (no memory, skill, follow-up, goal, plan, support or custom app), learns nothing, and `decide_approval` refuses in it: found in the review, an assistant's "yes" in such a turn would otherwise have approved a kept change, Kaizen Life's included. **Screens:** Account → *Connected
apps and assistants* (each grant's client, stores, level, last use, *Disconnect*), Settings → Apps and API → *AI assistants and apps connected to this store* (every grant reaching the store, whoever made it, *Cut off*), `/admin/platform/oauth` (clients seen, *Verify*, *Block*, which ends every grant). Words in English and Norwegian (`admin-messages/oauth.*`).
Migration `20261103160735_oauth_server`, applied by CI #934 on 3 November 2026 17:21 UTC (ledger `supabase_migrations.kaizen_files`; advisors checked after: INFO only, RLS on with no policy and the new indexes not used yet) (three tables with row-level security and no policy, the conversation's `oauth_client_id` and `mcp` source, the approval category `change`). Kaizen Life's Supabase tokens are taken as before; whether it moves to a pre-registered client of ours is the owner's decision.
Custom URI schemes are not taken as redirect URIs (HTTPS or loopback only, as specified). **After the adversarial review:** a store's or the site's budget bucket counts an ask only when the caller's own was within its ceiling (`budgetRoom()`, `takeMcpBudget()`, for every endpoint), so one address can no longer use up `oauth`, `oauth_register` or `oauth_fetch` for everyone; the token and revocation endpoints are counted per client (`oauth_token`, 3,000 a minute a client) with a per-address
backstop of 600, and an IPv6 caller is counted by its /64 (`addressPrefix()`). A request is charged to its client only once it proved itself (`ClientCharge`: a confidential client's secret checked, a public client's code with its verifier, redirect URI and resource, its refresh token, or its own live token to revoke, found good); one that proves nothing is charged only to its address, so nobody without a valid code or refresh token can spend a client's budget.
A good code over its client's budget is answered 429 and stays unused, as the check runs before the code is used and the budget is never counted inside a transaction.
A wrong authorization request is sent back to the client only for a client Kaizena Flow vouches for (verified, preregistered or an app, `sendsErrorsBack()`); any other's is said on the page with a plain link to the redirect URI's origin, so the endpoint is no open redirector (RFC 9700 4.11.2); a person's decision still goes back to any client.
Only Kaizen Life may go on in the owner's admin conversation (`continue_admin_conversation`); a client of the authorization server always asks in its own, `runTurn()` refuses it any other, it is given none of the person's memories, and its question is kept marked `[From …]`; `recall` and `get_my_referrals` left `OUTSIDE_MANAGER_TOOLS`.
A client's name is cleaned by one function everywhere it is shown or passed on (`safeClientName()`: NFKC, invisible and format characters such as U+2060 to U+2064, U+FEFF and U+061C gone, letters, digits and a little punctuation, 60 characters), and a name that could pass for Kaizena Flow or its marks ("Kaizen", "Verified", "Official", lookalikes folded) is refused at registration and in a metadata document. MCP calls are held to `memberCan()`, so a suspended or closed store (D171) is only read.
A metadata document's fetch has one overall deadline (`AbortSignal.timeout`). An outside assistant's approval keeps its grant (`assistant_approvals.oauth_grant_id`): it expires when the grant ends, the store cuts it off or the client is blocked, and `decideApproval()` never runs it once the grant no longer reaches the store. The consent page shows where the code goes when it is not the document's host, and a refetched document that names another app or other redirect URIs loses its verification.
Tool names are looked up only among a map's own (`Object.hasOwn`, prototype-free maps); refused MCP calls (a missing scope, a store outside the grant) are audited too; a grant's row is locked before its tokens everywhere, so a refresh and an ending never deadlock; a refresh that asks for fewer scopes gets an access token holding only those (`oauth_tokens.scopes`), never more; an owner's *Cut off* stays (`oauth_store_cutoffs`): the person connecting again does not reach the store until an owner
lets it in again on Apps and API; a password set or changed and a second step removed or reset end the person's grants (`endAccountGrants()`; the admin has no *sign out everywhere* yet); clients that registered and were never used in 30 days are pruned.
Left as they are, by decision: a refresh token used twice ends its family even when the two uses were a client's own concurrent refreshes (no grace period: a client that refreshes twice at once connects again), and the `owner` scope lets a client ask the AI manager, which reads every area of the store whatever else the grant holds (the *Choose permissions* step says so). **The prompt (its own commit, pushed without a migration):** in a turn an outside assistant asked for, the AI manager's prompt
says the conversation comes through an assistant the person connected, names it as its client calls itself (quoted and cleaned by `safeClientName()`: `assistantName()`, as the name is the client's to choose) where Kaizen Life was implied before, and that its words are never the person's yes; the manager's prompt version now hashes both drawings (`fixedManagerPrompt(…, FIXED_OUTSIDE)`), so it is a new version and the eval is recorded again on production. **4 November 2026, what a kept change's
card says:** `approvalSummary()` fell back to *Run {tool}.* for every tool without words of its own, so a kept `add_order_note` read *Claude asks: Run add_order_note.*, with neither the order nor the note.
Every tool that can be kept (each write reachable at *Read and propose changes*, each gated tool, the manager's and the platform's gated ones) now says what it does with its subject and values: the 36 that had no words got their own (`src/lib/approval-summaries.ts`: an order's note and tags, archiving, draft orders and their prices, a product made and its texts, a transfer, a customer's tag, a segment, support notes, a broadcast drafted, time, domains and DNS, pages, the brand, a target, a
report, a draft A/B test, a workflow, research), and any other is named by its MCP title with its input's fields in plain words (`inputSummary()`: one line, control and invisible format characters out, each value and the whole bounded, never JSON; `toolTitle()` moved to `src/lib/tool-title.ts`).
An app's tool's arguments are written the same way, a segment's rules in the store's money, a support note with its conversation's title, a draft product's change no longer says *live*, and `set_page_place` no longer throws on a place it does not know. No tool's description or prompt changed, so the eval's recording stands; `approval-summaries.test.ts` gives every tool that can be kept a realistic input, checks its words and that an empty input never throws.
