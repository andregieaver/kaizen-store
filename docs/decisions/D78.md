# D78: Sorting and filtering product listings

**Sorting and filtering product listings: a "Filter and sort" dialog on the products page (new, `/s/{store}/{market}/products`, a menu link kind "All products"), category and tag pages and search results, over every kind of product.** The choices are the page's address (`src/lib/listing-filters.ts`: `kind`, `category`, `tag`, `o.{option}` for variant options, `min`/`max` in whole units, `stock=1`, `sort`), applied on the server (`listingProducts()` in `src/server/listing.ts`) and shown above the
list, each with a link that takes it away. The dialog (`FilterDialog`) offers only what the page's products have and would narrow them, with counts (`listingFacets()`): kinds, categories (with those below them), tags as features, each variant option by name (size, colour, a rental's period …; any value of an option, every option on the same variant) and the price range.
Prices are compared as the shopper is shown them: without VAT for a business (`shownPrice()`), and a store selling to both lists each kind of buyer only their products. Sorts: featured (the page's own order, search relevance for results), newest, price either way, name. Category, tag and search conditions are shared with search's filters (`src/server/product-conditions.ts`).

Date: 2026-09-27

Asked for by the owner. Filters in the address make a filtered list shareable and work with the back button, and keep the page's own list prerendered: listing pages show it as the fallback while the filtered list streams in per request, so they stay fast and readable without script, and canonical addresses point at the unfiltered page.
Categories and tags are the only "features" the catalogue has; `products.attributes` is unused, and variant options are free text per product, so options are matched by name and value as typed. Counts are over the page's products before filters, not after, to keep one cached query per page. `products` is now a reserved store page address.
