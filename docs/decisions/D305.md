# D305: The page builder's undo and redo, and a page's versions

**The page builder's undo and redo, and a page's versions.** Undo and redo are the editor's (`src/lib/edit-history.ts`, pure): what the page was before each change, a hundred steps back and forward, changes of one kind within 800 ms one step (letters typed, a slider dragged), any new change ending what could be redone; the buttons beside Publish and Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y, which leave a field, a text being typed in or an open dialog to their own undo.
A page's versions are `commerce.page_versions` (`src/server/page-versions.ts`): every save (`saved`), publish (`published`) and change made on the live site (`site_text` D192, `site_css` D306) keeps the page's content once, in the same transaction, written only by `keepVersion()` (the same content as the newest is no new version, unless it now went live), never changed (a trigger), the newest fifty kept per page (`VERSIONS_KEPT`), going with a deleted page. *Versions* in the editor lists them
newest first with what made each, when and who (an account's name, never an email); *Use this version* puts one in the editor as unsaved changes, one step Undo takes back, so nothing on the site changes until the person saves or publishes. Read for whoever may read that kind of page (`checkPageTypeAccess(…, "read")`, a platform admin for Kaizena Flow's); a theme's workspace keeps none. `never` in `COPY_RULES`; in `NOT_PERSONAL` (a page's own rows).
