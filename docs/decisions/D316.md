# D316: A font Kaizena Flow cannot serve is only the fallback font

**A font Kaizena Flow cannot serve is only the fallback font.** React holds a streamed `<Suspense>` boundary until the stylesheets linked with `precedence` have loaded (`$RR`) and gives the boundary up when one fails: the browser draws it again, the server's copy stays in its hidden segment, and the page holds its content twice (React error 419, "Switched to client rendering").
`/api/fonts/css/{slug}` (D59) therefore never fails a stylesheet a page links: every slug of a family name's shape (`FONT_SLUG`) is answered with the installed stylesheet (a year, `immutable`, as before) or, when there is none (never installed, kept empty), an empty stylesheet kept a minute, and, when the database does not answer, one not kept at all; a name of another shape is a 404 and `<FontLinks>` links none.
`fontCss()` keeps a miss for seconds rather than days, so a family installed after a page asked for it is served at once, and a stylesheet kept empty counts as not installed, so `installFont()` fetches the family again and replaces it. `e2e/missing-font.spec.ts` holds a store page whose streamed headings name an empty and a missing font, and the design preview with an empty one: each draws once, `main` visible, with no page error or failed font request.

Date: 2026-10-16

Found on the public design preview with a font row whose stylesheet was empty (two canvases, `main` hidden in the theme store's frame); D255's stand-in stylesheets in the signed-in specs worked around it. Integration tests that seed fonts to avoid Google give them a stand-in stylesheet, since an empty one is installed again. No migration.
