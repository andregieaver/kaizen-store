# D817: Contracts sent a month on Usage and limits: a count, and a soft limit nobody sets yet

**Contracts sent a month on Usage and limits: a count, and a soft limit nobody sets yet (19 November 2026).** The contracts' design
(`docs/contracts.md` 6) said Usage and limits counts contracts sent per month; the owner left open whether plans cap it, so it is a count
now. A counter `contracts_sent` (`src/lib/usage-metrics.ts`), measured by the daily usage job from `contracts.sent_at`
(`contractsSql()`, `src/server/usage-sql.ts`; a new version sent counts again), and a limit `contracts_sent_month`
(`src/lib/limits.ts`): soft, so reaching it only ever warns, and set by no plan, so it reads as unlimited. A platform admin can give it a
number on the Limits editor whenever plans should speak of it. The store's Usage and limits shows the line only once the store has sent a
contract this month (`storeUsageLines()`), so a shop without Deals never reads a zero about contracts. Its words in the admin's English
and Norwegian and the plans page's four hand-written languages. Migration `20261119191205_contracts_sent_usage` widens the three name
rules (`store_usage_daily_metric`, `plan_limits_known`, `limit_overrides_known`). Idle cost: the daily usage job sends two more
statements (one count per day it measures, 22 to 24) and reads two more rows a store (the limit's sources), 263 with twenty stores. Tests:
`contracts.int.test.ts` (a sent contract counted on its day; the line appears after it).
