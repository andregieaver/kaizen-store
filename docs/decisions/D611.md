# D611: A save in the admin draws its route once

**A save in the admin draws its route once (bloat review step 0.18; 14 November 2026).** The rule (`docs/rules/admin/platform.md`): a server action that changes what a screen shows refreshes the route itself on success (`refresh()`, `refreshTag`, `revalidatePath`), and the client part that called it does not call `router.refresh()` after it; a client refresh stays only after a fetch to a route handler, in a poll, after an action that does not refresh, or where the client call also runs when the
action fails. 44 doubles were removed from the inventory screens, moving in, redirects, the import flows, the fields toolbar and the editors and settings forms; an editor that goes back to its list (discounts, campaigns, automation rules, reminders) keeps its `router.push`. `src/components/admin/router-refresh.scan.test.ts` holds what is left per file (48 in 28 files, 92 in 50 before) and only lets it fall.
The platform's own screens follow the same rule (the chat agent's, the docs guide's and the plan reminders' forms were among them). No migration. Commits on main up to 35724ae.
