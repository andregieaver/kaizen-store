# D273: One concept

**One concept: themes, with presets, each look starting a store from its demo store.** Design profiles, store templates and the themes installed on Kaizena Flow's own site were three pages and three words for what an owner sees as one thing.
Now a person or an assistant reads only *theme*, *preset* and *demo store* (`theme-words.scan.test.ts` walks every string, as D240's did, failing on *design profile*, *store template* and the template words of nb, sv and da; code keeps `design_presets` and `starters`). **Owners.** Sign-up, *Create a store* and approving a request offer one choice, the theme and its presets (the Standard card first); a new store's content is the chosen look's demo store, worked out on the server by
`demoStoreForLook()` from the look the theme store shows it on (`ThemeListing.pack`/`presetPacks`, `themeLooks()`), the theme's own look's when the preset is gone, the Standard store when the look has none or it is not published. Each card says what it starts with.
The store-template cards and the recommended design per template are gone. **The platform.** One Themes page under Stores (`/admin/platform/themes`): the themes, a *Demo stores* card (the content packs: set up, pictures made by the job, *Publish* with one press, which themes show each; store templates made by hand before are *Older demo stores*, which no look starts from), and on each theme's page a *Demo stores* card choosing each look's demo store with previews there (`saveThemeDemoStores()`,
saved at once; the listing's save keeps it). A demo store's own page is `/admin/platform/themes/demo-stores/{id}` (publish, features, archive, delete); no store template is made from the admin any more. Kaizena Flow's own site's installed themes moved to Website → *Design* (`/admin/platform/site-design`). The old addresses redirect (`LEGACY_THEME_REDIRECTS`), the public preview moved to `/admin/account/themes/{id}/preview`, and an install's id at a theme's address goes on to Design.
`docs/themes-unified.md` is the contract.
