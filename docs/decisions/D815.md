# D815: Kaizena Flow's Stripe webhooks are replaced new first: the old ones go only after the new secrets are saved

**Kaizena Flow's Stripe webhooks are replaced new first (19 November 2026, `createPlatformWebhooks()` and `retirePlatformWebhooks()` in `src/server/stripe.ts`).** D811's tests found that connecting the platform's webhooks again deleted the endpoints at
Kaizena Flow's addresses before making the new ones: a Stripe failure part way (an endpoint limit, a timeout) left no working payment, account or plan webhook until someone pressed connect again. Now the three new ones are made first while the earlier ones keep
working; `connectPlatformWebhooks()` saves every new secret, then retires the earlier ones by id. A failure, or a missing secret, deletes only what that call made. While both stand Stripe sends each event to both: `claim_webhook_event()` handles it once
(D529), and a delivery signed with a secret not yet saved is refused and retried. An earlier endpoint Stripe will not delete is logged (`stripe.webhooks_left`); it only receives events it can no longer sign. The address keeper (`keepStripeWebhooksCurrent()`, D406)
updates in place and is unchanged. Tests: `stripe.test.ts` (the earlier ones kept through a failure, only they retired) and `connect.int.test.ts` (retired after the secrets are saved).

Date: 2026-11-19
