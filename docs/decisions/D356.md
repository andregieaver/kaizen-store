# D356: Workflows

**Workflows (wave 9 unit C, `docs/wave-9-platform.md` section 3, C); built.** Settings → Workflows (`/admin/{store}/settings/workflows`, `settings:read` to see, `settings:write` to change): a workflow is a trigger (one of the store's events, as unit A's endpoints get them, or a schedule: every day or a weekday at a time in the store's time zone), conditions on the event's fields (`WORKFLOW_FIELDS` per subject, operators is, is not, contains, more than, less than; all must hold) and one to ten
actions (`ACTION_KINDS`: tag the order, add a note to it, tag the customer, email staff (those chosen for automation under Notifications, else the owners), post to Slack (`postToSlack()`), send the event to one of the owner's endpoints (a delivery unit A's job signs and sends), ask the AI manager (`askFromWorkflow()`, an owner's, counted with the order rules' asks)), checked by `workflowInputSchema` and `workflowProblems()` (`src/lib/workflows.ts`).
It is `commerce.workflows`, written only by `src/server/workflows.ts`: saved off, a save raises its version, and it is switched on only once *Test* ran that version (the database refuses otherwise); *Test* reads the latest event of its trigger (`latestSubject()`) and says what each action would do, doing nothing.
The database's intake (`queue_integration_event()`) makes one `commerce.workflow_runs` row per workflow and event (the event, its subject and its transaction as the key), `capped` once a workflow ran 100 times in the hour; `runWorkflows()` (every minute, in the integrations job) queues each day's schedules once, claims each run, reads the event's data as it is then (`subjectData()`), checks the conditions and runs the actions through their screens' functions, recording each outcome; runs are
kept 90 days. No action makes an event a workflow waits for, so a workflow cannot start itself; an email to a customer, a refund or anything that spends is not an action. The AI manager's `draft_workflow` (ungated, `settings:write`) saves one off from a sentence, its words through `findClaims()`. Order rules (D238) keep working as they are. Audited `automation.workflow_*`; both tables `never` copied, `NOT_PERSONAL`. Closes `platform.workflow-automation-flow`.
