# D256: Theme presets

**Theme presets (the theme showcase plan, phase 1 step 1, `docs/theme-showcase-phase-1.md`).** A theme gets up to five presets besides its own look: named designs over it (a whole D60 theme each: colours light and dark, fonts, buttons, corners, product cards, elements, section styles), sharing its header, footer, product page and CSS. *Presets* in the interface, variations in code (`design_variations`, `snapshot.variations`), because `design_presets` are themes.
They are edited on the theme's *Presets* tab as part of its draft (added as a copy of the theme's look, renamed, ordered, removed, each in the theme editor), checked one by one at Publish (`checkedDesign()`) and written into the version, which is version 2 only when it has presets.
Owners and platform admins add or apply a preset as they do a theme (each preset its own card), the install keeps the preset's key and follows it through updates, falling back to the theme's own look while a version has none of that key (said in *What's new*); the preview takes `preset={key}`; the theme page shows a theme's presets above its previews and tries the one chosen; cards say how many.
