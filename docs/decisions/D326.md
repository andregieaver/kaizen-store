# D326: Content types

**Content types (wave 6 unit H, `docs/wave-6-catalogue.md` Unit H); built.** An owner defines a type (`content_types`: a fixed key, a name, a web name, fields from `FIELD_TYPES`, which field is the title, summary and picture, whether entries have pages) and keeps entries of it (`content_entries`: a draft and a published `FieldData` with search texts per language, the owner's order) on Website → Content.
Values are checked and drawn by the custom fields' own functions; a new field type `entry` references entries, and deleting one clears every reference in the same transaction. A content grid lists a type's published entries; a type with pages serves `/{type}/{entry}` through the nested-page route, drawn by its layout (an `entry_layout` page bound to its fields) or the standard view, in the sitemap while published.
Entries are in the translation worklist, the AI manager's tools and store copies (references remapped). Kaizena Flow's own site has types too.

Date: 2026-10-27

*Why:* `catalogue.metaobjects`: Shopify's metaobjects are standalone entries of an owner's own type; Kaizena Flow's fields could only sit on things it already had.
