# D245: Seamless switching, step 4

**Seamless switching, step 4: updates of installed themes (`docs/theme-phase-2.md`).** A published version stays as it is and now carries the admin's *What's new* note (`design_preset_versions.notes`).
An install keeps what it placed in the store (`store_theme_installs.placed`: settings, CSS, each layout page with a fingerprint), so the owner's own changes are told from the theme's: an update lays the new version under them again (`mergeSettings()`, a three-way merge key by key; `cssFate()`), replaces a layout page the owner has not touched and keeps one they edited or chose, with the new version's made as a draft beside it (`layoutFate()`).
Installs follow updates unless the owner turns it off (`follows_updates`); the five-minute job updates them, others wait for *Update now*. Each update keeps the look before and after for 90 days (`commerce.theme_install_updates`) and can be undone while the look is still what it left. *What's new* (`whatsNew()`) is the note plus sentences from facts. Publishing a version without a core section style the last one had is refused.
The database lets an install's version move only within its own theme. Audited `store.theme_updated`, `store.theme_update_undone`, `store.theme_follows_updates`.
