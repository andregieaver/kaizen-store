# D294: Nested columns, one level deep

**Nested columns, one level deep.** A column can hold a *Columns* component (the Components tab's *Columns*, two columns to start), whose columns are columns like a row's, with their own settings, lines and widths; a nested column holds any component but another Columns.
It is a block, so text and pictures can sit above and below it in the same column, and everything that walks a page (styles, fonts, pictures, translation, visibility, templates, copies, forms, motion, A/B parts, design profiles, page rules) sees what it holds.
The canvas reuses the row's column drawing and its edits: a component dragged into a nested column goes there, a row's column dragged onto a nested column becomes one of its columns, a nested column dragged out goes back to the row, and the *New line* strips and dividers work inside it as in a row. A column holding a Columns component never moves into one (that would nest two levels), and the component goes when its last column leaves.
Nesting by dragging (asked for after the first release, where only the Columns component nested): while a column, the *Column* tile or a row's layout from the Rows tab is dragged, every column of the page that is not itself nested shows a *Nest columns here* strip above and below its components; dropped there, the column moves into a new Columns component at that place (`nestColumn()`, its old row or component going when left empty), the tile brings one new column and a layout its columns
(`newColumnsBlock()`). The builder measures its drop targets throughout a drag (`MeasuringStrategy.Always`), since strips that appear when a drag starts move what is below them. With it, a fix for dragging columns in Kaizena Flow's own pages: a column's tools (its drag handle among them) now show whenever anything in the column is pointed at, at its top-right.
Before, only the innermost part under the pointer showed its tools, so a column whose first component starts at its top edge (as Kaizena Flow's columns do, with no padding of their own) showed that component's tools in the very place of its own, and its handle could not be reached to drag it onto a new line.

Date: 2026-10-20

The owner: "a column should be able to nest a subset of columns", for all builders. A component rather than a column of columns, as Beaver Builder does, so a column keeps its own components around the nested ones and no reader of `column.blocks` breaks; the column edits run on the component as a row (`held()`), so nested columns behave exactly as a row's without a second set of edits.
