# D771: Cold starts are a production figure

**Cold starts are a production figure (bloat review step 1.16; 18 November 2026).** Each server instance notes its first answer once (`src/server/instance-start.ts`, `noteFirstRequest()` from the proxy, the beacons, health and the store, admin and site entries): after the answer, one log line `instance.start` and one row of `commerce.instance_starts` with what it was started for (health, beacon, proxy, store, pay, site, admin, platform admin, api, job), the milliseconds to `register()` and to
the first answer, its memory and the bytes of translated text read at start (`uiBytesAtStart()` in `src/server/ui-text-read.ts`); nothing about the visit. Platform → Usage and limits shows cold starts by kind (median and slowest, the proxy's and beacons' distance from health), the daily job prunes rows after 30 days, and the morning briefing says when translated text read at start is over 1 MB.
Idle cost: per request, one boolean test after an instance's first answer; per cold start, one insert after the answer; per scheduled run, one delete in the daily job (the daily route's statements 174 to 175). A store that does not use anything pays the same. A local build answered `/api/health` with one line (register 850 ms, first answer 7,735 ms, 397 MB). The cart-reminders route reaches 1,502 files and is named in the route-load baseline's heavy handlers.
Migration versions (applied by CI, 18 November 2026): `20261118124829_instance_starts`, `20261118124835_instance_starts_rules`. Advisors after: INFO only.
