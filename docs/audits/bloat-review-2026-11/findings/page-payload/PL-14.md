# PL-14 A search results page asks the server for suggestions nobody typed for

What a page sends: document, payload and requests (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P0. **Effort:** S. **Confidence:** high. **Step:** 0.15.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/components/search-box.tsx:53`, `src/components/search-box.tsx:60`, `src/components/search-section.tsx:110`, `src/app/s/[store]/[market]/search/actions.ts:11`, `src/app/s/[store]/[market]/search/actions.ts:18`, `src/server/request-budget.ts:138`, `src/server/search.ts:376`, `evidence/routes.json`
- **Evidence:** The results page draws the search box with the query as its starting value (search-section.tsx:110, defaultValue={typed}). The box's effect asks for suggestions whenever its value has two letters or more (search-box.tsx:53-67), and it runs on mount, so the page calls suggestAction for the query it is already showing results for. The list is closed (open starts false), so nothing of the answer is drawn. In routes.json the search page made POST /s/demo/no/search?q=lampe after load (183 bytes decoded); it is the only storefront page that posts for a visitor who does nothing. Per call the action resolves the shop, takes one unit of the type-ahead budget, a write to commerce.chat_usage (actions.ts:18, request-budget.ts:138-155: two upserts in one statement), and runs the keyword match (search.ts:376-387). The store's type-ahead budget (6,000 a minute for all visitors, request-budget.ts:24) is spent by page views, not typing.
- **Cost today:** Per view of a search results page: one server action call through the proxy, one write statement for the budget and one match query, for an answer nobody sees. Paid by: The server and the database per search results view; a shopper's browser (one request).
- **Saving:** Measured: one server action call per search results view. By code: one budget write and one match query with it.
- **Risk:** Low: on the results page the suggestions show a moment after the box is focused instead of at once.

## The fix

1. src/components/search-box.tsx: add a state asked (false at first). Set it true in the input's onChange and onFocus (lines 100-106). In the effect (lines 53-67) return early while it is false, and add it to the effect's dependencies. Suggestions for the words already in the box then arrive when the shopper puts the cursor in it, 150 ms after focus, and never on a page load.
2. e2e/search.spec.ts: add that a load of /s/demo/no/search?q=lampe makes no POST until the box is focused, and that focusing it brings the list (the existing test at lines 27-37 types from an empty box and must pass unchanged).
3. Lower PL-13's after-load fetch count for the search page if it is added there.

**Done when:** A cold load of /s/demo/no/search?q=lampe makes 0 POST requests before any press (1 today, by measure-routes.mjs's after-load list), held by the new assertion in e2e/search.spec.ts.
