## The fix

1. src/app/s/[store]/[market]/cart/cart-contents.tsx, loadCartView() (lines 76-80): take readCartBonus(store, market) out of the Promise.all and use `const bonus = summary.bonus` (cartSummary() already returns it, built by the same cartBonusOf() from the same signed-in customer and cookie cart). Remove the import of readCartBonus from this file.
2. src/lib/bonus.ts: export `cartBonusOff(signedIn: boolean): CartBonus`, the object cartBonusOf() returns for a programme that is off (src/server/bonus.ts:402-414), and make cartBonusOf() return it there, so there is one 'off' shape.
3. src/app/s/[store]/[market]/checkout/checkout-section.tsx:73: `const bonus = featureOn(store, "bonus") ? await readCartBonus(store, market, cartId) : cartBonusOff(false)` (the credits panel is not drawn while `enabled` is false; check CheckoutCredits reads nothing else of it).
4. src/server/cart-summary.ts: add `features?: FeatureSource` to the third parameter. When given and Bonus is off (`!featureOn(features, "bonus")`), use a new `bonusProgramOff(market)` exported from src/server/bonus.ts (BONUS_DEFAULTS, the market's currency, no rates, featureOn false, on false) in place of `bonusProgram(db(), storeId)` at line 99. When Referrals is off, set `friend = null` and call neither codeInPlay() nor friendState() (line 101). Without `features` it reads as today. Pass `features: store` from cart-contents.tsx:77.
5. Do NOT change placeOrder() (src/server/checkout.ts:559 and :590): it reads the switches and settings inside its own transaction, under its locks, and stays the one that decides.
6. One summary per render: add `requestCartSummary(store, market)` to src/server/cart-summary.ts, built on perRequest() (src/server/request-memo.ts:13) with the key `cart-summary:{store.id}:{market.slug}`: it reads the cart once and returns `{ cart, summary }`. Use it in loadCartView(), for the bonus in loadCheckoutView(), and give deliveryView() (src/server/delivery-choice.ts:16) an optional `known` summary that deliveryBlock() passes (checkout-section.tsx:465). Server actions keep calling cartSummary() directly: they read after they write.
7. Checkout rules, same change or the next: when activeRules() (src/server/checkout-rules.ts:185) is called with the pool and not a transaction, read the store's enabled rules through a `'use cache'` function tagged `checkout-rules:{storeId}`, refreshed by the writers in the same file (save, switch, order, delete). Read the caching guide in node_modules/next/dist/docs first (AGENTS.md). placeOrder() keeps its own read.
8. Leave gift cards as they are: cards already sold stay usable while the feature is off (src/lib/store-features.ts:117-118), so their read cannot follow the switch.
