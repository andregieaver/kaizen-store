## The fix

1. src/server/status.ts: move the two deletes at :266-269 into an exported pruneStatus() and call it from the daily route (src/app/api/cron/subscription-reminders/route.ts, the list at line 79). The five-minute job then only inserts. No new index.
2. src/server/docs-search.ts writeDocsIndex(): give the upsert a condition, `where (commerce.docs_index.text_hash, commerce.docs_index.doc, commerce.docs_index.item, commerce.docs_index.path, commerce.docs_index.url, commerce.docs_index.position, commerce.docs_index.checked, …every column the set list writes) is distinct from (excluded.text_hash, excluded.doc, …)`, so an unchanged row is not rewritten. Replace the delete at :120 with delete from commerce.docs_index where key <> all(<the keys just written, as a text array>).
3. Carts (owner's period, code review Question 6): a second step beside retention.ts:255-272 that deletes, in batches by id, carts whose period has passed (the same coalesce(case when status = 'open' then expires_at end, updated_at) < cutoff) and that no order points at: and not exists (select 1 from commerce.orders o where o.store_id = c.store_id and o.cart_id = c.id). Lines, gift cards, quotes, reservations and reminders go by cascade. State the period in src/lib/retention.ts with a seed() row and in the privacy text.
4. Processed webhook events and the other tables of FD8 (email_messages, experiment_events, referral_visits, work_events): a delete step each in runRetention() with its period, as step 3.15 of the code review describes; for webhook_events delete by id range or add an index on processed_at.
5. page_versions (owner's choice): if an age rule is wanted, keep all 50 for 90 days and then the newest 10 a page. Add VERSIONS_FULL_DAYS and VERSIONS_KEPT_OLD to src/lib/page-versions.ts, a daily prunePageVersions() in src/server/page-versions.ts called from the daily route, and say it in the Versions panel's words.
6. docs/audits/code-review-2026-11.md: set step 3.15's retention half to Done with date and commit when steps 3 and 4 land, and add a change-log line.
