# TC-13 Each test file that opens the database spends half a second importing Drizzle and the schema, one small module at a time

Tests, CI and the build (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P1. **Effort:** S. **Confidence:** medium. **Step:** 0.39.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `vitest.integration.config.mts:6-20`, `vitest.config.mts:4-19`, `src/db/client.ts:3-11`, `node_modules/vitest/dist/chunks/plugin.d.C8mmycim.d.ts:3467-3470`
- **Evidence:** Vitest gives each test file a fresh worker (isolate defaults to true; the integration config also runs files one at a time, vitest.integration.config.mts:16) and loads packages from node_modules natively, module by module. A probe in scratch, 20 one-test files per variant, one niced worker, warm cache, two or three runs each: an empty test 1.9-2.1 s; a test importing @/db/client 11.3-11.9 s; the same packages without the schema 8.2-8.6 s; drizzle-orm/node-postgres alone 7.2-7.8 s, which is 0.27 s a file over empty against 57 ms in plain Node; drizzle-orm alone 4.7-4.9 s; pg 2.2-2.5 s; zod 2.6-3.0 s. With Vitest's dependency optimizer told to pre-bundle drizzle-orm (test.deps.optimizer.ssr, enabled, include drizzle-orm and drizzle-orm/node-postgres), drizzle-orm/node-postgres falls to 2.4-2.6 s and the client's packages without the schema to 3.4-3.6 s. By the import graph 525 of 556 integration files and 25 unit files load src/db/client.ts. No test mocks drizzle-orm (rg).
- **Cost today:** 0.48 s per file for the client today, 0.07 s with the schema gone (TC-5) and Drizzle pre-bundled. For 525 integration files that is about 250 s of a serial run, about 85 s of wall time in each of the 3 shards on every push; about 0.25 s a file of it is Drizzle's own modules (estimate from the probe; real test files and CI runners will differ). Paid by: CI's integration shards on every push; agents running pnpm test:int
- **Saving:** About 0.25 s per test file that opens the database: about 130 s of the integration run across its three shards and 6 CPU-seconds of the unit run (estimate from a 20-file probe). With TC-5 the client's import falls from 0.48 s to 0.07 s a file, about 215 s across the shards.
- **Risk:** Low to medium. What could break: an identity check across two copies of drizzle-orm, or a mock of a pre-bundled package behaving differently. Either shows as a failing integration test in the trial of step 2, before anything is pushed.

## The fix

1. After TC-5. vitest.integration.config.mts: inside `test` add `deps: { optimizer: { ssr: { enabled: true, include: ["drizzle-orm", "drizzle-orm/node-postgres"] } } }`. Put the same block at the root of vitest.config.mts so the projects of TC-3 inherit it (25 unit files open the client).
2. Time one shard before and after on the same machine (`pnpm test:int --shard=1/3`, Vitest's duration line), then run the whole integration suite and the unit tests of src/db.
3. If a test fails because two copies of drizzle-orm meet (one pre-bundled, one loaded natively by a package Vite does not transform), add that importing package to the include list. If that does not settle it, drop the setting: do not change app code for it.
4. Turn on Vitest 5's import breakdown for one run (the `importDurations` option in its config types, `print: true`) to see whether another package costs as much as Drizzle did; pg and zod were 0.02 and 0.04 s a file in the probe.

**Done when:** On one machine, `pnpm test:int --shard=1/3` reports a duration at least 30 s shorter than before the change (expected: about 44 s, 0.25 s for each of the roughly 175 files in a shard), with the same test counts.

**Tests and rules that hold today's behaviour, and change with it:**

- vitest.integration.config.mts and vitest.config.mts: the only files that change. No scan test reads them.
- The optimizer writes its bundle under Vite's cache folder in node_modules (ignored by git); in CI it is rebuilt each run, about a second in the probe.
- CLAUDE.md's rule that integration tests run against a real database (pnpm test:int after scripts/db-setup.mjs --seed) is untouched: only how a package is loaded changes.
- src/db/testing.ts (PGlite) does not import drizzle-orm, so the unit tests' database is not involved.

**Comes after:** TC-5
