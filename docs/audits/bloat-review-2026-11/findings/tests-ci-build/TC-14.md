# TC-14 A push that changes only tests builds and deploys production again

Tests, CI and the build (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 3.18.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `.github/workflows/ci.yml:10-14`, `.github/workflows/ci.yml:273-331`, `vercel.json:12-19`, `scripts/await-deploy.mjs:1-16`, `docs/build-memory.md:44-46`
- **Evidence:** The push filter leaves out only *.md and docs/** (ci.yml:10-14). Every other push to main runs `pending`, which after the gate calls Vercel's deploy hook (ci.yml:317-325), and the hook builds the head of main; vercel.json has no step that skips a build. Nothing looks at what changed. In this clone's history 75 of the last 92 commits with files run CI, and 6 of those 75 (8%) change only test files (*.test.ts, e2e/**, e2e-live/**): 74179fc, 7b59c18, 07cec9b, fe454bc, 0bce04f, 9f7ea0b. The deployed app cannot differ after such a push: no route imports a test file.
- **Cost today:** About one deploy in twelve rebuilds an unchanged app (estimate: 8% of commits, and a commit is not always a push of its own): a Vercel build at the 8 GB edge (docs/build-memory.md:44-46) that prerenders 1,426 pages again, and a `pending` runner that waits for it, up to 20 minutes. About 3 a day at today's pace (estimate from about 35 CI runs a day). Paid by: The build on Vercel; CI's pending runner while it waits
- **Saving:** About 8% of deploys (estimate): at today's pace about 3 Vercel builds a day, each several minutes of an 8 GB build machine.
- **Risk:** Low to medium. A wrong pattern would hold back a real change. Noticed by: /api/health lagging main after a non-test push; the guard of step 2 and the next code push both repair it.

## The fix

1. .github/workflows/ci.yml, job `pending`: before the gate, a step `changed` that lists the push's files (`git diff --name-only ${{ github.event.before }} ${{ github.sha }}`, after fetching the `before` commit) and writes `deploy=false` when every file matches `\.test\.tsx?$`, `^e2e/`, `^e2e-live/`, `^test/` or `^src/test/`. A forced push or a `before` that cannot be fetched writes `deploy=true`.
2. A guard in the same step: read /api/health as scripts/await-deploy.mjs does; if production does not report the push's parent commit (or a later one) as live, write `deploy=true`, so a test-only push after a failed deploy still brings production up to date.
3. Add `&& steps.changed.outputs.deploy != 'false'` to the `if` of the deploy-hook step and of the wait step (ci.yml:318 and 327). The gate's lint and type check still run: they cover the tests too.
4. Words: the comment block at ci.yml:260-272, the Workflow paragraph of CLAUDE.md ('Pushes of *.md and docs/** alone run nothing' gains: a push of tests alone is checked but not deployed), docs/ci-migrations.md, a decision row.

**Done when:** A push that changes one *.test.ts file shows `pending` green with the deploy step skipped while /api/health still reports the previous commit; a push that changes one non-test file under src deploys as before.

**Tests and rules that hold today's behaviour, and change with it:**

- CLAUDE.md, Workflow: a push to main deploys (D5), and each deploy waits until /api/health reports the commit (D389). A skipped deploy must skip that wait too, or the job fails after 20 minutes.
- D530 (the hook builds the head of main, so the ledger is read again before the call): the new condition sits beside that check and does not replace it.
- src/lib/ci-playwright.scan.test.ts reads ci.yml's job texts for browser installs only: unaffected.
- The pattern list must not include scripts/ or .github/: scripts/next-build.mjs and the workflow do change what is built and deployed.

**Notes:** Small and true. Not worth a change of its own: do it when ci.yml is open for TC-1. It matters a little more after opening, when each needless deploy is also a moment of cold functions for real visitors.
