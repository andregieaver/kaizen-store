# TC-11 ✓ The same mocks and store-makers are written out in hundreds of test files

Tests, CI and the build (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** duplicate. **Priority:** P2. **Effort:** M. **Confidence:** medium. **Step:** 4.3.
- **Second check:** confirmed.
- **Where:** `vitest.integration.config.mts:6-20`, `test/server-only.ts:1-3`, `test/integration-setup.ts:1-19`, `src/server/invoice-test-fixture.ts:1`
- **Evidence:** Recounted with rg: vi.mock("server-only", ...) is in 579 test files, 448 of them integration tests, where the config already aliases server-only to a stub (vitest.integration.config.mts:10). vi.mock("next/cache", ...) is in 465 integration files in at least seven shapes that grew as Next's API grew: 318 share one line, 39, 25, 24 and 15 share four others, 40 are multi-line. vi.mock("next/headers", ...) has 89, 19, 12 and 10 files on four single-line shapes and 75 multi-line. vi.mock("next/server", ...) has 41, 14, 11 and 8. makeStore is defined in 52 test files, paidOrder in 30. The integration config has no setup file.
- **Cost today:** About 2,800 lines of 325,579, under 1%. No run-time cost worth naming. The real cost is that a change to Next's cache API or to what a store needs means editing hundreds of files. Paid by: Agents and reviewers, in edits and in context read
- **Saving:** About 2,000 to 2,800 lines, and one place to change when a mocked API changes. No run time.
- **Risk:** Low to medium. A file-level mock that differs on purpose must keep its own; a shared mock could hide that a test never needed the module. Noticed by: the integration suite itself, shard by shard.

## The fix

1. New test/integration-mocks.ts, listed as `setupFiles` in vitest.integration.config.mts: vi.mock("next/cache") with the widest shape in use (cacheLife, cacheTag, updateTag, revalidateTag, refresh as no-ops); vi.mock("next/headers") with cookies (get, getAll, set, delete) and headers returning new Headers(); vi.mock("next/server") spreading the original and replacing connection and after with no-ops. Check on one file first that a test file's own vi.mock of the same module still wins.
2. Delete the 448 vi.mock("server-only", ...) lines in *.int.test.ts with a codemod; the alias makes them redundant. Run one shard.
3. Delete the single-line next/cache, next/headers and next/server mocks that equal the shared shape, one shape per commit. Leave the multi-line ones and the one that records tags.
4. Add the server-only alias to vitest.config.mts as well, then delete the 131 server-only mocks in unit tests.
5. makeStore and paidOrder: group identical bodies with a script, move the largest identical group of each into a shared module under src/server (beside invoice-test-fixture.ts) and import it; leave the variants.

**Done when:** `rg -l 'vi\.mock\("server-only"' src --glob '*.int.test.ts' | wc -l` prints 0 (448 today), `rg -l 'vi\.mock\("next/cache"' src --glob '*.int.test.ts' | wc -l` prints under 60 (465 today), and `pnpm test:int` passes.

**Tests and rules that hold today's behaviour, and change with it:**

- vitest.integration.config.mts:10 (the server-only alias) and test/server-only.ts: the stub the integration tests already get.
- The 91 integration files that mock no next/cache today would get the shared stand-in: run the whole suite once to see that none relied on the real module.
- Code review FH9 / step 1.9 (test what gets owners paid) adds integration tests; they should start from the shared setup.
- CLAUDE.md, Admin: 'src/server/*.int.test.ts are integration tests against a real database' stays true.
