# Tests, CI and the build (TC)

Part of `docs/audits/bloat-review-2026-11.md`, on commit 0bd814c. Read by one reviewer, challenged by a second (who re-opened every citation, re-measured every number and applied the owner's note that the platform is not open yet) and planned by a third. A tick (✓) marks a finding the second reviewer confirmed or corrected; one the planner added has none. Each finding has a file of its own beside this one.

**In short.** The tests are not the bloat: 325,579 lines of tests against 768,202 of source, no snapshots, and the browser suite does not repeat the unit tests (37 of 781 end-to-end tests use no page). The waste is in how the checks run, and it is paid per push whoever uses the platform: one push type-checks the same commit five times (183 s each here, 70% of the build) and builds it four times; every unit test file first loads 1.9 MB of admin English in a fresh worker (a 187-file sample takes 90 s today and 27 s without both); lint re-reads about 6,200 files on one thread (about 3 minutes, 1 s with a cache); and 229 server modules form one import cycle that 12 import lines close. Four small changes (TC-1, TC-3, TC-5, TC-12) remove about 9 runner-minutes of repeated type checks, about a quarter of the unit run and about 3 minutes of lint per push without checking any less. Before opening is the cheap time for the two with risk: cutting the cycle (TC-2) and changing the rule for what runs before a push (TC-6, the owner's call).

## Well made, and should stay

- Nothing in this dimension argues from 'no store uses it'. Every finding is a cost per push, per build or per test run, so the owner's clarification changes no verdict here. CI cost follows commits, not shoppers; what grows at opening is the price of a late or killed deploy.
- Test volume is healthy: tests are 30% of src lines; no __snapshots__ folder, no .snap file, no toMatchSnapshot or toHaveScreenshot; the largest fixture is 39 KB and the agent-eval recording 20 KB.
- The end-to-end suite does not repeat the unit tests: 742 of 781 tests drive a browser page and only 37 are plain HTTP calls (my count), most of them checks that a route refuses a visitor without a session.
- No single test file sets the floor of the unit run: the largest, src/db/commerce.test.ts (8,166 lines, 324 tests), runs alone in 9.7 s (timed here).
- A unit run prints 9 lines when it passes (timed sample, output counted), so the test count does not flood an agent's context.
- The unit tests' database is well made: 4 baseline files, a template named by a hash of the migration files, built in 5.9 s (timed here), a copy per test file in 1.1-1.5 s. Caching it in CI would save seconds.
- Very little tests dead code: about a dozen source files are imported only by tests. The six *.test.ts files under docs/ are page generators with their own config (docs/site-pages/vitest.config.mts), run by hand; they are not dead tests.
- A docs-only push runs nothing (ci.yml:10-14) and the content/** exception is deliberate; a run on main is never cancelled (ci.yml:27-32); the audit job needs no install.
- The typing patterns the brief suspected are not what makes the type check heavy: schema.ts and its imports 573 MB, every admin catalogue 537 MB, page-content 358 MB, against about 5 GB for the whole program. The catalogues are plain object literals. The check is big because the program is big.
- ESLint runs no type-aware rule and its import plugin has one single-file rule (eslint-config-next/dist/index.js:172), so lint builds no type program and a per-file cache is safe.
- Browser budgets exist and run in CI: first scripts and page weight per route in e2e/performance.spec.ts:21-58.
- Lazy imports in server code are an established pattern: 58 await import() calls in 30 files of src/server (rg), so cutting the cycle that way introduces nothing new.
- Only one test pins CI's configuration (src/lib/ci-playwright.scan.test.ts: image tags and the list of browser jobs). No test pins the build's type check, the Vitest setup files, the lint script or the schema argument, so the fixes below fight no existing check except where TC-7 says so.
- src/lib is nearly a clean layer already: 1 of its 1,146 files has a run-time import out of lib and 10 import a type from server, components, app or db.
