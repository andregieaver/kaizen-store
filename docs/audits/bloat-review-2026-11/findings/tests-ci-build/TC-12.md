# TC-12 Lint reads all 6,213 files on one thread every time, with no cache: about 3 minutes, and it is on the deploy path

Tests, CI and the build (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P0. **Effort:** S. **Confidence:** high. **Step:** 0.26.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `package.json:9`, `eslint.config.mjs:1-20`, `.github/workflows/ci.yml:55`, `.github/workflows/ci.yml:297-299`, `CLAUDE.md:12`, `node_modules/eslint-config-next/dist/index.js:172`
- **Evidence:** package.json:9 is `eslint --max-warnings 0`: no --cache and no --concurrency, though the installed ESLint 9.39.5 has both (its --help; concurrency defaults to off). ESLint walks everything but .next, out, build, next-env.d.ts and .claude (eslint.config.mjs:9-17): 6,213 lintable files by find (5,910 in src, 236 in e2e, 37 in scripts). Timed here on every fifth file of src, e2e and scripts (1,235 files), one thread: 36.4 s and 40.5 s, so about 3 minutes for the whole tree (estimate from the sample; it fits the gate's written 5 min 11 s for lint, type check and smoke tests). With --concurrency auto: 26.5 s and 32.1 s. With --cache --cache-strategy content: 37.6 s to fill the cache, then 1.0 s for the same files, twice; the cache file is 515 KB. The config has no type-aware rule and the import plugin's only rule is no-anonymous-default-export (eslint-config-next/dist/index.js:172), so a file's result depends on that file and the config alone.
- **Cost today:** About 3 minutes of one core per lint (estimate): twice per push in CI (static at ci.yml:55 and the gate at :299, the second before the deploy hook), and once before every push in each agent session (CLAUDE.md:12). At about 35 CI runs a day that is about 3 runner-hours a day, nearly all of it on files that did not change. Paid by: CI on every push; the owner in minutes before each deploy; every agent session before each push
- **Saving:** From about 3 minutes to seconds for every lint after the first: on the sample, 1.0 s for 1,235 unchanged files against 36 to 40 s. Per push that is about 2 to 3 minutes off the deploy gate, the same off static, and the same off each agent push after a session's first (estimate).
- **Risk:** Low. A stale pass could hide an error only if a rule read other files; none does today (checked in the config). What would show it: `eslint --no-cache` disagreeing with the cached run; run that now and then in a scheduled workflow if wanted.

## The fix

1. package.json:9: `"lint": "eslint --max-warnings 0 --cache --cache-strategy content --cache-location node_modules/.cache/eslint/"`. That folder is ignored by git and by ESLint already; the unit tests' database template is kept beside it.
2. .github/workflows/ci.yml: in `static` and `pending`, after `pnpm install`, add a cache step for the path `node_modules/.cache/eslint` with key `eslint-${{ hashFiles('pnpm-lock.yaml', 'eslint.config.mjs') }}-${{ github.sha }}` and restore-keys `eslint-${{ hashFiles('pnpm-lock.yaml', 'eslint.config.mjs') }}-`. The content strategy compares file hashes, so a fresh checkout's new file times do not empty the cache.
3. Optional: add `--concurrency auto` for the cold run (a session's first lint, a changed config): 21 to 27% less on the sample.
4. Words: one clause in CLAUDE.md's Commands list (lint keeps a cache in node_modules/.cache/eslint; delete the folder to lint from nothing) and a decision row.

**Done when:** A second `pnpm lint` on an unchanged tree finishes in under 15 s on the machine where the first took minutes, and the gate's lint step takes under 30 s on a CI run that restored the cache (read from the step's time, or TC-8's summary).

**Tests and rules that hold today's behaviour, and change with it:**

- No test reads the lint script (rg for 'max-warnings' and 'pnpm lint' in src/**/*.test.ts finds nothing).
- CLAUDE.md:12, README.md:57 and docs/capacity.md:97 (lint before every push) are kept; the rule becomes cheap.
- ESLint drops a cached result when its config or version changes, so a Dependabot bump (.github/dependabot.yml, weekly) re-lints everything.
- Code review step 4.1 will move import bans into lint with no-restricted-imports, a single-file rule: the cache stays valid. A cross-file rule (import/no-cycle) or a type-aware one would not be; such a rule must run in a second, uncached eslint call.

**Notes:** Missed by the report, which called lint 'not measured'. Confidence is high on the sample's times and medium on the whole-tree total, which is the sample times five. One line in package.json gives agents the saving at once; the CI cache step gives it to the gate.
