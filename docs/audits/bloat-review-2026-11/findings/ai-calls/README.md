# What every AI call carries (AI)

Part of `docs/audits/bloat-review-2026-11.md`, on commit 0bd814c. Read by one reviewer, challenged by a second (who re-opened every citation, re-measured every number and applied the owner's note that the platform is not open yet) and planned by a third. A tick (✓) marks a finding the second reviewer confirmed or corrected; one the planner added has none. Each finding has a file of its own beside this one.

**In short.** The shopper chat is lean (about 5,000 characters of prompt and tools a call); the AI manager is the heavy part: about 161,700 characters a call (roughly 40,400 tokens, an estimate at 4 characters a token), 91% of it 124 tool definitions that do not depend on the question, on up to 11 calls a turn. A lean default drawn with the app's own functions is 48,600 characters on Home and 77,000 on an orders page; it is already step 3.18 of the code review, still Open, and the eval meant to guard it does not test whether the model finds a tool (9 manager cases, none uses load_tools), so that check comes first. Around the AI, screens, polls and five-minute jobs fetch the AI connection and walk every site before knowing there is work (237,563 connection reads against 19,104 AI calls): small today, rising with every store, clearest in the alt-text job. The one quick, safe win is in the browser: the chat's script is 496 KB, of which about 370 KB is the model's tool catalogue and admin map.

## Well made, and should stay

- The shopper chat (src/server/chat-agent.ts, src/lib/chat.ts): 6 hand-written tools (2,613 characters), a 2,536-character prompt, history capped at 20 messages, results cut at 6,000, product tools dropped for a website, support tools chosen by desk mode. Knowledge search hands back at most 5 passages of at most 1,200 characters (src/server/knowledge.ts:345, src/lib/knowledge.ts:16).
- Tools of store features that are off are already dropped (src/server/offered-tools.ts, src/lib/owner-tool-features.ts: 121 tools behind a feature), and tools a role may not use are never offered.
- The admin map in the prompt is one line a group (2,171 to 5,824 characters) and follows features and role. The 58,402 characters of playbooks load only through use_skill.
- History: only the last 20 messages as text (src/server/owner-assistant.ts:663-669, 766); earlier turns' tool results are never resent. Memories: at most 8 short lines a turn. The memory pass after a turn sends at most 4,000 characters of the exchange and asks for 400 tokens (src/server/assistant-memory.ts:332-358).
- The turn budget (src/lib/turn-budget.ts): 240 s, 400,000 tokens, the month's allowance checked between rounds, a daily cost ceiling for platform admins.
- An autopilot step, an autopilot event and a Dream Factory step are each held to their own few tools, not the 124 (src/server/owner-assistant.ts:714, 732; src/server/dream-factory.ts:724-748; src/lib/dream-factory.ts:347-362). A plan's tenth step carries about 9,700 characters of earlier steps as history beside a 1,700-character message (my draw of taskMessage() with ten synthetic steps): bounded by the 20-message window and small beside the prompt.
- The Dream Factory makes each product in a conversation of its own, so product turns do not drag the run's history along (src/server/dream-factory.ts:675-677).
- The launcher on every admin page fetches the chat script and the AI's abilities only when the panel is first opened (src/components/admin/ai-manager-launcher.tsx, D444; docs/performance.md:153-160).
- Search understanding, the recommendation rerank and a search's vector are kept in the search cache and call a model only on a miss (src/server/query-understanding.ts:81-85, src/server/recommend.ts:575-590, src/server/query-vector.ts:18-25). Product vectors are refreshed when a product is saved, imported or bulk-edited.
- The docs index gives a row a new vector only when its words changed (text_hash) and is rewritten only when a deployment's rows differ from the stored fingerprint (src/server/docs-search.ts:94-127, 174-186): the 49,347 updates on 1,845 rows are about 27 rewrites, which is deploy churn. An idle run is one small read, the AI connection and one select.
- The docs guide (4,776-character prompt, 7 tools), the product writer (1,272 characters of instructions) and the legal writer (about 6,000 characters plus the passages) are small per call and run only when someone asks. The page studio writes each section with the same system prompt, which suits a provider's prefix cache (src/lib/page-ai.ts:657-700).
- AI page looks are taken only when a tool or a person asks for one (src/server/page-looks.ts:101-124); the listing check reads at most 10 listings a dispatcher run (src/server/content-moderation.ts:37-39); the briefing's AI note is written only for a briefing that is sent, and a quiet period sends none (src/server/briefing.ts:67-79).
- The autopilot's, follow-ups' and Kaizen Life hand-offs' five-minute jobs each ask one or two global 'is anything due' questions, not one per store. The every-minute autopilot route is a fixed cost that belongs to the scheduling dimension.
- The owner MCP (/api/mcp) and custom apps' tools cost a store that does not use them one small read per AI manager turn and nothing per request. That no store has connected one yet says nothing about whether they are wanted.
- Tool descriptions are not the heavy part: median 441 characters, 90th percentile 760, longest 1,183; cutting every one to 600 would save 10,313 characters over all 254 tools (my measure, plan-ai/desc.ts). The weight is the number sent and a few large schemas.
