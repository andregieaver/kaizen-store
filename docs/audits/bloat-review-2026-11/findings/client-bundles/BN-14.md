# BN-14 Thirteen preview screens load the whole page builder to draw a page

The built client bundles, by page (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P0. **Effort:** S. **Confidence:** high. **Step:** 0.10.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/app/admin/(gated)/[store]/pages/[pageId]/preview/page.tsx:3`, `src/app/admin/(gated)/[store]/pages/editor-views.tsx:7`, `src/app/admin/(gated)/[store]/pages/editor-views.tsx:8`, `src/app/admin/(gated)/[store]/pages/editor-views.tsx:277`, `src/app/admin/(gated)/[store]/pages/drawing.tsx:4`, `src/app/admin/(gated)/platform/pages/editor-views.tsx:6`, `src/app/admin/(gated)/platform/pages/editor-views.tsx:231`, `src/app/admin/try/[sandbox]/[kind]/[pageId]/preview/page.tsx:11`, `src/app/admin/try/[sandbox]/editor.tsx:8`, `src/app/admin/try/[sandbox]/editor.tsx:31`, `src/lib/permission-guards.ts:48`, `docs/performance.md:162`
- **Evidence:** The report counted 39 'builder routes' and said they need the builder's modules. Thirteen of them end in /preview: seven of a store (pages, articles, headers, footers, product layouts, content layouts, experiment variants), five of the platform and the sandbox's, each with the builder's own first-load figure (3,303,372, 3,220,818 and 3,220,824 bytes). A preview draws the saved draft with PageDrawing, which imports the storefront's renderer and no editor (drawing.tsx lines 1 to 19). It loads the builder because its view lives in the editors' module: the route file imports StorePreviewPageView from editor-views.tsx (preview/page.tsx:3), and that module imports PageEditor and DualPageEditor (lines 7 and 8); the platform's is the same (lines 6 and 231); the sandbox's preview imports two small helpers from editor.tsx (line 11), a module that imports both editors (lines 7 and 8). A route loads every client component its server modules import, drawn or not, which docs/performance.md lines 162 to 164 records as the reason the lists were split from the editors on 4 November. Simulated on the built chunks with the two editor roots dropped: a store's preview 3,262,756 to 1,356,216 model bytes, the platform's 3,182,011 to 1,265,136, the sandbox's 3,181,591 to 750,092; the sandbox's template preview, the same drawing with no editor import, is 786,423 bytes in the build.
- **Cost today:** 1.8 to 2.3 MB raw of script per open of a preview, about 60 to 75% of what the screen loads; it includes the rich text editor (435 KB), the four storefront languages (319 KB) and the builder itself. Paid by: An owner's browser on every press of Preview in the builder; and a visitor trying the builder in the sandbox before signing up, with no account and a cold cache.
- **Saving:** Simulated on the real chunks: 1.82 MB raw off each of the 12 signed-in previews (3,186 to 1,324 KB for a store's) and 2.32 MB off the sandbox's (3,107 to 733 KB); with the frame cuts a store's preview is about 831 KB.
- **Risk:** Low: functions move between files and nothing they do changes. A wrong import path fails the type check; a guard entry left on the old file fails permissions.scan.test.ts.
- **Already tracked:** No. docs/performance.md describes the 4 November split of lists from editors, which left the previews with the editors. The same change as AC-2 steps 1 to 3 (admin-client): do it once.

## The fix

1. Store previews: new file src/app/admin/(gated)/[store]/pages/preview-views.tsx with StorePreviewPageView moved from editor-views.tsx (lines 276 to 329) and only the imports it uses (Link, notFound, z, requireFeature, PAGE_TYPE_COPY, adminLangOf, adminText, requirePageTypeAccess, testOfVersionPage, getPageForEdit, stagedCopy, storePagesBase from ./context, PageDrawing from ./drawing). It must not import editor-views.tsx. Point the seven store preview route files at it: pages, articles, headers, footers, product-layouts, content/layouts and experiments/variants, each .../[pageId]/preview/page.tsx.
2. Platform previews: the same for PreviewPageView (platform/pages/editor-views.tsx line 231 on) into platform/pages/preview-views.tsx, with the helpers it shares with the editors (load, editedElsewhere, themeStoreView) moved to a small module both import; point the five platform preview route files at it (pages, articles, headers, footers, themes/pages).
3. Sandbox preview: move sandboxAndKind and isPageId (src/app/admin/try/[sandbox]/editor.tsx lines 31 and 40) into a new src/app/admin/try/[sandbox]/params.ts; editor.tsx imports them from there; [kind]/[pageId]/preview/page.tsx line 11 imports from params.ts, never from editor.tsx.
4. src/lib/permission-guards.ts line 48: StorePreviewPageView names the new file.
5. Budgets: add a draft preview to e2e/signed-in/admin-scripts.spec.ts and delete the previews from BN-11's exception list.
6. docs/rules/admin/website.md lines 111 to 114 and docs/performance.md lines 162 to 164: previews live apart from the editors, for the same reason the lists do.
