# BN-16 A store page with a recommending grid downloads 650 KB more script once recommendations answer: zod, the page model and all four languages

The built client bundles, by page (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P1. **Effort:** M. **Confidence:** high. **Step:** 2.5.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/components/recommended-grid.tsx:16`, `src/components/recommended-grid.tsx:133`, `src/components/content-grid.tsx:9`, `src/components/content-grid.tsx:12`, `src/components/content-grid.tsx:63`, `src/components/content-grid-section.tsx:141`, `src/components/content-grid-section.tsx:145`, `src/lib/part-css.ts:33`, `src/lib/theme-elements.ts:22`, `src/lib/typography.ts:1`, `src/lib/storefront-bundle.scan.test.ts:10`, `src/lib/recommendations.ts:45`, `e2e/performance.spec.ts:61`, `docs/performance.md:34`
- **Evidence:** A product grid that recommends (D139) is drawn by the server and, where the store's recommendations are on, wrapped in RecommendedGrid (content-grid-section.tsx:141 to 145). In the browser it asks /api/recommendations and, on any good answer, draws the shopper's own products with ContentGridView, loaded by import('./content-grid') (recommended-grid.tsx:16 and 133). content-grid.tsx has no 'use client' line: it is the server's view, and it imports t from lib/i18n (line 9, used at 63), three helpers from lib/page-content (line 12) and lib/part-css, which reaches lib/theme-elements and zod (part-css.ts:33, theme-elements.ts:22). In the build, all 56 store routes point at one copy of the grid's script (3-461jjwuauv9.js), whose loader for that import names seven chunks: 649,561 bytes raw, 203,834 gzip, among them 1u2592k6jkhim.js (all four storefront languages, 318,693 / 102,965), 1-5xy7dnrat0_.js (zod, 116,870 / 32,660) and 3553h5joaqwch.js (the page model, 74,836 / 21,199). A store home's own first scripts are 680,264 bytes. The written rules say no zod, no page model and no whole language in a visitor's scripts (docs/performance.md lines 34 to 37 and 52 to 62); the scan that holds them walks static imports only and says so (storefront-bundle.scan.test.ts line 10: 'the recommended grid's, which this walk does not follow'), and the end-to-end check for a whole language opens the demo store's front page only (performance.spec.ts line 61 on). Recommendations are off for a new store (recommendations.ts:45), so this is paid only where the feature is used; what is wrong is its size, not that it loads.
- **Cost today:** 650 KB raw / 204 KB gzip of script on a shopper's first view of a page with a recommending grid, nearly as much again as the page's own 680 KB / 239 KB gzip; the files are cached after that, and on every such page view they are parsed and run after load on the phone's main thread (zod builds the page model's schemas at import). 79% of it is the three files a grid of product tiles has no use for. Paid by: A shopper's browser in every store that turns Recommendations on, on each page with such a grid (a product page's 'goes well with' is the usual place). Nothing today; it grows with each store that uses the feature.
- **Saving:** Measured by the sizes of the chunks the loader names: 318,693 bytes raw / 102,965 gzip (the four languages) from steps 1 to 3; 191,706 raw / 53,859 gzip more (zod and the page model) from step 6; about 79% of the 650 KB in all. The remaining 139 KB is the grid's own view, its price and carousel helpers and the returns texts, not looked at further.
- **Risk:** Medium-low. A text missed in a browser file shows English on a tile for that language, which the catalogues' tests and the recommendations spec catch. Step 6 touches modules many parts read; the type check and the builder's specs hold them, and it is best done inside the page model's planned split.
- **Already tracked:** No. The scan test's own comment names the gap (it does not follow the recommended grid's import()). The admin-client plan's AC-6 notes in passing that the grid's lazy chunk holds lib/i18n and leaves it to the storefront's review, which did not count it. Code review step 3.2 (Open) is where step 6 fits.

## The fix

1. The words: the texts ContentGridView reads (readMore, viewProduct, the tile's Add to cart and quantity words, quotes.priceOnRequest, preorder.page, group.choose) and the three Price reads (yourPrice, priorPrice, fromPrice) move into each src/lib/messages/{nb,sv,da,en}-browser.ts under one key, written once: the whole language module already spreads its browser file in, and for a nested text the whole module points at the browser file's. This is the rule of docs/performance.md lines 52 to 62 for a text a visitor's client component reads.
2. src/components/content-grid.tsx: ContentGridView takes m as a prop typed to those texts and no longer imports lib/i18n (line 9). Server callers pass t(data.lang) (content-grid-section.tsx, blog-listing.tsx lines 164 and 242, platform-routes/terms.tsx lines 100 and 116); the builder's preview is BN-6 step 3. Narrow Price's m to the three texts it reads.
3. src/components/recommended-grid.tsx line 133: pass browserText(data.lang)'s grid texts as m. A language translated by AI works the same way (browserText() reads the registered texts).
4. src/lib/storefront-bundle.scan.test.ts: follow import() from a visitor's client component (BN-11 step 7). lib/i18n through components/content-grid must be gone after step 2; list the remaining chains to zod and lib/page-content (content-grid to page-content; part-css, brands and gallery to page-content; theme-elements, typography, colour and fonts-schema to zod) as a list that may only shrink.
5. e2e/recommendations.spec.ts: after the grid has swapped in the shopper's products, expect that no script the page loaded holds a whole language (the four sentences of e2e/performance.spec.ts line 63), and record the bytes of the scripts loaded after the answer.
6. The rest, with code review step 3.2 (one definition per block, which splits lib/page-content): move contentSides, frameStyle and gridImageShape and the constants part-css reads into small modules without zod, and give typography.ts, colour.ts and theme-elements.ts a *-schema.ts beside them as the written rule asks, until the list of step 4 is empty.

**Done when:** On a built store with Recommendations on, the scripts a page with a recommending grid loads after /api/recommendations answers are at or under 335,000 bytes raw after steps 1 to 5 (649,561 today) and hold no whole language, held by e2e/recommendations.spec.ts; and at or under 140,000 once step 6's list is empty.
