# BN-12 ✓ One stylesheet for shoppers and owners: a quarter of what a shopper downloads styles only the admin

The built client bundles, by page (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P2. **Effort:** M. **Confidence:** medium. **Step:** 2.11.
- **Second check:** corrected.
- **Where:** `src/app/globals.css:6`, `src/app/globals.css:7`, `src/app/globals.css:9`, `src/app/admin/layout.tsx:13`, `src/app/admin/layout.tsx:17`, `src/app/s/[store]/[market]/layout.tsx:43`, `docs/build-memory.md:34`
- **Evidence:** globals.css is imported by 15 layouts and error pages outside the admin and by the admin's root layout (rg), and Tailwind reads all of src for it (lines 6 to 9), so one file (3-w0shgm-eqtf.css, 183,124 bytes raw, 31,864 gzip) serves every page; the admin adds 21,083 bytes of its own. The verified report split the built file by rule: 45.6 KB of utility rules are named only under components/admin, app/admin or lib/admin-*, none of them appears in the saved HTML of 16 public pages, and the file rebuilt without them is 136.0 KB raw, 25.3 KB gzip. The browser's coverage figure (20 to 31% unused) is not a measure of this; it is the same on the admin home as on a store home.
- **Cost today:** About 47 KB raw / 6.6 KB gzip of render-blocking CSS on a shopper's first page of each store; small beside the scripts. Paid by: A shopper's browser, first page per store; the admin pays the mirror image (about 32 KB raw of public-only utilities), which matters less.
- **Saving:** Measured by the skeptic's rebuild: 183.1 to 136.0 KB raw, 32.0 to 25.3 KB gzip for every public page. The css planner's compile of the proposed entry gave 129,745 bytes raw and no more scan memory than today (204 to 212 MB against 221 to 223 MB); that compile was not re-run here.
- **Risk:** Medium for a small gain. A class written only in admin code but drawn on a store would lose its style silently; the scan test covers imports and the eye covers the rest. The build is at its memory limit (docs/build-memory.md: killed once on 11 November); the Tailwind step may need no more, but Next may run two entries in two workers, so measure first and keep a way back.
- **Already tracked:** Not in the repo's plans. docs/build-memory.md explains the present @source lines. The same finding as CS-1 (css, with the measured plan) and SC-5.

## The fix

1. Follow the css dimension's plan CS-1, which is the detailed one: first BN-2 (no prefetch of /admin from the site, or the site would pull the admin's whole sheet) and a stylesheet budget at today's figures.
2. Measure the build's peak under the 8 GB cap with Vercel's settings before and after, as docs/build-memory.md lines 9 to 10 describe.
3. Move the hand-written rules of src/app/globals.css into a shared partial; globals.css becomes the public entry whose @source lines leave out src/app/admin and src/components/admin and then name, one by one, each admin file a public page draws; a new src/app/admin/admin-entry.css reads all of src (the builder's canvas and the previews draw store parts inside the admin) and is what src/app/admin/layout.tsx line 13 imports.
4. A scan test that walks value imports from public code and requires every reached admin file with a className to be named by an @source line of the public entry.
5. Build, read the two sheets' sizes, run the whole e2e suite and look at the pages a missing class would show, in light and dark; send the owner screenshots.
6. Docs: docs/build-memory.md (two entries and the measured peak), docs/performance.md, docs/admin-style.md, CLAUDE.md's Commands sentence about the @source lines.
