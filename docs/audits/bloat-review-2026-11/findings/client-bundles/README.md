# The built client bundles, by page (BN)

Part of `docs/audits/bloat-review-2026-11.md`, on commit 0bd814c. Read by one reviewer, challenged by a second (who re-opened every citation, re-measured every number and applied the owner's note that the platform is not open yet) and planned by a third. A tick (✓) marks a finding the second reviewer confirmed or corrected; one the planner added has none. Each finding has a file of its own beside this one.

**In short.** Shoppers' pages are lean and the admin is where the weight is: a store page's first scripts are 680 to 778 thousand bytes, about 447 thousand of them React and Next, while the 432 signed-in admin routes have a median of 1,155,530 bytes and every one carries Supabase's client (253 KB) and zod (114 KB) before it is used. Seven small import changes (BN-1, BN-3, BN-4, BN-5, BN-7, BN-14, BN-2) take the admin's median to about 604 KB in a simulation on the built chunks, 13 preview screens from 3.2 MB to 0.8 to 1.4 MB, one Work screen from 4.27 MB to about 1.4 MB, and stop Kaizena Flow's front page from downloading 437 KB of admin scripts it cannot use; routes over 1.3 MB fall from 90 to about 26, the builder's own. This pass added three things the report missed: the previews that load the whole builder, the AI manager's chat script (496 KB, about 95% of it three tables read for two labels) and a store's recommending grid, which downloads 650 KB (204 KB gzip) of zod, the page model and all four languages into a shopper's page. Nothing here argues from a feature being unused: each figure is bytes an owner or a shopper downloads and parses per page load, the cuts move imports and remove no feature, and before opening is the cheapest time to make them; one check over all 560 routes after each build (BN-11) keeps them.

## Well made, and should stay

- No route outside /admin has zod, Supabase's client, the rich text editor, the builder's English or a whole storefront language in its first scripts: searched by marker string in the first-load chunks of all 560 routes (markers.mjs). The rule in docs/performance.md and storefront-bundle.scan.test.ts holds for first scripts; BN-16 is about a script fetched later.
- Chunks carry almost no passengers: on the store home, product page, cart, category, admin home, product editor, pages list and builder, 4 to 11 KB of the modules in a route's first-load chunks are not reachable from that route's own client roots (sim.mjs). What a page loads is what its server modules import, so the cuts are import cuts.
- The store home's own share is small: its 35 client roots add 20 KB at most each (site forms 19.8 KB, the header's moving parts 17.7, the buyer switch 15.0, the filter dialog 11.8), and the forms are in first scripts by a tested rule (docs/performance.md: what is pressed before a part's script runs is lost).
- The heavy optional parts are separate files no route lists first: the 3D viewer (06bnvraa8v5pm.js, 1.05 MB), the video compressor (3ioq0_ppuc4fl.js, 562 KB) and the CSS code editor (3ek9gab7cmp8l.js, 383 KB), each identified by its text.
- The admin frame's own parts are light once BN-1, BN-3 and BN-4 are done: the menus, rail, trail, tooltips, colour and scheme sync, the AI manager's launcher (14 KB) and the storefront header's moving parts the frame reuses (17.7 KB) together are about 64 KB by what leaves when each is dropped.
- The public site is even: 23 routes at 673,899 bytes, its form pages (status, report, cookies, get-domain) at 684,680 to 685,386, sign-up at 694,279, the docs at 525,643 and the bare pages (passport, SMS, supply, theme preview) at 479,303; the admin's sign-in, forgot-password, two-step and sandbox start pages are 500,765 to 513,540, close to the 447,102-byte floor.
- The admin's English is fetched per area (D540) and the AI manager's chat only when its panel opens (ai-manager-launcher.tsx:32); the storefront's inline editors load only for a signed-in person who turns them on (page-edit-link.tsx). BN-15 is about what the chat's script holds, not about when it loads.
- Scripts and styles are served immutable for a year (routes.json cacheControl), so a returning person downloads a chunk again only when a deploy changed it; what repeats on every full page load is parsing and running.
- Recommendations are off for a new store (DEFAULT_SETTINGS.enabled is false, src/lib/recommendations.ts:45) and the grid's view loads only after the store's recommendations answer: BN-16's cost follows use; what is wrong is its size.
- No finding of this dimension proposes retiring, hiding or merging a feature, and none rests on a table being empty or a feature being unused before opening.
