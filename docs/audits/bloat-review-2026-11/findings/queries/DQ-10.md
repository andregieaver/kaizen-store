# DQ-10 ✓ Some reads fetch whole JSON documents where a field, a card or a count is needed

How data is asked for (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P2. **Effort:** M. **Confidence:** medium. **Step:** 4.4.
- **Second check:** corrected.
- **Where:** `src/server/theme-store.ts:134-146`, `src/server/theme-store.ts:173-183`, `src/server/pages.ts:134-155`, `src/server/fonts.ts:171-182`, `src/server/analytics-speed.ts:103-119`, `src/lib/speed.ts:22-24`, `src/lib/speed.ts:83-84`, `src/server/ai.ts:208`, `src/server/chat-agent.ts:93`, `src/server/accessibility.ts:120-128`, `src/server/green-claims.ts:52-55`, `src/server/store-translate.ts:123-127`
- **Evidence:** 61 selects name a page's document column and 14 a theme's (the verified re-run of the scan). That count is not the size of the problem: many are single-page reads by id for an editor that needs the document. The reads where less would do, after DQ-2, DQ-6 and DQ-7: (1) theme-store.ts:137 reads every published theme with its whole snapshot to draw cards: 10,851 calls, 107,917 rows, 27 s. (2) theme-store.ts:176 reads every version's whole snapshot of a theme to write a changelog. (3) pages.ts:136, the admin's Pages list, reads draft and published of every page to show a title, a state and a thumbnail. (4) fonts.ts:180 reads a family's whole stylesheet to pick one file name (42,211 calls). (5) analytics-speed.ts:116 loads every speed sample of 28 days, up to 10,000 a store day (src/lib/speed.ts:22-24), to work out a 75th percentile in code (percentile75, nearest rank, speed.ts:83). (6) select * on the two hottest setting reads: ai.ts:208 (237,563 calls) and chat-agent.ts:93 (48,492). (7) accessibility.ts:120, green-claims.ts:54 and store-translate.ts:125 read every page of the store, but these are admin screens an owner opens, bounded by that store's content, and the first two need the content to check it in code.
- **Cost today:** 27 s for the theme cards read; the rest is bytes and parse time on each call, not yet large. The theme reads grow with themes, not stores. The Pages list and the speed report grow with one store's content and traffic: the speed report can load up to 280,000 rows for one screen. Paid by: The server (memory and parse) and the database; an owner on the Pages list or the speed report; the theme store's visitors on a cold render.
- **Saving:** Estimate: the theme card read shrinks from whole themes to card facts (most of 27 s); the admin Pages list and the speed report stop growing with document size and sample count.
- **Risk:** A derived column can drift from its document: the card and the preload file are written by one function each, held by the scan test, and both fall back to the document when null. A percentile that differs by one rank would move a store's speed rating: the unit test of step 5 holds it. Noticed on the theme store's cards and the Speed report.
- **Already tracked:** no (code review FD7, Open in step 3.15, names the width of orders but not these reads)

## The fix

1. Theme cards: add a card jsonb column to commerce.design_presets (src/db/schema.ts, pnpm db:generate) holding what cardOf() reads from the snapshot (the looks, the swatch, the section style names). Write it where a theme is published (src/server/design-presets.ts). loadCards() (theme-store.ts:134-146) selects card instead of snapshot and falls back to the snapshot while card is null; the daily theme sweep of DQ-1 fills the nulls once.
2. Changelog (theme-store.ts:173-183): keep the notes it shows on commerce.design_preset_versions when a version is published, and read only them.
3. The admin's Pages list (pages.ts:134-155): take title and thumbnail with JSON operators and the state in SQL (published_at is null, draft is distinct from published), as publishedPageNames() does; no document leaves the database. Add a limit when step 1.13 of the code review gives lists paging.
4. Fonts (fonts.ts:171-182): add preload_file text to commerce.fonts, written by installFont() with latinUprightFile(css). fontPreloadFile() reads it and, while it is null, falls back to the stylesheet and writes the answer back.
5. Speed report (analytics-speed.ts:103-119): work out the percentile in SQL, grouped by kind, screen and day: percentile_disc(0.75) within group (order by lcp_ms) and the same for the other three, with the sample count. percentile_disc is the nearest-rank rule of percentile75(); prove it in a unit test on the fixtures of src/lib/speed.test.ts before switching.
6. Name the columns in the two hot select * reads (ai.ts:208, chat-agent.ts:93), through typedRows() as the conventions ask for reads that are touched.
7. Leave the accessibility, green claims and translate screens until a store's size makes them slow; they are paid by the owner who opens them.

**Done when:** theme-store.int.test.ts asserts that the rows loadCards() reads have no snapshot key once cards are filled, and speedReport() on a store seeded with 10,000 samples issues one statement that returns at most 28 rows per kind and screen.
