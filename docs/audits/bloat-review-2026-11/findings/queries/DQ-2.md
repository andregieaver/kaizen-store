# DQ-2 ✓ Every published page is read whole to find one page or a few titles

How data is asked for (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P0. **Effort:** M. **Confidence:** high. **Step:** 0.19.
- **Second check:** confirmed.
- **Where:** `src/server/pages.ts:664-681`, `src/server/pages.ts:713-735`, `src/server/pages.ts:797-800`, `src/server/pages.ts:859-863`, `src/server/platform-navigation.ts:135-153`, `src/server/legal-links.ts:20-30`, `src/server/platform-roles.ts:34-38`, `src/server/checkout-terms.ts:46`, `src/components/site-chat.tsx:110`, `src/app/s/[store]/[market]/page.tsx:29`, `src/app/s/[store]/[market]/[slug]/page.tsx:18-24`, `src/app/s/[store]/[market]/blog/blog-listing.tsx:89`, `src/server/media-alts.ts:25-55`
- **Evidence:** listPublishedPages() (pages.ts:664-681) selects id, slug, published (the whole document) and two dates for every published page of an owner, parses each with zod, then looks up library alt texts for every picture on every page (withPageAlts). I listed its call sites with rg: 35. At least 12 then do .find() for one id: the front page (s/[store]/[market]/page.tsx:29), the products page (pages.ts:799), a page by id (pages.ts:862), the platform's role pages (platform-roles.ts:37), the checkout's terms (checkout-terms.ts:46), three account pages, the blog's listing page (blog-listing.tsx:89), the chat's page (site-chat.tsx:110) and two admin previews. Others read only titles: the platform's header and footer load every page and every article whole to build a map of id, slug and title (platform-navigation.ts:138-146); a store's footer loads them all to print up to five legal titles (legal-links.ts:24-29); generateStaticParams loads them all for the slugs (s/[store]/[market]/[slug]/page.tsx:20). Production: 79,778 calls, 781 s, 2,334,038 rows, 29 rows a call: the most expensive app statement, 33% of the listed app time. publishedPageNames (pages.ts:713) already shows the slim shape.
- **Cost today:** 781 s in 78 days, 9.8 ms a call, on the team's demo stores. Estimate: about 90 KB a call on disk (29 rows at about 3 KB), more as JSON on the wire, parsed each time. After opening, the size of a call follows one store's own page count (a blog with 300 articles sends 300 documents for one listing or one sitemap), and the number of calls follows cold renders across all stores, because the cache lives in one instance. Paid by: The server on every cold render of a page's frame; the database; a visitor waits for it on the first view after a deploy or on a cold instance.
- **Saving:** Estimate: most of the 781 s (rows shrink from whole documents to a few short columns, or to one row), the zod parse of every document per call, and the alt lookup for pages not being drawn. The saving per call grows with a store's content.
- **Risk:** A caller that silently needed another field of the content: the type checker shows it, since content leaves the index type. A cold page then makes two small reads (the index and one document) where it made one large one. A wrong title in a menu or footer would be seen in e2e/store-pages.spec.ts and on the platform's own header.
- **Already tracked:** no (code review step 3.9, Open, is the same idea for products: 'Stop reading the whole catalogue for one page')

## The fix

1. In src/server/pages.ts add publishedPageIndex(owner, type = 'page'): 'use cache', cacheLife('hours'), cacheTag(pagesTag(owner)), the same where and order by as listPublishedPages, but no document. Columns: id, slug, published ->> 'title' as title, the translated titles as one small object (select jsonb_object_agg(t.key, t.value ->> 'title') from jsonb_each(published -> 'translations') t where coalesce(t.value ->> 'title', '') <> ''), published_at, first_published_at. Type PublishedPageEntry = { id, slug, title, titles, publishedAt, firstPublishedAt }. Add a further field only when a caller moved in step 3 needs it, each taken with a JSON operator. Write the store filter with DQ-8's owned().
2. Add publishedPageById(owner, id): same cache settings and tag; select id, slug, published, published_at, first_published_at from commerce.pages where id = the id and the owner's branch and published_at is not null; parse; withPageAlts([page]). The primary key serves it.
3. Move the readers of one page to publishedPageById: src/app/s/[store]/[market]/page.tsx:29, src/server/pages.ts:799 and :862, src/server/platform-roles.ts:37, src/server/checkout-terms.ts:46, src/components/site-chat.tsx:110, src/app/s/[store]/[market]/blog/blog-listing.tsx:89, src/app/s/[store]/[market]/account/change/[token]/page.tsx:60, account/exchange/[token]/page.tsx:60, account/pay/[token]/page.tsx:55, src/app/admin/try/[sandbox]/[kind]/[pageId]/preview/page.tsx:28 and src/app/admin/account/themes/[presetId]/preview/page.tsx:91.
4. Move the readers of titles and addresses to publishedPageIndex: src/server/platform-navigation.ts:138 and :140 (id, slug, title, titles are exactly what byId() builds), src/server/legal-links.ts:24, and generateStaticParams in src/app/s/[store]/[market]/[slug]/page.tsx:20 and [slug]/[...sub]/page.tsx:22. legal-links.ts takes the title through localizePage(content, locale): add a small pure helper in src/lib/page-translation.ts, localTitle(entry, locale), that picks from titles by the same key rule as localizePage, with a unit test that both give the same title on the fixtures of src/lib/product-layout.test.ts.
5. Leave on listPublishedPages, with a doc comment saying it is for readers that need every document: src/server/seo.ts (lines 465, 600, 687, 796, 872), src/server/page-ai.ts:96-97, src/server/blogs.ts:114, blog/article-page.tsx:40 and :53, src/components/platform-routes/blog.tsx:45, src/components/platform-routes/page.tsx:24 and the admin's search page. Move a sitemap or robots reader to the index later, when the fields it reads are in it; the type checker shows which those are, because content is not on the index type.
6. Run pnpm typecheck, pnpm test and pnpm test:int; build and run pnpm test:e2e for the store and platform pages.
