## The fix

1. 1 (S, first). src/server/site-cookies.ts:89-121: start the independent reads together with one Promise.all (storeFeatures, getChatAgent, usesRememberedModals, referralPublicSettings or affiliateSite, getRecommendSettings, storeHasExperiments, getPlatformLangs, siteFindings) and work out languages and touch from the answers afterwards. No behaviour changes; 8 round trips in a row become one wait.
2. The modal answer where pages are saved. In src/db/schema.ts add to pages a stored generated column has_remembered_modal boolean, generated always as (published is not null and jsonb_path_exists(published, the path at page-modals.ts:24)), and a partial index pages_remembered_modal_idx on (store_id) where has_remembered_modal; pnpm db:generate. usesRememberedModals() becomes select exists (… where the owner's branch and has_remembered_modal). jsonb_path_exists is immutable (pg_proc on the local database says so; the _tz variant is not), so the column is allowed, and the schema already has stored generated columns (8 in commerce). Adding it rewrites the pages table (1,389 rows today): cheap now, before opening.
3. One 'site facts' read per store. New src/server/site-facts.ts, siteFacts(storeId): one statement with scalar and exists subqueries for what the frame asks per feature: features and visit_counting of the store, the chat agent's enabled flag, recommendation settings' enabled, whether an A/B test runs, the referral or affiliate and creator capture flags and days, the latest finished scan's items, the cookie notes as json_agg. 'use cache' with the union of the tags today's readers carry (cookiesTag, chatTag, pagesTag, and the tags in recommend-settings.ts:35-41, experiments.ts:155-161 and affiliates.ts:82-94), so nothing shows stale. siteCookies() reads from it; the per-feature readers stay for their own screens.
4. The frame's menus and page titles read DQ-2's publishedPageIndex instead of whole pages (platform-navigation.ts:138-140).
5. Not to do: a remote cache handler for these short reads. Next's guide says it adds a network round trip per check and gains little for reads this small.
6. Count a store's cold frame with DQ-11's counter before and after, and write the number in the baseline.

**Done when:** DQ-11's int test counts at most 4 statements for siteCookies() of a seeded store with none of the features on (8 or 9 today by the code), and on production a week after the deploy no statement containing jsonb_path_exists on commerce.pages is among the 40 costliest in pg_stat_statements (121 s today).
