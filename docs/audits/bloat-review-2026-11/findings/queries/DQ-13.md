## The fix

1. The per-site job loops are fixed where their findings are: the media loop in DQ-3, the embeddings and cadences in DQ-5, the knowledge loop in DQ-6, the invoice loop in DQ-15, and the one AI provider read for all sites in DQ-9 step 4. Do not repeat that work here.
2. The pattern for a new job: one set-based statement that returns only the sites with work (as storesWithDocumentWork() does at invoice-issue.ts:71), then the loop. Write it as a line in docs/rules/admin/platform.md under the cron rules.
3. cart-reminders.ts:353-362: fold the 'bought since' lookup into the statement that finds the due carts (a left join or a not exists), so a run is one read plus one write per reminder sent.
4. theme-shots.ts:118-128: insert the missing units with one statement and many value rows, as embeddings.ts:59-70 already does.
5. Leave the order's inserts (checkout.ts, order-insert.ts) to code review step 3.7 'Stage placeOrder'; they are the money path and cost follows use.
