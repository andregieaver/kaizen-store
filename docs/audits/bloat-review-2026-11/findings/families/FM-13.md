## The fix

1. Move the walk of src/lib/storefront-bundle.scan.test.ts (its IMPORT pattern, typesOnly(), resolve(), files() and reach()) into src/lib/import-walk.test-helper.ts and use it from both tests. Add src/lib/server-reach.scan.test.ts with three rules. (a) Light entries: the four routes under src/app/api/visit, src/app/api/recommendations/events/route.ts, src/app/api/health/route.ts and the routes under src/app/api/ab may not reach server/chat-route.ts, server/chat-agent.ts, server/auth.ts or lib/admin-text.ts, and reach at most 200 modules each. (b) No file outside src/app/admin and src/components/admin value-imports '@/lib/admin-text': a list of today's 35 that may only shrink, empty after FM-1. (c) Two 'would notice' cases, as the model test has: a route that imports server/chat-route.ts fails rule (a); src/app/api/health/route.ts passes.
2. Add scripts/lib/copies-count.mjs with two counters taken from the review's scripts: lines inside an 8-line window repeated in another file (8,041 today; blank lines, comments, imports and lone brackets dropped; catalogues and schema.ts aside), and twin pairs (41 today: 20 or more shared lines of 30+ characters and 30% of the smaller file). Add src/lib/copies.baseline.json with both numbers and a 'reason' field, and src/lib/copies.scan.test.ts, which fails when either number is above its baseline and names the new pair or the files that added clones.
3. Add scripts/copies.mjs to write the baseline: it lowers a number freely and raises one only with --reason "...", which it stores. A copy made on purpose is then a recorded choice, not a blocked change. Do not put these counts in src/server/ratchet.baseline.json: scripts/ratchet.mjs refuses any rise, which would block honest work.
4. Write the three checks into docs/performance.md (a heading 'What a server route loads') and one line under Conventions in CLAUDE.md: a light route stays light (server-reach.scan.test.ts), and a copied file is said in copies.baseline.json.
