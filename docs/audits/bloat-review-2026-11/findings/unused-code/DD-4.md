Code nothing uses (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** no check. **Priority:** P1. **Effort:** S. **Confidence:** high. **Step:** 1.17.
- **Second check:** corrected.
- **Where:** `eslint.config.mjs:5`, `package.json:9`, `scripts/lib/ratchet-count.mjs:16`, `src/server/ratchet.scan.test.ts:1`, `scripts/ratchet.mjs:1`, `src/server/ratchet.baseline.json:422`, `docs/audits/bloat-review-2026-11/scripts/unused-code.mjs:1`
- **Evidence:** ESLint runs Next's two presets with --max-warnings 0: they fail on an unused local or import, never on an unused export. None of the 46 scan tests mentions unused, orphan or importers, and package.json has no tool for it. An export keyword on a name its own file does not use switches off the compiler's and the linter's check: that is the 263 plus 655 suspects, found only because a scanner was written for this review (256 lines on the repo's own TypeScript, 8.8 s over 6,191 files; it is in the repo at docs/audits/bloat-review-2026-11/scripts/unused-code.mjs). The other 2,205 over-exported names are used in their own file and hide nothing. Test support has no single name either: 9 of the 34 test-support files end in something the existing ratchet does not know (NOT_COUNTED, scripts/lib/ratchet-count.mjs:16), so src/server/trust-fixtures.ts is held to production rules with 5 unchecked reads in ratchet.baseline.json.
- **Cost today:** No budget: each unit adds a few helpers and word constants nothing reads. In 47 days that came to about 2,700 lines, about 57 a day. Paid by: Maintainers and agents, later: each dead name is a false lead in a search and context spent.
- **Saving:** Keeps DD-2 and DD-3 from growing back (about 57 lines a day at the measured rate). Costs about 9 seconds in the unit-test run; the quick gate before a deploy is not slowed.
- **Risk:** Low. A wrong alarm can come from an export Next reads by convention in a new kind of file: add the file kind to the scan's CONVENTION list. The scan under-counts where a file is namespace-imported, so it can miss, never fail wrongly, there. A legitimate new test seam fails case (b) until it is listed with its reason, which is the point.

## The fix

1. Make the scan a library: copy docs/audits/bloat-review-2026-11/scripts/unused-code.mjs to scripts/lib/unused-scan.mjs and export unusedScan(root), which returns three sorted lists: unusedExports and testOnlyExports as 'file#name', testOnlyFiles as paths. Keep its rules as they are: entry points are Next's convention files under src/app, src/proxy.ts, src/instrumentation.ts, scripts/** and the config files; tests are *.test.*, *.spec.*, e2e/**, e2e-live/** and src/test/**; exports of convention files and register in src/instrumentation.ts are skipped; a namespace, star or dynamic import marks a whole file as used.
2. One name for test support: in scripts/lib/ratchet-count.mjs export TEST_SUPPORT = /(fixtures?|test-support|testing|test-helper|test-days)\.tsx?$/ and use it in NOT_COUNTED and in the new scan, so test support is known by name (src/db/migration-files.ts is the one left over; it goes with DD-10 and is listed in testOnlyFiles until then). Then run node scripts/ratchet.mjs: src/server/trust-fixtures.ts leaves ratchet.baseline.json.
3. scripts/unused.mjs (the twin of scripts/ratchet.mjs): writes src/server/unused.baseline.json with four parts: unusedExports (list), testOnlyExports (list), keptForTests (an object 'file#name' to the reason a test needs it: an oracle, a guard list, a reset helper) and testOnlyFiles (an object path to reason, for files only tests reach that are not test support: i18n-glossary.ts, legal-wording-nb.ts, store-export-scope.ts, signature-themes.ts, experiment-legacy.ts today). It refuses to add an entry to the two lists unless run with --first, and prints what was removed.
4. src/server/unused.scan.test.ts: (a) every export the scan calls unused is in unusedExports, else the message says 'delete it or use it'; (b) every tests-only export is in testOnlyExports or keptForTests, else 'a helper only tests need lives in a *-test-support.ts file; an oracle is listed in keptForTests with its reason'; (c) every tests-only file that is not test support is in testOnlyFiles; (d) the baseline holds nothing that is no longer a suspect (run node scripts/unused.mjs), as the ratchet's fourth case does.
5. Write the first baseline as things stand (917 suspect exports, and the 9 files only tests reach that are not test support by name: five guard files, the three dead ones of DD-8 and migration-files.ts), with keptForTests filled from the oracles and seams the review named (buildInvoiceSnapshot, buildEditInvoiceSnapshot, creditNoteSnapshot, editCreditNote, nextState, validateExport, STORE_MATCHER, replayAgentEval, closeDb, forgetUpsTokens, resetTicks, the two registerProblems, SECRET_TABLES, NOT_EXPORTED). DD-3, DD-8 and DD-2 then shrink the lists.
6. CLAUDE.md, Conventions, one sentence: an export nothing imports is deleted; a helper only tests need lives in a *-test-support.ts file; unused.scan.test.ts holds both, and node scripts/unused.mjs lowers its baseline.
