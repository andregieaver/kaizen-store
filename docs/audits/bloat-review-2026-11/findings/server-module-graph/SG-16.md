# SG-16 Every cold function reads a 10.4 MB list of server references before its first request

The server code every route loads (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 1.8.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `.next/server/server-reference-manifest.json`, `node_modules/next/dist/server/route-modules/route-module.js:206-212`, `node_modules/next/dist/server/route-modules/route-module.js:463-465`, `node_modules/next/dist/server/load-manifest.external.js:40-66`, `node_modules/next/dist/build/templates/app-route.js:132`, `src/server/stores.ts`
- **Evidence:** Next's route module loads server/server-reference-manifest.json for every app route, pages and route handlers alike, in prepare() before the first request (route-module.js:206-212 and 463-465; the app-route template calls it at line 132). loadManifest reads the file, parses it and deep-freezes it, once per process (load-manifest.external.js:40-66). The file is 10,397,955 bytes. Timed with Next's own loadManifest in a fresh node process, 3 runs: 80 to 91 ms and 20 to 24 MB of heap (39 MB of RSS); split: read 20 ms, parse 40 to 43 ms, deep freeze 30 ms. The other manifests a route loads add about 26 ms and 7 MB (prerender-manifest.json 2.0 MB: 13.6 ms; routes-manifest.json 0.5 MB: 6 ms). None of this is in the cold-load figures above, which time only the route's chunks. Why it is so large: it lists 1,454 references, each with one entry per route whose bundle holds it: 81,027 entries. 85 of the references are 'use cache' functions and they hold 55,974 of the entries: 74 of the 85 are listed for more than 700 of the 807 routes, because the cycle of SG-1 puts every cached reader in every route (the widest, a cached read in stores.ts, is listed for 804). The 1,369 server actions hold 25,053 entries (30 of them are listed for 420 routes: the admin shell's account actions). A model of the manifest from the build's graph (for each route, the references whose file it reaches by sync imports) gives 78,743 entries today against the real 81,027, and 67,681 with the cuts of SG-1, SG-3, SG-4 step a, SG-6 and SG-15 in.
- **Cost today:** 80 to 91 ms and 20 to 24 MB of heap per cold instance of every function, the lean ones included: about a third on top of /api/health's 0.16 to 0.24 s. Measured here with Next's own loader; whether Vercel's packaging changes how the file is read was not checked. Paid by: The server per cold instance of every function, whatever the route. It grows with routes times references: each new cached reader adds about 660 entries today, each new route about 100.
- **Saving:** About 10 to 12 ms and 3 MB of heap per cold start from the cuts already planned (14% of entries, by the model). The rest, about 70 ms and 20 MB, stays until the admin's pages stop bundling every cached reader or Next reads the manifest per route. The certain gain is the budget: the file stops growing unseen.
- **Risk:** None in the steps (a measurement and a budget). The risk is in over-reading the number: it is this machine's time for Next's own loader, and a host with a faster disk or a bytecode cache changes the read and parse parts.

## The fix

1. Measure it where it matters first: Next traces this step as the span 'load route manifests' (route-module.js:463-465). Read that span for one cold request in production (or log the time around the first request once) to confirm the function pays what this machine shows.
2. Put the file's size and its entry count in the report of scripts/route-budget.mjs (SG-14) with a budget of today's 10.4 MB and 81,027 entries that may only fall, so growth is seen at the push that causes it.
3. Land SG-1, SG-3, SG-15 and SG-17: a route that no longer bundles every cached reader is no longer listed for it. Expect about 14% fewer entries (the model: 78,743 -> 67,681) and read the real number from the next build.
4. The larger part is the admin: 547 of the 807 listed routes are admin routes and hold 62,816 entries. It falls only as admin pages stop bundling every feature's cached readers, which is the reader and writer split of SG-8 inside code review step 3.13. Do not patch Next for this.
5. If the production measurement confirms the cost, report it upstream with these numbers: one global manifest, parsed and frozen whole by every function, grows with routes times references.

**Done when:** scripts/route-budget.mjs prints the manifest's bytes and entry count on every CI build and fails when either rises, and after SG-1, SG-3 and SG-15 the file is at least 10% smaller: under 9.4 MB and 73,000 entries (today 10.4 MB and 81,027).

**Tests and rules that hold today's behaviour, and change with it:**

- No test or rule in the repo names the manifest (rg over src, scripts, docs).
- patches/next.patch (D423) is the repo's one patch to Next and CLAUDE.md says an upgrade that changes the patched lines fails the install: a reason not to add a second patch here.
- docs/performance.md: the new section 'What a server route loads' (SG-14) gets the figure and the two growth rates.

**Comes after:** SG-1; SG-14; SG-15

**Notes:** The functions dimension lists the manifest's size as a metric and says what a Vercel function loads 'was not visible'; the load in route-module.js (used by the route templates themselves) and the deep freeze were not seen there. With the start hook of SG-5 this means a lean route's fixed cost before its own code (about 0.27 to 0.30 s plus about 0.1 s here) is larger than the code (0.16 to 0.24 s): the reason SG-5 is P0.
