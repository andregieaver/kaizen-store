The server code every route loads (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P1. **Effort:** M. **Confidence:** high. **Step:** 2.20.
- **Second check:** confirmed.
- **Where:** `src/proxy.ts:10-16`, `src/proxy.ts:53-60`, `src/server/house-switch.ts:8-17`, `src/server/house-switch.ts:27-41`, `src/server/holding.ts:9-10`, `src/server/holding.ts:17-36`, `src/server/not-found.ts:21-27`, `src/server/redirect-resolve.ts:19-23`, `src/server/experiments.ts:23-24`, `src/app/s/[store]/[market]/legacy-redirect.ts`, `.next/server/middleware.js`
- **Evidence:** The proxy runs on Node.js and its second matcher lets through every page address (proxy.ts:53-60). Its built entry names 18 chunks, 9,729 KB (summed here). It reaches 1,969 module paths: owner-tools.ts through house-switch.ts -> pages.ts -> visibility.ts -> customers.ts, the admin catalogues through holding.ts -> auth.ts -> two-step.ts -> admin-text.ts, sharp through house-switch.ts -> seo.ts -> theme-store.ts, the Stripe SDK through stores.ts. What it calls is five small readers: siteStore() (house-switch.ts:27-41), holdingFor() (holding.ts:17-36), recordNotFound(), privateGate() and storeRequestAnswer(), runningExperiments() and storeIdOfSlug(). Each sits in a file that also holds the admin's writers and their audit entries (house-switch.ts:8 and holding.ts:9 import audit from auth.ts). Four of house-switch.ts's imports are cache tags only (pagesTag, STORES_TAG, SITE_STORE_TAG, storeTag). I ran one more simulation: with no change to the proxy's own files, the cuts of SG-1, SG-6 and SG-4 step a alone take it to 915 paths and 2.4 MB; the tag leaf and the readers' split then take it to about 450 paths and 0.8 MB. The storefront layout reaches the admin's permission map (src/lib/admin-map.ts, 201 KB) the same way: legacy-redirect.ts -> not-found.ts -> permissions.ts.
- **Cost today:** 0.87 to 1.04 s and 87 to 96 MB of heap per cold proxy instance (the skeptic's re-measurement, 3 runs). A cold visitor can pay this and then the page function's own cold start. Paid by: Every shopper's page request that lands on a cold proxy instance, prerendered pages included, since the proxy runs first. It grows with stores and traffic more than anything else in this area.
- **Saving:** Simulated on the proxy's own analyzer data: 1,969 module paths and 9.2 MB -> 915 and 2.4 MB from SG-1, SG-6 and SG-4 step a with no change here; -> about 450 and 0.8 MB with the tag leaf and the readers split (the skeptic's sequence: 959 and 5.1 MB with the tag leaf alone, 491 and 1.5 MB with the readers, 447 and 0.8 MB with SG-6). Cold load from about 0.9 s to an estimated 0.2 to 0.25 s (a measured route of 685 modules and 1.75 MB takes 0.24 s).
- **Risk:** The proxy decides redirects and private-store gating: the split must move code without changing it, and each reader must keep the writer's way of forgetting its memory (forgetStoreFacts, forgetHolding, forgetRunning), or an owner's change would show late. The e2e specs above and the proxy's unit test notice a wrong decision; a forgotten memory shows as a change that takes its full 10 to 30 seconds to appear.
- **Already tracked:** Not in the repo's plans. In this review the readers' split is storefront-data SD-1 step 1 (same files) and functions SF-2.

## The fix

1. Each old file imports them from the leaf and re-exports them, so nothing breaks.
2. change the importers that take only tags to the leaf's path (96 import lines today; list them with the regex pass in the review's scratch script sk-sg/tags.js, or rg for imports whose every name ends in Tag or _TAG). A re-export cuts nothing: the edge goes only when the importer's path changes.
3. Step 3, the proxy's readers become leaves that import only the database client, src/server/log.ts, src/server/redirect-live.ts and pure src/lib modules (the file list of storefront-data SD-1 step 1, same names): src/server/short-memory.ts (remembered and forgetRemembered from redirect-live.ts), src/server/store-facts.ts (storeFactsOf, FACTS_MS, forgetStoreFacts, privateGate, mainMarketOf from redirect-resolve.ts), src/server/not-found-record.ts (recordNotFound and its throttle from not-found.ts), src/server/holding-read.ts (holdingFor and its memo from holding.ts, plus forgetHolding(apex) that setHolding() calls), src/server/site-switch-read.ts (siteStore from house-switch.ts), src/server/experiments-running.ts (storeIdOfSlug, runningExperiments, forgetRunning from experiments.ts); countHit (redirects.ts:508) moves to redirect-live.ts. src/server/redirect-resolve.ts keeps storeRequestAnswer (line 287) and takes catalogTag from the tag leaf (its line 19), recordNotFound from the new leaf (line 21) and countHit from redirect-live.ts (line 23). Each old file imports its reader and keeps the writers. Code moves; no logic changes.
4. src/proxy.ts:10-16 imports from the reader files. src/app/s/[store]/[market]/legacy-redirect.ts and src/server/redirect-resolve.ts import recordNotFound from src/server/not-found-record.ts, which takes the admin's permission map off storefront pages.
5. add src/proxy.ts to the guard of SG-14: it may not reach src/server/auth.ts, pages.ts, stores.ts, catalog.ts, seo.ts, customers.ts, src/lib/admin-text.ts or src/db/schema.ts, and its module count is held in the baseline.
