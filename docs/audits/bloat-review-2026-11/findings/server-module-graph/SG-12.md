# SG-12 ✓ Four storefront languages are imported for every server route; a request needs one

The server code every route loads (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P3. **Effort:** M. **Confidence:** medium. **Step:** tolerated.
- **Second check:** corrected.
- **Where:** `src/lib/i18n.ts:1-12`, `src/lib/i18n.ts:17`, `src/lib/messages/en.ts`, `docs/decisions.md:223`
- **Evidence:** i18n.ts statically imports da, en, nb and sv (about 95 KB of source each, plus their returns, quotes, reviews and exchange parts): 413 KB in 26 modules on /api/visit. Turbopack merges all four into one factory, which took 12.8 ms in the skeptic's profile. The file's own comment and D212 state the rule: the server and the admin read all four here; only the browser gets one. In my simulation of a storefront page after the other cuts, the three extra languages are 256 KB of the 3.8 MB left.
- **Cost today:** About 290 KB parsed and roughly 10 ms of evaluation more than a one-language request needs, per cold instance. Paid by: The server per cold instance.
- **Saving:** About 290 KB and about 10 ms per cold start (measured share of one merged factory); it grows by about 100 KB per language added by hand.
- **Risk:** t() is called synchronously in many places; a language not yet loaded would fall back to English in front of a shopper. The saving is small against that risk.

## The fix

1. Leave it until SG-1 to SG-6 are in, then measure the per-factory profile again.
2. Only if it then matters: keep English static and load the other languages through the registry the AI-translated languages use (src/lib/ui-registry.ts), filled in the market layout and the email senders before the synchronous t() is first called. That keeps D212's reason (a synchronous t() that never waits).
3. Add a test per entry point (a page, an email, a cron sender) that draws a text in each of the four languages in a fresh process.

**Done when:** If done: a new next analyze export shows /s/[store]/[market] listing only src/lib/messages/en*.ts as sync modules. If not done: the profile after SG-1 to SG-6 is in docs/performance.md with the decision to leave it.

**Tests and rules that hold today's behaviour, and change with it:**

- D212 (docs/decisions.md:223) and the comment at src/lib/i18n.ts:14-17: the server reads all four; a change rewrites that rule's server half.
- docs/rules/storefront.md, 'Interface text lives in src/lib/i18n.ts': to update with it.
- src/lib/i18n*.test.ts and every test that calls t('nb'): would need the language loaded first.

**Comes after:** SG-1; SG-4; SG-6
