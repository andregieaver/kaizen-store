# SF-11 ✓ The build writes the same large server chunks many times

Server functions: size, cold start, per-request overhead (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** duplicate. **Priority:** P3. **Effort:** S. **Confidence:** low. **Step:** 1.13.
- **Second check:** corrected.
- **Where:** `.next/server/chunks/_030vf3oprhjaf._.js and 17 files with the same content (4.0 MB each)`, `.next/server/chunks/src_lib_05q7dyrt2q-qx._.js and 9 with the same content (2.7 MB each)`, `.next/server/chunks/ssr/_0_w2fqt8kybui._.js and 4 with the same content (3.9 MB each)`, `docs/build-memory.md:38-46`, `docs/audits/code-review-2026-11.md:65`
- **Evidence:** Re-measured by comparing chunk files without their last (source map) line: 5,174 server chunk files hold 4,662 distinct contents; 512 are copies, 123.6 MB of 195.5 MB. Three chunks make 107.5 MB of the copied bytes: the 4.0 MB application chunk written 18 times (67.7 MB), the 2.7 MB admin catalogue chunk 10 times (24.2 MB) and a 3.9 MB page chunk 5 times (15.6 MB). Each entry loads one copy. .next/server is 1.4 GB on disk; the build took 263 s and peaked at 7.26 GiB (scratchpad/m/build-summary.txt).
- **Cost today:** Disk and upload in the build. Whether the copies add to the build's peak memory, or to a function's package when Vercel groups entries that use different copies, was not measured. Paid by: The build and CI.
- **Saving:** Estimate: up to about 105 MB of JS and a like share of source maps off the build output once the three chunks are split or shrunk. No effect on the build's peak memory is shown.
- **Risk:** None in measuring.
- **Already tracked:** related only: code review FH10, step 1.8 'Give the build room' (Open) covers the 8 GB limit, not this cause.

## The fix

1. No code change of its own: there is no setting for it. The lever is the size of the three chunks, and SF-1 and SF-5 shrink exactly those.
2. scripts/route-budget.mjs (SF-7 step 3) prints the bytes of identical chunk copies on every CI build (hash each file under .next/server/chunks without its sourceMappingURL line).
3. After SF-1 steps 1 to 5 and SF-5 are in, read the number. If large copies remain, report it to Next with these figures.

**Done when:** scripts/route-budget.mjs prints less than 60 MB of identical server chunk copies on a CI build (123.6 MB today).

- docs/build-memory.md:38-46 (the 8 GB limit and what was measured under it) gains the figure once it has moved.
