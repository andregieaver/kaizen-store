# SF-2 ✓ The proxy runs before every page and prefetch, and loads the whole application to do six small reads

Server functions: size, cold start, per-request overhead (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P1. **Effort:** M. **Confidence:** high. **Step:** 2.20.
- **Second check:** confirmed.
- **Where:** `src/proxy.ts:3-16`, `src/proxy.ts:53-61`, `src/server/house-switch.ts:8-17`, `src/server/house-switch.ts:30-43`, `src/server/holding.ts:9-10`, `src/server/holding.ts:21-37`, `src/server/not-found.ts:21-27`, `src/server/not-found.ts:61-77`, `src/server/redirect-resolve.ts:19-23`, `src/server/redirect-resolve.ts:203-232`, `src/server/redirects.ts:508-519`, `src/server/redirect-writers.test.ts:38-47`, `src/server/redirect-writers.test.ts:122-131 (the proxy's allowed imports)`, `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md:255`, `.next/server/middleware.js.nft.json (343 files, 45.7 MB)`
- **Evidence:** The proxy is a Node function (Next 16's default) and its matcher takes every page address with its prefetches: one page view sends 13 to 54 requests through it (verified report, from the local production build; not re-run). Re-measured here: its trace is 343 files and 45.7 MB (sharp and libvips 18.9, taxonomy 12.7, chunks 12.5); a cold load takes 838 to 884 ms (2 runs) with 70.9 MB of heap, 151 MB RSS and sharp's native binary loaded. On my graph it reaches 1,309 source files. I traced each of its six server imports: house-switch.ts (pagesTag from ./pages, STORES_TAG from ./seo, audit from ./auth) and redirect-resolve.ts (catalogTag from ./catalog at line 19) reach the cycle; holding.ts and not-found.ts reach 315 and 332 files because the proxy's read sits beside admin writers that import ./auth and ./permissions; redirect-resolve.ts also takes countHit from ./redirects (329 files) and recordNotFound from ./not-found; experiments.ts reaches 108 files (the page model and media-alts). Simulated with those edges cut and the reads in leaves: 136 files with experiments.ts as it is, 89 with its two reads in a leaf too, none of them auth.ts, admin-text.ts or the Stripe SDK. One scan test already holds the proxy's direct imports by name (redirect-writers.test.ts:122-131), but nothing holds what those modules import in turn.
- **Cost today:** About 0.65 s and 50 MB more than a lean route on every cold proxy instance, in front of every page of every store, cached pages included. Paid by: Every shopper and visitor whose request meets a new proxy instance; the server's memory. The cron routes do not keep it warm (the matcher leaves /api out), so quiet hours and each deploy leave it cold.
- **Saving:** Estimate: the proxy reaches about 95 files instead of 1,309 and starts near /api/ab/assign's measured 240 ms and 22 MB (113 files) instead of 838 to 884 ms and 71 MB. sharp leaves its trace with this fix; the taxonomy only with SF-8.
- **Risk:** The proxy decides every store's addresses, private mode and redirects, so a slip shows on every store. Move code without rewriting it. It would be noticed by src/proxy.test.ts, the redirect and private-mode integration tests, e2e/store-hosts.spec.ts and CI's hosts job; a module-level memo that ends up in two copies (the old file and the leaf) is the one way to break it silently, so each memo must live in exactly one file after the move.
