Exactly 14 files inside the cycle's closure of 1,305 import admin-text.ts, not three: src/lib/two-step.ts and the 13 listed under where, each for one or two areas (staffEmails in 7, customers in 3, customReports in 2; order, reports, work, screens and signIn once each). - **Saving:** Estimate from the chunk's measured cost (120 to 130 ms and 15 MB) and the share of catalogue source that stays loaded (548 of 3,561 KB): about 100 to 110 ms and 13 MB off each cold start of the roughly 740 entries inside the cycle, the proxy and the beacons among them, and of the 45 small handlers that reach the catalogues through auth.ts; the font route starts in about 0.25 s.
- **Risk:** Low: each edit swaps one lookup for the same object. A wrong area or language would show as wrong words in one staff email, which the email tests read. The type of each area's nb file is checked against its English file, so a mismatch fails the type check.

2. New src/lib/admin-area.ts: export const areaWords = <T>(lang: AdminLang, en: T, nb: T): T => (lang === "nb" ? nb : en); with a comment: a server module that needs one area imports that area's two files, never admin-text.ts.
3. New src/lib/two-step-words.ts: move enrolReasonText() and lockedText() from src/lib/two-step.ts:57-63 and :90-94; they read areaWords(lang, signInEn, signInNb) from ./admin-messages/sign-in.en and .nb. Delete line 13 of two-step.ts (and its fillWords and AdminLang imports if nothing else there uses them). Importers: src/app/admin/sign-in/two-step/set-up/page.tsx:11 (enrolReasonText) and src/server/two-step.ts:11 (lockedText); src/lib/two-step.test.ts imports the two from the new file. On the graph this alone frees 45 handlers, the four font routes among them.
