# SF-12 The list of every store's own domains is parsed again for every link a page draws

Server functions: size, cold start, per-request overhead (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P1. **Effort:** S. **Confidence:** medium. **Step:** 0.16.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/lib/paths.ts:35-42`, `src/lib/paths.ts:78`, `src/lib/paths.ts:98`, `src/lib/paths.ts:103`, `src/lib/paths.ts:133-143`, `src/lib/paths.ts:152-162`, `src/lib/paths.ts:217`, `src/proxy.ts:65`, `src/server/redirect-resolve.ts:300-301`, `src/lib/ab-routing.ts:53-57`, `next.config.ts:95`, `next.config.ts:103`
- **Evidence:** storeHosts() runs JSON.parse on process.env.NEXT_PUBLIC_STORE_HOSTS on every call and keeps nothing (paths.ts:35-42). The value is every store's active domains, written into the code when a deployment is built (next.config.ts:95, 103). marketPath(), which makes each internal link of a store page, reaches storeHosts() twice (marketCountryHost() at line 154, and again through marketHost() at line 140) and a third time for a market with a language (line 143); storeOrigin() once (line 78). The proxy reaches it three times per page request (proxy.ts:65, then countryHosts() and languageHosts() at redirect-resolve.ts:300-301), and storeOfHost() then walks every store's entry (ab-routing.ts:55-57). Measured here with a synthetic list of two hosts a store: one parse takes 0.02 ms at 100 stores (12 KB), 0.38 ms at 1,000 (122 KB) and 2.5 ms at 5,000 (606 KB). The saved store pages hold 67 to 102 links (scratchpad/m/html). The verified client-bundles report found the list does not reach the browser. The call counts are read from the code, not profiled.
- **Cost today:** Nothing to speak of today, with few domains. It grows with the number of stores that have a domain, for every store's pages, whether or not the store being served has one. Estimate at 1,000 such stores: about 64 ms of parsing for each render of a page with 85 links, and about 1.1 ms in front of every page request in the proxy; at 100 stores about 4 ms and 0.07 ms. Paid by: The server per render and per proxied request; the shopper waits for it on every page that is rendered.
- **Saving:** Estimate from the measured parse: at 1,000 stores with a domain, about 64 ms per render of a page with 85 links and 1.1 ms per proxied request become one 0.4 ms parse per instance. Nothing today.
- **Risk:** Low. A caller that changed the returned object would now change it for everyone, hence the freeze; none does today (read all six).

## The fix

1. src/lib/paths.ts:35-42: keep the last parse. Module variables parsedFrom (the text last parsed), parsed (its StoreHosts) and byHost (a Map from host to slug, from each store's primary and hosts). storeHosts() reads raw = process.env.NEXT_PUBLIC_STORE_HOSTS || "{}" and parses only when raw !== parsedFrom; tests stub the variable between cases, so the memory is keyed on the text, never on first use.
2. Freeze what is returned (the map, each entry and each hosts array) once after the parse: it is now shared, and its six readers only read (paths.ts:78, :98, :103, :217, proxy.ts:65, src/server/domains.ts:69).
3. Export storeOfCustomHost(host) from paths.ts (a byHost lookup on the host in lower case without its port). src/proxy.ts:65 becomes storeOfCustomHost(host) ?? storeOfHost(host, storeDomain(), {}): the same answer, without walking every store's entry. storeOfHost() in src/lib/ab-routing.ts keeps its signature and its tests; src/server/usage-traffic.ts:60 already calls it with an empty list.
4. src/lib/store-hosts.test.ts: with the variable stubbed to a 1,000-store list, 1,000 calls of marketPath() call JSON.parse once (a spy), and a second stub with other text is seen by the next call.

**Done when:** The new case in src/lib/store-hosts.test.ts passes: 1,000 calls of marketPath() with a 1,000-store hosts list call JSON.parse once (2,000 or more today).
