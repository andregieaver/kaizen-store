The usual next line is the cached getStore(slug). A cached helper exists: storeSlugOf() in menus.ts:282 ('use cache', cacheLife days, 12 callers). storeOf() in product-data.ts:27 does the same uncached. storeAndMarket() (content-grid.ts:151) makes the lookup uncached on storefront sections. The earlier checks said no code rewrites a store's slug. That is not quite so: commerce.adopt_sandbox() sets a new slug when a sandbox is kept (baseline_1_schema.sql:786-790, called from platform.ts:388), and the trigger stores_sandbox_rules() lets only that function move a sandbox's address (:19349). Wider than the slug, by my count: 152 single-row reads of commerce.stores by id in 102 server files with about 30 column lists (time_zone 13 times in 10 files); forms.ts:57-60 loads the store and then reads its time zone with a second query. Most of the others are admin writes that need a fresh value and should stay. Which callers make the 560,090 calls was not measured.
- **Cost today:** One database round trip each time code knows a store by its id; today about 7,200 a day from builds, crawlers, scheduled work and the team's testing. On storefront sections it is paid per uncached render, so it grows with shoppers and with stores. Paid by: The database and the server, per render and per scheduled run.
- **Saving:** 27 hand-written lookups become one helper (about 25 lines). Fewer database calls per uncached storefront render and per job; how many of the 560,090 calls go is not known until it is measured.
- **Risk:** Low, with one trap. A slug changes once, when a sandbox is kept: an answer remembered before that would point at an address that no longer exists, and the kept store's menus, forms and custom fields would draw nothing. Steps 1 and 1b stop it (sandboxes are not remembered in the Map and the tag is marked stale); the new case in sandbox.int.test.ts is how it would be noticed. Two smaller things: a remembered answer for a deleted store whose slug a new store took, which the id check in getStoreById() stops; and a test that mocks menus.ts for storeSlugOf, which fails at once.
