# AS-12 Videos, 3D models and theme photographs are stored with a one-hour or five-minute cache, though their addresses never change; pictures get a year

Files that ship or are stored (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 0.23.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/components/admin/video-upload.tsx:129`, `src/components/admin/media-compress.ts:62`, `src/components/admin/product-media-tools.tsx:220`, `src/components/admin/field-file-upload.ts:27`, `src/server/media.ts:80`, `src/server/media.ts:192`, `src/server/media.ts:217`, `src/server/media.ts:258`, `src/server/media.ts:309`, `src/server/theme-shots.ts:252`, `src/server/theme-shots.ts:269`, `src/server/replicate-assets.ts:83`, `node_modules/.pnpm/@supabase+storage-js@2.118.0/node_modules/@supabase/storage-js/dist/index.mjs:598`, `docs/media-compression.md:51`, `https://supabase.com/docs/guides/storage/cdn/smart-cdn, read 12 November 2026`
- **Evidence:** Added by the completeness check. Pictures are uploaded by the server with cacheControl "31536000" (media.ts:80). Videos, 3D models and custom-field files go from the owner's browser straight to Storage with uploadToSignedUrl(path, token, file, { contentType }): no cacheControl, so supabase-js sends its default "3600" (storage-js index.mjs:598-599 and 1620). Each goes to a new random path (media.ts:192, 217, 309), so the file never changes under its address. uploadBytes() stores with "300" (media.ts:258): theme photographs (theme-shots.ts:252; a unit's files are written, then it is marked done, and a failed try removes them, 264-298) and the videos the page replicator copies to a random path (replicate-assets.ts:82-83). Supabase's guide says the browser's lifetime is this option ('You can still control how long assets are stored in the browser using the cacheControl option', default one hour), while its Smart CDN (Pro plan and above) keeps the file at the edge whatever it says. docs/media-compression.md:51 states the intent for pictures only: kept for a year under their address.
- **Cost today:** Not measured. After an hour (a background video, a product video, a 3D model) or five minutes (a theme photograph, a copied video) a returning visitor's browser must ask Storage again before it may reuse the file: one round trip per file. On a plan without Smart CDN the edge also fetches the file from the origin again (videos up to 50 MB, models up to 20 MB). Which plan production is on was not checked. Paid by: A shopper's browser in stores that use videos or 3D models; owners and visitors browsing the theme store; Supabase egress where Smart CDN is not on.
- **Saving:** Not measured: one round trip to Storage less per video, model or theme photograph each time a visitor returns after its lifetime; origin fetches at the edge where Smart CDN is not on.
- **Risk:** A file kept for a year cannot be replaced under the same address: none of these paths is written twice (random names; a finished theme unit's files are never written again). A deleted file stays in browsers that hold it until their copy ends, as with pictures today.

## The fix

1. Add cacheControl: "31536000" to the options of uploadToSignedUrl at src/components/admin/video-upload.tsx:129, src/components/admin/media-compress.ts:62, src/components/admin/product-media-tools.tsx:220 and src/components/admin/field-file-upload.ts:27. Each path is new and random.
2. src/server/media.ts uploadBytes() (line 247): a fifth argument keep: "year" | "short", default "short" (300, as today). Pass "year" from src/server/replicate-assets.ts:83 and from src/server/theme-shots.ts:252. Leave the replicator's work pictures (src/server/replicate-store.ts:322, one path per job that is written again) at 300.
3. A scan test: every uploadToSignedUrl( under src/components names cacheControl (9 calls today, none does; the CSV import flows and the product's private files say "0").
4. docs/media-compression.md:51: 'Pictures, videos and 3D models are kept for a year under their address.'
5. Files already stored keep the lifetime they were uploaded with. Before opening these are only the team's demo files: leave them, or upload them again.

**Done when:** rg -n 'uploadToSignedUrl\(' src/components shows cacheControl on all 9 calls (0 today), and a video uploaded on a test store answers cache-control: max-age=31536000 from Storage (curl -sI on its public address).

**Tests and rules that hold today's behaviour, and change with it:**

- e2e/product-media.spec.ts (video and 3D model uploads) must pass unchanged.
- src/server/theme-shots.int.test.ts injects upload through ShotDeps: its signature changes with step 2.
- docs/media-compression.md:51.
- Private buckets (digital files, data jobs, invoices, review pictures) keep "0" or their own short lifetimes on purpose and are not touched.

**Notes:** Small per visitor, but the lifetime is fixed when a file is uploaded, so it is cheapest before real owners upload videos: do steps 1 and 2 before opening even though the saving is modest.
