# CA-12 ✓ A per-instance poll every minute and a five-minute prune that could run far less often

Caching and rendering (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P3. **Effort:** S. **Confidence:** medium. **Step:** 0.8.
- **Second check:** corrected.
- **Where:** `src/server/ui-text.ts:31`, `src/server/ui-text.ts:106`, `src/app/api/cron/cart-reminders/route.ts:144`, `src/app/api/cron/cart-reminders/route.ts:263`, `src/server/search-cache.ts:78`, `src/server/status.ts:413`, `src/app/api/cron/subscription-reminders/route.ts:79`
- **Evidence:** Opened in this pass. Every server instance reads commerce.ui_translations when it starts and every minute after (ui-text.ts:31 FRESH_MS = 60,000; startUi() at :106-115 sets the interval): 278,393 calls in 78 days. The dispatcher's 'cache' job (cart-reminders/route.ts:144) refreshes nothing: pruneSearchCache() (search-cache.ts:78-83) deletes kept search answers older than 30 days, 288 times a day. The dispatcher also marks the status page stale on every run that measured something (route.ts:263), though statusOverview() already revalidates each minute (status.ts:412-416).
- **Cost today:** About 3,570 polls and 288 prunes a day. Neither is among the costliest statements; the prune is about 15 s of database-bound time a day (288 times 53 ms). The polls grow with the number of live instances, not with stores. Paid by: The database; the server per instance and per five minutes.
- **Saving:** About 3,500 statements a day (from the measured counts), worth very little database time. A tidy-up, not a cut.
- **Risk:** The first machine-translated language shows on other instances up to ten minutes later. Low.

## The fix

1. The poll is DQ-12 of the database dimension: with no migration, while the last answer had no translated language let the timer wait 10 minutes instead of one (a setTimeout chain in startUi(), src/server/ui-text.ts:106-115); reloadUi() already refreshes the instance that made a change.
2. Move pruneSearchCache() from the dispatcher's job list (src/app/api/cron/cart-reminders/route.ts:144) to the daily job beside runRetention() (src/app/api/cron/subscription-reminders/route.ts:79), inside tracked() as the cron rule asks.
3. Drop the dispatcher's revalidateTag(STATUS_TAG) (route.ts:263) or the minute's lifetime on statusOverview(); keep the tag refresh on an incident (status.ts:279).

**Done when:** The dispatcher's job list has no 'cache' entry (rg -n 'pruneSearchCache' src/app/api/cron shows it only in the daily route), and on production the ui_translations statement grows by fewer than 200 calls a day per instance with no translation edited.
