## The fix

1. One per-visitor answer. New route src/app/api/shop/mine/route.ts, modelled on src/app/api/shop/tiles/route.ts (connection(), sameSite(), ?store=&market=, lockedOut(), no-store; /api addresses are outside the proxy's matcher, src/proxy.ts:54-60). It answers { cart: number, saved: string[], hint: null or { toBase, offer, go, close, label, lang } } with Cache-Control private, no-store. cart is getCartCount() and saved is savedProductIds(), both only while the shop is on (resolveShop(), then featureOn(store, 'shop')). hint is built exactly as country-hint-section.tsx:18-32 builds it today (isBot, hintCountry with x-vercel-ip-country, the words from t(market.lang).countryHint) and is null for a store with one country.
2. A marker so a visitor with nothing of their own asks nothing. New helper markOwn(storeId) (src/server/own-marker.ts) sets the cookie own_{storeId}=1: not httpOnly, sameSite lax, path /, 365 days, secure in production. Call it where the three httpOnly cookies are set: setCartCookie() (src/server/cart.ts:717), currentOwner() when it creates the wishlist cookie (src/server/wishlists.ts:44) and the customer's session (src/server/customers.ts:416). It says only yes; the cart id stays httpOnly (D14). When the mine route finds cart 0, nothing saved and no signed-in customer, it expires the marker. List it in KNOWN_COOKIES beside cart_… (src/lib/cookie-consent.ts:437): category necessary, on store, feature shop, pattern /^own_[0-9a-f-]{36}$/, purpose in en, nb, sv and da.
3. One store in the browser.
