- **Kind:** eager. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 0.16.
- **Second check:** corrected.
- **Where:** `src/components/platform-routes/themes.tsx:52`, `src/components/platform-routes/themes.tsx:59`, `src/server/theme-store.ts:85`, `src/server/theme-store.ts:96`, `src/server/theme-store.ts:138`, `.next/prerender-manifest.json`
- **Evidence:** Opened in this pass. /themes and /no/themes are 'resuming' in the manifest (re-counted: with /get-domain they are the site's only prerendered pages that need a function per view). The filter reads searchParams inside a Suspense whose fallback is the whole unfiltered list (themes.tsx:52-59; a written choice: search engines and a first visit read every theme at once). So the shell (20,586 bytes) holds the list and the function draws it again; the verified report measured 71,345 bytes served, 8,189 of them the list's HTML a second time. themePreviewNeighbours(slug) (theme-store.ts:96-102) calls loadCards() (every published theme with its whole snapshot, photographs and prices) instead of the cached themeStoreCards() (theme-store.ts:85-90), so each theme's preview fills its own copy. Production: the snapshot statement ran 10,851 times returning 107,917 rows.
- **Cost today:** One function run and the list's HTML sent twice per /themes view; one read of all snapshots per theme preview on a cold cache. /themes is one page of Kaizena Flow's own site, so this grows with visitors to that page, not with stores. Paid by: The server per request; the database; the visitor's browser (the list twice).
- **Saving:** Neighbours: one read of all snapshots per cold instance instead of one per theme. /themes, if made static: 1 function run per view becomes 0 and the list's HTML is sent once (about 71 KB to about 63 KB; the page data stays).
- **Risk:** Step 1: none seen. Step 2: a filtered address shows the full list until its script runs, and a filter no longer works without JavaScript. Noticed by the theme store's e2e specs.

## The fix

1. src/server/theme-store.ts:100: previewNeighbours(await themeStoreCards(), slug) in place of loadCards(). One line; the tags are the same.
2. Later, if /themes should be static: filter the cards in the browser. ThemeStoreList gets a small client wrapper that reads the address's query with useSearchParams inside its own Suspense and hides the cards that do not match; ThemesRoute stops awaiting searchParams (themes.tsx:52-61). Keep the rule that the unfiltered list is in the static HTML.
