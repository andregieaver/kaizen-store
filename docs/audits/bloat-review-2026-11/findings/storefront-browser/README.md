# What a shopper's browser loads (SC)

Part of `docs/audits/bloat-review-2026-11.md`, on commit 0bd814c. Read by one reviewer, challenged by a second (who re-opened every citation, re-measured every number and applied the owner's note that the platform is not open yet) and planned by a third. A tick (✓) marks a finding the second reviewer confirmed or corrected; one the planner added has none. Each finding has a file of its own beside this one.

**In short.** A shopper's first page is mostly well kept, and nothing here argues for removing a feature: a cold home page sends 680 KB of scripts (213 KB gzip), 63 % of it React and Next, with no third-party script and no font file. What is left is cost that does not follow use and that grows with page views once stores open. On a default store every document load makes two extra function calls (a wishlist read that is nearly always empty and, on pages with a product grid, a stock read for tiles that show nothing), carries about 48 KB raw / 16 KB gzip of admin words, catalogues and one unused library in its first scripts, and sends the store's layout twice (25 KB) with the store's 404 page inside. Eleven working routes share one 54-module bundle (30 KB gzip more than a built page), stores with several languages prefetch 70 to 105 KB of views a press never opens, and a store in an AI-translated language would send its whole interface text, about 100 KB, in every page. Thirteen findings: six are small and safe (P0); the two that move route files (per-route bundles, the drawer's slot) are cheapest before opening; the budgets that should have caught the growth have about 150 KB of room and cover two storefront routes.

## Well made, and should stay

- No large object crosses into client components in the four hand-written languages: the inline payloads of the home, product, category and cart pages hold none of the Store's fields; props are small labels and ids. A product grid's tile words are sent once and referenced by the other tiles. The exception is an AI-translated language (SC-13).
- The extras are server-gated and lazy: chat widget, consent manager, owner's code, referral capture, country hint and first-visit keeper are drawn only when the store has them (src/app/s/[store]/[market]/extras.tsx, src/components/lazy/extras.tsx) and load as their own chunks, the chat and referral capture only when idle. A store pays for these only when it uses them.
- Motion runtime: a 702-byte stub; the runtime is a dynamic import. The 3D viewer loads only on a press. web-vitals is a dynamic import.
- Visit and speed beacons are drawn only while the owner has visit counting on (src/components/store-visits.tsx:12), off by default. Once on, each page view sends a beacon: that cost follows use.
- No third-party script, font file or beacon on a storefront page by default: 0 third-party requests and 0 font files on the 12 measured pages. A store's own fonts are one stylesheet a family, kept for a year, with the Latin file preloaded (src/components/font-links.tsx, font-preloads.tsx); not measured here because the demo store uses none.
- zod, the page model and whole-language texts stay out of the visitor's scripts (src/lib/storefront-bundle.scan.test.ts:16, e2e/performance.spec.ts:27).
- Product tiles in content grids are plain anchors, never prefetched (src/components/content-grid.tsx). The language switcher part (LanguageLinks) draws plain anchors too, so it never prefetches (src/components/language-links.tsx:84).
- Language, currency and country links exist only in stores that offer more than one (src/components/store-layout.tsx:173, 224), so their prefetch cost (SC-1) falls only on those stores.
- Features with empty tables in production (A/B tests, reviews, gift cards, AI-translated interface texts, 3D) are not findings: the platform has not opened. Where their client code is lazy and server-gated, a store that does not use them pays nothing. Where it is not, the finding is about the idle cost or the size, never about the feature.
- Weighed and left: the browser texts of all four languages load together (24,831 raw / about 7.2 KB gzip). docs/performance.md:52-60 (D212) records that a per-language load made the page wait and lost presses.
- Weighed and left: filter-dialog (11,773 raw), site-form (6,348) and carousel (6,712) are in every built page's first scripts; the written rule keeps what is pressed before its script runs (docs/performance.md:38-51).
- Weighed and left: back-to-admin, admin-return and page-edit-link run on every page by design: the browser, not the server, decides whether the visitor is staff, so the page stays cached for all (src/components/back-to-admin.tsx:31-38).
- Not a finding: m/loaded.md lists admin-messages/moving.en.ts and inline-edit/site-css-editor among the home page's scripts. That is a mismatch in that file's chunk matching; a string search of the scripts the home page asks for finds neither.
