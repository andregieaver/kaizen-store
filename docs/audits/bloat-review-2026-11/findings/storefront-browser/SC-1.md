Content page /om-oss: 34 prefetches, 143,036 bytes, of which the four views no-sv, no-da, no-en and no-sek take 12 requests and 70,459 bytes, the footer's cookies link 2 / 6,450 and its withdrawal link 2 / 5,675. The prefetch answers carry s-maxage, so they are cached shells, not page renders. - **Cost today:** Per cold document load, not per client-side move. Stores with several languages or currencies: 17.3 to 17.7 KB and 3 requests for each such link in view (70 KB for four, 105 KB for six). Every store: 12 KB and 4 requests for the footer's cookies and withdrawal links when the footer is in view, and 33 KB for the header's four tools. The answers are fetched again on each document load; content-grid tiles and every entry into the cart or checkout are document loads, so one visit pays several times. Paid by: A shopper's browser (data, battery). The edge and proxy.ts once per prefetch request. Not a page render: the answers are cached shells.
- **Saving:** Measured: 70,459 to 104,635 bytes and 12 to 18 requests per document load where 4 to 6 language and currency links are in view (stores that offer several). Measured: 12,125 bytes and 4 requests more on every store when the footer is in view. Not counted: the header tools (a trade) and the countries list (not measured).
- **Risk:** Low. The first press on one of these links waits for the server instead of showing a prefetched shell; they are whole view changes or rarely pressed pages. A broken language press would be caught by e2e/localization.spec.ts and e2e/language-switcher.spec.ts.
- **Already tracked:** No step or rule. docs/plan.md:120 names partialPrefetching in the intended stack, but next.config.ts never set it.

## The fix

1. src/components/view-menu.tsx line 56: add prefetch={false} to the Link. Nothing else changes: the click handler already does the navigation with router.push, and without scripts the link still leads to that view's front page.
2. src/components/store-layout.tsx: add prefetch={false} to the footer's cookies link (line 498), to WithdrawalLink (line 443), to the legal pages' links (line 511), and to the three country lists (lines 236, 419, 537).
3. src/components/site-parts.tsx: the same for the builder's footer parts: the cookies link (line 224), the countries list (line 191), and the withdrawal and legal links drawn there (rg -n 'withdraw|legalPages' src/components/site-parts.tsx).
4. Leave the header's search, account, wishlist and cart links and the menus as they are. Write the trade into docs/performance.md: about 33 KB per document load buys an instant shell for four links. The cart link changes with SC-7.
5. e2e/performance.spec.ts: add a test. Phone context, cold, /s/demo/no/om-oss, wait 2 s after load, collect requests that carry the next-router-prefetch header. Expect none whose path is another view of the store (/s/demo/no-), /cookies or /withdraw.
6. docs/performance.md, under The rules: 'A link whose press does not open its href (a language, a currency), or that few visitors press (legal pages, cookies, countries), is not prefetched.' Add a decision line in docs/decisions.md.
7. Apart and later, with the caching work: try partialPrefetching: true (node_modules/next/dist/docs/01-app/02-guides/adopting-partial-prefetching.md). One shared shell per route would cut what the header tools and each listing card cost. The root layout reads the store and market from the address, so it is not a one-line change; it is not part of this finding's saving.

**Done when:** The new test in e2e/performance.spec.ts passes (0 prefetch requests to another view, /cookies or /withdraw on /s/demo/no/om-oss), and work/measure-routes.mjs shows the content page's RSC prefetches fall from 34 requests / 143,036 bytes to 18 requests / about 60,500 bytes.
