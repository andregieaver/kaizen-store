# SC-12 Every page with a product grid loads the tile's Add to cart script and asks the server for stock, also in a store whose tiles show neither (the default)

What a shopper's browser loads (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P0. **Effort:** S. **Confidence:** high. **Step:** 0.12.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/lib/shop-tiles.ts:21`, `src/lib/shop-tiles.ts:35`, `src/components/content-grid-section.tsx:37`, `src/components/content-grid-section.tsx:139`, `src/components/content-grid.tsx:222`, `src/components/lazy/blocks.tsx:29`, `src/components/tile-shop.tsx:21`, `src/components/tile-shop.tsx:56`, `src/app/api/shop/tiles/route.ts:14`, `src/server/shop-tiles.ts:27`, `src/server/product-settings.ts:14`, `e2e/shop-components.spec.ts:50`, `docs/rules/admin/website.md:728`, `evidence/routes.json`
- **Evidence:** Read in code in this pass. The store's two switches are off by default (DEFAULT_PRODUCT_SETTINGS, shop-tiles.ts:21; both columns default false; the seed holds no row). But tileAsk() answers 'store' for a grid with no choice of its own and so never null (shop-tiles.ts:35-39), content-grid-section.tsx:37 and 139 hand every product grid that ask, and content-grid.tsx:222 draws a TileShop island in every product tile. The island is a lazy chunk (lazy/blocks.tsx:29) that asks /api/shop/tiles for all the page's tiles (tile-shop.tsx:21-41) and learns the store's settings only from the answer (tile-shop.tsx:56). The route calls connection() and answers no-store (route.ts:14-27); tileFacts() reads the settings, then the products and variants, then their live stock, whatever the settings say (server/shop-tiles.ts:27-52): three reads. The settings are read per request on purpose (product-settings.ts:14-16). Measured (m/routes.json, demo store): the home page and /products each make one GET /api/shop/tiles (2,914 bytes transferred, 1,193 decoded) and load two lazy chunks before load: 2tx5m_kkz3wgc.js (1,804 bytes, the island) and 3r0si1dhleclm.js (17,228 bytes, Add to cart with its quantity chooser and the cart drawer's opener), 19,032 bytes raw and 11,152 transferred. Nothing is drawn from them. The home page's payload names the island 9 times, once per tile. The content page and the product page, which have no product grid, make neither request. Built on 10 and 11 November 2026 (D557); the comment at lazy/blocks.tsx:28 says 'loaded only on a page whose grids show them', which is not what the default does.
- **Cost today:** Per document load of any page with a product grid (a store's front page and /products in the standard setup), for every selling store: one more function call with three database reads and 2.9 KB of answer; once per browser 19 KB raw (11 KB transferred) of scripts. Paid by stores that never switch the feature on, and it grows with page views. Paid by: The server per request and the database; a shopper's browser
- **Saving:** Measured on the demo store: per document load of the home page and /products, one function call with three database reads and 2,914 bytes; once per browser 19,032 bytes raw / 11,152 transferred of scripts. For every store that leaves the two switches off, the default.
- **Risk:** Low. A change of the settings shows once the catalogue's tag is refreshed rather than on the very next request; the save does that itself, and a row written by hand in SQL needs the refresh (the e2e test changes for that reason). A stale 'off' can only hide stock on a tile, never show wrong stock.
- **Already tracked:** No. D557 (10 November 2026) wrote the present design into docs/rules/admin/website.md:728.

## The fix

1. src/server/product-settings.ts: beside getProductSettings() add productSettingsCached(storeId) with 'use cache', cacheLife('hours') and cacheTag(catalogTag(storeId)), as src/server/catalog.ts:285-287 does. In saveProductSettings() call refreshTag(catalogTag(member.store.id)) (src/server/refresh.ts:10) after the write. Correct the comment at lines 13-15.
2. src/lib/shop-tiles.ts: add the pure tileAskFor(own, store): tileShows(tileAsk(own), store) turned back into an ask of 'show' or null for each of the two, and null when neither shows. Unit tests in src/lib/shop-tiles.test.ts: default settings with no own choice give null; a grid's own 'show' gives an ask; a store's switch on gives an ask; a grid's own 'hide' beats the store.
3. src/components/content-grid-section.tsx lines 37 and 139: const tiles = place.owner ? tileAskFor(block.shopTiles, await productSettingsCached(place.owner)) : null. A grid that shows neither then draws no island, loads no chunk and asks nothing.
4. The route and tileFacts() stay: stock is still asked per request, only by grids that show it. The answer may keep its settings field for pages already in the cache.
5. e2e/shop-components.spec.ts:50-71: the test inserts the settings row after the page was first drawn and expects the next load to show stock. With the cached read give it two stores: one whose row is inserted before its first page view (stock shows), one without (assert no request to /api/shop/tiles and no [data-tile-shop]). Add a signed-in check that saving Settings, Products shows on the next load.
6. Docs: docs/rules/admin/website.md:728 and D557: 'the store's two switches are read with the catalogue's cache and refreshed when saved; stock is asked per request, only by grids that show it'. Correct the comment at src/lib/shop-tiles.ts:6-8. Lower the home page's after-load budget (SC-6).
