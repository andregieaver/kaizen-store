# AD-11 ✓ The orders list re-reads store facts it already holds and waits in a row for the count

What the server does for an admin navigation (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** duplicate. **Priority:** P2. **Effort:** S. **Confidence:** high. **Step:** 4.4.
- **Second check:** confirmed.
- **Where:** `src/server/order-list.ts:44-57`, `src/server/order-list.ts:195-224`, `src/server/stores.ts:239-242`, `src/server/localization.ts:191`, `src/server/localization.ts:217`, `src/app/admin/(gated)/[store]/orders/page.tsx:68-73`
- **Evidence:** loadOrderListContext() runs two statements, one after the other, for the store's time zone, market codes and currency rates; all three are in the cached Store the page already holds (store.timeZone, store.allMarkets, and the currencies with their rates read at stores.ts:239-242), and 'today' can be worked out in code. listOrdersPage() then reads rows, tags, the page before and the count one after another, though the count does not depend on the rows. This pass checked the open risk the skeptic left: both writers of currency rates refresh the store's tag (the owner's save at localization.ts:191, the ECB job at localization.ts:217), so the cached rates follow a change.
- **Cost today:** 2 statements and 3 to 4 sequential waits per orders-list view, out of 9 to 11 statements. The orders list will be the most opened admin page of a selling store. Paid by: The server per request; the owner waits a little longer for the list to stream in.
- **Saving:** Estimate: 2 statements and 2 sequential waits per view.
- **Risk:** Low. 'Today' worked out in Node must be the store's day, not the server's: todayIn() with the store's time zone, and the equality case run near midnight in a test with a fixed clock. Sort by total uses the cached rates; they are refreshed when rates are saved.

## The fix

1. src/server/order-list.ts: add orderListContextOf(store) that builds the same OrderListContext from the Store: timeZone, today through todayIn(new Date(), store.timeZone) (src/lib/analytics-period.ts, as control-center.ts:296 does), marketCodes from store.allMarkets, totalFactors from the store's currencies. Keep loadOrderListContext(storeId) for jobs and the 12 integration tests that call it.
2. src/server/order-list.ts (resolveOrderList) and src/app/admin/(gated)/[store]/orders/page.tsx:70: let the page pass the store, so the context costs no statement.
3. src/server/order-list.ts:195-224: start countOrders() together with the rows (Promise.all of the rows statement and the count); tags and the page before still follow the rows.
4. Add one integration case: orderListContextOf(store) equals loadOrderListContext(store.id) for the seeded store, so the two cannot drift.
