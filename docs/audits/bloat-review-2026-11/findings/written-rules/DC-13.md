# DC-13 A table's definition is in the repo four times, and a search for its name returns more lines from old migrations and Drizzle's snapshot than from code

The written rules and the agents' context (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 0.27.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `supabase/archive/20261111172838`, `supabase/migrations/meta/20261111172838_snapshot.json`, `supabase/migrations/20261111172839_baseline_1_schema.sql`, `src/db/schema.ts`, `.vercelignore:1-2`, `src/app/globals.css:1-9`, `src/db/migration-files.ts:25`, `CLAUDE.md:70-72`, `package.json:19`
- **Evidence:** ripgrep lists 796 files and 11.3 MB under supabase: the 4 baseline files (4.0 MB), Drizzle's snapshot (one JSON of 2.7 MB) and the 789 squashed migrations kept in supabase/archive (4.6 MB). A table is therefore written in schema.ts, in the snapshot, in the baseline and in its old migrations. A search for gift_cards from the repo root returns 172 lines from non-test source (25 of them in schema.ts), 141 from the baseline, 81 from the snapshot and 124 from 13 archived files; for order_lines 326, 227, 192 and 221 (56 files); for store_starters 145, 100, 103 and 112; for webhook_endpoints 67, 52, 48 and 31. The build and Tailwind were already told to skip the snapshot (.vercelignore:1-2, globals.css:1-9: it once held Vercel's build past its memory); searches were not. The archive is 'outside every path that applies migrations' (D572) and tests reach it through src/db/migration-files.ts. The baseline is different: functions, triggers and reference data live only there, so it must stay searchable.
- **Cost today:** For a table or column name, 79 to 413 extra lines (12 to 69 KB) per search in the four names tried, in a tool that shows 250 lines by default, so history and generated JSON take places from code. No runtime cost. Paid by: An agent's session
- **Saving:** 791 files and 7.3 MB leave default searches; 79 to 413 fewer lines per table-name search in the four names tried.
- **Risk:** The filter is silent: an agent asking when a column was added finds nothing unless it names supabase/archive. A person's editor search built on ripgrep skips the two folders too. Tested in a scratch folder only, not in the repo (the review is read-only).

## The fix

1. Add supabase/.rgignore with two lines: archive/ and meta/. Put it in supabase itself, never inside supabase/archive: src/db/migration-files.ts:25 reads every entry there as a folder of migrations.
2. Commit it before running pnpm db:check: that script fails on any untracked file under supabase (package.json:19).
3. The core's line from DC-7 step 4 names old migrations and the snapshot among what default searches skip, and says: to see when something changed, search supabase/archive by name.

**Done when:** rg --files supabase | wc -l prints 5 (today 796), rg -c gift_cards supabase sums to 141 lines (today 346), and rg -l gift_cards supabase/archive still lists files when the folder is named.
