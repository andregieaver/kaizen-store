# AC-12 ✓ Every navigation link in view is prefetched one by one: 23 to 46 background requests per admin screen

What an owner's browser loads in the admin (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P1. **Effort:** S. **Confidence:** medium. **Step:** 0.13.
- **Second check:** corrected.
- **Where:** `src/components/admin/store-admin-nav.tsx:94`, `src/components/admin/store-admin-nav.tsx:131`, `src/components/admin/store-admin-nav.tsx:195`, `src/components/admin/admin-rail.tsx:47`, `src/app/admin/(gated)/[store]/layout.tsx:132`, `next.config.ts:42`, `docs/plan.md:120`, `node_modules/next/dist/docs/01-app/02-guides/adopting-partial-prefetching.md:15`, `node_modules/next/dist/docs/01-app/02-guides/adopting-partial-prefetching.md:69`
- **Evidence:** The rail, tabs and sidebars use plain Link; 4 places in the admin set prefetch={false} and none in src sets prefetch or prefetch={true}. Next's guide: with Partial Prefetching a Link prefetches the route's shell, built once per route and reused, "rather than prefetching each link separately as it did before"; and when cacheComponents is on without a partialPrefetching value Next logs a warning, which the production server's start log here shows (scratchpad m/start.log line 9). The browser run (m/routes.json and routes.md) measured, after load: the store home 28 prefetch requests for 13 targets (two per link: about 590 bytes and 8 to 10 KB; 98 KB on the wire in all), orders 32, products 38, the pages list 46 (160 KB on the wire), settings 44. On this local build the View store link is prefetched too: 4 requests, 62 KB decoded, and 9 storefront scripts fetched after load; in production a store is on its own host, where a link to another origin is not prefetched. Most of the admin's prefetch answers carried no Cache-Control on the local server. Whether Vercel answers them from a prerendered shell or a function was not measured.
- **Cost today:** Measured locally: 23 to 46 requests and 78 to 160 KB on the wire per admin screen view, on top of the page. In production each is a request to Vercel; whether it also runs a function is unknown. Paid by: An owner's browser (network) and the hosting bill per request. The team's own clicks today; it grows with every owner and every screen they open.
- **Saving:** Not known until tried: fewer and smaller prefetches per screen is what the guide describes. The View store link alone is 4 requests and about 62 KB decoded per screen on a deployment where stores share the admin's host.
- **Risk:** Medium: a framework setting that changes what every Link fetches, across the storefront too. A page whose shell cannot be built shows as an insight in development and as a slower first paint after a click in production. Turning prefetch off everywhere instead would make navigation feel slower, so it is not proposed.
- **Already tracked:** No. docs/plan.md line 120 names partialPrefetching as part of the stack; the config never set it, and no decision says why.

## The fix

1. next.config.ts line 42: add partialPrefetching: true beside cacheComponents (docs/plan.md line 120 named both for the stack). There is no <Link prefetch> or prefetch={true} in src, so the guide's audit of full prefetches has nothing to migrate.
2. Run next dev and open the store home, orders, products, a product, the builder and a storefront page; fix what the instant-navigation insights name (URL data read outside Suspense), or set `export const instant = false` on a route that is not ready, with a note saying why.
3. src/app/admin/(gated)/[store]/layout.tsx line 132 (View store) and the platform's link to its site: prefetch={false}. The storefront has another root layout, so the navigation is a full page load and a prefetch can never be used.
4. Measure the same five admin pages again the same way (Chromium against pnpm start, requests carrying _rsc after load) and write before and after into docs/performance.md.
5. After the deploy, read one admin session's requests in Vercel's logs to learn whether a prefetch reaches a function. If it does and the count is still high, set prefetch={false} on the sidebars' deeper links (store-admin-nav.tsx lines 94, 131 and 195) and keep the rail's.

**Done when:** pnpm start prints no partialPrefetching warning, the e2e and signed-in suites pass, and the repeated measurement shows the store home's after-load prefetches at or under today's 28 requests and 98 KB on the wire, with the figures written into docs/performance.md.
