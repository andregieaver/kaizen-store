# What an owner's browser loads in the admin (AC)

Part of `docs/audits/bloat-review-2026-11.md`, on commit 0bd814c. Read by one reviewer, challenged by a second (who re-opened every citation, re-measured every number and applied the owner's note that the platform is not open yet) and planned by a third. A tick (✓) marks a finding the second reviewer confirmed or corrected; one the planner added has none. Each finding has a file of its own beside this one.

**In short.** The admin's browser load is moderately bloated, and the worst of it is cheap to fix before opening: a plain screen loads 1.15 MB of script (median of 449 routes), of which 481 KB is Supabase's client, zod and the builder's English, brought in by three stray imports. 26 screens load an editor they never draw, an order screen carries 0.69 MB for custom fields the store may not have, one Work screen ships a 1.7 MB chunk of text, and the builder loads 3.3 MB at once. Four small fixes (AC-1, AC-2, AC-3, AC-7) and two checks (AC-10, AC-11) take a plain screen to about 0.72 MB and keep the leaks from coming back; the builder, the text handed down in each page (36 to 85% of its data) and link prefetching (23 to 46 background requests a screen) need more care. Two things the report missed are added: the notice badge costs four database statements per open tab per minute whatever the store uses (AC-13), and the Products list sends every product to the browser at about 0.9 KB each (AC-14, already code review step 1.13, open); no finding judges a feature by its use, and every cost is per screen view, so it starts the day owners arrive.

## Well made, and should stay

- The CSS editor (CodeMirror), three, model-viewer, mediabunny and Stripe Connect load only when used: I searched the 324 chunks that are in some admin route's first load for their markers and found no CodeMirror, three or Stripe Connect code; model-viewer and mediabunny appear only as names in the small modules that load them later.
- The heavy editors are client modules of their own routes only: product-editor.tsx on 2 routes, media-library.tsx on 2, menu-editor.tsx on 2, campaign-editor.tsx on 2, theme-editor.tsx on 5. What leaks is listed in AC-2 (page-editor.tsx on 13 previews, terms.tsx on lists, the content editors).
- No data table reaches admin client code: no file of src/data, no font list, country list or taxonomy file over 20 KB is in any admin route's client closure (fonts.ts is 5 KB, product-taxonomy.ts 17 KB). The exception is the AI chat's closure (AC-8).
- Icons are imported by name (lucide-react, simple-icons); no namespace import.
- The admin loads no web font: its root layout (src/app/admin/layout.tsx) sets font-sans and imports only CSS. Its two stylesheets are 204,207 bytes raw / about 36 KB gzip, cached for a year; one of them (183,124 bytes) is the same file the storefront loads, so it is a question for the storefront's review, not a second download.
- The admin's service worker is small and keeps only the offline page and one icon (src/lib/admin-sw.ts lines 13-37); it caches no page, script or data.
- The per-area English fallback of 10 November (D540) holds: admin-text.tsx statically imports only common and sign-in.
- The AI manager's chat is fetched when its panel opens (ai-manager-launcher.tsx line 32), and web-vitals after the page (speed-beacon.tsx line 53).
- Polls other than the notice badge run only while their work runs: the store draft every 10 seconds while a page is being built (store-drafts.tsx lines 39-45), the replicate panel, live analytics, the Work timer on Work screens. The notice badge is AC-13.
- The owner's avatar goes through /api/gravatar with a one-hour browser cache and a one-day shared cache; the media library draws thumbnails (media-library.tsx line 507).
- No server-only module leaks into a client bundle: the import graph reaches no file under src/server from admin client code apart from server action stubs.
- Sign-in, two-step and forgot-password load about 0.50 MB and no Supabase client.
- No test or written rule pins the three shell imports of AC-1: docs/rules/admin/platform.md line 51 only requires that SessionKeeper refreshes tokens in the browser.
- Non-text flight data is not oversized on the sampled lists: the orders list's rows after the words are element trees of the page itself (largest 14 KB, the top bar).
