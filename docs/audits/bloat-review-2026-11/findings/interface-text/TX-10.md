# TX-10 ✓ English refusals are kept twice and matched back to their Norwegian by regular expression

Interface text (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** duplicate. **Priority:** P3. **Effort:** M. **Confidence:** medium. **Step:** tolerated.
- **Second check:** corrected.
- **Where:** `src/lib/known-words.ts:13-49`, `src/lib/marketing-words.ts:12-37`, `src/lib/discount-words.ts:43`, `src/lib/redirect-words.ts:27-28`, `src/lib/experiment-words.ts:15-64`, `src/app/admin/(gated)/[store]/settings/tax/actions.ts:18`, `src/lib/broadcasts.ts:40-45`, `src/server/settings.ts:70`, `src/lib/product-media.ts:60-61`, `src/lib/admin-messages/product.en.ts:130-131`
- **Evidence:** Server modules write refusals as English sentences; the catalogue repeats each as a template; words modules (known-words, marketing-words, discount-words, redirect-words and experiment-words among them) build one RegExp per entry and match the server's sentence to find the Norwegian. This is a written decision (D312 A6 and A8: the server answers in English because the AI manager and the tests read it). Ten tables hold 300 entries and 16.7 KB of English that also sits in code (verified report). For 19 entries no literal sentence is in the code, but at least 7 of those are built from parts and do match at run time (broadcasts.ts:40-45, settings.ts:70), so a text search cannot tell drift from design. One real gap, re-checked: the server says 'Use at most N videos.' and 'Use at most N 3D models.' (product-media.ts:60-61); no table carries those sentences, and the catalogue's product.media.tooManyVideos and tooManyModels ('A product has at most {n} videos.') are named by no code.
- **Cost today:** About 17 KB of English kept in two places with nothing checking that they still match. A refusal that stops matching reaches a Norwegian owner in English without any error. The run-time cost is negligible (about 300 regular expressions built once per instance). Paid by: An owner who reads an untranslated refusal; whoever edits a sentence in one place only.
- **Saving:** No measurable bytes or time. The gain is no silent English for a Norwegian owner. The full change (step 3) would remove about 17 KB of duplicated source.
- **Risk:** A guard based on text search would raise false alarms on sentences built from parts; the guard here calls the validators instead. Step 3 must keep the English the AI manager reads word for word, or the eval recording changes.

## The fix

1. A guard that tests real refusals, not text: one test per words module (beside it, for example src/lib/marketing-words.coverage.test.ts) calls the module's validators with input that fails each rule and asserts every refusal returned is matched by an entry (knownText(refusal, english, nb) differs from the refusal). Start with broadcasts (src/lib/broadcasts.ts), discounts, redirects, experiments and the tax and payments settings.
2. The product media pair: either add the two sentences of product-media.ts:60-61 to the table the product editor matches and delete product.media.tooManyVideos and tooManyModels, or make mediaProblems() say the catalogue's sentences. Decide with TX-11, which lists the two keys as unread.
3. Only if step 1 keeps turning up drift: the server answers with a code and values, and both the English for the AI manager and the Norwegian come from the catalogue entry. That changes tool answers, so the AI eval recording must be made again.

**Done when:** The coverage tests of step 1 pass for the five validators named, and product.media has no entry that no code reads (rg tooManyVideos outside the catalogues finds a reader, or the keys are gone).
