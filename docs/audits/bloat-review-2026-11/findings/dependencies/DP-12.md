Dependencies (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** eager. **Priority:** P2. **Effort:** M. **Confidence:** medium. **Step:** 2.22.
- **Second check:** added by the planner, not checked a second time.
- **Where:** `src/server/stores.ts:14`, `src/server/stores.ts:25`, `src/lib/theme.ts:9`, `src/lib/theme-elements.ts:2-17`, `src/lib/page-roles.ts:1`, `src/lib/page-roles.ts:16-19`, `src/lib/visit-record.ts:8`, `src/lib/page-content.ts:379-380`, `src/lib/page-content.ts:2644-2670`, `src/lib/page-content.ts:2925`, `docs/audits/code-review-2026-11.md:104`, `docs/audits/code-review-2026-11.md:472`
- **Evidence:** src/lib/page-content.ts is 4,319 lines with 468 zod constructor calls, imported by 251 non-test files. The store reader (server/stores.ts, behind getStore()) reaches it four ways: stores.ts:25 parses the theme, and theme.ts:9 takes two numbers (CONTENT_MAX_MIN, CONTENT_MAX_MAX) from it; theme-elements.ts takes themeElementSchema (page-content.ts:2925, built from the spacing, border, shadow and background schemas) and mapChildBlocks; stores.ts:14 takes the type guard isPageRole from page-roles.ts, whose first line imports newPageContent; and the beacon's visit-record.ts:8 takes two lists of reserved slugs. Cutting the three small imports alone does not free it (walked: theme-elements.ts still reaches it). Measured as bundles in a fresh process: the page model and its 52 files 63-64 ms, 8.2 MB heap, 36 MB RSS (zod alone 18-19 ms, 2.2 MB, 9 MB); the store reader with schema.ts and the Stripe SDK stubbed 127-136 ms, 15.6 MB, 49 MB, against 67-87 ms, 7.5 MB, 29 MB for the health route without the schema. So once DP-10 and DP-1 are done, about half of what the beacon still loads is the page model.
- **Cost today:** About 45 ms, 6 MB of heap and 20-26 MB of resident memory per cold start (this sandbox) on every route that reads a store but draws no page: the beacons, the tile and cart APIs, webhooks, cron routes. Page routes need the model anyway and gain nothing. Paid by: The server per new function instance on API and beacon routes. Small beside the hub today; it becomes the largest single piece of the beacon after the other cuts.
- **Saving:** Estimate from the bundles: up to 45 ms, 6 MB heap and 20-26 MB RSS per cold start on routes that read a store and draw no page. The share of the 468 schemas the theme truly needs was not counted, so the real figure is somewhat lower.
- **Risk:** Medium for a small gain if done alone: 251 files import the page model, and a careless split changes import order or creates a cycle. Low when done inside step 3.2 with re-exports. A cycle shows as an undefined schema at import in pnpm test.
- **Already tracked:** Partly: code review step 3.2 (FB6, FB9), Open, splits page-content.ts into a folder but with the same exports and no rule about which file may import which, so by itself it saves nothing at load.

## The fix

1. Do this as part of code review step 3.2, which already turns src/lib/page-content.ts into a folder with the same exports. Add one constraint to that step: the part-style schemas (spacing, border, radius, shadow, background, size overrides, typography groups) and themeElementSchema live in a leaf file of the folder that imports no block schema, for example src/lib/page-content/part-styles.ts.
2. src/lib/theme-elements.ts and src/lib/theme.ts import from that leaf file, not from the folder's index; CONTENT_MAX_MIN and CONTENT_MAX_MAX move to a constants file both import; mapChildBlocks moves to a file of plain block helpers without schemas.
3. Move PAGE_ROLES and isPageRole (page-roles.ts:16-19) to src/lib/page-role-names.ts; page-roles.ts re-exports them; src/server/stores.ts:14 imports from the new file.
4. Move RESERVED_STORE_PAGE_SLUGS and RESERVED_ARTICLE_SLUGS (page-content.ts:2644-2670) to src/lib/reserved-slugs.ts; page-content re-exports them; src/lib/visit-record.ts:8 imports from the new file.
5. Add to DP-6's graph test: src/server/stores.ts and the four /api/visit routes may not reach the block schemas' file.
6. Re-time the beacon after the build (fresh-process load of .next/server/app/api/visit/route.js).
