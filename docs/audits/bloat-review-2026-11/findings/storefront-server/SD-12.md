# SD-12 ✓ Whole rows and documents are read for one fact

What the server does for a storefront request (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** oversize. **Priority:** P3. **Effort:** S. **Confidence:** high. **Step:** tolerated.
- **Second check:** confirmed.
- **Where:** `src/server/fonts.ts:176-182`, `src/server/ai.ts:206-211`, `src/server/chat-agent.ts:89-94`, `src/server/chat-agent.ts:135-141`, `src/server/page-modals.ts:16-27`
- **Evidence:** fontPreloadFile() reads a family's whole stylesheet to find one file name (fonts.ts:176-182; 42,211 calls in production). aiFor() runs 'select *' on ai_providers, keys included (ai.ts:206-211), where the chat button needs 'is there a text model, can it speak' (chat-agent.ts:139; 237,563 calls over four shapes, jobs included). getChatAgent() runs 'select *' on chat_agents, instructions included, for a name and a greeting (chat-agent.ts:89-94). usesRememberedModals() runs jsonb_path_exists over every published page of a site for one yes or no (page-modals.ts:16-27; 68,878 calls, 121 s). All but aiFor() are cached for hours, so each is paid per cold fill.
- **Cost today:** 121 s of JSON scanning in 78 days (about 1.5 s a day) and wider rows than needed on every cold fill. The modal scan grows with a store's page count. Paid by: The database per cold render.
- **Saving:** The widget's reads shrink to a few bytes and no longer carry keys or instructions; the modal scan falls with SD-8. Small.
- **Risk:** Low.

## The fix

1. chatWidgetFor() (src/server/chat-agent.ts:135-141) asks a new two-column read in src/server/ai.ts (does the site have an enabled provider with a text model, can it speak) instead of aiFor(); no key leaves the database for the widget.
2. the widget's read of the agent selects the columns the widget shows (name, occupation, avatar, greeting, voice, enabled), not the instructions.
3. fontPreloadFile() (src/server/fonts.ts:176-182) takes cacheLife("days") like fontCss(): a stylesheet never changes once installed and installFont() refreshes its tag.
4. leave the modal scan as it is until SD-8 lengthens the pages' life; then it runs once per change of the site's pages. A flag column would need a migration and a writer and is not worth it now.

**Done when:** chatWidgetFor() calls neither aiFor() nor a 'select *' (rg over src/server/chat-agent.ts:135-160), and fontPreloadFile() is at days.

**Tests and rules that hold today's behaviour, and change with it:**

- src/server/fonts.int.test.ts, src/lib/fonts.test.ts, e2e/fonts.spec.ts; the chat's tests and docs/rules/storefront.md:384-390 (chatWidgetFor()'s tags, see SD-16); src/lib/cookie-consent-modals.test.ts.

**Comes after:** SD-8

**Notes:** P3: every one of these is cached, and together they cost about 1.5 s of database time a day. Step 1 has a second reason to do it when SD-16 touches the same function: an API key should not travel into a cached widget read.
