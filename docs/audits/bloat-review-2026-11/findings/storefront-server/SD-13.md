- **Kind:** no check. **Priority:** P1. **Effort:** M. **Confidence:** high. **Step:** 1.7.
- **Second check:** confirmed.
- **Where:** `docs/performance.md:34-37`, `docs/performance.md:110-113`, `src/lib/pay-routes.graph.test.ts:1-40`, `e2e/performance.spec.ts:40-45`, `e2e/performance.spec.ts:119-130`, `src/server/store-writers.scan.test.ts:1-25`
- **Evidence:** First scripts have a byte budget per route and a scan keeps zod out of visitors' scripts. The one server-side number is the first byte of two warm store pages, under 250 ms (e2e/performance.spec.ts:127-130; measured under 10 ms). It cannot see any finding here: the shell answers first and the statements run in the stream after it. Nothing counts the proxy's import graph (1,311 modules), a page's statements per view (about 18 on a product page), what a page load asks for after the document (SD-14, SD-15), that a cached read sets a life and a tag (2 set no life), or that a store's action refreshes only that store's tags (SD-16). The import walk and the statement count used in this review are each a few lines, in the style of tests the repository already has.
- **Cost today:** No bytes today. It is why SD-1, SD-2, SD-8, SD-14, SD-15 and SD-16 could grow unseen, and they will grow faster once real stores switch features on. Paid by: Everyone later: shoppers, the server, the database.
- **Saving:** No direct saving. It keeps the savings of SD-1, SD-2, SD-8, SD-14, SD-15 and SD-16 from growing back.
- **Risk:** Low. A statements budget can flicker with background work in the server (the minute poll of SD-7): the margin of 2 and one retry cover it.
- **Already tracked:** No. ratchet.scan.test.ts (step 1.2, Done) ratchets unchecked reads and casts, not graphs, statements per view or cache lives.

## The fix

1. src/proxy.graph.test.ts (SD-1 step 5): forbidden modules and ceilings that may only fall for src/proxy.ts, the market layout and src/instrumentation.ts. Share reach() with src/lib/pay-routes.graph.test.ts through a test helper.
2. src/server/use-cache.scan.test.ts: every 'use cache' function calls cacheLife and cacheTag, with a short list of exceptions that names each reason (campaignNoticesAt and ownerSells follow an inner life; storeSlugOf has no tag). The same test holds a list of platform-wide tags (CATALOG_TAG, STORES_TAG and the platform's AI tag) that no file under src/app/admin/(gated)/[store] may refresh.
3. scripts/server-budget.mjs, run as its own step of CI's e2e job after Playwright has finished, against the same built app and Postgres: for the home page, a product, All products, a category, and the home page with a cart cookie it reads xact_commit from pg_stat_database, requests the page once, waits, reads again, and fails above the budget kept in the script. First budgets are today's numbers plus 2 (product 21, search 14, category 5, home 3); SD-2, SD-10 and SD-11 lower them as they land. It runs alone because parallel specs would add commits.
4. the e2e that loads the home page and All products asserts which requests follow the document: none to /wishlist/saved (after SD-15) and none to /api/shop/tiles on a store with the switches off (after SD-14).
5. docs/performance.md gains a section 'Server budgets' with the numbers and how to lower them; CLAUDE.md Conventions gains one line naming the three checks.
