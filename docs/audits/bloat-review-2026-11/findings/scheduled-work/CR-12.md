# CR-12 ✓ The daily job is scheduled twice, at the same minute

Scheduled and background work (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** duplicate. **Priority:** P2. **Effort:** S. **Confidence:** medium. **Step:** 1.22.
- **Second check:** confirmed.
- **Where:** `vercel.json:6-11`, `supabase/migrations/20261111172842_baseline_4_roles_and_supabase.sql:102`, `src/app/api/cron/subscription-reminders/route.ts:53-59`, `src/server/cron-auth.ts:39-44`, `docs/security.md:264`
- **Evidence:** vercel.json schedules /api/cron/subscription-reminders at '0 7 * * *' and pg_cron schedules the same route at '0 7 * * *'. The route's comment says this is meant: 'Supabase's scheduler calls it (D33), and Vercel Cron too where CRON_SECRET is set; each reminder goes once whoever calls.' That was written when the route sent reminders; it now runs about 40 functions (24 prunes, erasures, currency rates, domain renewals). Whether CRON_SECRET is set in Vercel, and so whether the second call runs or is answered 401, was not checked (no Vercel access in this review). No test pins the crons block (searched src, e2e and scripts).
- **Cost today:** If the secret is set: the whole daily job runs twice at the same moment every day, each on five connections, both deleting the same rows (a statement may wait 5 s for a lock, then fails). If not: one refused call a day. Either way a second scheduler to reason about. Paid by: The server and the database once a day; and anyone debugging a daily job that ran twice.
- **Saving:** At most one duplicate run of the daily job a day; one scheduler instead of two.
- **Risk:** Vercel's call was the only scheduled call that did not depend on pg_cron. If pg_cron stops, nothing runs, the status probe included (it runs from the dispatcher); the platform home shows the jobs as late to whoever looks. A daily duplicate of one route never covered that. If a watchdog outside Supabase is wanted, point Vercel's cron at a small check of the ledger instead; that is a new feature, not this step.

## The fix

1. vercel.json: remove the 'crons' block (lines 6-11). pg_cron stays the one scheduler (D33, D263).
2. src/app/api/cron/subscription-reminders/route.ts:53-55: drop 'and Vercel Cron too where CRON_SECRET is set' from the comment.
3. Keep CRON_SECRET in src/server/cron-auth.ts: the e2e tests (e2e/support.spec.ts:68, e2e/cookie-scan.spec.ts) and triggerLook() use it.
4. docs/decisions.md: a short new decision that replaces D33's last sentence; docs/security.md:160 and 264 stay true.
