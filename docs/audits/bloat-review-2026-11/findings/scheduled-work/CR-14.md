# CR-14 ✓ Nothing limits or measures scheduled work, so each feature adds a poll

Scheduled and background work (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** no check. **Priority:** P1. **Effort:** S. **Confidence:** high. **Step:** 1.6.
- **Second check:** confirmed.
- **Where:** `src/server/cron-routes.scan.test.ts:43-48`, `docs/capacity.md:200-203`, `src/app/api/cron/cart-reminders/route.ts:94-116`, `src/server/cron-runs.ts:62-73`, `src/server/cron-runs.ts:139-149`, `src/app/admin/(gated)/platform/capacity/page.tsx:41`, `docs/audits/psi-followups.md:477`
- **Evidence:** The scan test asks only that a cron route has a maxDuration and is tracked. The written rule ('new heavy work gets a route of its own') has produced nine every-minute routes, from six on 24 October; each PSI audit since has noted it under PERF-10 and none stopped it. A new job is one line in runJobs() with no cadence, no due check and no reason. The ledger cannot show idle cost or growth: for the seven routes that work after answering it records 0 to 1 ms (the answer only), and for dispatcher jobs it records time spent waiting for one of five connections (sum 12.1 s against a 1.3 s run). No check asks whether a job's work is per store or set-based, which is how the loops of CR-3, CR-4, CR-6, CR-9, CR-15 and CR-16 got in. The dispatcher's description is one comment line of 4,212 characters in a 24 KB route file, repeated by the inline comments.
- **Cost today:** Unbounded growth: 83 jobs now, and nobody sees which ones will cost per store. An agent reading the dispatcher pays about 6,000 tokens for the file (estimate from 24,495 bytes). Paid by: Everyone later: the database, the server, and each agent session that opens these files.
- **Saving:** No direct saving; it keeps CR-1 to CR-4 from growing back and turns the next audit into a query instead of a code read.
- **Risk:** Low. The registry must not become a second place to forget: generate the runJobs() list from it. A job mislabelled 'set' hides a loop; the label is checked by review, not by the test.
- **Already tracked:** Partly: REL-06's open item (docs/audits/psi-followups.md:477) covers recording the after-answer routes' real work; PERF-10 in the PSI audits names the growth; no plan sets a cadence, a gate or a budget.
