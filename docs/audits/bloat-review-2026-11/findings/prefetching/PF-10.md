# PF-10 ✓ Nothing sets or checks what the router may fetch ahead

Prefetching: what the router asks for unasked (`README.md` beside this file), part of `docs/audits/bloat-review-2026-11.md`.

- **Kind:** no check. **Priority:** P1. **Effort:** M. **Confidence:** high. **Step:** 2.3.
- **Second check:** corrected.
- **Where:** `e2e/performance.spec.ts:118-175`, `e2e/a11y.ts:51`, `docs/performance.md:70-75`, `src/server/ratchet.scan.test.ts:1-60`, `src/server/ratchet.baseline.json`, `scripts/ratchet.mjs`
- **Evidence:** 943 of 947 links take Next's default; the four that set the prop do it to protect a file link, none for cost (re-counted here: 400 files import next/link, 335 of them in the admin). The speed budget counts bytes until two seconds after load at the top of a phone page (performance.spec.ts:152-155), so it sees 11 of the 47 router requests and holds no request count at all; its comment already notes a page that 'never reaches' network idle, and a11y.ts:51 swallows the same wait. The loop of PF-1 ran in CI unnoticed. docs/performance.md has no line on prefetching. The repo already has the tool for a rule that 400 files cannot meet at once: a ratchet whose counts may only fall (ratchet.scan.test.ts, ratchet.baseline.json, scripts/ratchet.mjs).
- **Cost today:** No direct cost; it is why PF-1 to PF-8 and PF-11 to PF-13 could grow unseen. Paid by: Everyone the other findings name.
- **Saving:** Keeps the gains of the other findings: phone home 47 to 3 router requests read to the footer, admin home 28 to 0 at rest (by subtraction from measured counts).
- **Risk:** Low. The ratchet stops new direct imports at once and lets the 400 files move as they are touched. A budget that is too tight fails on an honest change: the room and the comment are there for that.

## The fix

1. The wrappers exist after PF-3 and PF-5 (src/components/policy-link.tsx, src/components/block-link.tsx, src/components/admin/ui/link.tsx). State the policy per group in docs/performance.md, 'What the router fetches ahead'. view: the cart link on phones, a header menu's top links, product tiles (held by PF-13's ceiling), the site's sign-up button. intent: the logo, search, account, wishlist, the bottom bar, footers (menu, cookies, withdrawal, legal pages), menu sub-links, the phone menu, swatches, builder blocks, every admin link. none: languages and currencies, countries, links that leave their root layout, file links, the cart link from 768 px.
2. scripts/lib/ratchet-count.mjs: count per file the imports of next/link outside the three wrapper files and tests (directLinks). src/server/ratchet.baseline.json gains that map (400 files today); src/server/ratchet.scan.test.ts gains two cases in the style of its untypedReads cases: a file not in the baseline imports next/link not at all, and the baseline is lowered (node scripts/ratchet.mjs) when a file moves over.
3. e2e/prefetch.spec.ts: gather the cases of PF-1, PF-2, PF-3, PF-4, PF-7, PF-11, PF-12 and PF-13 under one table of budgets (page, screen, scroll, most router prefetch requests) and one helper; e2e/signed-in/prefetch.spec.ts holds PF-5's and PF-6's. A budget is the measured count with a little room, and its comment says a change that passes it is a regression to look at, not a number to raise (the wording of performance.spec.ts:118-125).
4. CLAUDE.md, Conventions: one bullet (for the owner to accept): a link says what it may fetch ahead through PolicyLink or AdminLink; next/link is imported only by them, and the ratchet and the request budgets hold it. The full rule goes under the same words in docs/rules/storefront.md and the admin frame's file in docs/rules/admin/.
