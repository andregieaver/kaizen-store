# Step 0.29: Let the listings' check record a try and read only reworded products

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The statements, recordTry()'s upsert and the four int cases are written out against the code as it is, but the step carries a migration and the candidate statements decide which listings the platform's DSA check ever reads, and an SQL slip could pass the cases the same model writes, so a stronger model should read the diff before the push. *(Rating checked twice, 12 November.)*

**Goal:** The listings' check records a try when the model's answer cannot be used and asks again a day later, stops a run at the first provider error, picks its candidates by the words' change marker without hashing every product, and reads no AI connection when there is nothing to check.

**Why:** Today every five minutes one statement sorts and hashes the words of every product on the platform, and a listing whose answer cannot be read is asked again on every run at the head of the queue: up to 2,880 AI calls a day on answers that cannot be read. After: a five-minute run hashes at most the 10 listings it picked, an unreadable listing costs 1 call a day, and the calls a day are at most the products created or reworded that day plus the notices plus 10.

**Closes:** [CR-15](../../findings/scheduled-work/CR-15.md). Each finding's file has the evidence.
