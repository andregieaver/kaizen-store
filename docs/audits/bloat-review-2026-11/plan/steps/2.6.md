# Step 2.6: Route every link through one wrapper with a stated policy

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Each edit is a named link getting a named policy and the request budgets catch a miss, but about thirty links in the store's and the site's chrome and an unknown number of admin files change, so a stronger model should read the diff before it is pushed.

**Goal:** Every storefront and site link in the header tools, bottom bar, footers and menus states what it may fetch ahead through PolicyLink (sight, intent or never), the policy per group is written in docs/performance.md, and a ratchet count directLinks lets direct imports of next/link only fall.

**Why:** Today 400 files import next/link directly, 947 links state no policy, the phone home makes 47 router prefetch requests read to the footer and the first Add to cart asks again for 32 links. After: at most 6 on the phone home, a product page, a content page and the cart, at most 10 after the first add, at most 8 on the home at 1280 px, and a new file that imports next/link fails pnpm test.

**Closes:** [PF-3](../../findings/prefetching/PF-3.md), [PF-8](../../findings/prefetching/PF-8.md), [PF-12](../../findings/prefetching/PF-12.md), [PF-10](../../findings/prefetching/PF-10.md). Each finding's file has the evidence.
