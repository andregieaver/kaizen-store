## The work

### Commit 1 of 3: The build prints its seconds and peak memory, on Vercel too

- **create** `scripts/lib/peak-memory.mjs`: Plain Node. Export readCgroupPeak(text): parses the text of /sys/fs/cgroup/memory.peak (a number of bytes and a newline) into a number, or null when it is empty or not a number. Export usedFromMeminfo(text): from the text of /proc/meminfo returns (MemTotal minus MemAvailable) in bytes (the file gives kB), or null when either line is missing. Export startPeakSampler({ everyMs = 2000 }): reads /proc/meminfo now as the base and then every 'everyMs', keeping the highest used figure; returns { stop() } where stop() ends the timer and returns { peakBytes: the highest used figure, baseBytes, source: 'meminfo' }; when /sys/fs/cgroup/memory.peak exists and parses, stop() returns that figure with source 'cgroup' instead. Where neither file exists (macOS, Windows) stop() returns { peakBytes: null }. Export formatGb(bytes): one decimal, 'GB'.
- **edit** `scripts/next-build.mjs`: Replace spawnSync with spawn from node:child_process (same command 'next', same arguments, same env with the 7 GB heap rule, stdio 'inherit', shell on win32). Before spawning: const started = Date.now(); const sampler = startPeakSampler(). On the child's 'close' event: stop the sampler, print exactly one line 'Build: <seconds> s, peak memory <x.x> GB (<source>)' (or 'peak memory not measured' when null), and when the environment variable GITHUB_STEP_SUMMARY is set append the same line to that file; when BUILD_REPORT is set write { seconds, peakBytes, source } as JSON to that path. Then process.exit(code ?? 1). Also handle the child's 'error' event (the command could not start): stop the sampler, print the same line and process.exit(1), so no path exits 0 without a successful build. The line is printed after a failed build too. On Vercel the line lands at the end of the build log.
- **create** `src/lib/peak-memory.test.ts`: Unit tests of the two pure parsers: '7730941132\n' gives 7730941132; '' gives null; a meminfo text with MemTotal 8000000 kB and MemAvailable 1500000 kB gives 6,656,000,000 bytes; a text without MemAvailable gives null; formatGb(7730941132) is '7.2 GB'.

### Commit 2 of 3: One recorder times every check, with ceilings, and pnpm check runs the pre-push rule through it

- **create** `scripts/timed.mjs`: Usage: node scripts/timed.mjs <label> [--warm-if=<path>] [--unit] [--playwright-report=<path>] -- <command...>. It runs the command with spawn (stdio inherit, except with --unit where stdout is piped and copied through so it can be read), measures wall seconds, and exits with the command's code. Order, so a failure can never turn green: when the command's code is not 0 (or it was killed by a signal, or spawn emitted 'error'), print the timing line, append it to the summary and the timings file, and exit with that code (1 for a signal or an error) at once, before any other check; the checks below run only after a successful command. It then: (1) labels the run 'warm' when --warm-if is given and that path existed before the command started, else 'cold' when the option was given, else no label; the ceiling key is '<label>' or '<label>:warm' / '<label>:cold'. (2) appends one Markdown table row to $GITHUB_STEP_SUMMARY when set (| label | warm or cold | seconds | ceiling |) and always prints the same as one plain line. (3) appends { label, key, seconds, sha: GITHUB_SHA, at } as a JSON line to the file named by TIMINGS_FILE when set (CI uploads it; the weekly check reads it). (4) fails (exit 1, after the command's own success) when seconds are over the key's ceiling in scripts/ci-budgets.json, with the line 'timed: <key> took <s> s, ceiling <c> s (scripts/ci-budgets.json): find what got slower, or raise the ceiling with a reason in the commit message'. A key with no ceiling yet prints 'no ceiling yet' and passes. (5) with --unit (the unit run): the caller adds '--reporter=default --reporter=json --outputFile=.vitest-report.json' to the vitest command; after the run, read that JSON: the files run are testResults[].name; compare them with the files on disk that match vitest.config.mts's include and exclude (src/**/*.test.ts, minus *.int.test.ts); a file on disk that did not run, or a file that ran and is not on disk, is printed with its path under 'Test files that did not run' in the summary and the plain output; in this step it never fails the run (no file list has been measured yet; a later step may make it fail). When .vitest-report.json is missing or not JSON, print 'timed: no vitest report' and pass. Parse the summary line vitest prints ('Duration 123.45s (transform 1s, setup 4.2s, ...)') from the piped stdout: when setup is over 10% of the whole duration, print 'timed: setup is N% of the unit run (limit 10%)' in the summary and the plain output; in this step it never fails the run (vitest's setup figure is summed over its workers and has never been measured against the wall time; no invented limit gates a deploy). (6) with --playwright-report=<path>: the caller sets PLAYWRIGHT_JSON_OUTPUT_NAME to that path; after the run read the JSON and list every test whose results have more than one entry and whose last status is 'passed': print them under 'Passed only on a retry' in the summary; this never fails the run. Export the pure parts (ceiling check, vitest duration parser, file comparison, retried-test finder) from scripts/lib/timed.mjs so they can be tested; scripts/timed.mjs is the thin command.
- **create** `scripts/lib/timed.mjs`: The pure functions named above: overCeiling(key, seconds, budgets), parseVitestDuration(stdoutText) returning { totalSeconds, setupSeconds } or null, filesDiffer(ranFiles, diskFiles) returning { notRun, notOnDisk }, retriedTests(playwrightJson) returning titles. Also ceilingProblems(budgets, medians): for each key with a median of ten runs, a problem when the ceiling is more than 25% above the median (10% for keys that end in ':memory'), and a problem when a key marked release: true has a ceiling over 600 seconds.
