# Step 2.5: Give crawlers on Next's bot list the cached page

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. One config property under a line that exists (cacheComponents, line 42), an e2e file whose six tests now name every address and text from existing specs, and two doc paragraphs; the manifest check, the curl and the crawler spec show at once whether Bingbot gets the cached page with its price and metadata, and it is one line to revert. *(Rating checked twice, 12 November.)*

**Goal:** Search and shopping crawlers on Next's bot list (Bing, Google's shop and ads fetchers, Apple, Yandex, Meta's catalogue) get the cached page like Googlebot does; only link-preview fetchers keep the blocking render.

**Why:** Today any user agent on Next's default list gets a full per-request render of every page, static ones included: /docs answers 'private, no-cache, no-store' to Bingbot and 'x-nextjs-cache: HIT' to a browser. After: Bingbot gets the HIT too.

**Closes:** [CA-15](../../findings/caching/CA-15.md). Each finding's file has the evidence.

### Commit 1 of 1: Crawlers on Next's bot list get the cached page; only link previews keep the blocking render

- **edit** `next.config.ts`: In the `nextConfig` object, directly under the line `cacheComponents: true,`, add the property `htmlLimitedBots: /facebookexternalhit|Twitterbot|LinkedInBot|Slackbot|Discordbot|WhatsApp|SkypeUriPreview|redditbot|quora link preview|vkShare|tumblr|bitlybot/i,` with this comment above it: `// Next renders every page per request, static ones included, for user agents on this list, so their metadata is in the head. Our prerendered pages already hold title and description in the head (scripts/render-modes.mjs checks it), so the list keeps only link-preview fetchers, which never run scripts and come once per shared link. Bing, Apple, Yandex, Google's shop and ads fetchers and Meta's catalogue then get the cached page, as Googlebot always has (bloat review step 2.5). Setting it replaces Next's default list (html-bots.js).` Change nothing else in the file.
- **create** `e2e/crawlers.spec.ts`: A Playwright file that uses only the `request` fixture (no browser page, so no scripts run). Constant `BING = "Mozilla/5.0 (compatible; bingbot/2.0; +http://www.bing.com/bingbot.htm)"`. Helper `read(request, path)` does `request.get(path, { headers: { "user-agent": BING } })`, expects status 200 and returns the body text. Test 1 `a crawler without scripts reads the home page`: for `/s/demo/no` expect the text to match `/<title>[^<]+<\/title>/`, `/<meta name="description" content="[^"]+"/`, `/<link rel="canonical" href="[^"]+"/` and `/<meta property="og:title" content="[^"]+"/`. Test 2 `... a product page`: `/s/demo/no/p/demo-keramikkopp`: the same four, plus the product's name `Demo: Keramikkopp` (e2e/smoke.spec.ts line 49 clicks that link name), plus a price (`/\d+[,.]\d{2}|\d+\s?kr/`), plus `application/ld+json` and, in the HTML, the text `"@type":"Product"` and `"price"` (allow escaped quotes: test with `/\\?"@type\\?":\\?"Product/`). Test 3 `... a category page`: `/s/demo/no/category/belysning` (e2e/terms.spec.ts line 24 opens it): the four head tags and the product name `Demo: Bordlampe`. Test 4 `... a blog article`: `/s/demo/no/blog/nye-produkter`: the four head tags and the article's title `Nye produkter i høst`. Test 5 `a crawler gets the cached page`: `request.get("/docs", { headers: { "user-agent": BING } })` has the response header `x-nextjs-cache` equal to `HIT` (retry once after a first request, which may be a MISS that fills the cache) and a `cache-control` that does not contain `no-store`. Test 6 `a link preview still gets its metadata in the head`: `/s/demo/no/p/demo-keramikkopp` with user agent `facebookexternalhit/1.1`: `<title>` and `og:title` come before `</head>` (compare `indexOf`).
- **edit** `docs/performance.md`: Under `## The rules` add a paragraph: which user agents get a blocking per-request render (the pattern in next.config.ts), why the default list was narrowed, that scripts/render-modes.mjs and e2e/crawlers.spec.ts hold what makes it safe, and that a crawler whose tool later shows a missing price or availability is put back on the list by adding its name to the pattern. Leave a line `Share of page runs by listed crawlers: to be measured after opening` for the after-deploy figure.
- **edit** `docs/rules/storefront.md`: In the rule that starts `The template store's product pages are prerendered at build time` (just above the cart's section) add the sentence: `A crawler that runs no scripts finds stock and add-to-cart at the end of the document in hidden containers, as Googlebot does; only link-preview fetchers get a blocking render (`htmlLimitedBots` in `next.config.ts`, `e2e/crawlers.spec.ts`).`
