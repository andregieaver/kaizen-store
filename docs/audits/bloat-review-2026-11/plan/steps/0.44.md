# Step 0.44: Give pictures in page content the 800 px copy

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every name is now step 0.33's real one (MEDIUM_COPY_WIDTH, pictureSources' medium, SizedPicture's medium, medium_url) and commits 2 and 3 are a pure module, a sizes string, an e2e case and docs, but commit 1 changes which file every page picture loads through the page reader, which one e2e case and unit tests only partly hold, so its diff wants a read. A smaller model may still do commits 2, 3 alone. *(Rating checked twice, 12 November.)*

**Goal:** A picture in page content (a picture component, a Before and after, a row's or a column's background picture) is offered the library's 800 px copy beside its 480 px and large files, and a picture in a column that stays beside others on a phone tells the browser its real share of the screen.

**Why:** After step 0.33 only product tiles and the gallery get the 800 px copy, so a full-width picture block on a 390 px 2x phone still takes the 1,600 px file (about 71 KB where 18 KB would do). After: that picture and a two-column picture at 390 px and 3x both draw the 800 px file.

**Closes:** GAP-code-s4. Each finding's file has the evidence.

### Commit 2 of 3: A picture in a column that stays beside others on a phone is sized by its share of the screen *(a smaller model may do this one alone)*

- **create** `src/lib/column-share.ts`: A pure module for the server (it imports the page model, so no client component may import it: src/lib/storefront-bundle.scan.test.ts forbids lib/page-content in visitors' scripts). Imports: ROW_LAYOUTS, columnLines, rowLayouts and the types PageRow and PageColumn from './page-content'; stackAt and valueAt from './responsive'. Export phoneShare(row: PageRow, column: PageColumn): number, the part of the row's width the column takes at the smallest screen size, between 0 and 1: return 1 when stackAt(row, 'sm') is true (columns are one under another); else find the line that holds the column: lines = columnLines(row), layouts = rowLayouts(row), i = the index of the line that includes a column with the same id; if none, return 1. widths = ROW_LAYOUTS[layouts[i]].widths. For each column c at position j of that line: w = valueAt(c, 'width', 'sm') ?? widths[j] ?? 1. If any w is 0 (a column as wide as what it holds) return 1. Return own / sum, where own is the w of the column asked for. A doc comment says: a hint for a picture's `sizes`, so 1 (the whole screen) is the safe answer whenever the share is not known.
- **create** `src/lib/column-share.test.ts`: Vitest unit test with hand-made rows (cast `as PageRow`, as src/lib/page-images-small.test.ts does).
