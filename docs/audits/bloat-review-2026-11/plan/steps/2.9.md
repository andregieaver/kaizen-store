# Step 2.9: Let each working route load its own parts

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. A character-for-character move of 42 switch cases into ten parts files, held by a scan test that now also checks every page passes its parts, but it touches the cart, checkout and order routes, nine page files and the pay-routes guard at once, so a stronger model should read the diff; commit 1 is a small split held by the type check and the cookie specs. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** Each working route (listing, cart, checkout, order, account, wishlist, subscription, deliveries, cookies, private) imports only the sections it draws, through a small parts module of its own on a shared frame; the search page imports none; and the cookie list no longer carries the consent manager.

**Why:** Today category, tag, search, cart, checkout, account, order, wishlist and cookies pages each load the same 54 client modules and 778,166 bytes of first scripts, 98 KB more than a built page, because RolePage imports one switch that imports every working page's sections. After: at most 650,000 bytes for a category, a tag, search, account, wishlist, order and cookies, at most 670,000 for the cart and the checkout, and at most 37 client modules on the listing routes.

**Closes:** [SC-2](../../findings/storefront-browser/SC-2.md), [BN-9](../../findings/client-bundles/BN-9.md), GAP-shopper-browser-s3. Each finding's file has the evidence.
