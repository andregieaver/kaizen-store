# Step 2.38: Use cached input

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Commit 1 (the append-only tool order, the time as the last line, and the reminder case with its argument check, all written out) is cheap-then-review work, but commit 2's cache marker depends on each provider's current reference and on a day of production figures, which the brief cannot settle. A smaller model may still do commit 3 alone. *(Rating checked twice, 12 November.)*

**Goal:** An AI manager round is built so its start never changes inside a turn and rarely between turns (fixed tool order, the time as the prompt's last line) and asks the provider to cache that start where the provider needs asking, so at least half of the input tokens are read from cache.

**Why:** No request asks for prompt caching and the prompt's second line carries the minute, so the cached share of input tokens is 0 today; a week after the change it is at least 0.5 over all AI manager rounds and at least 0.8 on rounds after a turn's first.

**Closes:** [AI-3](../../findings/ai-calls/AI-3.md). Each finding's file has the evidence.
