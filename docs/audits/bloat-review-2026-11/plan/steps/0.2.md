# Step 0.2: Store a daily reading of production, so every later step has a 'before'

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. A new table, two migrations and one SQL writer, fully specified and held by an int test, but it is a migration and a daily production job, so a stronger model should read the SQL and the migration before the push.

**Goal:** Once a day the daily cron route writes a dated reading of production's own statistics into the new platform table commerce.platform_readings (one row per commerce table, one per schema, at most 80 statement rows), kept 90 days.

**Why:** Today production's statistics are read by hand and no reading is kept: 0 stored days. After this step there is one reading a day, so step 0.23 and every later fix has a stored 'before' and 'after'.

**Closes:** . Each finding's file has the evidence.

- **create** `src/server/production-reading.ts`: Start with `import "server-only";` and import sql from drizzle-orm, db from @/db/client, log from ./log, col and typedRows from ./typed-rows. Export `const READING_KEEP_DAYS = 90` and `const READING_STATEMENTS = 40`. Export `async function recordProductionReading(now: Date = new Date()): Promise<{ tables: number; schemas: number; statements: number }>`. It runs inside one db().transaction: (1) `insert into commerce.platform_readings (day, kind, name, figures) select <day>::date, 'table', relname, jsonb_build_object('rows', n_live_tup, 'bytes', pg_total_relation_size(relid), 'seq_scan', seq_scan, 'seq_tup_read', seq_tup_read, 'idx_scan', coalesce(idx_scan, 0), 'inserted', n_tup_ins, 'updated', n_tup_upd, 'deleted', n_tup_del) from pg_stat_user_tables where schemaname = 'commerce' on conflict (day, kind, name) do nothing returning 1`; (2) the same shape for kind 'schema': `select n.nspname, jsonb_build_object('bytes', coalesce(sum(pg_total_relation_size(c.oid)), 0), 'tables', count(*)) from pg_class c join pg_namespace n on n.oid = c.relnamespace where c.relkind in ('r', 'm') and n.nspname not in ('pg_catalog', 'information_schema') and n.nspname not like 'pg_toast%' group by 1`; (3) statements, only where the view can be read: first `select n.nspname as schema from pg_extension e join pg_namespace n on n.oid = e.extnamespace where e.extname = 'pg_stat_statements'` (read through typedRows with { schema: col.text }); when no row comes back, skip step 3 and count 0; when one does, check the name matches /^[a-z_]+$/ and build the view's name with sql.raw(`${schema}.pg_stat_statements`). Then one insert: `with mine as (select s.queryid::text as id, s.calls, s.total_exec_time, s.mean_exec_time, s.rows, left(s.query, 2000) as query from <view> s where s.userid = (select oid from pg_roles where rolname = current_user) and s.queryid is not null), by_time as (select id from mine order by total_exec_time desc limit 40), by_calls as (select id from mine order by calls desc limit 40) insert into commerce.platform_readings (day, kind, name, figures, query) select <day>::date, 'statement', m.id, jsonb_build_object('calls', m.calls, 'total_ms', round(m.total_exec_time::numeric, 1), 'mean_ms', round(m.mean_exec_time::numeric, 3), 'rows', m.rows, 'top', case when m.id in (select id from by_time) and m.id in (select id from by_calls) then 'both' when m.id in (select id from by_time) then 'time' else 'calls' end), m.query from mine m where m.id in (select id from by_time union select id from by_calls) on conflict (day, kind, name) do nothing returning 1`. Wrap step 3 alone in a savepoint (tx.transaction(async (inner) => …)) with try/catch that logs `log("warn", "production_reading.statements_failed", {}, error)` and counts 0, so a database where the extension is installed but not loaded still gets its table and schema rows. <day> is now.toISOString().slice(0, 10). The 40 are the constant READING_STATEMENTS passed as a parameter. Return the three counts (rows returned by each insert). Also export `async function pruneProductionReadings(now: Date = new Date()): Promise<number>`: `delete from commerce.platform_readings where day < <day>::date - 90 returning 1`, in try/catch that logs `production_reading.prune_failed` and returns 0, exactly as pruneOwnSpeedSamples() in src/server/own-speed.ts does. No console.error anywhere.

## Do not

- Do not apply the migration to production by hand or with a Supabase tool: CI applies it.
- Do not add a store_id column, a screen, a flag or a briefing line: step 1.13 does those.
- Do not store a statement's text beyond 2,000 characters, and do not read pg_stat_activity (it holds live values).
- Do not put the reading inside the route's big Promise.all or let a failure of the reading fail the route: it is its own tracked() job.
- Do not use a plain `set statement_timeout`; the reading needs no longer timeout (it reads statistics views only).
- Do not reset pg_stat_statements or any statistics.
- Do not hand-edit the generated migration or a baseline file, and do not rename an existing column or table.
