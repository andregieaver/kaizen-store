# Step 0.14: End the prefetch loop on /s/ addresses, and write both router settings down

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. Two config lines with their exact place, one text test and one spec whose addresses and thresholds are fixed; a wrong or useless flag fails the type check, the build-warning grep or the spec, and nothing touches money, sign-in or data. *(Rating checked twice, 12 November.)*

**Goal:** A store page opened at an /s/{store} address stops asking the server for router prefetches a few seconds after load, and next.config.ts states both router settings (optimisticRouting: false, partialPrefetching: false) with their reasons.

**Why:** Today the search page at /s/demo/no/search?q=lampe makes 624 router prefetch requests in 4 s and never stops (about 165 a second reach the server); with route guessing off it makes about 55 and goes quiet. The build also prints a partialPrefetching warning on every build and start; after this step it prints none.

**Closes:** [PF-1](../../findings/prefetching/PF-1.md), [SC-9](../../findings/storefront-browser/SC-9.md), [CA-6](../../findings/caching/CA-6.md), [CA-7](../../findings/caching/CA-7.md). Each finding's file has the evidence.
