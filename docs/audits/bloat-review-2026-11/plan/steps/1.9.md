## The work

### Commit 1 of 3: A statement counter in the database client, off unless asked

- **create** `src/db/statement-count.ts`: A module with no import but node:async_hooks (it must not import 'server-only', React, drizzle or pg, so tests and scripts can load it; performance is the global). Export type StatementRecord = { text: string; values: unknown[]; rows: number | null; ms: number; startedAt: number; control: boolean }: startedAt is performance.now() when the statement was handed to the driver, ms is performance.now() - startedAt when its answer (or error) came, and control is true for a statement whose trimmed lower-case text starts with 'begin', 'commit', 'rollback', 'savepoint', 'release' or 'set local'. Keep one module-level `const store = new AsyncLocalStorage<{ statements: StatementRecord[] }>()` and one module-level `let renderCounter: (() => { statements: number } | null) | null = null`. Exports, exactly these six: (1) `setRenderCounter(get: (() => { statements: number } | null) | null): void` sets renderCounter (src/server/render-count.ts calls it once, commit 3; this file stays free of React). (2) `countStatements<T>(run: () => Promise<T>): Promise<{ result: T; statements: StatementRecord[]; count: number; ms: number }>`: runs `run` inside `store.run({ statements: [] }, …)` and returns the records, count = the number of records whose control is false, ms = the time the whole run took. (3) `noteStatement(text: string, values: unknown[]): ((rows: number | null) => void) | null`, in this order: if renderCounter is set, call it and, when it returns an object, add 1 to its statements; then `const s = store.getStore(); if (!s) return null;` (no record, no allocation: this is the path of every production query outside a test); otherwise push a record { text, values, rows: null, ms: 0, startedAt: performance.now(), control } and return a function done(rows) that sets the record's rows and ms (a second call does nothing). (4) `waves(records: StatementRecord[]): number`: leave out control records, sort the rest by startedAt, and count 1 for the first and 1 more for each record whose startedAt is at or after the largest startedAt + ms of all records before it (a statement that starts after every earlier one has answered begins a new wave: sequential reads are a wave each, a Promise.all is one wave); 0 for no records. (5) `sameStatementTwice(records: StatementRecord[]): string[]`: the texts that appear twice or more with JSON-equal values (control records left out), for later budgets. (6) the type. There is no statementsOf() and no WeakMap. Every function body is wrapped in try/catch so that a failure inside the counter returns null (noteStatement), [] or 0 and never fails a query; countStatements rethrows only what `run` throws.
- **edit** `src/db/client.ts`: In create(), after 'pool.on("error", () => {});', add `pool.on("connect", (client) => { … })` that replaces client.query once per client (mark it, e.g. a symbol property, so a client is never wrapped twice). The wrapper is a plain function (not an arrow) so it keeps `this`, takes `(...args)`, and: reads the text (args[0] when it is a string, else args[0]?.text) and the values (args[0]?.values when args[0] is an object with values, else args[1] when it is an array, else []); calls noteStatement(text, values) from './statement-count'. When noteStatement returned null: `return original.apply(this, args)` untouched. When args[0] has a function `submit` (a Submittable such as a cursor): call done(null) and return original.apply(this, args). When the last argument is a function (pg-pool's pool.query, which drizzle uses for every statement outside a transaction, ALWAYS calls client.query(text, values, callback): node_modules pg-pool index.js line 467): replace that last argument by `(err, res) => { done(err ? null : (res?.rowCount ?? res?.rows?.length ?? null)); return cb(err, res); }` and return original.apply(this, newArgs). Otherwise (the promise form, used inside transactions): `const result = original.apply(this, args);` attach `result.then((r) => done(r?.rowCount ?? r?.rows?.length ?? null), () => done(null));` as a separate branch and return `result` itself (not the branch; add no await). Both pools get it, because create() makes the primary and the replica. Change nothing else in this file: withRows(), db(), replicaDb(), readDb(), longerTimeout() and closeDb() stay as they are.
- **create** `src/db/statement-count.int.test.ts`: An integration test (it runs with pnpm test:int against DATABASE_URL). Cases: (1) outside countStatements nothing is recorded: run db().execute(sql`select 1`) and assert noteStatement('x', []) returns null. (2) inside countStatements, two db().execute calls give count 2, and each record has the statement's text, its values (select ${7}::int gives values [7]) and rows 1. (3) a db().transaction with one insert into a temp table and one select gives count 2 and two control records (begin, commit). (4) two countStatements running at once (Promise.all) do not see each other's statements. (5) the same select sent twice with the same value is reported by sameStatementTwice(). (6) a statement that fails (select 1/0) is recorded with rows null and the error still reaches the caller. (7) waves(): two awaited selects one after the other give waves 2, and the same two in one Promise.all give waves 1 (run each inside countStatements after one warm-up statement, so the pool has its connections). (8) with setRenderCounter(() => box) where box = { statements: 0 }, two db().execute calls outside countStatements raise box.statements to 2; reset with setRenderCounter(null) in a finally. Every record of cases 2 and 7 has ms above 0 (the callback path fills it).

## Do not

- Do not log a statement's text or values anywhere in production code: the record lives in memory inside countStatements() and is read by tests. The log line has statements and ms only.
- Do not add an await or a try/catch that swallows errors around the real query: the wrapper returns the driver's own promise.
- Do not wrap pool.query as well as client.query: pool.query calls client.query inside, so a statement would count twice.
- Do not call requireMemberAny(), requirePermission() or requirePlatformReader() from the int test, and do not add a bypass to sign-in for it.
- Do not lower a baseline figure by removing a read in this step: this step counts; steps 0.17, 2.32 and 2.33 cut.
- Do not keep the same number in a second test: steps 1.10, 1.11, 1.12 and 1.25 use this counter for their own figures.

## Stop and report if

- A figure of the five differs between two runs on the same database: say which statements differ (print the two records) and stop; do not add a margin.
- Moving a screen's reads into src/server/admin-screens.ts changes its rendered output or a signed-in e2e spec.
- pool.on('connect') does not fire for the clients drizzle uses (case 2 of statement-count.int.test.ts counts 0): report it; do not patch drizzle.
- An existing integration test fails after commit 1.
- A wave figure differs between runs while the statement count does not (the pool of 5 connections queued part of a Promise.all): report the two records; do not change waves() or add a margin.
