# Step 1.13: Flag in production what a test cannot see in the database

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The rules, the reader and the screen are fully specified against step 0.2's table, but the change widens a check by migration, edits the daily job and the morning briefing and adds words in two languages, so a stronger model reads the diff before the push.

**Goal:** Platform, Usage and limits shows the day's difference between the two latest stored readings of production and raises eight flags from them, each flag is also a line in the platform's morning briefing, and each has a seeded case in an integration test.

**Why:** A test cannot see production: 564 MB of scheduler log, 13 unused duplicate indexes and a job that refreshed a tag on every run were found only by this review reading statistics by hand. After this step eight written rules read the stored daily reading and say so on one screen and in the morning email.

**Closes:** GAP-database-1, GAP-database-s5. Each finding's file has the evidence.

## The work

### Commit 1 of 3: Database flags: eight rules over two daily readings, as pure code with a test each

- **create** `src/lib/platform-flags.ts`: Pure: no import of server code, zod or the database. Types: StatementReading = { key: string (the statement's id in the reading: its queryid, or a hash of its text), text: string, calls: number, totalMs: number, meanMs: number, rows: number }; TableReading = { name: string, rows: number, bytes: number, seqScans: number, seqRowsRead: number }; IndexReading = { table: string, name: string, scans: number, backsConstraint: boolean }; JobReading = { job: string, runs: number, worked: number | null }; AiReading = { feature: string, figure: string, value: number, bar: number, daysOver: number }; DailyReading = { day: string, statements: StatementReading[] (the 40 costliest and the 40 most called, without repeats), tables: TableReading[], schemas: { name: string, bytes: number }[], indexes: IndexReading[], jobs: JobReading[], ai: AiReading[] }. Export the two written lists as constants with a reason per entry: WHOLE_READ_ALLOWED: at most 5 { table, reason } entries (start empty) and COSTLY_ALLOWED: { key, reason, ceilingMs }[] (start empty; at most 3 when the plan ends: a comment says so). Export HOT_TABLES = ['orders','order_lines','visits','products','product_variants','customers','carts','cart_lines'] (CLAUDE.md's list). Export type PlatformFlag = { id: FlagId, subject: string, values: Record<string, string | number> } and FLAG_IDS = ['new_top_statement','whole_table_read','idle_write','cron_schema_large','unused_hot_index','costly_statement','idle_route_calls','ai_over_bar']. Export platformFlags(today: DailyReading, yesterday: DailyReading, options: { openedOn: string | null, cronSchemaMaxBytes: number (default 80 MB; step 3.1 lowers it to 20 MB), idleCallsOn: boolean (default false; step 3.2 switches it on) }): PlatformFlag[]. The day's difference of a counter is today's value minus yesterday's, and 0 when negative (the statistics were reset). Rules: (1) new_top_statement: a statement among today's 25 highest by calls-difference whose key is not in yesterday's reading at all. (2) whole_table_read: a table with rows over 500 whose seqScans difference is over 10, unless WHOLE_READ_ALLOWED names it. (3) idle_write: a statement whose text starts with update, delete or insert (case-insensitive, after trimming), with a calls-difference of at least 10, whose rows-difference is under one tenth of its calls-difference. (4) cron_schema_large: the schema 'cron' over options.cronSchemaMaxBytes. (5) unused_hot_index: only when options.openedOn is at least 56 days before today.day: an index on a HOT_TABLES table with scans 0 today and backsConstraint false. (6) costly_statement: a statement among today's 40 highest by totalMs-difference with a calls-difference over 10 and (totalMs-difference divided by calls-difference) over 5, unless COSTLY_ALLOWED names its key and its mean is at or under that entry's ceilingMs. (7) idle_route_calls: only when options.idleCallsOn: the sum over jobs whose name starts with 'route.' of (runs-difference minus worked-difference) over 1,100. (8) ai_over_bar: an AiReading with value over bar and daysOver at least 7. Export dayDifference(today, yesterday): the rows the screen shows: per schema the bytes change, the 10 statements with the largest totalMs-difference, the 10 tables with the largest seqRowsRead-difference.
- **create** `src/lib/platform-flags.test.ts`: One test per rule with a small hand-made pair of readings, each with the case that raises the flag and the nearest case that does not: an 8 ms statement run 20 times raises costly_statement and the same at 4 ms does not; a 600-row table scanned 20 times raises whole_table_read, 400 rows does not, and the same table named in an allowed list passed as a parameter does not; an update called 100 times that changed 5 rows raises idle_write and one that changed 50 does not; a statement new among the top 25 raises new_top_statement; the cron schema at 81 MB raises, at 79 MB not, and at 21 MB with cronSchemaMaxBytes 20 MB raises; an unused index on orders raises only when openedOn is 56 days or more before and it backs no constraint; 1,200 idle route calls raise only with idleCallsOn; an AI figure over its bar for 7 days raises and for 6 does not. One test that a counter that went down (a reset) gives a difference of 0 and no flag. One test that WHOLE_READ_ALLOWED has at most 5 entries and COSTLY_ALLOWED at most 3, each with a reason of at least 20 characters.

## Do not

- Do not query pg_stat_statements, pg_stat_user_tables or any statistics view when the screen is opened: the screen reads the stored readings only.
- Do not store or show a statement's values: Postgres has already replaced them in the reading; show the text as stored.
- Do not add an entry to WHOLE_READ_ALLOWED or COSTLY_ALLOWED to quiet a flag in this step; both start empty.
- Do not email flags on their own: they ride in the existing morning briefing, which the platform's owners switch on themselves.
- Do not use a paid log or monitoring service; everything is read from the database's own tables.
- Do not rename or drop a column of commerce.platform_readings, and do not remove an allowed kind from its check.
