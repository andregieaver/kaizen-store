# Step 0.34: Give the admin's colour names a value on public pages

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The renames, the CSS block (now at specificity 0) and the scan's three rules are given whole and the scan and the /report and /status e2e check catch a miss, but it is a visible colour change on every public page judged partly from screenshots and the scan's import walk is easy to write subtly wrong yet pass its planted cases, so a stronger model reads the diff and the screenshots. *(Rating checked twice, 12 November.)*

**Goal:** No shop or site file names an admin colour class, every admin colour that an admin part drawn on a public page reads has a value outside the admin in light and in dark, and the main button on Kaizena Flow's status and report pages is filled.

**Why:** Thirteen admin colour roles have a value only under html[data-admin], yet 20 uses in seven shop and site files and 125 in eleven admin parts drawn on public pages read them: the submit button on /status and /report has a see-through background today. After: 0 uses in shop and site files (20 today), every role those parts name has a value under html:not([data-admin]), and the buttons have a computed background-color other than rgba(0, 0, 0, 0).

**Closes:** [CS-7](../../findings/styles/CS-7.md), [CS-9](../../findings/styles/CS-9.md), GAP-styles-s1. Each finding's file has the evidence.
