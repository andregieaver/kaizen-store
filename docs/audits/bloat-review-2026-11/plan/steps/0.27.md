# Step 0.27: Let the knowledge job read no document when nothing was published

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The design and SQL are now fixed (the test assertions sit in the commit that makes them true, the wordless-page rule no longer re-upserts, the idle test has no fallback), but the step adds a table and a fill migration CI applies to production and rewrites when the chat's passages and their paid vectors are cut again, where a wrong stale expression passes the few int cases, so a stronger model should read both diffs. *(Rating checked twice, 12 November.)*

**Goal:** The five-minute knowledge job sends one statement when no site has anything new to cut, fetches a page's document only when that page must be cut, and cuts a wordless page once instead of every five minutes.

**Why:** Today the job reads about 40 whole published documents a call every five minutes and re-cuts every page that has no words on every run: 91,200 empty transactions in 78 days (about 1,170 a day). After: an idle run is 1 statement over all sites and 0 documents, and the delete of a page's passages runs only when a page was published.

**Closes:** [DQ-6](../../findings/queries/DQ-6.md), [DS-5](../../findings/database-shape/DS-5.md), [PM-3](../../findings/page-builder-model/PM-3.md). Each finding's file has the evidence.
