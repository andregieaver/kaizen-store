# Step 2.4: Serve store pages with nothing per visitor as static files, and let Add to cart answer a number

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Commits 1 and 2 are now written out to the import and the key, but they move every store page from per-request to static and three per-visitor reads to the browser, and commit 3 still needs the judgement of which add forms must redraw (basket notes in store parts and product parts, the cart's upsells), which the brief frames but cannot remove; only commit 4, deleting the old route a deploy later, is the cheap model's alone. A smaller model may still do commit 4 alone. *(Rating checked twice, 12 November.)*

**Goal:** A store page with nothing per visitor (home, built pages, blog, info pages) is served as a static file; the cart count, the saved products and the country hint come from one small call, /api/shop/mine, asked only when a marker cookie or a several-country store calls for it; and Add to cart answers the new count without redrawing the page.

**Why:** Today 148 of 149 prerendered store routes are 'resuming' (a render function runs on every view, 97,919 of /s/demo/no's bytes come from it) and one Add to cart makes 16 requests and 193 KB. After: /s/demo/no, /s/demo/no/om-oss and the blog routes are 'static', and one Add to cart is 1 request with an answer under 5,000 bytes.

**Closes:** [CA-1](../../findings/caching/CA-1.md), [CA-17](../../findings/caching/CA-17.md). Each finding's file has the evidence.
