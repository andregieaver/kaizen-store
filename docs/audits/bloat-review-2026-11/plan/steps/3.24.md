# Step 3.24: The product-words sweep reads no product when no text changed

Phase 3 (One of each) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. After the edits every statement, clause and test case is written out, but a reviewer should read the probe's SQL against step 3.3's record() as built and check the store_is_active() join and the baseline diff. *(Rating checked twice, 12 November; first written as strong.)*

**Goal:** The product-words sweep (embeddings) asks first, with one index probe on product_translations.text_changed_at (step 0.28's mark), whether any product text changed since its previous run began or that run left work behind or threw; when not, and outside the daily full check at 03 UTC, an idle tick reads no product, translation, variant or AI provider.

**Why:** The hourly embeddings sweep reads every active store's products, translations and terms to compare hashes even when no text changed, 24 full reads a day when nothing changed (it reads no variant). After the step an idle run is one statement, a changed text or a backlog is embedded on the next run, and a change to a product's categories or tags is caught by the daily full check.

**Closes:** no finding on its own. Split out of step 3.6 on 12 November. The findings close when the steps of the split are Done.

At its top, before `aiFor(null, ...)`, write `const now = options.now ?? new Date(); const full = options.full ?? now.getUTCHours() === 3;` and, when full is false, send one statement read with `typedRow(z.object({ changed: col.bool }), sql\`...\`)` (import z from 'zod' and typedRow and col from './typed-rows' where the file lacks them): `select exists (select 1 from commerce.product_translations t where t.text_changed_at > coalesce(j.last_started_at, '-infinity'::timestamptz)) or coalesce(j.last_worked_at >= j.last_started_at, false) or coalesce(j.last_error_at >= j.last_started_at, false) as changed from (select 1) as one left join commerce.cron_jobs j on j.job = 'dispatcher.embeddings'`. When changed is not true, return { embedded: 0, failed: 0 } and send nothing else (no aiFor, no ai_providers read, no staleTranslations). Why each clause holds (put this in the function's doc comment, shortened): the ledger row is written when a run finishes (record() in src/server/cron-runs.ts), so while this run reads it, it holds the previous run. (1) last_started_at is when that run began, so a text changed while it ran is newer and is not missed; with no row yet, '-infinity' makes any translation count. (2) step 3.3 sets last_worked_at to the finish time only when workedOf() found embedded or failed above 0, so last_worked_at >= last_started_at means the previous run embedded something (it may have left more than PER_RUN, 256 per AI) or failed at the provider (embedWith() returns failed instead of throwing): the sweep reads on until one run embeds nothing and fails nothing, and stops after that run. (3) last_error_at >= last_started_at means the previous run threw (a statement timeout, a database error): record() still wrote its last_started_at, so without this clause a text changed before that run would wait for the 03 UTC net. A new translation gets now() from the column's default, so it counts as changed. Also write in the doc comment what the probe does not see and the full run at UTC hour 3 catches (at most a day late, then 256 per AI an hour through clause 2): a category or tag added to, removed from or renamed on a product (commerce.product_terms and commerce.terms, the third input of the hash in staleTranslations()); a product's status changed by a path that does not call refreshStoreEmbeddings() (the savers in the file's top comment do); a store that becomes active; a changed embedding model or provider (commerce.ai_providers has no timestamp: meaning search finds nothing for those stores until the net re-embeds them, keyword search goes on); and a save whose transaction began before a run started and committed after its probe (text_changed_at is the transaction's now()).
