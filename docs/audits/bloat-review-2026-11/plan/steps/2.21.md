# Step 2.21: Read a page without importing the code that saves pages

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. The first two commits are mechanical moves the cheap model can do, but the last one means reading import paths from the renderer and choosing where to cut each, which the brief cannot list before the earlier steps have changed the graph.

**Goal:** The reads of published pages live in src/server/page-reads.ts, which imports only the database client, the tag leaf, the page model and the media library's alt texts; src/server/pages.ts keeps the writers and re-exports the reads; the files that only read import the new module; and the graph test forbids the reader and the page renderer the code for saving, designing and AI-writing pages.

**Why:** Today reading a page imports src/server/pages.ts, which reaches 1,307 modules and 20.5 MB of source (savePage, the checker, fonts, audit, redirects), and the page renderer reaches 1,396. After: page-reads.ts reaches 130 modules or fewer with no path to pages.ts, and page-article.tsx reaches none of pages.ts, design-presets.ts, page-ai.ts or src/lib/signature.

**Closes:** [PM-12](../../findings/page-builder-model/PM-12.md). Each finding's file has the evidence.
