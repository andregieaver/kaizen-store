# Step 3.7: Call the PDF route when a document waits

Phase 3 (One of each) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The edits are small and named, but one commit replaces the SQL function every scheduled route depends on, so a stronger model should read that migration before it is pushed.

**Goal:** The one-minute tick of step 3.1 calls /api/cron/document-pdfs when an invoice or credit note waits for its PDF, the route is tracked and out of NOT_SCHEDULED, a copied AI picture keeps its mark, and the finished AI-picture-marks backfill is retired.

**Why:** Today nothing calls the PDF route (a 102 MB function with Chromium), so the owner's 'Try again' sentence ('tried again within a few minutes') is not true and a missing PDF is made only on first download. After: a waiting document gets its PDF within two ticks, and the dispatcher runs one job fewer (aiPictureMarks).

**Decided by the owner (12 November, the recommended way):** Made ahead by the scheduled job, as recommended: the tick calls the PDF route when a document waits, so 'Try again' is true. The route and its function stay.

**Closes:** [CR-11](../../findings/scheduled-work/CR-11.md), [DD-12](../../findings/unused-code/DD-12.md). Each finding's file has the evidence.
