# Step 0.39: Let a test load only what it uses

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Commits 1, 3 and 4 are now exact (the config verbatim, every deleted case named, the three re-pointed cases written out and checked against the live migrations, a fixed rule for a slow optimizer), but commit 2 asks the model to repair tests that fail only in a shared worker, where moving files or blanket resets is the tempting shortcut and a weakened test passes every check, so its diff, and commit 4's deletions, need a reader. A smaller model may still do commits 1, 3, 4 alone. *(Rating checked twice, 12 November.)*

**Goal:** A unit test file loads only what it uses: the admin's English only where parts are drawn, the test database only where it is opened, plain files share a worker, Drizzle is pre-bundled for the tests, and no test replays or quotes the 789 archived migrations.

**Why:** Today every one of 1,215 unit files loads all the admin's English (93 modules, 1.9 MB) in a fresh worker though 91% cannot use it: setup is 40% of Vitest's duration and a plain file costs 0.48 s; each file that opens the database client spends 0.48 s importing Drizzle; one test replays all 789 archived migrations on every run and 17 files quote them. After: setup under 10%, a plain file at 0.15 s or less, the client's import at 0.10 s or less, and 0 test files reading the archive.

**Closes:** [TC-3](../../findings/tests-ci-build/TC-3.md), [TC-13](../../findings/tests-ci-build/TC-13.md), [DD-13](../../findings/unused-code/DD-13.md), [DD-10](../../findings/unused-code/DD-10.md). Each finding's file has the evidence.
