# Step 2.43: Add a related test run for the push

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The renames and scripts are mechanical, but the commit that edits ci.yml changes what holds back a production deploy, so a stronger model should read that diff before it is pushed.

**Goal:** `pnpm test:changed` runs only the unit tests a change can reach plus every `*.scan.test.ts` file, the pre-push rule in CLAUDE.md is lint, the type check and `pnpm test:changed`, the deploy gate runs the same related tests after its three steps, and `pnpm check` runs that rule through the recorder.

**Why:** Today a session spends 11 to 12 minutes of machine time before each push (lint about 3 min, the type check about 3 min, 1,215 unit test files in 5 min 34 s). After this step a one-line change in src/lib runs fewer than 250 test files and `pnpm check` takes 5 min 30 s or less cold and 2 minutes or less on a second run, while the gate checks more than today's six money files.

**Decided by the owner (12 November, the recommended way):** The way the panel suggests in the build's card. Before a push a session runs lint, the type check and the tests the change can reach (about 2 minutes); the deploy gate runs the same related tests after its three steps (about 2.5 to 3 minutes in all), and the whole unit suite keeps running beside the deploy and reports, as today. It is the cheapest to run, the gate checks more than today's six money files, and going back is one sentence in CLAUDE.md and one line in ci.yml.

**Closes:** [TC-6](../../findings/tests-ci-build/TC-6.md), GAP-build-s4. Each finding's file has the evidence.

### Commit 2 of 5: pnpm test:changed: the tests a change can reach, and every scan test

- **create** `scripts/lib/test-changed.mjs`: A pure module, no imports but node:path. Export `WHOLE_SUITE_PATHS`, an array of regular expressions: /^package\.json$/, /^pnpm-lock\.yaml$/, /^vitest.*\.config\.mts$/, /^tsconfig.*\.json$/, /^src\/test\//, /^test\//, /^supabase\// . Export `testPlan(changedFiles)` (an array of repo-relative paths): returns 'whole' when the argument is null (the reference could not be read) or when any path matches one of WHOLE_SUITE_PATHS, otherwise 'related'. The reason for supabase/: the database tests replay the migration files from disk and import none of them, so the import graph cannot see that change.
- **create** `scripts/test-changed.mjs`: A Node script (ES module, node:child_process spawnSync with stdio 'inherit', shell false). Argument 1 is a git reference, default `origin/main`. Steps: (1) run `git rev-parse --verify --quiet <ref>^{commit}`; if it fails, print 'test:changed: <ref> is not in this clone, running the whole unit suite' and run `pnpm exec vitest run`, exit with its status. (2) Otherwise collect the changed files: the union of `git diff --name-only <ref>...HEAD`, `git diff --name-only --cached` and `git diff --name-only` (lines, trimmed, no blanks). If the three-dot diff fails (no merge base in a shallow clone), treat it as step 1 does. (3) Call testPlan() from ./lib/test-changed.mjs. If 'whole': print which path caused it and run `pnpm exec vitest run`. If 'related': run `pnpm exec vitest run --changed <ref> --passWithNoTests`, and if it exits 0 run `pnpm exec vitest run .scan.test.` (Vitest's file filter is a substring of the path, so this runs every *.scan.test.ts in every project). Exit non-zero if either run failed. Print one last line: `test:changed: related run, then scans` or `test:changed: whole suite`. Do not parse Vitest's output.
- **edit** `package.json`: In "scripts", add after "test:smoke": `"test:changed": "node scripts/test-changed.mjs"`. Keep "test", "test:smoke" and every other script as they are.
- **create** `src/lib/test-changed.scan.test.ts`: Imports testPlan and WHOLE_SUITE_PATHS from ../../scripts/lib/test-changed.mjs (src/lib/await-deploy.test.ts shows how a test imports a script's module). ## Do not

- Do not remove `pnpm test` from the `static` job, and do not remove the money tests step or the `test:smoke` script: the whole suite must keep running beside the deploy.
- Do not edit the body of a renamed test to make it pass, and do not rename *.int.test.ts files.

- Do not use `--changed` without a reference in CI, and do not set fetch-depth: 0 on every job.
- Do not add a paid CI service or a larger runner.
