# Step 0.9: Take Supabase's client, zod and the builder's English off every signed-in screen

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every edit is a move or an import change and the build's marker counts prove the result, but it changes when the admin's session client loads and how nine uploads reach Storage, which no e2e covers, so a stronger model should read the diff and someone must do the upload checks by hand.

**Goal:** A plain signed-in admin screen's first scripts hold no Supabase client, no zod, no page-builder English and no sign-in English, and the admin layout no longer hands every screen the 'setup' words.

**Why:** Today three stray imports put 481 KB on 432 of 449 admin routes: /admin/[store] loads 1,194,862 bytes of first scripts and the median admin route 1,152,953. After: /admin/[store] at or under 700,000 bytes and the median at or under 645,000.

**Closes:** [AC-1](../../findings/admin-browser/AC-1.md), [BN-1](../../findings/client-bundles/BN-1.md), [BN-3](../../findings/client-bundles/BN-3.md), [BN-4](../../findings/client-bundles/BN-4.md), [DP-4](../../findings/dependencies/DP-4.md), [TX-4](../../findings/interface-text/TX-4.md), GAP-owner-browser-s4, GAP-text-s6. Each finding's file has the evidence.
