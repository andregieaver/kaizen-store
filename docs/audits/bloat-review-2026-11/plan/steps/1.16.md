# Step 1.16: Show cold starts as a production figure

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. A new table, an edit to the proxy and to the store layout's per-request part: each small, but a wrong placement changes render modes or cold-load weight, so a stronger model reads the diff.

**Goal:** Each server instance records its cold start once (the kind of entry, milliseconds to the end of register() and to the first answer, resident memory and the bytes of translated text read at start), as one log line and one row, and Platform, Usage and limits shows cold starts a day with the median and the 95th percentile by kind against three lines.

**Why:** No production figure exists for a cold start: the review's 0.84 to 1.3 s for a fat entry is one machine's. After this step production shows, per kind of entry, how many cold starts a day and how long each took, against the targets (the proxy within 150 ms of the health check, a store page within 400 ms, an admin page within 600 ms).

**Closes:** GAP-server-3. Each finding's file has the evidence.

### Commit 2 of 3: Each instance logs and stores its cold start once

- **create** `src/lib/instance-start.ts`: Pure, no import. The 'later' argument is how the caller runs work after its answer: a route handler or a server component passes Next's after, the proxy passes (work) => event.waitUntil(work()). ## Do not

- Do not pass the request, its headers, its path, a store or an account to noteFirstRequest() or into the log line.
- Do not import the database client statically in src/server/instance-start.ts: the beacons and the proxy import this file.
- Do not add cookies(), headers() or connection() to a layout to make a place for the call: that would move every page under it to per-request.
- Do not use a log drain, Observability Plus or any paid service to read the figures back.
- Do not time anything on later requests: one boolean test, then return.
- Do not write the migration's SQL by hand, edit a baseline file or apply the migration to production yourself.
