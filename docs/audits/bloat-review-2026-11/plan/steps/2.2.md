# Step 2.2: Send the store's layout once

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Commits 1, 2 and 4 are small and held by tests; commit 3 is now fully listed (the move commands, the alias one-liner and eleven exact path edits in tests that throw on a missing path), but it moves every storefront route including cart, checkout and the pay routes, so its diff and the whole e2e run want a read before the push. A smaller model may still do commits 1, 2, 4 alone. *(Rating checked twice, 12 November.)*

**Goal:** Every storefront document carries the store's layout once: the cart drawer's slot sits in a (shop) route group one level under the market layout, the cart count is read once per render, and from 768 px the header's cart link is a plain link to the cart page.

**Why:** Today /s/demo/no is 138,523 bytes raw with two html elements in its inline payload and 26,534 bytes of duplicate rows, because a parallel slot on a root layout makes Next draw the layout a second time as a not-found fallback. After: one html element, under 2,000 duplicate bytes, under 112,000 bytes, and at 1280 px a cart press is one document request with no router request.

**Closes:** [SC-8](../../findings/storefront-browser/SC-8.md), [PL-2](../../findings/page-payload/PL-2.md), [PM-1](../../findings/page-builder-model/PM-1.md), [CS-5](../../findings/styles/CS-5.md), [SC-7](../../findings/storefront-browser/SC-7.md), [PF-7](../../findings/prefetching/PF-7.md), GAP-page-model-s6.
