### Commit 1 of 1: Count handed against named words at every hand-down site of the admin

- **create** `src/components/admin/admin-words-handed.scan.test.ts`: Vitest. It reads sources with node:fs and imports `adminText` from `@/lib/admin-text` and `ADMIN_LANGS` from `@/lib/admin-lang` (add `vi.mock("server-only", () => ({}))` first if the import needs it). If step 0.1 has put the review's script at docs/audits/bloat-review-2026-11/scripts/handed.mjs, read it for the idea; this test needs none of its helper files. (A) The import graph. Copy `IMPORT`, `typesOnly`, `resolve`, `directive` and `files` from src/lib/storefront-bundle.scan.test.ts (same rules: `@/` is `src/`, type-only imports skipped, import() not followed). Build once a map from every non-test `.ts`/`.tsx` file under src to the files it imports by value, and `reach(file)` (memoised) as the set of files reached. (B) The sites. In every non-test file under src/app/admin and src/components/admin, except src/lib/admin-text.ts, src/components/admin/admin-areas.tsx, src/components/admin/admin-text.tsx and src/components/admin/admin-text-context.tsx, find each `adminTexts(<lang expression>, <areas>)` call (regex `/adminTexts\(\s*([^,]+),\s*(\[[^\]]*\]|[A-Z_]+)\s*\)/g`) and each `<AdminAreas areas={<areas>}` (regex `/<AdminAreas\s+areas=\{(\[[^\]]*\]|[A-Z_]+)\}/g`). `<areas>` is either a literal array of string literals (take the strings) or a constant name (`EDITOR_AREAS`, `PLATFORM_SITE_AREAS`): find `const NAME = [ … ]` (with or without `export`, with or without `as const`) in the same file, else in the file the name is imported from, and take its strings; if an element is a spread of another constant, resolve that too. A site's id is `<repo-relative file>#<areas>`, where `<areas>` is the literal array's strings joined with `+` in the order written (`views.tsx#website+schedules`), or the constant's name for a constant (`#EDITOR_AREAS`, `#PLATFORM_SITE_AREAS`); only when one file has two sites with the same `<areas>` do the second and later get `#2`, `#3` appended in source order (`…#products#2`). An id therefore does not change when another hand-down is added or moved above it in the file. A site whose areas cannot be resolved fails the test by name. (C) Bytes handed. For each site and each lang of ADMIN_LANGS (`en`, `nb`): `handed[lang] = sum over its areas of Buffer.byteLength(JSON.stringify(adminText(lang, area)))`. (D) The parts under a site. `under(site)` is `reach(site file)`; and when the site's file is a `layout.tsx`, also the reach of every `page.tsx`, `layout.tsx`, `default.tsx`, `loading.tsx`, `error.tsx` and `not-found.tsx` in that layout's folder and below (a layout hands words to pages it does not import). Keep only files with the `"use client"` directive. (E) What a part names. For one client file and one area, return either `whole` or a set of top-level group names, by these rules applied to the file's text: (1) `useAdminText("<area>").<name>` names `<name>`; (2) `const { a, b: c, ...rest } = useAdminText("<area>")` names `a` and `b`, and `whole` if there is a rest element; (3) `const V = useAdminText("<area>")` (or `let`): look at every later occurrence of the identifier `V` as a whole word; `V.<name>` and `V?.<name>` name `<name>`; any other occurrence (`V` passed as an argument or a prop, `V[`, spread, returned) means `whole`; (4) any other `useAdminText("<area>")` (for example passed straight into a function) means `whole`; (5) the same four rules for `useHandedText("<area>")`. A site's named groups for an area are the union over `under(site)`; `whole` wins. (F) Bytes named. `named[lang] = sum over the site's areas of: whole ? bytes of the area : sum over named groups g of Buffer.byteLength(JSON.stringify(adminText(lang, area)[g])) (0 for a group the catalogue does not have)`. An area with no part naming it at all goes in the site's `unnamed` list. (G) The baseline, src/components/admin/admin-words-handed.baseline.json: `{ "sites": { "<id>": { "areas": [...], "handed": { "en": n, "nb": n }, "named": { "en": n, "nb": n }, "whole": [areas a part takes whole], "unnamed": [areas nothing names] } } }`, keys sorted. With `WRITE_ADMIN_WORDS_BASELINE=1` one `it.runIf` test writes it from the code: a new site is written as it is; for an existing site whose `areas` list is the same as the baseline's, `handed.en` and `handed.nb` are written as min(old, new) and `unnamed` as the old list minus what is now named (never longer); a site whose `areas` differ from the baseline's (a constant whose strings changed) is written as new, from the code. All comparing tests are skipped while writing. (H) The comparing tests. (1) `every hand-down site is in the baseline`: the set of ids found equals the baseline's keys; message for a new one: `run WRITE_ADMIN_WORDS_BASELINE=1 pnpm exec vitest run src/components/admin/admin-words-handed.scan.test.ts and commit the baseline`; for one that is gone: the same. Also expect at least 188 sites, so a broken pattern cannot pass by finding none. (2) `no site hands more than its baseline`: for each site and lang, `handed[lang] <= baseline.handed[lang] + 200` (200 bytes of room for a reworded string); message: `<id> hands <n> bytes of <lang> words, <baseline> in the baseline: hand a cut of the area (only the groups the parts name), or move the part's words to an area of its own`. (3) `no site hands an area nothing names`: `unnamed` now is a subset of the baseline's `unnamed`; message: `<id> hands "<area>" and no client part under it reads it: take it out of the hand-down`. (4) `the baseline is as low as the code`: fails when a site's `handed` is more than 1,000 bytes under its baseline or its baseline `unnamed` holds an area that is now named or no longer handed, with the message to rewrite the baseline. (5) `would notice`, in memory only: take the pages list's site, the first site of src/app/admin/(gated)/[store]/pages/views.tsx (`adminTexts(…, ["website", "schedules"])` today), and compute it again with one more area appended to its areas: `"schedules"` if the site does not hand it, else `"capacity"`; expect that the handed bytes pass the baseline by more than 200 and, when no part under the site names the added area, that it shows in `unnamed`. Do this by calling the same functions with a changed area list, not by editing views.tsx.
