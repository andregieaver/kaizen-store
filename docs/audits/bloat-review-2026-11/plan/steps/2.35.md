# Step 2.35: Answer a store's own domain without a deployment

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort L. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. It is every store's front door on its own domain: the redirect and rewrite rules must be reproduced exactly in code, the matcher cannot name hosts, links must follow, and a mistake takes stores off the air where today it fails the build; only the first commit (the leaf reader and its test) is safe for a cheap model.

**Goal:** A store's own domain is resolved when the request arrives: the proxy looks the host up (one indexed read, remembered for 60 seconds per instance), serves the store's pages and files from /s/{store}, and sends the store's other addresses to its primary; next.config.ts compiles no rule per store domain, and activating, removing or re-pointing a domain asks for no deployment.

**Why:** Today every store domain is compiled into each deployment: 4 to 8 routing rules per domain against Vercel's cap of 2,048 (the app's own routes take about 705), a ceiling near 270 stores with a domain, and a full production deploy per domain change. After: .next/routes-manifest.json holds the same number of redirects and rewrites with 0 or 300 active store domains, and a domain activated after the build answers within a minute.

**Decided by the owner (12 November, the recommended way):** Yes. A store's own domain is looked up when the request arrives, in place of decision P8's compiled routing rules; the critic says the server area needs it for an A, and it lifts the ceiling of about 270 domains. It lands in two pushes so the compiled rules stay until the lookup is seen to answer.

**Closes:** [SF-13](../../findings/server-functions/SF-13.md). Each finding's file has the evidence.

## Do not

- Do not remove the compiled per-store rules in the first push: they stay until the lookup has answered every active domain in CI and for a day in production.
- Do not let a failed or slow lookup serve another store, a cached answer of another host, or an error page: it leaves the request to what the platform answers for an unknown host today.
- Do not read anything of the visitor for routing (no cookie, no IP, no header but Host): P6.
- Do not put a host name into the proxy's config.matcher: matcher values must be constants and the hosts differ per environment.
- Do not make the proxy import auth.ts, stores.ts, pages.ts, catalog.ts, seo.ts, stripe.ts or src/lib/admin-text.ts for this: the lookup is a leaf.
- Do not drop commerce.platform_settings.domains_deploy_requested_at or any index of commerce.store_domains in this step.
- Do not change how kaizenaflow.com, the docs host, the themes host or {store}.{store domain} are routed.
- Do not remove the Vercel deploy hook or src/server/vercel.ts's domain calls (adding a domain to the Vercel project and reading its DNS state stay); only the 'deploy' call for routing goes.
- Do not ask for a higher routes limit or any paid plan from Vercel.
- Do not add a test-only bypass or endpoint to forget a host.

## Stop and report if

- Step 2.20 is not done (no short-memory helper, the proxy still imports @/server/experiments and the other heavy readers directly): the lookup would be one more heavy import in front of every page.
- With the lookup added, e2e/store-hosts.spec.ts or e2e/inline-edit-hosts.spec.ts needs an assertion changed, or a seeded domain answers differently than before.
- A request for a file with an extension on a store's own domain that is not in the fixed list (a feed, a download) is found to be served today by the compiled rewrite: list those addresses and stop; widening the matcher to every file on every host is a cost decision.
- The proxy's rewrite to /s/{slug} breaks a server action's POST, a prefetch (RSC request) or the pay routes' Content-Security-Policy on an own domain: these were served by a config rewrite before; report which.
- On a preview deployment Vercel routes an unknown host to the deployment differently from a known one (the domain must still be added to the Vercel project by src/server/vercel.ts for the request to arrive at all): report what was seen.
- After the first push production logs show '[own-host] proxy' errors, or the lookup's statement appears among the slowest statements: do not make the second push.
- Anything here would need a migration on a hot table or a change of the checkout's routes.
