# Step 2.24: Shrink the server-reference manifest

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort L. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Commits 1 to 3 are now named function by function (the reference table, the shell's actions per file, the beacons' visitStoreOf() with its select), but commit 4 moves some forty features' cached reads into reader files, each needing a judgement of which helpers, row types and importers move, until a measured budget is met, and a wrong move passes the type check and fails only at press time. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** The server-reference manifest that every cold function reads is under 5 MB and 40,000 entries: a cached read or a server action is listed only by routes that can use it, because cached reads live in reader files no writer imports, the admin shell's actions live in small files of their own, and the visit beacons reach no cached read and no action.

**Why:** Today .next/server/server-reference-manifest.json is 10,397,955 bytes with 81,027 entries (80 to 91 ms and 20 to 24 MB to load before a function's first request). 74 cached reads are each listed by more than 500 of the 807 routes (54,977 entries), an admin route lists 115 at the median, and /api/visit lists 74 it never calls. After: under 5 MB and 40,000 entries, an admin route's median at 60 or fewer, /api/visit at 0, and the loader's time on CI's machine under 45 ms.

**Closes:** GAP-server-s4. Each finding's file has the evidence.
