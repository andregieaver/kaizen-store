# Step 1.11: Hold the storefront's server side: statements per page, cached reads and render modes

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Commit 1 is a fully named scan with trials that prove it bites; commits 2 and 3 are now specified (the hole rule, no house page, prices through set_price) but add two hard gates to CI's e2e job whose first baselines and quiet-window logic want a read. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** Three checks hold the storefront's server side: a scan test lists every cached read's life and tags, scripts/render-modes.mjs holds the render mode and holes of named routes from the build, and scripts/server-budget.mjs counts the statements of eight store pages and two pay pages on the built app in CI.

**Why:** The browser's side has budgets and the server's has none: a product page sends about 19 statements and one cookies() read in a shared part could move every store page to per-request without any check failing. After this step each page has a statement budget (today's figure plus 2), each named route has its compute mode and hole count in a baseline, and a cached read without a tag fails pnpm test.

**Closes:** [SD-13](../../findings/storefront-server/SD-13.md), [CA-16](../../findings/caching/CA-16.md), GAP-page-model-s2. Each finding's file has the evidence.

### Commit 2 of 3: Render modes: CI holds which routes are static, how many holes each has, and what the demo store's resume data keeps

- **create** `scripts/render-modes.mjs`: Plain Node, run from the repo root after pnpm build. For each route of a named list it reads .next/prerender-manifest.json (routes[route] has renderingMode, compute, initialRevalidateSeconds) and the files .next/server/app<route>.html and .meta (for '/', find the file by the manifest's dataRoute or by listing .next/server/app; do not guess). It records per route: compute ('static', 'resuming' or 'blocking'; a route missing from the manifest is 'per-request'); holes: the number of '<template id="B:<n>"' markers in the .html for which the same file has no '<div hidden id="S:<n>"' with the same <n> (a boundary whose content was not streamed into the prerendered file); platformTags: the entries of the .meta's headers['x-next-cache-tags'] that are neither a path tag (they start with _N_T_) nor carry a store's id, slug or an owner (no ':' in them), sorted; revalidate: initialRevalidateSeconds; titleInHead: whether <title> and a meta property og:title stand before </head> in the .html. The list: '/', '/docs', one docs article ('/docs/owners/getting-started/create-your-store'), '/themes', '/s/demo/no', '/s/demo/no/om-oss', '/s/demo/no/blog/nye-produkter', '/s/demo/no/products', '/s/demo/no/category/belysning', '/s/demo/no/p/demo-keramikkopp', '/s/demo/no/search', '/s/demo/no/cart'. Kaizena Flow's own store ('kaizenaflow') is not in the list: step 0.3 switches its site on only in the hosts job's seed (e2e/hosts-seed.mjs), so the e2e job's build, where this script runs, has no house page to measure. It also records totals over the whole manifest: routes by compute, and dynamic route patterns without a fallback. Then it runs step 0.1's .meta reader, docs/audits/bloat-review-2026-11/scripts/meta-reader.mjs (read its first lines for what it prints; reuse its parsing by importing or by copying the few lines that read 'postponed'), and records three numbers for the demo store's entries (every .meta under .next/server/app/s/demo): entries whose resume data ('postponed') keeps a list of page documents; entries whose tags hold both the store-wide pages tag (pages:<store id>) and one page's own tag; and the median bytes of 'postponed' per entry. Baseline: scripts/render-modes.baseline.json. The script exits 1, naming the route and both values, when a route's compute got worse (static to resuming to blocking to per-request), its holes rose, a platform tag appeared, its revalidate fell, a prerendered public page lost its title in the head, the first two .meta numbers rose, or the median bytes moved by more than 5% either way. Like scripts/ratchet.mjs it also exits 1 when a figure got better, until --write lowers the baseline; --write refuses to make a figure worse unless --first.

Expect '/' and '/docs' static and the /s/demo/no routes resuming, as the build of 11 November had them.

### Commit 3 of 3: Server budget: CI counts the statements of store pages, the cart and the checkout on the built app

- **create** `src/db/statement-log.ts`: A log switch for scripts, with no import. 'const LOG = process.env.STATEMENT_LOG === "1"' read once at module load. Export logStatement(text: string): void: when LOG is false it returns at once; when true it writes one line with process.stdout.write: JSON of { event: 'db.statement', text: the statement's text with runs of white space collapsed to one space and cut to 160 characters } and a newline. Never the values. It never throws (wrap the body). Production never sets the variable.
- **edit** `src/db/client.ts`: In the client.query wrapper that step 1.9 added inside pool.on('connect', ...), call logStatement(text) from './statement-log' on the line before noteStatement(text, values). Nothing else changes. - **create** `scripts/lib/budget-seed.mjs`: Exports seedLargeStore(sql, { slug: 'budget-500', products: 500 }) for scripts: with the 'postgres' package (as test/integration-setup.ts uses it) it makes one open store the way src/server/capacity-test-support.ts makeCapacityStore() does (insert into commerce.access_requests, select commerce.approve_access_request(...)), sets setup_completed_at = now(), status active and private_mode false, and inserts 500 active products with one variant each and stock 5, by insert ... select from generate_series, copying the required columns from one product of the store 'demo'. Prices go through commerce.set_price only (CLAUDE.md: prices only change through it; never insert into commerce.prices): after the variants exist, run one statement `select commerce.set_price(v.id, ${code}, 19900) from commerce.product_variants v where v.store_id = ${storeId}::uuid`, where code is `select code from commerce.markets where store_id = ${storeId}::uuid order by active desc, code limit 1` read first (markets has no position column; its key is (store_id, code)). set_price(p_variant_id uuid, p_market_code char, p_amount_minor bigint) is in the baseline schema. It returns the slug, the market's path segment and one product's handle. It does nothing when the store already exists.
- **create** `scripts/server-budget.mjs`: Plain Node, run after pnpm build with DATABASE_URL set, on its own (no other test running against the server). Steps: (1) seedLargeStore(). (2) Start the built app on port 3210 with spawn('pnpm', ['-s', 'start', '-p', '3210'], { env: { ...process.env, STATEMENT_LOG: '1' } }) as scripts/perf.mjs serve() does, and collect its stdout lines whose event is db.statement, each with the time it arrived. (3) Wait until the server answers, then 5 seconds: every statement text seen in that quiet window is background (the start hook's poll) and is ignored from then on. (4) For each page: request it once with fetch (not measured), wait until no statement has arrived for 2 seconds, mark the time, request it again, wait until no statement has arrived for 2 seconds, and count the non-background statements since the mark: that is the page's warm count. Pages, all on http://localhost:3210: home /s/demo/no; product /s/demo/no/p/demo-keramikkopp; all products /s/demo/no/products; category /s/demo/no/category/belysning; search /s/demo/no/search?q=lampe; home with a cart cookie; and the large store's home and one product of it: eight pages (Kaizena Flow's own store is left out: its site is switched on only in the hosts job, not in the e2e job where this script runs). (5) The cart cookie: with playwright-core (createRequire as docs/audits/bloat-review-2026-11/scripts/measure-routes.mjs does; Chromium from PLAYWRIGHT_CHROMIUM_PATH when set) open three product pages of the demo store, press Add to cart on each, and read the context's cookies; send them as the Cookie header of the fetches for 'home with a cart cookie', 'cart with three lines' (/s/demo/no/cart) and 'checkout at its first step' (/s/demo/no/checkout). (6) Cold counts: restart the server and request the large store's home once and count; restart and request its product page once and count. Budgets live in scripts/server-budget.json: { page: { statements: measured, max: measured + 2, bar?: number } }; the cart's entry carries bar 12 (a guest's filled cart, after step 2.19) and the checkout's carries the bar of step 2.19 when that step sets one. The script exits 1 when a page is over max, naming the page, the count and the ten most repeated statement texts; it retries a failing page once. --write lowers max to measured + 2 and refuses to raise it unless --first. It prints a Markdown table, and with --doc it rewrites the table between the markers '<!-- server-budget:start -->' and '<!-- server-budget:end -->' in docs/performance.md. Always stop the server in a finally block.

## Do not

- Do not add cacheTag or cacheLife to a cached read in this step to make the scan pass: a read without one goes on NO_LIFE or NO_TAG with its reason, and later steps (2.15) change them.
- Do not move a store admin's refresh of STORES_TAG or AI_TAG in this step: the six files start on the exception list.
- Do not keep a store page's statement count in any other test: step 1.12's journey test holds tables and rows, not counts.
- Do not count commits (pg_stat_database) and do not require pg_stat_statements: CI's database is the image pgvector/pgvector:pg17 without it.
- Do not put a statement's values in the log line, and do not set STATEMENT_LOG anywhere but in scripts/server-budget.mjs's spawn; never in vercel.json, a workflow's global env or .env files.
- Do not hold bytes of the demo content in render-modes' baseline, only modes, counts and the one median the plan names.
- Do not change next.config.ts, src/proxy.ts or any cache setting.
