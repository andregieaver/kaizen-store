# Step 0.15: Make no server call after load for a visitor with nothing to fetch

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every edit is named against the code and two grep checks now catch a missing refreshTag or markMine, but the step adds a 'use cache' read with its own tag, a consent-declared cookie and a call in startSession (sign-in), where a wrong but compiling edit (a wrong tag, the marker set httpOnly, the call after a return) passes the tests, so commits 2 and 3 need a read of the diff. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** A new visitor to a store with both tile switches off makes no request of the page's own after load: no GET /wishlist/saved, no GET /api/shop/tiles and no suggestion POST on the search results page.

**Why:** Today all 12 measured store pages ask /wishlist/saved (a function call and a proxy run for a 15-byte answer), the home and listing pages ask /api/shop/tiles (three statements) and the search results page posts for suggestions nobody typed for. After this step each of these is 0 for a visitor with nothing to fetch.

**Closes:** [SC-10](../../findings/storefront-browser/SC-10.md), [PL-7](../../findings/page-payload/PL-7.md), [SD-15](../../findings/storefront-server/SD-15.md), [SC-12](../../findings/storefront-browser/SC-12.md), [PL-8](../../findings/page-payload/PL-8.md), [SD-14](../../findings/storefront-server/SD-14.md), [PL-14](../../findings/page-payload/PL-14.md). ## Do not

- Do not delete src/app/s/[store]/[market]/wishlist/saved/route.ts: the marker design keeps the route (two findings proposed deleting it for another design; the plan chose the marker).
- Do not make the marker cookie httpOnly: the page's script must read it. Do not put anything but '1' in it.
- Do not cache stock or tileFacts(): only the two switches are cached.
- Do not tag productSettingsCached() with the catalogue's tag: a settings save must not refresh the catalogue.
- Do not remove getProductSettings() or point the facts route at the cached read.
- Do not seed the saved products through the market layout as well: one design, not both.
- Do not rename the `asked` ref in search-box.tsx or change suggestAction or its budget.
