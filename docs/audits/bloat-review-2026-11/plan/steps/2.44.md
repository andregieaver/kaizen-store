# Step 2.44: Show by trial whether component and database tests need a fresh worker

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. Two timed trials with a written pass rule and one config line each; a wrong setting shows as a failing test run.

**Goal:** A decision row holds the results of two timed trials (component tests without a fresh worker per file; where a database test file's 3 s goes), the Vitest config keeps whichever setting the trials proved, and the unit run's ceiling in scripts/ci-budgets.json is the new median plus 25%.

**Why:** After step 0.39 the unit run is expected at 3 min 25 s to 4 min 15 s (5 min 34 s today), and three quarters of it is 281 component and database test files at 0.74 s and 3.0 s a file. The target is 3 min 30 s or less for the whole unit run.

**Closes:** GAP-build-3. Each finding's file has the evidence.

## The work

### Commit 1 of 2: Component tests share a worker: isolate off in the components project, proved by three runs

- **edit** `vitest.config.mts`: Before editing, check that step 0.39 is done: the file must define three projects (test.projects, each with a name; one holds the component tests and lists src/test/admin-english.ts and src/test/eager-lazy-views.ts in its setupFiles, one holds the tests that open the test database, one holds the plain unit files with isolate: false). If the file still has one include list and no projects, stop. First take the BEFORE figures with the commands in this commit's checks (the sample and the full project), and write them down. Then, in the components project only, add `isolate: false` (Vitest then reuses one worker's module registry for all files of that project, so the admin's English in src/test/admin-english.ts is loaded once per worker and not once per file). Change nothing else in that project: same include, same setupFiles, same pool. Then run the three AFTER runs in the checks. Keep the line only if all three runs pass with every file green AND the sample's time is at most 61% of its BEFORE time (the review measured 16.3 s falling to 10 s or less for 22 files; the review's own 22 files were not kept, so the ratio is the rule). If a file fails only with isolate off, do NOT edit that test to make it pass and do not add a reset to it: remove the `isolate: false` line again, and write the failing file names into the decision row. A third way is allowed only if at most 5 files fail: move exactly those files into a fourth project named components-isolated with the same setupFiles and isolate left on, by listing them in its include and in the components project's exclude; then rerun the three runs.

Before the push:

- BEFORE and AFTER, the sample: SAMPLE=$(rg --files src/components -g '*.test.ts' -g '*.test.tsx' | sort | head -22 | tr '\n' ' '); time pnpm exec vitest run $SAMPLE : run it twice and take the second (warm) time; AFTER must be at most 0.61 x BEFORE
- pnpm exec vitest run --project <the components project's name as written in vitest.config.mts> : every file passes; run it twice
- pnpm exec vitest run --project <same name> --sequence.shuffle.files : every file passes (a third run, shuffled; note the seed Vitest prints)
- pnpm test : the 'Test Files' and 'Tests' totals on Vitest's last lines equal the totals of a run made before this commit (no file lost from every project)
- pnpm lint && pnpm typecheck && pnpm test: exits 0

### Commit 2 of 2: A database test file's time, split into its four parts, and the db project's worker setting that follows

- **edit** `vitest.config.mts`: This commit first measures and only then may change one line. Measure one database test file (use src/db/commerce.test.ts and one small file that opens the test database, found with: rg -l 'db/testing' src -g '*.test.ts' -g '!*.int.test.ts' | head -3). Split its time into four parts without committing any timing code: (1) worker start = the 'prepare' and 'environment' figures on Vitest's Duration line for a run of that one file; (2) PGlite start, (3) template load, (4) tests: add temporary console.time/console.timeEnd pairs inside src/db/testing.ts around the call that creates the PGlite instance and around the call that loads the template made by src/test/test-db-template.ts, run the file, write the four numbers down, and remove the timing lines again (git diff src/db/testing.ts must be empty before the commit). Decision rule: if PGlite start (part 2) is over 0.5 s a file, add `isolate: false` to the database project in vitest.config.mts and run that project three times, one of them with --sequence.shuffle.files; keep the line only if every file passes all three times and the project's wall time falls. If part 2 is 0.5 s or less, change nothing in the config: the commit then holds only the docs rows of this step (the decision row and docs/build-memory.md are not touched; see docs).
- **create** `scripts/ci-budgets.json`: This file is made by step 1.20 and does not exist before it. If it is not there, stop: the dependency is not done. If it is there, do not overwrite it: change only the unit run's ceiling. Run pnpm test five times on the machine CI uses if you can read CI's run times (the recorder of step 1.20 prints them in the run summary), otherwise locally, take the median wall time, and set the unit run's ceiling to that median times 1.25, rounded up to a whole second. Keep every other key of the file as it is.

## Do not

- Do not edit, skip or weaken a test so that it passes without a fresh worker: a file that needs isolation is a result, to be named in the decision row.
- Do not turn isolate off in vitest.integration.config.mts: the integration tests share a real database and are not part of this step.
- Do not remove src/test/admin-english.ts or src/test/eager-lazy-views.ts from the components project's setupFiles.
- Do not change pool, poolOptions, maxWorkers or testTimeout: the trial is one option.
- Do not commit console.time lines in src/db/testing.ts.
- Do not raise the ceiling in scripts/ci-budgets.json; it may only go down in this step.

## Stop and report if

- vitest.config.mts has no projects (step 0.39 is not done) or scripts/ci-budgets.json does not exist (step 1.20 is not done).
- The totals of 'Test Files' or 'Tests' differ from the run before the step: a file fell out of every project.
- More than 5 component files fail with isolate off: revert the line, name them in the decision row, and hand back; the step is then done with the result 'kept isolation'.
- A file passes in order and fails only when shuffled: that is an order dependency; do not fix it here, record the seed and the file and revert.
- After both trials the unit run is still over 3 min 30 s: write the measured figure in the decision row and report; do not look for a third cut on your own.
