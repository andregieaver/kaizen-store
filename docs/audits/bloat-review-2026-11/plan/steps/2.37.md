# Step 2.37: Slim the tool schemas, so no first round is over 56,000 characters

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. The first commit is mechanical, but splitting update_product means choosing which fields go where and registering two tools in about a dozen maps, and the step ends in an eval run that only a person with platform access can make.

**Goal:** The tool schemas the AI manager's model is sent carry no maxLength, minLength or pattern, a long tool result reaches the model as valid JSON that says it was cut, update_product is split, and no first round is over 56,000 characters.

**Why:** After step 2.36's lean round, string bounds still take 4,006 to 7,654 characters a round (5,562 in a lean orders round), update_product alone is 11,908 characters and a cut result is broken JSON; after the step no round's tools hold a string bound, no tool is over 2,500 characters outside a named list, and no first round is over 56,000 characters (34,000 with no page and no question).

**Closes:** [AI-8](../../findings/ai-calls/AI-8.md). Each finding's file has the evidence.
