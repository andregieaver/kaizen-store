# Step 2.25: Load the admin's words by area on admin routes too

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort L. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Long but mechanical: a generator and a regex codemod (both specified to 0.7's real module shape) do the work and the type check catches a wrong area or a missing argument, but the middle commits rewrite hundreds of files and the English defaults turned into required props could be fed English again, which only the fallback spec would see, so their diffs want a read; commits 1 and 4 are generated or proved by the type checker. A smaller model may still do commits 1, 4 alone. *(Rating checked twice, 12 November; first written as strong.)*

**Goal:** Every one of the 67 admin text areas has a small module of its own, every server call adminText(lang, 'area') and adminTexts(lang, [...]) in src reads its area's module instead, and src/lib/admin-text.ts holds the types only: no table of every area, no adminText() and no adminTexts().

**Why:** Today every admin page and action loads all 67 areas in both languages, 3.46 MB of catalogue source, where its own code names a median of 15. After: a median admin entry reaches at most 30 areas and 1.31 MB (the last stretch to 18 areas and 0.9 MB is step 2.50's), and the server code of /admin/[store]/orders is lower than before.

**Decided by the owner (12 November, the recommended way):** No third admin language is planned for the first half year, so this step and step 2.50 stay in phase 2. If one is wanted sooner, both steps land before the language is added.

**Closes:** [SG-4](../../findings/server-module-graph/SG-4.md). Each finding's file has the evidence.
