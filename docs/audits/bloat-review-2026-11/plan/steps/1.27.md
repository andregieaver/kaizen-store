# Step 1.27: Hold by name what a store page's first scripts may hold

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. One test file is extended with walks whose rules, inputs and expected counts are given, and a baseline is generated; nothing that ships changes, and the planted cases prove the test bites.

**Goal:** src/lib/storefront-bundle.scan.test.ts holds by name what a store page's first scripts may hold: the client modules the server code of a built page, the product page, a listing and the cart imports are a baseline list that only shrinks, the walk follows import(), no visitor component reaches the admin's words (the sign-up wizard aside) or, from those four pages, the cookie purposes, and the four browser-language files stay under 34,000 bytes together.

**Why:** A byte budget's 3% of room is 18,000 to 21,000 bytes, so a part of 5 to 20 KB passes unseen: the cart's forms that reached every product page on 10 November were 18,876 bytes. Today 0 modules are held by name; after, every client module of four store pages is (21 on a built page, 40 on the product page and a listing, 41 on the cart today), and the browser-language files are held at 34,000 bytes (32,864 today).

**Closes:** GAP-page-model-s4, GAP-text-s3. Each finding's file has the evidence.
