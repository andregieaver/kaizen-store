# Step 1.24: Measure what a session really loads, and hold source file size

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. The ratchet edit copies an existing pattern with a baseline written by the script, and the session-load script's input shapes, output keys, privacy rule, test cases and the one ignore file to extend are all given; nothing deployed changes and a mistake shows as a wrong count in a docs folder. *(Rating checked twice, 12 November.)*

**Goal:** scripts/session-load.mjs reads a session's own transcript and writes one small file saying what it loaded and read of rules and docs; working sessions collect 20 such files as the 'before'; and the code ratchet holds two counts that only fall: source files over 100 KB (15) and over 2,000 lines (11).

**Why:** Every figure for the written rules is a file size or an estimate at four characters a token: what a session really loads has never been measured (0 samples today). After: 20 measured sessions with a printed median per code change, and the two file-size counts held at 15 and 11.

**Closes:** GAP-rules-3, GAP-rules-s2. Each finding's file has the evidence.

### Commit 2 of 2: scripts/session-load.mjs: what a session loaded and read, from its own transcript

- **create** `scripts/session-load.mjs`: A Node script with no dependency, in the style of scripts/ratchet.mjs (a header comment that says what it is for and how to run it). Two modes. Mode 1, `node scripts/session-load.mjs [--transcript <file.jsonl>] [--step <id>]`: finds the running session's transcript and writes one file. Finding it: if `--transcript` is given use it; else the folder is `path.join(os.homedir(), ".claude", "projects", process.cwd().replace(/[^a-zA-Z0-9]/g, "-"))` and the transcript is the `*.jsonl` file in it with the newest modification time. If none is found, print `no transcript found in <folder>; pass --transcript` and exit 1. Also read every `*.jsonl` under `<folder>/<session id>/subagents/` if that folder exists (the session id is the transcript's file name without `.jsonl`). Reading: one JSON object per line; skip a line that does not parse. (a) Always loaded: lines with `type === "attachment"` and `attachment.type === "instructions"` hold `attachment.files[]`, each `{ path, content }`: record each path with `Buffer.byteLength(content)` and how many times it was loaded (a compaction loads it again). (b) Read with the Read tool: lines with `type === "user"` whose `toolUseResult` is `{ type: "text", file: { filePath, content } }`: add `Buffer.byteLength(file.content)` to that path and count the read. (c) Read through the shell: for each assistant `tool_use` block with `name === "Bash"`, keep `input.command` by the block's `id`; when the matching `tool_result` arrives (same `tool_use_id` in a user line; its text is `toolUseResult.stdout`), and the command names a file under `docs/` or `CLAUDE.md` or `AGENTS.md` or `.claude/` (regex `/(?:^|[\s"'=/])((?:docs|\.claude)\/[\w./\[\]()-]+|CLAUDE\.md|AGENTS\.md)/`), add the stdout's bytes to the first such path under a separate map `shell`. (d) Omitted long lines: in every tool result's text (Grep's `toolUseResult.content`, Bash's `stdout`) count occurrences of the exact text `[Omitted long matching line]`; record per occurrence group `{ tool, path, count }` where `path` is the Grep input's `path` or `glob` (or `""`), never the pattern and never the command. (e) Code change: true when any `tool_use` named `Edit`, `Write` or `NotebookEdit` has an `input.file_path` under the repo's `src/`, `e2e/`, `scripts/` or `supabase/`. Make every path repo-relative (strip `process.cwd() + "/"`); drop paths outside the repo from the lists and keep only their summed bytes as `outsideRepoBytes`. Split the repo paths into `rulesAndDocs` (CLAUDE.md, AGENTS.md, anything under `docs/` or `.claude/`, any `*.md`) and `source` (the rest). Writing: `docs/audits/bloat-review-2026-11/session-load/<YYYY-MM-DD>-<first 8 hex characters of sha256(session id)>.json` (create the folder), two-space JSON with exactly these keys: `date`, `session` (the 8 hex characters; never the session id, an email, a prompt or any message text), `step` (from `--step`, else null), `phase` (`"after"` when CLAUDE.md is under 15,000 bytes AND the folder docs/decisions exists, that is after steps 2.1 and 2.40; else `"before"`), `subagents` (how many subagent transcripts were read), `codeChange`, `alwaysLoaded` (array of `{ path, bytes, times }`), `read` (array of `{ path, bytes, reads, via: "Read" | "shell" }` for rulesAndDocs only, sorted by bytes, largest first), `omitted` (the array of d), and `totals: { alwaysLoadedBytes (each file once), alwaysLoadedBytesWithReloads, rulesAndDocsReadBytes, sourceReadBytes, outsideRepoBytes, omittedLongLines }`. Running it twice in one session overwrites the same file. Print the totals and the file's path. Mode 2, `node scripts/session-load.mjs --summary`: reads every `*.json` in the folder, sorted by file name. For `phase` before and after apart, it takes the first 20 files of each and prints: how many files; how many with `codeChange` true; the median over those code-change sessions of `totals.alwaysLoadedBytes + totals.rulesAndDocsReadBytes` (the figure the rules area's measure 8 holds at 25,000); the median of `omittedLongLines`; and for each file under docs/rules that any session read, its size on disk now and the median bytes read of it, with the line `WHOLE FILE READ` when the median is 80% or more of the size (that is the signal that the plan needs a step splitting the seven rule files by section). With fewer than 20 files it prints `n of 20` and still prints the medians. Export the pure parts (`readTranscript(lines)`, `summarise(files)`) so the test can call them; run the command-line part only when the file is the entry (`import.meta.url === pathToFileURL(process.argv[1]).href`).
