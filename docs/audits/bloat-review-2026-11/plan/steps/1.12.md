# Step 1.12: Count a shop-only store's journey, and what one placed order writes

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Choosing the server calls that stand for each page, mapping about 300 tables to features and judging which reads are stable needs a model that can read the storefront; commit 1 alone is cheap.

**Goal:** An integration test walks a store that has only the shop switched on from its home to its checkout, keeps the exact list of tables each page scans and the rows it reads for 1 and for 20 stores, and keeps what one guest order of three lines and one counted visit write, all in src/server/ratchet.baseline.json where the lists may only shrink and the numbers only fall.

**Why:** No test walks a shop-only store and nobody has measured what one order writes, so a read of a switched-off feature's table or a trigger that writes a row arrives unseen. After this step each page has a named list of tables, equal rows read for 1 and 20 stores is asserted on seven reads, and an order's statements, inserts and updates are numbers that only fall.

**Closes:** GAP-surface-1, GAP-database-3, GAP-database-s1, GAP-surface-s2. Each finding's file has the evidence.
