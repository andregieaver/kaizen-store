# Step 0.37: Remove the old admin redirects and the bookings and deliveries twin switch

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every deletion, the SQL of the migration and the test edits are spelled out and the suite catches a miss, but the third commit replaces a trigger on commerce.stores and three SQL functions and changes about twenty test expectations, so a stronger model should read that diff before it is pushed.

**Goal:** The eight redirects from old admin addresses are gone, and bookings and subscription boxes are switched in one place only (stores.features): the two module setters and the legacyModule field are deleted, and the database no longer mirrors the two features into stores.modules, which holds only 'work'.

**Why:** Today eight redirects keep addresses alive that only the team ever had, and bookings and deliveries are stored twice (stores.features and stores.modules), held equal by a 50-line trigger that fires on every write of either column, for code that no longer exists. After: rg for the four names prints nothing (about 20 lines today), and no store has 'bookings' or 'deliveries' in modules.

**Closes:** [DD-11](../../findings/unused-code/DD-11.md). Each finding's file has the evidence.
