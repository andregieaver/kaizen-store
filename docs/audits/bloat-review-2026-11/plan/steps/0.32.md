# Step 0.32: Serve pictures as stored, and give every file with a fixed address a long lifetime

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Each edit is one named line, and the scans now pin every file's lifetime value and the e2e tests catch a missing picture, but the step changes next.config.ts and cache headers for public files and font files across 18 files, where a wrong lifetime on a private file or a stale public file would pass the build, so a stronger model reads each commit's diff before the push. *(Rating checked twice, 12 November.)*

**Goal:** Every picture is served as stored (Next's image service is off, so a suggested product's uploaded thumbnail shows), every file with a fixed address is stored with a long lifetime, font files are kept at the CDN, public files are kept a day, a hidden flag is not fetched, and the flags folder is under 20 KB.

**Why:** Today the search suggestions ask /_next/image for uploaded pictures and get a 400, /_next/image answers 200 to anyone, none of the 9 uploadToSignedUrl calls names a lifetime (videos and 3D models get one hour, theme photographs five minutes), the font file route sends no s-maxage, public files answer max-age=0 and the flags weigh 176 KB. After: /_next/image answers 404, 9 of 9 calls name a lifetime, a new video or theme photograph answers max-age=31536000, a font file is a CDN HIT on its second request, /flags/no.svg answers max-age=86400 and the folder is under 20 KB.

**Closes:** [AS-4](../../findings/files/AS-4.md), [AS-9](../../findings/files/AS-9.md), [AS-12](../../findings/files/AS-12.md), [AS-5](../../findings/files/AS-5.md), GAP-code-s3. Each finding's file has the evidence.
