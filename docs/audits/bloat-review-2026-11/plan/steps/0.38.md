# Step 0.38: Run each check once in CI

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. The edits are a few named lines with a scan test, but they change the conditions under which production is deployed and what CI checks, so a stronger model should read the ci.yml diff of each commit before it is pushed.

**Goal:** On a push, the whole program is type-checked in two CI jobs (static and the quick gate) and not inside the three browser jobs' builds, the schema check runs in one integration shard, lint keeps a cache locally and in both CI jobs that lint, and a push that changes only tests is checked but not deployed.

**Why:** Today one push type-checks the same commit five times (183 s each, three hidden inside CI's builds), runs the schema check in three shards, lints 6,213 files with no cache (about 3 minutes, on the deploy path), and 8% of deploys are for pushes that change only tests. After: tsc in two jobs, the schema check in one, a second lint on an unchanged tree in under 15 s, and no deploy for a tests-only push.

**Closes:** [TC-1](../../findings/tests-ci-build/TC-1.md), [TC-12](../../findings/tests-ci-build/TC-12.md), GAP-build-s5, [TC-14](../../findings/tests-ci-build/TC-14.md). Each finding's file has the evidence.

- **create** `scripts/deploy-needed.mjs`: A node script in the style of scripts/await-deploy.mjs (read it first: a header comment, exported pure functions, `main()` run only when the file is the entry point, nothing secret printed). Exports: `TEST_ONLY = [/\.test\.tsx?$/, /\.spec\.ts$/, /^e2e\//, /^e2e-live\//, /^test\//, /^src\/test\//]`; `testsOnly(files)`: true when the list is not empty and every path matches one of TEST_ONLY; `deployNeeded({ files, reported })`: returns { deploy: boolean, why: string }: deploy true with why 'production's commit is unknown' when `reported` is null; true with 'the files changed could not be listed' when `files` is null; false with 'only tests changed since <reported>' when testsOnly(files); else true with 'code changed'. main(): read PRODUCTION_URL (default https://kaizenaflow.com) and GITHUB_SHA; fetch `${url}/api/health` as reportedCommit() in await-deploy.mjs does (copy that function; 15 s timeout; null on any failure); when it gives a commit, run `git fetch --quiet --depth=1 origin <reported>` and `git diff --name-only <reported> <GITHUB_SHA>` with execFileSync inside try/catch (any failure gives files null); when the reported commit equals GITHUB_SHA the list is empty, which is not tests-only, so the answer is deploy true (the deploy step is then a harmless repeat). ## Do not

- Do not remove `pnpm typecheck` from the static job or from the quick gate: they are the two checks that remain.
- Do not set SKIP_BUILD_TYPECHECK anywhere but the three browser jobs: not in the repository's variables, not in vercel.json, not in package.json's build script.
- Do not change the conditions of the `release` job, the concurrency block, or the step that reads the ledger again before the deploy (D530).
- Do not add scripts/, .github/, package.json, config files, supabase/ or content/ to the tests-only patterns.
- Do not make deploy-needed.mjs fail the job: a doubt means deploy.
- Do not merge jobs, share a build between jobs or change the shards: that is step 3.18.
- Do not add --concurrency to lint in this step, and do not add a type-aware or cross-file ESLint rule without moving it to a second, uncached call.
- Do not move to a larger or paid runner.

- A browser job's build fails after the first commit with an error the type check used to hide or catch differently: report the log; do not remove the variable from only one job.

- The second pnpm lint takes more than 15 s: report the time and `ls -la node_modules/.cache/eslint`.
- actions/cache cannot be used in this repository (a policy refuses it): keep the package.json change and report; the gate's 30 s figure then waits.
- On the trial tests-only push the deploy step ran, or on a code push it was skipped: report the line the step printed; revert the two `if:` additions if a code push was held back.
- ci.yml is not as described (a job renamed, the gate's steps moved): report the difference before editing.
