# Step 3.6: Indexes that fit the document jobs' windows

Phase 3 (One of each) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every statement is named, but it is a migration CI applies to production, and a partial index whose predicate differs from the reading statement by one cast still passes db:check and the commerce.test.ts text check while Postgres never uses it; a reviewer compares each predicate with einvoice-sending.ts lines 64 to 93 and invoice-notices.ts lines 131 to 162. *(Rating checked twice, 12 November; first written as strong.)*

**Goal:** Eight partial indexes on invoices, credit_notes, work_invoices, work_credit_notes, order_events and order_edits fit the document jobs' windows, each written with the reading statement's own predicate, so the jobs' exists() checks become index probes.

**Why:** The invoice, document-email and e-invoice jobs re-check every invoice, credit note and failed-invoice event on each five-minute tick (all 2,000 rows of each in the test store), because no index fits the windows they read. This step adds the indexes, which change no behaviour on their own; step 3.21's marked path and its 2,000-order case rely on them.

**Closes:** no finding on its own. Steps 3.21, 3.22, 3.23, 3.24 were split out of this step on 12 November. The findings close when the steps of the split are Done.

## The work

### Commit 1 of 1: Indexes that fit the document jobs' windows

- **create** `supabase/migrations/*_document_job_indexes.sql`: Custom migration: `pnpm exec drizzle-kit generate --custom --name document_job_indexes`, then `node scripts/prune-snapshots.mjs`. Eight plain `create index if not exists` statements; none of these tables is on the hot list (orders, order_lines, visits, products, product_variants, customers, carts, cart_lines), so no `concurrently`: (1) invoices_issued_at_idx on commerce.invoices (issued_at); (2) credit_notes_issued_at_idx on commerce.credit_notes (issued_at); (3) invoices_business_issued_idx on commerce.invoices (issued_on) where (snapshot -> 'buyer' ->> 'type') = 'business'; (4) credit_notes_business_issued_idx, the same on commerce.credit_notes; (5) work_invoices_business_issued_idx on commerce.work_invoices (issued_on) where status <> 'draft' and not imported and (buyer ->> 'business')::boolean is true; (6) work_credit_notes_business_issued_idx on commerce.work_credit_notes (issued_on) where (buyer ->> 'business')::boolean is true; (7) order_events_invoice_failed_idx on commerce.order_events (created_at) where type = 'invoice.failed'; (8) order_edits_documents_waiting_idx on commerce.order_edits (store_id) where status = 'applied' and documents = 'waiting'. Write each predicate with exactly the expression the reading statement uses (src/server/einvoice-sending.ts lines 64 to 93, src/server/invoice-notices.ts lines 131 to 162), or Postgres will not match the partial index. Mirror all eight in src/db/schema.ts on their tables so `pnpm db:check` agrees (drizzle's index().on(...).where(sql`...`)); if db:check still reports a difference for an expression index, keep the SQL file as the source and follow what docs/ci-migrations.md says for rules Drizzle cannot express.
