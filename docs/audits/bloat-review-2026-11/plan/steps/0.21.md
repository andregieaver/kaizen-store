# Step 0.21: Read the AI connection only to call a model, and give search a ceiling

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Commit one is mechanical and commits two to four are now specified line by line, but the month's cost touches the AI allowance (money and limits), the search ceiling threads a visitor through the chat, and commit five's scan of public model paths still needs the entries found and each one's ceiling judged. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** The AI connection (key and month's cost) is read only by code about to call a model; screens ask a keyless 60-second memo; the month's AI cost is daily rows plus today; search reads no connection on a cache hit and has a ceiling on a miss; and a store's AI settings refresh that store's tag only.

**Why:** Today commerce.ai_providers is read 12.4 times for each AI call made, the month's cost statement takes 37 to 57 ms a call, 319 prerendered entries carry the platform-wide tag 'ai-providers' that any owner's save expires, and a visitor's search can reach a model with no ceiling. After: at most 2 reads per call, under 5 ms, 0 entries with the wide tag, and a search_ai budget.

**Closes:** [AI-2](../../findings/ai-calls/AI-2.md), [DQ-4](../../findings/queries/DQ-4.md), GAP-ai-1, [SD-16](../../findings/storefront-server/SD-16.md), [CA-11](../../findings/caching/CA-11.md), GAP-ai-s5. Each finding's file has the evidence.
