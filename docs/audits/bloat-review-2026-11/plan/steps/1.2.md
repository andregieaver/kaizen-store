# Step 1.2: Hold every route's first scripts

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model alone. A reader of one JSON file with a pure comparison and a unit test; a wrong script is caught by the planted import and by CI's first run.

**Goal:** After every build in CI, scripts/bundle-budget.mjs compares the first-load script bytes of every route (560 today) with a committed baseline, fails when a route is more than 15,000 bytes over it or has no entry, and prints and holds the number of routes whose first-load chunks contain each of eight marker strings.

**Why:** Budgets watch 15 of 560 routes today (9 of the admin's 449, none of its worst four), so growth such as 12.6 KB a day on the admin home passes unseen. After: all 560 routes are held within 15,000 bytes of their figure, and eight marker counts can only fall.

**Closes:** [AC-10](../../findings/admin-browser/AC-10.md), [BN-11](../../findings/client-bundles/BN-11.md). Each finding's file has the evidence.

## The work

### Commit 1 of 1: scripts/bundle-budget.mjs: every route's first scripts against a baseline, and eight marker counts

- **create** `scripts/lib/bundle-budget.mjs`: The pure part, node built-ins only, nothing read from process.cwd() (callers pass data). Exports. (1) ROOM = 15_000. (2) MARKERS, an array of { key, text, only? } in this order: { key: 'supabase', text: 'GoTrueClient' }, { key: 'zod', text: 'ZodError' }, { key: 'editor', text: 'ProseMirror' }, { key: 'builderEnglish', text: 'Set for {size}' }, { key: 'signInEnglish', text: 'Open your authenticator app and type the six-digit code' }, { key: 'storefrontLanguage', text: 'Kommer ihåg om du valde ljusa' }, { key: 'cookiePurposes', text: 'Remembers whether you chose' }, { key: 'commonEnglishOnStores', text: 'is switched off under Settings', only: '/s/' }. Before using each text, check it is in the source with rg -n -F '<text>' src/lib src/components | head -2; if a text has been reworded since 12 November, take the new wording of the same sentence and say so in the commit message. (3) parseStats(json): throws an Error that starts 'route-bundle-stats.json is not what this script reads' unless json is a non-empty array whose every item has a string route, a number firstLoadUncompressedJsBytes and an array firstLoadChunkPaths of strings; returns it. This file is written by Next's build and is not in its docs (node_modules/next/dist/build/route-bundle-stats.js), so an upgrade may change it: the error must be loud. (4) routeBytes(stats): an object route -> bytes with its keys sorted. (5) markerCounts(stats, textOf): textOf(chunkPath) returns the chunk's text; for each marker count the routes (only those whose route starts with marker.only when it is set) that have at least one chunk in firstLoadChunkPaths whose text includes marker.text; return { key: count }. Read each chunk once (cache in a Map). (6) problems(now, baseline): now and baseline are { routes: { route: bytes }, markers: { key: count } }; returns a list of strings: for each route in now.routes not in baseline.routes: '<route>: new route at <bytes> bytes; run node scripts/bundle-budget.mjs --write to add it'; for each route more than ROOM above its baseline: '<route>: <bytes> bytes, baseline <b> (+<diff>). Find the import that grew it (node docs/audits/bloat-review-2026-11/scripts/markers.mjs and docs/performance.md say how); a budget is not raised to pass.'; for each marker whose count is above the baseline's: '<key> (<text>) is in the first scripts of <n> routes, baseline <b>'. (7) fallen(now, baseline): strings for each route more than ROOM under its baseline, each route in the baseline that the build no longer has, and each marker count under its baseline, each ending '; run node scripts/bundle-budget.mjs --write in this change'. (8) lowered(now, baseline): the baseline to write: for every route of now: the new figure when it is lower than the old one or the route is new, else the old figure; routes gone from the build are left out; markers: Math.min(now, old) per key, a new key takes now.
- **create** `scripts/bundle-budget.mjs`: The command, run from anywhere (root = path.join(import.meta.dirname, '..'), as scripts/ratchet.mjs). It reads <root>/.next/diagnostics/route-bundle-stats.json; when the file is missing it prints 'No .next/diagnostics/route-bundle-stats.json: run pnpm build first.' and exits 1. It builds now = { routes: routeBytes(stats), markers: markerCounts(stats, (p) => readFileSync(path.join(root, p), 'utf8')) } (the chunk paths in the file are relative to the repository root, for example '.next/static/chunks/33fehdj3n8030.js'). Sanity check on the markers: for each marker, when its text is found in NO .js file under <root>/.next/static/chunks at all (read the folder once), print '<key>: the marker text is in no chunk; the library or the sentence changed, update MARKERS' and exit 1; a marker may be in 0 routes' first scripts and still be in a lazy chunk. Modes. No flag (the check CI runs): read scripts/bundle-budget.baseline.json; print one line per marker '<key>: <n> routes (baseline <b>)'; print the five heaviest routes; print every string of problems() and fallen(); exit 1 when either list is not empty, else print '<n> routes within 15,000 bytes of the baseline' and exit 0. --write: refuse with exit 1 and the list when problems() has a route over its room or a marker above its baseline ('The bundle budget only falls. Not written:'); else write lowered() (new routes added, fallen ones lowered, gone ones removed) with JSON.stringify(x, null, 1) and a final newline, and print how many routes fell. --first: write now as it stands, only when the baseline file does not exist. There is no flag that raises a number.
- **create** `src/lib/bundle-budget.test.ts`: Vitest unit test of the pure file ('../../scripts/lib/bundle-budget.mjs'). Cases: parseStats throws on {} and on [{ route: '/x' }] and returns a good array; routeBytes sorts; markerCounts on three made-up routes and two made-up chunk texts counts a marker once per route even when two of its chunks hold it, and honours `only: '/s/'`; problems(): a route 20,000 bytes over its baseline is reported and one 14,000 over is not (this is the planted 'branch that adds a 20 KB import to one admin route'); a route missing from the baseline is reported; a marker count one above its baseline is reported; fallen(): a route 16,000 under, a route gone from the build and a marker count one under are each reported; lowered() never returns a figure above the old one for a route that was in the old baseline, drops a route the build no longer has, and adds a new route.
