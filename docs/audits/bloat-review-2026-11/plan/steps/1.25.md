# Step 1.25: Count tag refreshes and store page draws in production

Phase 1 (Budgets, so it stays removed) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Every line is now named (the flush that retries, note() that cannot throw, the second shop line, the clock that a prerender allows, a manifest check of the store pages' mode), but it adds a migration, wraps every cron job and the function every cache refresh goes through, and puts an after() in the storefront's market layout, so a wrong but compiling edit could stop owners' changes reaching pages or slow store pages, and a stronger model reads commits 2 and 3. A smaller model may still do commit 1 alone. *(Rating checked twice, 12 November.)*

**Goal:** Every refresh of a cache tag and every draw of a store's layout is logged as one line and counted per day by tag family, subject and caller in a small table of our own, and Platform, Usage and limits shows a week of them and flags a store whose tag a job refreshed more than 10 times in a day.

**Why:** Today nothing in production sees why a cached page is drawn again: the alt-text job refreshed one store's tag 10 times in 10 runs and only this review found it (0 counts kept). After: a week of refreshes and draws by family on the platform's screen, a flag at 11 job refreshes of one store's tag in a day, and 0 job refreshes on a quiet day for a store where nothing changed.

**Closes:** GAP-server-s6. Each finding's file has the evidence.

### Commit 2 of 3: refreshTag() logs and counts each refresh by family and caller

- **create** `src/server/cache-events.ts`: Starts with `import "server-only";`. (1) `import { AsyncLocalStorage } from "node:async_hooks";` and `const jobScope = new AsyncLocalStorage<{ job: string }>(); export const inJob = <T>(job: string, run: () => Promise<T>): Promise<T> => jobScope.run({ job }, run); export const currentJob = (): string | null => jobScope.getStore()?.job ?? null;`. (2) `export function tagParts(tag: string): { family: string; subject: string }`: `family` is the text before the first `:` (the whole tag when there is none), cut to 40 characters; `subject` is the text between the first and the second `:` (empty when there is none), cut to 64 characters. Examples for the comment: `store:demo` gives store and demo; `catalog:7b1e...` gives catalog and the id; `catalog` gives catalog and empty; `terms:platform:article` gives terms and platform. (3) A module-level `Map<string, { kind; family; subject; source; count: number; statements: number }>` keyed by `kind|family|subject|source`, and `export function countCacheEvent(kind: "refresh" | "draw", family: string, subject: string, source: "action" | "job" | "route" | "render", statements = 0): void` that adds to the map and then, when a module-level `let flushScheduled = false` is false, tries `after(() => flushCacheEvents())` (after from `next/server`) inside try/catch and sets flushScheduled = true only when that call did not throw (outside a request `after` throws: flushScheduled stays false, so the next event in a request tries again). The whole body is inside try/catch and never throws. (4) `export async function flushCacheEvents(): Promise<void>`: set flushScheduled = false, take the map's entries and clear it, return if empty, and write them in one statement: `insert into commerce.cache_events_daily (day, kind, family, subject, source, count, statements) values ... on conflict (day, kind, family, subject, source) do update set count = commerce.cache_events_daily.count + excluded.count, statements = commerce.cache_events_daily.statements + excluded.statements, updated_at = now()` with `day` as `(now() at time zone 'utc')::date`; catch any error and `log("warn", "cache.events_failed", { rows }, error)` (a count must never break a request). (5) `export async function cacheEventsWeek(now = new Date())`: read the last 7 UTC days through `typedRows()` with `col` (src/server/typed-rows.ts), `select day, kind, family, subject, source, count, statements from commerce.cache_events_daily where day > (now() at time zone 'utc')::date - 7 order by day desc, kind, family, count desc`, and return `{ rows, flagged }` where `flagged` is the rows with `kind = 'refresh'`, `source = 'job'`, `subject <> ''` and `count > JOB_REFRESH_FLAG` (export `const JOB_REFRESH_FLAG = 10`). (6) `export const pruneCacheEvents = () => db().execute(sql`delete from commerce.cache_events_daily where day < (now() at time zone 'utc')::date - 90`)`.

## Do not

- Do not await a database write inside refreshTag(), staleTag() or a render: counts are buffered and written after the response.
- Do not change which of updateTag and revalidateTag is called, or their arguments.
- Do not log a person's data: the tag's family and subject (a store's id or slug) only.
- Do not read cookies() or headers() in the market layout for the draw line.
- Do not apply the migration by hand, and do not push commit 2 before commit 1 has deployed.
- Do not use a paid log or observability product to count: the table is the store.
- Do not fix a job that refreshes too often in this step: report it.
