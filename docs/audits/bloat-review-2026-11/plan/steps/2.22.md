# Step 2.22: Read a store without the Stripe SDK and without the whole page model

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. Commit 1 (the Stripe modes, the setup file now proven by an int case, and a 'stores' entry in step 1.8's walker) is fully specified for the cheap model with a review of the test setup, but finding the closure of the theme's schemas inside a 4,319-line module and cutting the remaining chains from stores.ts in commit 3 needs judgement about the page model. A smaller model may still do commits 1, 2 alone. *(Rating checked twice, 12 November.)*

**Goal:** getStore() learns which payment modes have keys without importing the Stripe SDK, and src/server/stores.ts reaches no file that defines a block schema: the theme's part-style schemas, the page-role names and the reserved slugs live in leaf files of the page model.

**Why:** Today every route that reads a store loads the Stripe SDK (189 modules, 212 KB) to check two keys, and builds the whole page model (468 zod schemas in a 4,319-line file, 63 ms and 8.2 MB of heap) for a theme's few fields. After: the five beacons have no stripe module and are each at or under 500 modules and 1.0 MB and under 130 source files, and the store's home is at or under 1,500 modules and 4.0 MB.

**Closes:** [SG-9](../../findings/server-module-graph/SG-9.md), [DP-12](../../findings/dependencies/DP-12.md). Each finding's file has the evidence.
