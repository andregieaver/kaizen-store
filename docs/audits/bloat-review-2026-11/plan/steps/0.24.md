# Step 0.24: Read one page, not all of them

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Each caller's edit is named with its line and the SQL is written out, and the type check, the int comparison and the scan test catch a wrong one, but it changes cached reads behind every store page across about 20 files (checkout terms among them), so a stronger model should read the diff. *(Rating checked twice, 12 November.)*

**Goal:** A reader that wants one published page reads that page (publishedPageById), a reader that wants addresses or titles reads a small index (publishedPageIndex), and listPublishedPages() is left to the readers that draw every document.

**Why:** listPublishedPages() selects every published page of a store with its whole content: 29 documents a call, 79,778 calls and 781 s of statement time in 78 days, through 37 lines of callers of which 13 keep one page. After: at most 14 lines call it, none to pick one page, and 0 of the demo store's 261 prerendered entries keep the page list in their resume data (45 today).

**Closes:** [CA-3](../../findings/caching/CA-3.md), [SD-4](../../findings/storefront-server/SD-4.md), [DQ-2](../../findings/queries/DQ-2.md), [PM-2](../../findings/page-builder-model/PM-2.md). Each finding's file has the evidence.
