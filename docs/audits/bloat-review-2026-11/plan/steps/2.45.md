# Step 2.45: Cut what the largest paint waits for on a themed page

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a stronger model. The step is measure, then choose the cut the table names; only the table commit and the preload commit can be written down fully, and judging Lighthouse noise against a 2-point margin needs judgement.

**Goal:** The launch-theme store's home, product page and listing and Kaizena Flow's front page score a median of 90 or more on a slow phone for seven nights in a row, with a table in docs/performance.md that shows what the largest paint waits for and a font-bytes budget in the nightly file.

**Why:** A themed page scored 83 to 88 with its largest paint at 3.7 to 4.3 s; 90 needs about 3.3 to 3.5 s, and the plan's other cuts take only about 26 KB of the 400 KB the paint waits for. The same page without fonts scored 93, so fonts are the first suspect.

**Closes:** GAP-shopper-browser-s1. Each finding's file has the evidence.

## The work

### Commit 1 of 5: What the largest paint waits for on a themed page: a blocking table in docs/performance.md

- **create** `scripts/perf-blocking.mjs`: A small Node script (ESM, no new dependency) that reuses scripts/perf.mjs's way of running Lighthouse (the same pinned `lighthouse@12.8.2` through npx, the same Chromium from PLAYWRIGHT_CHROMIUM_PATH or CHROME_PATH, form factor mobile). Arguments: one or more page addresses. For each address it runs Lighthouse five times in each of four modes and prints the median largest paint (ms), blocking time (ms) and score per mode as one Markdown table row: (a) nothing blocked; (b) fonts blocked: --blocked-url-patterns='*.woff2' ; (c) scripts blocked: --blocked-url-patterns='*/_next/static/chunks/*.js' ; (d) stylesheets blocked: --blocked-url-patterns='*/_next/static/css/*' and '*/_next/static/chunks/*.css' (read the page's HTML first and block exactly the href of each <link rel="stylesheet"> it has). It only reads public pages with GET; it sends nothing else. It needs no key and no paid service: Lighthouse runs locally or in the GitHub Actions job of step 1.14.
- **edit** `docs/performance.md`: Add a section 'What the largest paint waits for (step 2.45)'. Run node scripts/perf-blocking.mjs against four production pages: the launch-theme demo store's home, one product page and one listing (the three addresses the nightly workflow of step 1.14 reads; copy them from that workflow file) and https://kaizenaflow.com/. Paste the table: one row per page and mode with largest paint, blocking time and score, and under it one sentence per page naming the mode whose blocking moved the largest paint most. Also paste the week of nightly figures of step 1.14 (seven rows per page). This commit changes no code the site runs.
