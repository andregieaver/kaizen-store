# Step 2.31: Keep the session without the whole Supabase client

Phase 2 (Load on demand) of `docs/audits/bloat-review-2026-11.md`. Effort M. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Commit 2 is now one scan rule with an empty starting list; commit 1 builds the admin's session client by hand from @supabase/ssr's and supabase-js's options (now listed exactly), and a refresh that fails after an hour would not show in any check, so a stronger model reads its diff. A smaller model may still do commit 2 alone. *(Rating checked twice, 12 November.)*

**Goal:** The admin keeps its session fresh with Supabase's auth client alone, so an idle admin screen loads none of Supabase's realtime, storage or database client; uploads still load the full client on the press.

**Why:** After step 0.9 the whole Supabase client (259 KB) still loads on every admin screen once it is idle, leaving an idle store home near 930,000 bytes of script (1,428,740 at the review); the auth client alone is about 117 KB, which brings the idle home to 800,000 or less.

**Closes:** GAP-owner-browser-2. Each finding's file has the evidence.
