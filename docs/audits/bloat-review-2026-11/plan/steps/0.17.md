# Step 0.17: Cut what a menu and a progress poll cost in the admin

Phase 0 (Before the doors open) of `docs/audits/bloat-review-2026-11.md`. Effort S. Read [how to carry out a step](../README.md) first.

**Who:** a smaller model; a stronger one reads the diff before the push. Commits 2 and 3 are given line by line and held by unit and int tests with exact content; commit 1 adds a process-wide memo to permissionOfPath(), which decides every role's menu, so its diff wants a read even with the new per-role equality and read/write cases. A smaller model may still do commits 2, 3 alone. *(Rating checked twice, 12 November.)*

**Goal:** The store menu is built with one memoised permission lookup per item, progress polls stop in hidden tabs and the Dream Factory's poll asks its run and not for a whole redraw, and the notice badge's count costs two statements.

**Why:** Today a menu build makes 220 lookups and takes about 125 ms of blocking CPU on every shell render; after, 110 lookups in under 2 ms. The badge's count runs 4 statements every minute per owner tab; after, 2.

**Closes:** [AD-1](../../findings/admin-server/AD-1.md), [AD-9](../../findings/admin-server/AD-9.md). Each finding's file has the evidence.

### Commit 2 of 3: Progress polls stop in a hidden tab, and the Dream Factory's asks its run *(a smaller model may do this one alone)*

- **create** `src/lib/progress-poll.ts`: Pure, no imports. Export `async function progressTick(o: { visible: boolean; status?: () => Promise<string | null>; last: { value: string | null }; refresh: () => void }): Promise<void>`: if !o.visible return; if o.status is undefined call o.refresh() and return; otherwise `const now = await o.status().catch(() => null);` if now === null return (a failed ask is caught by the next tick); if o.last.value === null set o.last.value = now and return (first answer: the page is already current); if now !== o.last.value set o.last.value = now and call o.refresh().
