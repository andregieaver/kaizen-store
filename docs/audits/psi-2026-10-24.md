## Audit scope and environment

**What the app is.** Kaizena Flow (code name `kaizen-store`) is a multi-tenant e-commerce platform operated from Norway and selling EU-wide: storefronts at `/s/{store}/{market}` (or a store's own domain), an admin at `/admin` with three levels (platform, owner, store), a shopper chat and support desk, an AI manager for owners and platform admins, an MCP server for a sister product (Kaizen Life), and a WordPress plugin.

**Stack (verified from the lockfile and the running app).** Next.js 16.3.6 (App Router, `cacheComponents`, `src/proxy.ts`), React 19.2.8, TypeScript 5 strict, Tailwind 4, zod 4.6.5, Drizzle 0.45.3 (schema and migrations only; reads are raw SQL), `pg` 8.23 with a pool of 5 behind Supabase's transaction pooler, Vitest 5, Playwright 1.63, pnpm 10.33, Node 22. Supabase project `ybsozesfuxuitoacntfo` in `eu-west-1` (database, Auth, Storage, `pg_cron`, Vault); Vercel with functions pinned to `dub1` (confirmed by production's `/api/health`: `region: "dub1"`, commit `2ac2fa0` = this HEAD); Resend for email; Stripe Connect (Accounts v2) and Mollie for payments; carriers Bring, PostNord, Porterbuddy, Helthjem; AI through an OpenAI-compatible client to six selectable providers (gateway, Mistral, OpenAI, OpenAI EU, Google, custom), today direct OpenAI per the residency register; Slack webhooks; Brønnøysund's open register.

**Surface map.** 421 pages, 157 route handlers (71 under `/api`: chat and support, consent, A/B, forms, reviews, stock requests, feeds, fonts, webhooks for Stripe ×3, Mollie, Resend, the Vercel log drain, 11 cron routes, the WordPress API, MCP, the inline editor's pass routes), 192 server-action files (550 store-bound actions), 11 `pg_cron` schedules plus one Vercel cron, 440 migrations. Data model: 300 tables in the private `commerce` schema (all with RLS enabled, zero policies, no grants to the API roles: deny-all for PostgREST, reached only through `DATABASE_URL`), 260 triggers, 439 functions, 700 foreign keys, 1,089 check constraints, 574 unique indexes, vector stores for products, knowledge and media (`pgvector`), Storage buckets (public: `product-media`, `page-videos`, `avatars`; private: `documents`, `imports`, `exports`, `digital-files`), `'use cache'` with tags for catalogue, store and pages, a `search_cache` table.

**Data classification.** Personal data: shoppers (customers, orders, addresses, emails, phones, support conversations, reviews, consents, subscribers, visit hashes), owners and staff (accounts, access requests, audit log, assistant conversations and memories), hosts (tax details, DAC7). Financial: orders, payments (facts only; card data never reaches the servers), invoices and credit notes, payouts, gift-card ledgers, Work invoices. Credentials: provider tokens and carrier secrets (AES-GCM encrypted), recovery codes (HMAC), webhook secrets. Special categories: none by design, but free-text notes and support messages can carry health information for clinic-type stores; no children's data handling. The register is `src/lib/personal-data.ts` (~130 tables), enforced by a test.

**Agentic layer.** Shopper chat and AI-first support (`src/server/chat-agent.ts`, `support*.ts`, tools over the store's own reads, customer actions on Confirm, staff requests for everything else); the AI manager (`src/server/owner-assistant.ts`: 140 owner tools, 28 platform tools, 9 manager tools, gates `send`/`public`/`spend`/`domain`, approvals kept and run on a yes, per-account memory, voice and live voice); the silent partner for support staff; background AI jobs (`page_ai_jobs`, pictures, theme shots, summaries, alt texts, embeddings) run as claimed rows by `after()` and cron; an MCP server for Kaizen Life; evals for query understanding and recommendations.

**What was exercised (grade A).** `pnpm install --frozen-lockfile`; `pnpm lint` (0 errors, 79 warnings); `pnpm typecheck` (pass, 2m49); `pnpm test` (874/875 files, 13,887/13,888 tests, one environment-dependent failure, 6m23); `pnpm test:int` against a local PostgreSQL 16 with pgvector built by `scripts/db-setup.mjs --seed` (358/358 files, 3,727 tests, 22m34); `pnpm audit --prod`; `pnpm build` with the e2e Auth stand-in (5m41, 756 static pages), then the real sign-in form for a store owner and a two-step platform admin; 16 pages scanned with axe-core (8 signed in), 7 keyboard walks, response timing on 9 local pages, an add-to-cart walk; direct SQL on the migrated database (RLS, constraints, triggers); `curl -sI` and timing against production's public pages (`/`, `/admin/sign-in`, `/themes`, `/api/health`); one read-only Supabase advisor call by a subagent. **Not exercised:** production signed-in pages (no credentials, none requested), IDOR probes against production, live model calls and prompt-injection runs (no AI key in this environment), Playwright e2e suites (CI runs them), Lighthouse, the Supabase and Vercel dashboards (exposed schemas, PITR, backups), load tests. Those points are grade B or C and say so.

**Rules kept.** No application file was modified; this report is the only new file. No real personal data was read or written; the local database holds the demo catalogue and test fixtures. Production was touched only by unauthenticated GETs of public pages.

No dependency scanning in CI. — Upgrade `next`, `sharp`, `zod` today; add `pnpm audit --audit-level high` to the `static` job and Dependabot.
2. **Backups unconfirmed and restore never rehearsed** — REL-04 (gating), SEC-09 — `docs/runbooks/restore.md:8-10,38-40`; no bucket backup for `documents` (invoice PDFs). — Confirm PITR, run the drill, write RPO/RTO, sync `documents` to a second EU bucket.
3. **Most deploys are not gated by CI** — REL-03, CODE-07, CODE-03 — `.github/workflows/ci.yml:208-218`: a push without a migration deploys at once; the checks "do not hold it back". — Make the deploy hook wait for the `static` job.
4. **No DPIA, no breach runbook, DPAs unsigned, platform AI in the US** — REG-07, REG-06 — `docs/decisions.md:680` (DPIA planned), `docs/residency-register.md` (every DPA "to do", direct `api.openai.com`), grep for a breach procedure: none. — Write the breach runbook and the DPIA for the AI features; sign the DPAs; move the platform's AI to the EU path.
5. **Security headers and CSP only on the pay routes** — SEC-05, SEC-07 — production `/` and `/admin/sign-in` return only HSTS; the admin is frameable; owner CSS and rich text render without a CSP. — A global headers entry and a nonce-based Report-Only CSP on admin and storefront.
6. **The AI manager's prompt lacks the "data, not instructions" rule its tool results need** — AST-01, SEC-12 — `owner-assistant.ts:280-300` (verified by grep) while the chat, partner, summary and replicator prompts have it; one injection eval case in total. — Add the rule and a shared injection corpus.
7. **No observability beyond console lines; cron can stop silently** — REL-02, REL-06 — 193 unstructured `console.error`, no request id, no job-run ledger, the five-minute dispatcher without `maxDuration` (`cart-reminders/route.ts:39-69`). — A JSON logger with request ids and a `cron_runs` table with a "not run" banner.
8. **Owners and staff have no erasure path; platform legal texts shipped unreviewed with a placeholder company name** — REG-03, REG-02 — `personal-data.ts:279-284` (`erasure: "none"`), `platform-legal/en.ts:4-6,13`. — Build account erasure; fill the legal name; get the three platform texts reviewed.
9. **Task parity about half; the agent cannot schedule or initiate** — AGT-01, AGT-04, AGT-11 — no tools for staff, billing, broadcasts, segments, reviews, Work; `scheduleExperiment()` and `scheduledFor` exist with no tool; nothing routes time or events into a turn. No workflow is above L3. — Add the frequent-visit tools gated as the others, and a scheduling/follow-up tool.
10. **Database reads are untyped despite a 12,810-line typed schema** — CODE-02 — ~4,000 `db().execute<Row>(sql\`…\`)` with `Row = Record<string, unknown>`; renames surface only in integration tests. — Typed-row helpers starting with money-carrying queries.

Also notable (verified): all 300 tables deny-all for the API roles with every store query bound to a store id and a 3,670-line permission baseline that passed; the test estate is unusually strong (13,887 unit and 3,727 integration tests, 26 convention scan tests, every migration replayed in PGlite); the consent banner is honest and nothing optional is set before consent; axe found no serious or critical issue on 16 pages including the signed-in admin.
