### Stop on the Pages list (`stopPageJobAction`, `stopPlatformPageJobAction`, `src/server/page-jobs.ts`)

- **Platform.** `stopPlatformPageJobAction` (`platform/pages/actions.ts:336-341`) asks `requirePlatformAdmin()`. That goes through
  `getAccount()`, which returns null for anyone held at their second step (`src/server/auth.ts:202-206,229-233`). It then passes
  `storeId = null`.
- **Tenant isolation.**
  - Every statement has `store_id is not distinct from ${storeId}::uuid` (`page-jobs.ts:41,49,89,96,113`). With a store's non-null id

  - `kind` is compared with two literals and `id` must parse as a UUID (`:84,108,125-129`), so input of the wrong type or another
    store's id ends as "already stopped".
  - The second lookup is also store-scoped (`:96`), so the answer is no oracle for whether another store's job exists.
  - Titles are rendered as text; links take the page's UUID from the database.

  - A stop from the list writes nothing to the activity log, while the AI's `cancel_page_build` is audited (`AUDITED_UNGATED`,
    `src/server/owner-tools.ts:2578`).
  - Picture jobs are stopped by page id within the store whatever the page's type, so `website:write` could stop pictures for a
    product layout's page. This stays inside one tenant and only stops an AI job.
